# rad0010 — opt-in routing-histogram lifecycle evidence

**Status:** untested
**Plan item:** RHP01

RHP01 steps 1–3 only. An isolated `radiance-routing-evidence` source recipe adds read-only instrumentation at the existing per-layer asynchronous histogram producer, DMA event, landed-bank reader, credit and teardown seams. Production recipes are unchanged. All upstream additions are one-line calls into package-owned `core/runtime/bc_moe_remote_evidence.h`. The 32-bank capacity is obtained from Radiance's `kRouteBanks`, never independently configured.

**Off by default.** `RAD_ROUTING_EVIDENCE=1` enables per-rank `RHP01 phase=...` lines on context teardown. Phase groups are prefill, decode, mixed, and draft (the final draft row represents several same-step passes). Metrics: unique `issued` layer/step histogram generations, `produced` calls, `completed` event-ready generations, `credited` once-only consumed rows, `overwritten` uncredited destroyed generations, `pending` uncredited surviving generations, `in_flight` pending transfers, weighted `produced_passes/credited_passes/lost_passes`, oldest-uncredited age (source steps), credit delay p50/p95 (capped at 64 steps), ring occupancy high-water, latest source step and overflow/rejected-event counters. For each phase, `issued = credited + overwritten + pending` with no counter overflow. A completed row may subsequently be overwritten; `completed` is *not* an extra term in this sum.

The existing device-to-host histogram is the only data producer. No new GPU transfer, device event, hot-path GPU/device synchronisation, or extra histogram row read is added. The existing `rad_event_query` gates bank selection. Event-ready rows still wait behind older uncredited rows for that layer; recycled/duplicate banks cannot receive credit. Extra event queries at **teardown only** happen *after Radiance's existing Ctx stream sync*, to distinguish completed-but-uncredited from truly in-flight rows. Teardown does not silently credit them.

HeatEngine still receives the existing histogram and exact `last_histogram_reports` multiplicity. If HeatEngine is static/deterministic/all-resident and `--expert-stats` is absent, an opt-in diagnostic-only drain calls the same `next_histogram`/ `mark_credited` methods without enabling adaptation or creating a collector. If `--expert-stats` is enabled, Radiance's normal shutdown drain applies the last landed rows before this report. Outputs are rank-local; do not sum identical mirrored tensor-parallel histograms into model-global totals.

**Important limitations:** No GPU reproduction has been run. A 32-bank ring is lossy on sustained run-ahead; the new counters classify loss rather than prevent it. Rows can also be destroyed when a contiguous DMA [lo,hi] overwrites an unchanged layer's older bank. Step 4's possible bounded staging/retirement/backpressure is explicitly deferred. This package is not promoted to production or accepted as a source for remote-owner placement until hardware coverage, quality and performance are measured.
