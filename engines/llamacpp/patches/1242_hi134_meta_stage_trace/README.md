# HI134 META stage trace

This package contains the optional META-stage attribution trace hook used by
HI134 profiling. It is diagnostic instrumentation, not a runtime selection
policy. The trace schema and profiling workflow are described in
`docs/reference/tooling/PROFILING.md`; patch identity and lifecycle metadata
are authoritative in `patch.toml`.

## Real hardware investigation (2026-09-12)

HI134 (this patch's owning plan item, `state = "completed"`) already ran
real profiling campaigns against META reduction on Brutus's heterogeneous
topologies using the proper `bigcherry profile-campaign` pipeline
(rocprofv3 --sys-trace, multi-GPU agent validation) -- see HI134's own
notes for that real evidence.

Attempted an independent ad-hoc confirmation this session (build with
`extra_cmake_args=[]`, force `GGML_HIP_REDUCE_PLAN=meta` +
`GGML_HIP_REDUCE_TELEMETRY=<path>`): no telemetry file was produced.
Traced the real cause via `strings` on the compiled `libggml-hip.so.0` --
neither `GGML_HIP_REDUCE_TELEMETRY` nor `GGML_HIP_REDUCE_PLAN` appeared
anywhere in the binary, confirming `GGML_HIP_DISPATCH` (which the whole
telemetry mechanism, including this patch's stage hook, is compiled
behind) was never defined for that build -- `ggml/src/ggml-hip/CMakeLists.txt`
only defines it `if (GGML_HIP_AUTOTUNE OR GGML_HIP_DISPATCH_REPLAY)`,
neither of which an ad-hoc `build_tree()` call sets by default.

Rebuilding with `-DGGML_HIP_DISPATCH_REPLAY=ON` got further but hit a real,
documented prerequisite: `ggml-hip/CMakeLists.txt` requires
`hip-autotune-registry.inc` to exist, generated by `python -m bigcherry
generate` before configuring -- a real pipeline step this ad-hoc single-patch
build script didn't run. Did not pursue further: HI134's own campaign
already used the correct, full tooling path (which runs `generate` as part
of its normal flow) and produced real evidence; redoing that through an
ad-hoc script would duplicate already-completed work rather than add new
evidence. This investigation is recorded here as a real, useful finding
about the ad-hoc build script gap itself (relevant to PA33's future
patch-validate orchestrator, which should call the correct pipeline steps
rather than a bare `build_tree()`), not as a gap in 1242 or HI134.

## Disposition

`state` stays `"untested"` -- `kind = "diagnostic"` (instrumentation, not a
production dispatch patch). HI134's real campaign evidence stands as this
mechanism's actual real-hardware proof; no further validation work is
needed here.
