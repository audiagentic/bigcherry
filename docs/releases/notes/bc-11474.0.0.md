## New and changed

- Flash-Next long-context prefill is 13% faster at 100K tokens and 28% faster at 200K tokens on AMD GPUs by enabling sparse flash attention. (QFP25, QFP17)
- Flash-Next long-context prefill gains a further 4% with a 1024-token micro-batch, made to fit by chunked attention masks. (QFP17)
- Flash-Next long-context prefill gains a further 3-6% from the tiled QSA indexer backported from upstream. (QFP17)
- Groundwork for running MoE models whose experts do not fit in VRAM: scheduler copy callback, optional expert cache, and a range-aware expert matmul primitive. (MET01, MET02, MET04)
- Scheduler copy callback for host-held MoE experts is now part of the validated build (no speed or output change by itself; groundwork for expert caching). (MET01)
- Experimental expert-parallel tensor split for Qwen4Exp MoE models, with separately configurable expert placement per GPU. (MET02, MET04)
- Flash-Next uses about 1.4 GB less VRAM on the R9700 at full context, with identical output and speed. (MSM03)
- Diagnostics and experimental per-card memory sizing for multi-GPU tensor split. (MSM01, MSM02, MET04)
- Expert-parallel MoE no longer re-quantises the same activation for every routed expert; output is unchanged and decode is slightly faster. (QFP30)
- Opt-in: the context-sized attention mask is no longer copied to cards that hold no attention (in qualification). (MSM03)
- Opt-in: the tensor split can size its working buffer per card at load, returning 140 MiB on each XTX and 642 MiB on the R9700 at 245K context. (MSM01, MSM02, MSM03)
- Flash-Next prefill is about 1.5% faster: two per-layer kernels no longer do a software 64-bit division per element. (QFP35)
- Opt-in: one scheduler reserve when speculative decoding switches on removes a re-plan per prefill chunk. (QFP32)
- Flash-Next prefill is about 2% faster: the expert routing helper now works on a batch with eight warps per expert. (QFP36)
- Flash-Next prefill is about 4% faster: the 4-row hyper-connection projections no longer go through a general GEMM. (QFP34)
- Flash-Next decode at long context is about 13-14% faster (gathered sparse attention), and its output is repeatable from run to run. (QFP40)
- The low-VRAM tensor-split layout is now the default (checked on Flash-Next, the 27B and Gemma 26B). (MSM02, MSM03, QFP31)
