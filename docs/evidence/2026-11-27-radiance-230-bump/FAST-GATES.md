Review baseline BigCherry main f818ec5da (includes 2020.23.2, PRs #1714, #1717 and #1718); target Radiance v2.3.0 3b13fd32663ef52252a7f0be255523480aa22ffe, previous b6b8751cccb0e834a13ae9e5afca824ee9a487aa. Source triage and failed patch probes remain in draft PR #1713. MEN24 owns execution sequence, not a new test framework.

## Review findings and decisions

* **Duplicate full build is real.** radiance_bump.ComponentGate.build configures and executes unqualified `cmake --build ... -j`, then builds all components. compile_checks also runs composition-anchors, composition-syntax, plugin ABI and component CTest. pin_bump.run_phase_lane_build later builds the lane. Use targeted compile and discrete tests while repairing code, then build/link one exact canonical lane once for a candidate intended for release; run ABI, component tests and installed tests against that output. Until the existing orchestrator supports reuse, do not label a manual scoped pass as completed formal compile phase or skip a required release gate. Reuse MEN24/MEN16; no new command or state machine. Reusing a different target set/flags/recipe is not equivalent.
* **Composition syntax is not general coverage.** CompositionGates.syntax uses production patch touched_files; compose_check.affected_units resolves local includes under libr4d only and checks gfx1100/gfx1201. It misses core/arch/ABI changes, libr2, owned overlays and new/renamed/header dependencies outside that graph. Resolve exact affected closure via existing RCS26 owner metadata/compiler dependencies; when closure unknown, widen compile to affected component, not automatically all hardware tests. Run actual selected build target host/device and link/export when boundary changes; excluded upstream unit does not prove its overlay.
* **Harness exists but is narrow.** unit_harness.py already has plan, build, measure, overlay-build, overlay-measure and run; unit_families.toml presently defines IQR and its three overlay cases, support_units include old r4d_gemm_fp8a8 (renamed r4d_gemm_i8a8 in target). Its PLUGIN map only gfx1100/gfx1201, --unit is resource-only, saved /graph is declaration not execution. Fix only target naming/closure and required missing oracle cases as encountered (M64, gated, U6/U7 and group256, weighted head; gfx1030/helper rows use existing libr2/worker tests). Do not build universal new harness, duplicate catalogue, runtime graph or separate test store. Use exact --tree, --reference/--release and BDF; test isolated plugin against same-target baseline if ABI changed. Never dlopen an ABI-incompatible old reference in a new harness; use independent old-run output/receipt or matched same-pin control. Do not compare numerical changes across unrelated pin/provider changes and attribute them to one patch.
* **Acceptance currently incomplete.** run_phase_accept calls acceptance.accept without explicit candidate lane; engine.toml has helper-ab/helper-kld only, latter self-records reference, 27B native quality missing. MEN17 owns minimal correction to pass exact candidate build and independent baseline. Existing gate E installation/lifecycle receipts do not prove model quality or all paths. For release combine the existing two canaries with shortest affected paths; do not repeat the same model run for every patch. A separate full S18 migration or PWR12 qualification is not required just because the pin moved; affected power controls still use existing owner/restore rules.
* **New RSC16–18:** shared capacity L/S/C feature and scheduler cleanup are separately pending. Reconcile current rad0011/rad0029/rad0028/rad0036 against candidate native per-rank headroom and admission changes; preserve legacy configuration/admission, uneven rank split and prefill governor. Use exact rounded group/page and rank-local shortfall unit cases (65 tokens at block16 -> 5 pages, 65+1 separate contexts -> 6; no new shared-mode allocator), existing VTP33 replay/serving resource tests, scheduler progress/rollback fixture. Distinguish preallocation proposal from observed carve and front-ready. Carry exact input/receipt for affected existing profiles to final lane; no 512K YaRN shared-mode experiment, new capacity knobs, flex/host geometry redesign, or new shared mode to unblock bump. If a legacy regression exists fix the demonstrated issue here, coordinate the owning plans; new-mode tests remain RSC16–18.
* **New XDP11 / rad0062:** #1718 recovered converter tooling and historical evidence; not a serving replacement or qualified converter on every ISA. rad0062 is untested, not in serving-core; target libquant/CMakeLists.txt still has LQ_HIP_SRC/LQ_CARD block, no RAD_QUANT_GPU_TARGETS. Preserve untested status and source recipe admission; run existing hermetic patch test / anchor rebase only when touched, no full conversion or repeated calibration for bump. If promoting converter separately, code-object inventory + one synthetic conversion under lease first, full recipe belongs to XDP11. Keep current immutable IQ6R container. Do not add to production recipe or enable it by accident. New upstream native converter reuse is unrelated to fat-binary coverage.
* **Encoding retirement:** actual four configured files show no retired block-FP8, MXFP4, M2XFP4 or ParoQuant plane set. Do not port or GPU-benchmark those kernels solely to preserve history; archive existing packages and evidence when dependency/actual row selection permits, not before. Flash-Next E4M3 row codes, E4M3 scale planes, FP8 KV, IQ8R/IQR and both drafter types are distinct live requirements. Native int8 expert path is promising, not proven. Keep local gfx11/gfx1030 providers where native coverage is absent. Do not mandate native libr3d migration to complete bump.

## Cheapest sufficient gate (per coherent change, not per commit)

| Change | First / normally sufficient development test | Escalation trigger |
|---|---|---|
| Patch anchor/rename only | Existing patch test + composition check; affected host/device compile; verify unchanged replacement semantics | Changed call/layout, missing closure or new behavior -> appropriate following row |
| Host option/ABI/row registration | Tiny existing parser/registry/layout/export fixture, size/offset/fingerprint and declined-row check; compile affected target | ABI change -> all consuming plugin rebuild/link at single integrated lane; native ABI44 vs local composed ABI number not proof |
| One kernel body/layout | Named family or overlay small plugin; independent oracle/hash on actual changed shape, representative normal and edge/tail, resource record | If arithmetic/layout changed, full required affected form/boundary coverage; replay only changed/performance-critical rows, cold/warm if relevant; failure or noisy/inconclusive -> expand targeted points |
| Collective/helper/TP | Existing discrete collective or worker harness, one affected rank/route/geometry and failure path | Inter-rank graph, shared rendezvous or service contract changed -> short multi-device/remote handoff test once; do not run whole model for each edit |
| Memory/KV/scheduler | Existing planner/allocator/scheduler fixture; exact per-rank/group bounds, legacy parity, one boundary/shortfall and progression case | Changed live allocation/accounting/attention -> targeted capacity + short mixed-length actual runtime check on final lane; not new-mode rollout |
| Converter/build-only | Existing CMake/patch fixture, code-object inspection, tiny synthetic conversion only if converter behavior/device target changed | Full conversion only for actual converter promotion/replacement, not existing-serving bump |
| Docs, evidence, archival | Link/diff/lint/recipe membership check; no GPU | If archive changes selected build/provider, test actual affected selection and dependency |

No new fixed sample counts, universal cross-product, repeated ABBA or full-family replay for pure rename. Use existing required oracle/coverage and measured noise standards, not arbitrary shortcuts. Resource-only and reduced replay are labelled scoped/diagnostic until all required affected cases covered; no required skipped/hashless/unknown pass. Existing certified unchanged evidence may be reused only where exact relevant source, ABI, layout, geometry, provider, toolchain and contract are demonstrated compatible; no blanket cross-pin reuse. Keep logs, results, rejected experiments and archive provenance. Missing oracle: smallest real test in owning harness; if it needs engine state, one focused integrated test, not a new framework.

## One release checkpoint, not repeated engine runs

1. Freeze exact target and selected composition, compare prior working config/headers; reconcile ABI and patch chains coherently. Re-run affected patch tests, rewrite checks and focused compile as edits land. Use existing compile groups/owned units; heavy builds nice -n 19, one at a time. No GPU for static checks.
2. Run discrete selected families/worker/collective tests using small queued leases. Map required rows to actual model/arch/role, include drafters and helper workers; do not treat declared graph as execution. For unchanged row with proof, reuse instead of repeat. Resolve failures before full build.
3. Build the complete candidate runtime once (normal target set, no R3_ONLY), link/check plugin ABI and relevant declared component tests; reuse the identical lane for installation and native inspection. All 18 current YAMLs: parse/semantic comparison and model/graph/row/admission preflight, including exact helper/rank/kv roles; preflight may need leased device allocation, no live service changes. Missing coverage blocks release, not a reason to automatically run 18 full engine benchmarks.
4. At release only, run smallest installed generation canaries covering each of four existing containers and distinct changed serving capabilities (IQ8R TP2/TP3, IQ6R TP3, Flash-Next TP1/TP2 helper modes, RDNA2 roles, existing cache modes). Combine tests in same load where possible; equivalent native-resolved variants share evidence; changed concurrency/capacity check actual allocator and representative short/mixed lengths, full-length test only where prior capacity/actual carve cannot otherwise be established or allocation/scheduler changed at that boundary. Verify accepted draft tokens, actual row/helper execution, measured capacity and no meaningful quality/perf regression. Reuse existing MEN17 matched independent baseline and existing Gate E installed stop/rollback; targeted paired repeats only on changed perf or uncertain results. Not full historical benchmarks, all context lengths, GPU permutations, new RSC16 shared mode or XDP11 conversion. A short canary proves generation, not 262K capacity by itself. If no proof for a distinct affected capability, extend just that case or keep release blocked. No silent model conversion, lowered context, removed configuration or disabled drafts.
5. Archive proven unnecessary code with evidence; final audit and deliberate qualified promotion. Planning merge is separate from actual pin/release merge, current 2.2 pin stays on main until #1713 passes. Bump implementation can progress incrementally without waiting for unrelated pending programmes.
