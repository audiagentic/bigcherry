# Serving measured-writer stop: baseline evidence

Baseline: `35744c47d`. The CPU-only Release serving test and its dependencies built successfully at low priority (`nice +19`, two build jobs). Repeating the complete `bc_serving_test` yielded **2 failures in 12 normal runs** and **1 failure in 12 CPU-loaded runs** (four competing busy loops on the test's four pinned cores).

All three local failures were the unrelated existing forced-placement negative-case report (`helper0 did not report its forced placement`), rather than the measured-writer cancellation reported by CI and release builds. These are full-suite rates, not an assertion that the specific writer race was observed locally.

Source analysis: the owner returns false from its event-driven planning wait on operator stop; `run_planning_child` verifies writer exit then throws `PlanFailed`. The plan callback boundary erases exception identity and the owner records a failed plan instead of a clean stop. The production fix should preserve a typed stop result through that boundary and retain verified cleanup, with no new timeout or retry.

## Stage 2 — production cancellation and test synchronization

- **Two contributing paths identified:** the `serve_and_stop` test's fixed 15-second watchdog unconditionally sent `stop` when planning took longer under scheduler contention; this could interrupt the still-running measured writer. Independently, the owner classified a legitimate stop during planning as `PlanFailed`, propagating a hard failure even after reaping the writer.
- **Test synchronization:** removed the watchdog-based forced stop. The test instead polls the owner's persisted `running` state and only then sends a control-socket stop; the existing CTest test-wide timeout bounds a genuinely hung run. Poll delays schedule rechecks and do not authorize a stop.
- **Production correction:** introduced `PlanStopped` to distinguish cancellation from plan refusal; preserved original plan exception identity through the guarded plan callback boundary; converted writer, measuring helper/readiness, engine, and VRAM-release wait cancellation to typed stop; and returned a successful terminal `stopped` only after the owner had verified child teardown, retired transport and restored power. Quality scoring still reports an interrupted score as a non-success.
- **Deterministic regression:** added a fake native-v3 owner case raising a real operator signal at the measured writer's registered start gate (event-driven, no sleep), checking stopped state, empty errors, no live processes, power restore and shared-memory retirement. Updated session stop-during-plan expectations.
- **Build and immediate validation:** `bc_serving_test` and `bc_session_test` rebuilt successfully at `nice +19` with two concurrent build jobs. One complete `bc_serving_test` run **passed** with the new writer-stop regression (before removing the original 15-second test watchdog); after that watchdog change a complete `bc_serving_test` run **failed** in the independent forced-placement negative case, not in the new writer-stop case. Session CTest groups 1–4 and host-start: **5/5 passed**, following a diagnostic-format compatibility fix found in an initial 4/5 run.
- **Stage status:** production fix and targeted regression committed, but **not yet gate-ready**: repeated 50+50 and full serving suite remain for Stage 3; existing forced-placement report flakiness must be resolved without a timeout extension or retry mask.
