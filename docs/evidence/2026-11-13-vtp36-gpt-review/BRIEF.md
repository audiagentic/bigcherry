# Brief: detailed review of TP3 performance (VTP36) - native Radiance, XTX + XTX + R9700

Work READ-ONLY: no edits, builds, GPU programs, commits or pushes. Return the full report as your answer.

## The system

- Engine: Radiance (C++/HIP), upstream pin v1.17.0, plus BigCherry managed patches. Plugin `qwen35_fp8` (MXFP4) and
  `qwen35_w8a8` (int8). Kernels: libr4d (gfx1201) and libr3 (our gfx1100 port of libr4d, generated by
  `components/libr3/r3_rewrite.py`).
- Model: Qwen3.8-27B dense: 64 layers (16 full attention, 48 Gated DeltaNet), hidden 5120, FFN 17408, DFlash2
  speculative drafter depth 3, fp8 KV.
- Cards: rank 0 and 1 RX 7900 XTX (gfx1100, 24 GB, PCIe Gen4 x8), rank 2 R9700 (gfx1201, 32 GB, Gen4 x4), each on its
  own CPU root port of an i7-12700KF. **No GPU peer-to-peer**: every collective is host-staged through pinned
  host-memory mailboxes. gfx1100 emulates fp8 but runs int8 natively.
- TP3 world: `--tp-ownership kv=1,1,2;ffn=...;lk=..;lv=..` sets per-rank shares per layer kind (rad0018/0019). Layouts
  `qwen27b-tp3` (MXFP4 6/6/12 throughput split), `qwen27b-tp3-capacity`, `qwen27b-tp3-int8` in
  `engines/radiance/layouts/qwen27b.toml`. Layout tuning: `tune_pin all_reduce:nblocks=4,nthreads=256`,
  `pipelined_prefill auto`, `pipelined_prefill_min_rows 256`.

## Current numbers (2026-11-12, build 8a6f2776, 3x ABBA)

| | 1 / 4 / 6 / 8 streams tok/s | one-prompt prefill tok/s at 512 / 2048 / 8192 |
|---|---|---|
| MXFP4 TP2 (two XTX) | 83.1 / 199.9 / 194.3 / 224.2 | 1595 / 2384 / 2846 |
| MXFP4 TP3 | 115.6 / 222.7 / 214.2 / 239.3 | 1848 / 1919 / 2709 |
| w8a8 TP2 | 65.3 / 175.9 / 167.9 / 194.4 | 1438 / 1487 / 1903 |
| w8a8 TP3 | 83.6 / 188.0 / 179.2 / 213.1 | 1547 / 1615 / 2181 |

Profiles (VTP31 experiments 8-9): collectives ~2/3 of TP3 prefill device time and ~50% (XTX) / 58% (R9700) of
8-stream decode device time; the R9700's extra share is mostly waiting for the XTX ranks. rad0023 timeline: the
R9700's fold was the longest decode phase. Decode all-reduce ~0.55-0.67 ms a call vs TP2 0.32 ms; 129 all-reduces per
decode step. TP2 has a fused all_reduce + RMSNorm + fp8 quant; TP3 does not (separate pass).

The headline gap: MXFP4 TP3 prefill at 2048 tokens is 19.5% slower than TP2 (1919 vs 2384 tok/s) and barely rises
from 512 to 2048 tokens, while TP2 climbs. int8 TP3 beats int8 TP2 at every length but is far below MXFP4.
