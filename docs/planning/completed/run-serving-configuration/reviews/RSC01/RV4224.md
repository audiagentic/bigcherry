# Owner direction: strict loader and manifest, not a command-line converter

## Notes



## Findings

The first RSC01 implementation was a resolver that regex-parsed the bash launcher for defaults and emitted engine argv plus helper environment variables. The owner rejected that shape (2026-11-02): start-up must be a clean, strict loader, not a command-line converter. Today the engine launch uses ~32 radiance flags and our components read ~80 R3_* environment variables. Nothing rejects an unknown or misspelt variable, and defaults live in three places.

## Conclusion

Redesign, owner-approved, with option (a) for the engine. One typed schema and a strict loader (unknown keys are errors; every value required or derived, with no silent defaults) produce an immutable, hashed, resolved manifest with provenance. Every process loads that manifest itself: helpers through a strict C++ loader (getenv removed), and the engine through a managed `--manifest` patch reusing radiance's own option table. `bigcherry serve` is the only entry point; the launcher and the R3_* environment variables are deleted with no fallback.
