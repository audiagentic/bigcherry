# Remove legacy compat.recipe patch-selection path

## Description

config/recipes.toml carries two parallel recipe-selection mechanisms: v2 canonical [source.*] patch-sets (resolved by campaign/resolution.py:resolve_lane(), used by build --lane and campaign tooling) and legacy [compat.recipe.*] states/groups blocks (loaded by recipes.py:_load_v2_compat(), used by pull, patch-rebase-check, patch-doc, pin-bump, probe-release/validate-ref, and doctor). The two can genuinely disagree about what's 'in' a named recipe -- surfaced as a real bug where `patches --recipe bigcherry` reported a patch as selected that the real v2 patch-set.framework used by actual builds does not include. recipes.py's own docstring calls _load_v2_compat() a temporary bridge ('exists only so old pull/audit/build commands can continue operating while the campaign path migrates') that was never finished.
