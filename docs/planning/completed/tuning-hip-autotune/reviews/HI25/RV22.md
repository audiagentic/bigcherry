# Progressive specialization of existing MMQ — hipEngine proved 44% regression for green-field WMMA; start from proven LDS decomposition

## Notes



## Findings

hipEngine's rejected Q8T16 × Q8_1 experiment proved that a straightforward integer WMMA kernel with prequantized activations and direct global loads is 44.66% slower than the existing FP16 WMMA kernel on gfx1100 (0.7542 ms vs 0.5213 ms). The bottleneck was not activation quantization (+0.016 ms) — it was that directly packing Q8 weights and scaling each K=32 integer result does not reproduce llama.cpp MMQ's efficient shared-memory tile and decomposition.

The worthwhile project is progressive specialization of the existing kernel, preserving its proven LDS layout:
- Stage 1: exact-shape clone measures genericity overhead (how much do templates cost?)
- Stage 2: occupancy variants (cheapest meaningful test)
- Each stage must independently beat baseline to continue

## Conclusion

The plan must start from llama.cpp's MMQ LDS layout, remove generic machinery, confirm parity with native, then test individual optimizations one at a time. The first two candidates are an exact-shape native clone and a t256-o1 variant. Those answer cheaply whether there is genuine room before investing in LDS pipelining or new packed formats. A 3% kernel speedup contributes ~0.93% aggregate matmul reduction — the justification threshold.
