# Public evidence confirms three genuinely novel projects — activation reuse, K-tile tuning, and fused integer-MMQ gate+up are all unexplored for gfx1100 prefill

## Notes



## Findings

Three genuinely novel projects confirmed by public evidence:

1. **Q8_1 activation reuse for prefill:** hipEngine's Q8_0 fusion uses FP16 WMMA (gguf_q8_0_prefill_dual_wmma_kernel — 40 dispatches, 3.42 ms total). Mainline PR #16715 merged GEMV fusion but restricted to N=1 (decode only). Nobody has done Q8_1 caching across separate MMQ calls for prefill.

2. **K-tile tuning:** No public RDNA3 experiment has compared K tile sizes (128/256/384/512) for Q8_0/Q8_1. Current K=256 with two halves is inherited, not optimised.

3. **Fused integer-MMQ gate+up for N=512:** hipEngine's fused gate+up uses FP16 WMMA (dequantizes to FP16). Nobody has done this via integer-MMQ path for prefill.

The design adds three components: MMQ graph planner, reusable Q8_1 activation pack, and gfx1100 MMQ candidate family. The core decision: optimise activation preparation and existing MMQ decomposition before replacing the matrix algorithm.

## Conclusion

Seven-phase implementation plan with clear deliverables per phase. Recommended first slice: instrument gate/up → confirm duplicate quantisation → extract prepacked entry point → add one execution-scoped Q8_1 pack → verify identical outputs → measure pp256/1024/4096. Do not write a new kernel until this slice is complete. The first specialised kernel slice preserves llama.cpp's LDS layout exactly and is compiled only for gfx1100.
