# bigcherry patch-gates CLI (--intent validate/promote/build/rebase, --json)

## Description

Expose PA21's shared evaluator through one deterministic, read-only CLI consumer. The command resolves a focal patch, its complete exact composition, the local resolved pin, optional PA16 reports, and the operation intent into GateContext; all policy remains in patch.gates and existing authorities.

## Steps

1. Register patch-gates in cli/main.py with positional patch_id, required --intent {validate,promote,build,rebase}, optional canonical --source, --rebase-report, --all-report, --no-legacy-grandfather, --json, and --llama-root.
2. For --source, resolve the named v2 source through campaign.resolution.resolve_canonical_selection and then re-resolve the returned ordered IDs through patchset.resolve_exact; require the focal patch to be in that composition. For validate/promote without --source, expand the focal patch's REQUIRES closure and resolve it exactly. Build/rebase require --source.
3. Resolve cfg.pinned and HEAD to full local commits through UpstreamRepository.resolve_ref; never fetch or accept an unresolved moving ref. Load reports only via patch.rebase.load_report and treat unreadable/non-object JSON as CLI errors.
4. Construct GateContext with the canonical descriptor, composition, PatchContext backend, catalog/config paths, local source root, resolved pin, reports, catalog states, full recipe composition IDs for G6, target revision, and grandfather policy.
5. Render one stable JSON schema (schema_version, patch_id, intent, source, composition, gates) or a human report derived from the same result objects. Evaluate every applicable gate; exit 0 only when all statuses are PASS/NA, exit 1 for FAIL/BLOCKED, and exit 2 for resolution/config/report errors.
6. Add offline CLI tests covering JSON and human output, all intents, source-required resolution, PASS/NA, FAIL/BLOCKED, malformed report handling, and exact composition forwarding. Cross-check a real rejected composition against patch_admission via the shared G7 evaluator.

## Detailed Solution & Technical Design

The handler is intentionally a thin adapter in tools/bigcherry/cli/patch.py. It imports the existing campaign resolution, patch registry, patchset, rebase report loader, UpstreamRepository, and patch.gates authorities; it must not call patch-verify-evidence as a substitute or recreate selection/evidence policy. Source mode carries the canonical source name and resolves its full ordered composition. Focal-only validate/promote mode uses expand_composition((patch_id,)) followed by resolve_exact. Build/rebase require source mode so G6 can treat the selected source composition as the recipe set. source_root is the selected llama.cpp checkout, while resolved_base_revision is cfg.pinned's local commit and target_revision is HEAD. The G6 all-report is passed as coverage_report; recipe_patch_ids is the complete composition ID set, not only the focal patch.

## Code Samples & Guidance

JSON schema v1: {"schema_version":1,"patch_id":"...","intent":"validate|promote|build|rebase","source":"name|null","composition":["id",...],"gates":[{"id":"G0","status":"PASS|FAIL|BLOCKED|NA","phase":"...","authority":"...","detail":["..."]}]}. Human output must be a presentation of this same payload and end with RESULT: PASS or RESULT: FAIL. Never omit an applicable gate or convert BLOCKED to success.

## Effort & Risk

Small code footprint but high policy-boundary risk: incorrect composition expansion, pin resolution, report authority, or exit-code mapping can create false confidence. Keep all resolution fail-closed, never fetch, never silently add a source patch, and do not let presentation code duplicate gate logic.

## Standards

CLI assembly belongs in cli/main.py and handlers in cli/patch.py per docs/reference/tooling/TOOLING.md. Use canonical v2 campaign resolution, exact patchset resolution, local-only pin identity, PA21 applicability, and the repository's exit-code convention. No second orchestrator, policy list, or compatibility shim.

## Acceptance Criteria

patch-gates reports every applicable PA21 gate for the exact requested composition; source mode agrees with campaign resolution; focal-only mode includes the full dependency closure; local pin/report identity is explicit; malformed or unresolved authority input fails closed; required FAIL/BLOCKED returns exit 1; CLI/config/report resolution errors return exit 2; JSON and human output describe the same results; no files or checkouts are mutated.
