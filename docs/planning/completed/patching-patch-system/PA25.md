# Audit focal evidence/G4 and exact-composition G7 for the seven promoted/touched patches

## Description

Current-state audit for 1225, 0840, 1224, 1200, 1001, 1002, and 1232. The audit must use the live PA21 gate authorities already implemented in `patch/gates.py`, not manually infer GateResults from README prose or evidence records.

Main now has a complete G0-G7 evaluator: G4 delegates to `patch_catalog.validation_evidence_statuses()`, G6 delegates to `disposition.compute_coverage()`, and G7 passes the complete resolved composition to `patch_admission.admit()`. The remaining audit blocker is selector identity: current `cmd_patch_gates` can evaluate only a canonical source or a focal dependency closure, while these prospective compositions need named experiments or deterministic focal overlays. PA34 owns that missing seam.

## Dependencies

- PA34 (hard, for experiment/focal-overlay contexts the current selector cannot express; source-representable contexts and evidence inspection may proceed before it).
- PA35 -> closure (hard): PA35 changes evidence/claims for five of this audit's focal patches (0840, 1224, 1225, 1002, 1232); closing before it makes the matrix stale.
- PA29 -> closure (recommended): PA29's consumer migration changes selector/base-source identity of audited compositions; audit matrix must reflect the post-migration identity.

This item may START early but must not CLOSE before PA35's evidence work and PA29's migration land (RV182).

## Steps

1. Pin the audit to one BigCherry revision, resolved llama.cpp revision, patch catalog snapshot, and evidence root. Record all identities in the receipt.
2. Run `patch-verify-evidence` for each focal patch and record the evidence authority result separately from any GateResult.
3. For contexts already represented by a canonical source, run the existing gate evaluator directly.
4. After PA34 lands, evaluate experiment/focal-overlay contexts with selector-matched G2 reports. Never create temporary recipe sources solely to make an audit runnable.
5. Record G4 only when `evaluate_evidence_gate()` actually ran. Use explicit `NOT_EVALUATED`/`NOT_RUN` audit state outside the GateStatus enum when selection or prerequisites prevent execution.
6. Evaluate G7 against the complete ordered composition selected for that audit context, never the focal patch alone.
7. Keep G4 and G7 independent: a focal patch can have current evidence while its production composition is not admitted, or vice versa.

## Required audit contexts

Use the existing named experiments where they express the real composition (`hi155-hybrid-allreduce-gate`, `hi18-reduce-probe`, `rd19-only`, `hip-internal-allreduce-only`). For 1002 and 1232, use PA34 deterministic focal-overlay selection over the intended base source rather than inventing permanent recipe entries.

## Files

Audit receipts only unless a genuine evidence/package defect is found. Consumers: `tools/bigcherry/cli/patch.py`, `tools/bigcherry/patch/gates.py`, `tools/bigcherry/patch/rebase.py`, `config/recipes.toml`, and each focal patch's evidence package.

## Validation

Every evaluated BUILD context must carry selector kind/name, source/ref, patch-set ID, ordered IDs/hashes, matching G2 report identity, all-patches G6 coverage report identity, and full G7 composition. A wrong-selector or stale report must fail closed.

## Acceptance Criteria

A machine-readable matrix exists for all seven patches with evidence-authority result, G4 evaluation state/result, exact selector/composition identity, G7 evaluation state/result, blockers, and artifact hashes. No result is promoted from historical prose into a current GateResult, and no recipes are modified solely for audit convenience.
