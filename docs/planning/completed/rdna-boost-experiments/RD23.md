SUPPORT-ONLY INVENTORY (2026-08-18), from live diffs of the two source commits (fetched read-only from https://github.com/stew675/llama.cpp, deleted after inspection, vendor/llama.cpp untouched):

Commit 18fc188f6eb93c2cdea116fa9b7d6a6b5fdb595e (RD05/RD06/RD07's source, RDNA4 WMMA + Q6_K mmq) contains exactly two support-only (non-runtime-behavior) pieces mixed into its performance work:
1. `GGML_CUDA_OP_TIMING` -- an env-gated (getenv, opt-in) per-op timing instrumentation block in ggml-cuda.cu: when set, wraps graph-node execution, accumulates elapsed ms per op, and logs a total + cumulative summary via GGML_LOG_INFO at the end of a run. Pure measurement -- no effect on kernel selection or output when unset (checked via `if (op_timing)` guards around timing-only code, not around the actual op dispatch).
2. `GGML_CUDA_FA_WMMA_256` -- an env-gated BEHAVIOR control, not a pure diagnostic: when set to 0, forces the WMMA flash-attention path off for head sizes where it would otherwise be enabled by default on RDNA4 (head <= 576). This is a kill-switch/rollback control, not an instrument -- it changes which kernel runs. RD23's own framing ("prevent diagnostics from entering production candidates") applies differently to this one: it is the correct SHAPE of a promotion-safety control (opt-out default-on), but it is scoped to RD05-07's own performance experiment, not a generic diagnostic -- keep it paired with whichever RD item ships the WMMA-256 change, do not generalize it.
3. tests/test-backend-ops.cpp gets a handful of new FLASH_ATTN_EXT/MUL_MAT perf test-case entries (labelled 'Qwen3.6-27B Q6_K prefill shapes (perf tuning targets)') -- these are test-case data, not instrumentation; they belong with RD04/RD05-07's own test additions, not RD23's diagnostic-support scope.

Commit d4aaf63b7b7a89639871a1835ceec40644722519 (RD08's source, Q6_K MMVQ VDR=2) contains NO env-gated diagnostics or timing instrumentation at all -- its correctness verification method was an offline Python bit-identical simulation plus test-backend-ops MUL_MAT cases (1194/1194), not runtime instrumentation. Nothing to extract from this commit for RD23's scope.
