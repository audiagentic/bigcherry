# Qualification-only ablation knobs for RD39-44 (stream/concurrency) and RD50-53 (GDN)

## Description

External review (2026-08-20): RD39-42's materialized patch (1215) intentionally combines active-stream routing, per-stream BLAS handle safety, scratch isolation, and shared-expert overlap into one patch/contract for correctness reasons (you cannot safely enable concurrency before stream routing is correct). But the fourth component -- actually overlapping the shared expert -- is the real performance hypothesis; the first three are safety prerequisites. If the bundle measures +5%, there is currently no way to know whether the overlap itself is +8% but the prerequisites cost -3%, or some other split. Same issue for RD50 (1221): chunked GDN kernel, DPP row-shift reduction, native exp2 decay, and launch-bounds/VGPR tuning are treated as one coupled experiment because they're inline micro-decisions inside one kernel body, not because they're causally inseparable.

## Steps

Add compile-time toggles or template knobs (temporary, qualification-only -- need not survive into production or become permanent patch files) so each component's real contribution can be isolated: for RD39-44, test native / safe-plumbing-only / safe-plumbing+overlap; for RD50-53, test generic-shuffle+expf+default-launch / +DPP / +exp2 / +launch-bounds. This preserves the correctness-driven decision to ship one coupled patch while restoring causal attribution of the measured gain.
