# RD08 correctness harness: fix tensor-name bug (dst -> out)

## Description

patches/1204_rd08_q6k_mmvq_vdr2/validation/rd08_correctness.py's find_digest_for_tensor()/find_metric_for_tensor() search test-backend-ops stderr for a tensor named "dst", but test_mul_mat's real output tensor is always named "out" (confirmed directly in vendor/llama.cpp/tests/test-backend-ops.cpp: ggml_set_name(out, "out"), no "dst" anywhere in that struct). Every RD08 correctness digest comparison has therefore been silently returning None/None and reporting a missing-evidence failure, not the real comparison result.

Both Luna and GPT (asked independently, 2026-09-01) recommend fixing this regardless of the separate RD102 numerical-equivalence-contract question: change the tensor name lookups from "dst" to "out", add a regression test proving evidence is extracted from "out" and that missing output evidence still fails closed (never silently None/None-passes), then re-run --run-rd08-contract so the committed evidence.json reflects the real reason (digest mismatch) rather than the misleading current one.

Expected outcome after the fix: RD08 still correctly fails (real hardware digests for subject/control genuinely differ on all 5 shapes -- see RD102), but the evidence record will be honest about why.
