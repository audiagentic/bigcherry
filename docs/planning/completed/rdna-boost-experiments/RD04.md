# Implement final native-BF16 flash-attention logical experiment

## Description

Future experimental port of the folded BF16 flash-attention series from commits cb05a6a, 0d66ba3, a1c082a, 4febe47, and 24b0899; retain cleanup/evidence history from ff58c5b and 444fea6.

## Steps

1. Port only the reviewed logical BF16 path. 2. Preserve F32 accumulation and native-BF16 guards. 3. Keep unsupported hardware on the existing fallback. 4. Separate cleanup and operand-order evidence from the implementation arm. 5. Gate promotion on correctness, precision, quality, and performance evidence.

## Detailed Solution & Technical Design

Treat this as one precision-path experiment, not six cherry-picks. Validate exact RDNA architecture guards and avoid claiming bit identity with F16. External v_perm verification is evidence to reproduce, not a trust input.

Cross-arch repeat (Brutus, non-XTX device) and the FLASH_ATTN_EXT correctness matrix before any promotion.
- Patch fix in this cycle (fffc2ee): the common.cuh edit's replace-text carried the anchor tail lines at the end instead of the start, injecting the BF16 helpers INSIDE the ggml_cuda_mad(float&,half2) function body -> 'function definition is not allowed here'. Fixed to match the fork's top-level placement; re-verified fresh apply + idempotent + window byte-identity vs fork.

PP-CHARACTERIZATION BENCH 2026-08-20 (follow-up: is the prompt delta real or noise?):
- Same two binaries; prompt-only (-p <pp> -n 0 -fa 1 -ctk/-ctv bf16), interleaved 5 reps (4 for pp4096) + 1 warmup each. Artifacts: tmp/rd04-bench-pp/*.json.
- pp512 : ctrl med 1178.7 (1142-1504, one 1503 warm-state outlier) | test med 1244.3 (1181-1313) | +5.57%
- pp1024: ctrl med 1507.1 (1486-1541) | test med 1501.4 (1488-1511) | -0.38%
- pp2048: ctrl med 1498.5 (1475-1516) | test med 1497.2 (1491-1505) | -0.08%
- pp4096: ctrl med 1441.9 (1437-1446) | test med 1443.6 (1436-1446) | +0.12%
- READING: at every well-measured size (pp>=1024) the two arms are indistinguishable (|delta| <= 0.4%, spreads fully overlap). A real attention-phase cost would grow with prompt length (attention is a bigger share of prefill and KV grows per ubatch) -- it does NOT. The pp512 'delta' flips sign between independent runs (first bench: test -3.51%; this bench: test +5.57%) and the control arm is high-variance there (a 1503 outlier) -- the signature of noise in the small-batch regime, not a cost.
- CONCLUSION: the first bench's pp512 -3.5% was measurement noise. There is NO prompt regression in the BF16 path. Combined with the clean tg +3.4% (non-overlapping arms), RD04 is a single-direction decode win with no measured prompt cost, not a tradeoff. The kernel-phase (KQ vs VKQ) breakdown is now moot: there is no regression to attribute. Still needs the correctness matrix + cross-arch repeat before promotion.
