## Detailed Solution & Technical Design

Hypothesis: Dynamically adjusting draft depth to observed acceptance beats one fixed depth across heterogeneous coding/prose phases.

What/why: Source dual-R9700 results showed meaningful coding uplift vs fixed depth, not universally winning on prose.

Where: speculative controller, not kernel backend.

--- Merged from NRO06 (2026-09-09) ---

Source adds a distinct `draft-mtp-adaptive` speculative type with per-sequence state. Draft depth starts at a configurable floor, climbs after sustained full acceptance, and drops after accumulated miss pressure -- reducing wasted verify work on unpredictable text while allowing deeper drafts on highly predictable spans. This is algorithm/runtime policy, not a GPU kernel optimization, and should be evaluated independently of kernel patches.

Source state machine:
- `n_cur` current depth in `[floor, n_max]`
- `n_climb` consecutive full-accept verifies
- `n_drop` accumulated `n_draft - n_accepted` pressure
- full accept resets drop pressure and may climb when a depth-specific streak threshold is reached
- any miss resets climb, accumulates drop pressure, and drops one level when `max(depth*5, 20)` is reached
- floor state does not accumulate pressure below the floor
- a hardened depth-3->4 barrier exists because acceptance reportedly collapses in ordinary prose beyond that point (PR author's own note: recommends spec-draft-n-max >= 7-8 to get real benefit, floor/cold-start default to 3, not recommended below 7)

BigCherry must treat those constants as source hypotheses, not universal truth -- instrument every requested/accepted depth transition and allow offline acceptance-trace replay so alternative constants can be evaluated without rerunning model inference, while runtime policy stays one fixed pre-registered candidate during qualification.

Correctness is primarily behavioral: adaptive and fixed modes may choose different amounts of speculative work but must preserve target-model semantics -- under deterministic sampling/temp=0, accepted final token sequence should match nonspeculative/reference generation subject to existing MTP determinism rules.

## Code Samples & Guidance

Keep controller logic pure/testable, e.g. a small struct with `reset()` and `update(n_draft, n_accepted, cap, floor)`. Separate controller policy from model/context plumbing so exhaustive state-machine tests require no GPU.
