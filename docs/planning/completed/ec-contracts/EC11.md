# CLI: validate/list/plan/run/report entry points

## Description

Add validate/list/plan/run/report entry points under existing bigcherry CLI conventions -- the operator-facing surface for EC01-EC10's machinery.

Full source: docs/reference/BigCherry_Experiment_Contract_Implementation_Guide.md (§7 EC11 row).

## Detailed Solution & Technical Design

Five subcommands, matching the guide's own naming:
- `validate` -- schema-check a contract file (EC01) without running anything.
- `list` -- enumerate loaded contracts (EC02's registry), their state, and which RD/EX plan item and patch module(s) they're backed by.
- `plan` -- show what campaign lanes a contract would expand into (EC03) without executing them -- a dry-run, matching this project's existing --dry-run conventions elsewhere (e.g. patcher.apply_all's dry_run parameter).
- `run` -- execute a contract's full lane set (EC03/EC04) end to end through aggregation (EC06), correctness gates (EC07), and generalisation (EC08).
- `report` -- render EC10's report for a contract that has already run, or re-render from stored evidence without re-running.

Follow this project's existing argparse subcommand conventions in `__main__.py` (see `bigcherry build`'s own `--experiment` flag, added this session, for the pattern of extending an existing subcommand tree rather than inventing a parallel CLI entry point).
