# Promotion gate: require all declared contract evidence + holdout proof

## Description

`promotion.py`/`tune_promotion.py` must require all declared contract evidence and holdout/generalisation proof where applicable before a contract-backed winner can promote -- the point where EC06 (A/B aggregation), EC07 (correctness gates) and EC08 (generalisation) all converge into a single pass/fail decision.

Full source: docs/reference/BigCherry_Experiment_Contract_Implementation_Guide.md (§7 EC09 row, §12 step 11, §16).

## Detailed Solution & Technical Design

Guide §12 step 11: "Promote only if contract thresholds, provenance, evidence completeness and existing promotion gates all pass." This item wires that into `promotion.py`/`tune_promotion.py`'s existing gate machinery (RE13's promotion pointer / RE12's balanced-comparison-report contract this session exercised heavily for the RE15 acceptance chain) as an ADDITIONAL required check, not a replacement -- a contract-backed promotion must still pass every existing BigCherry promotion gate (production-class provenance, decision-grade comparison report, replay coverage, etc.) on top of the contract-specific requirements.

Handles the asymmetric correctness-first case from EC07's notes: for contracts like RD20/RD22/RD26 where performance is a regression budget rather than the primary claim, this gate must accept correctness-only acceptance (target_kernel_gain_pct absent or explicitly zero) without treating that as an incomplete contract.

## Validation

A contract with complete performance evidence but a FAILED correctness gate (EC07) cannot promote, even with a large measured gain. A contract explicitly declaring a performance-neutral, correctness-only acceptance profile CAN promote on correctness evidence alone. A contract whose generalisation handoff (EC08) hasn't run yet, when its acceptance section requires holdout proof, cannot promote -- evidence completeness is checked against what the CONTRACT declares as required, not a fixed global checklist.
