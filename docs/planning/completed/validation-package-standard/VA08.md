# Status-aware patch-verify-evidence: ported-benched/deferred-hardware obligations, packaged-patch coverage fix

## Description

patch-verify-evidence currently only evaluates patches with patch.toml state='validated' (returns not-required for everything else). Extend it to also enforce: the ported-benched obligation (current-pin compact evidence proving a real control/subject benchmark occurred with build/hardware identities recorded per VA07's resolved schema; correctness failure forbids the status) and the deferred-hardware EVIDENCE-FRESHNESS obligation only (the structured BLOCKED-evidence entry itself and its freshness -- NOT the structural README/validation.toml/contract-binding requirements, which GPT round 4 corrected to belong in VA02). MUST resolve the pin to its immutable commit SHA and pass it as resolved_base_revision, not just cfg.pinned -- GPT round 4 found cmd_patch_verify_evidence() currently supplies only cfg.pinned even though evidence verification already supports resolved_base_revision. No legacy grandfathering: old b10502 evidence remains historically retained but cannot itself authorize a current-pin (b10692, by resolved commit) ported-benched/ported-validated status claim -- distinct from VA01/VA02's structural-grandfather, which only protects package SHAPE, never evidence CONTENT/freshness.
