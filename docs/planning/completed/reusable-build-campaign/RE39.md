# Introduce CatalogSnapshot: one immutable patch-catalog read per command/campaign

## Description

Thread the existing CatalogSnapshot through one command/campaign execution instead of rescanning patches/ and catalog.toml. build_snapshot() exists and is tested, but currently only cmd_patches uses it; resolution/materialization/build planning still rescan independently.

## Steps

Add snapshot to campaign request/context or an execution-scoped immutable input; pass it through resolve_lane/resolve_patch_set, source planning/materialization, build planning, and reporting; preserve explicit custom patches_root behavior; reject snapshot/catalog drift at boundaries; remove redundant catalog()/load_catalog() calls only after call sites are migrated.

## Detailed Solution & Technical Design

Keep CatalogSnapshot immutable and include module bytes/content hashes plus canonical metadata digest, not merely metadata keys. Reuse HIP's current exact resolution and identity semantics first; do not change selection or patch_set_id in this item. Make snapshot injection optional only at compatibility boundaries, then require it for campaign execution. Tests should prove one read, custom-root correctness, and mid-run mutation cannot change the resolved plan.

## Code Samples & Guidance

```python
@dataclass(frozen=True)
class CampaignCatalog:
    snapshot: CatalogSnapshot

# Build once at command entry and pass it through planner -> lane -> source.
snapshot = patch_catalog.build_snapshot(
    patches_dir=context.patches_root,
    catalog_path=context.patches_root / "catalog.toml",
)
lane = campaign_resolution.resolve_lane(..., catalog=snapshot.modules,
    catalog_snapshot=snapshot)
```
Use a compatibility overload temporarily: if `catalog_snapshot` is absent, construct one at the outermost boundary and never inside lower-level functions. Replace `patchset.catalog()` calls in `resolve_patch_set`, `campaign_source`, and materialization only after tests prove the snapshot root matches the supplied modules.
