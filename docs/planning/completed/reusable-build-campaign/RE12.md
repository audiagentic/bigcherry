# Implement explicit balanced comparison planner and campaign reports

## Description

Preserve A/B statistics while adding identity-aware arms, intentional-difference policies, pairwise comparisons, and report generation.

## Steps



## Detailed Solution & Technical Design

### Narrowed scope (locked per RV50; code claims verified 2026-08-17)

Verified state: comparisons.py is a PLANNER whose BenchmarkArm carries a raw `executable: Path` plus caller-supplied hashes/identity strings; promotion.pointer_from_campaign_result() accepts caller-supplied campaign_plan_id, report bytes and a valid flag (architectures ARE already cross-checked against build evidence — keep that); PromotionPointer is schema 2; ab_benchmark.py already owns schedule(), block_bootstrap_effect(), validate_replay_coverage() and _run_arm(). Do NOT build a second benchmark framework — wire artifacts into the existing runner.

**6.1 Artifact-backed arms.** BenchmarkArm identifies: runtime_bundle_artifact_id, binary_artifact_id, replay_cache_artifact_id | None, source_slice_id, build_plan_id, effective_build_id, workload_id, environment, device assignment. No caller-supplied executable path as authority — the executable path is obtained only after rehydrating/verifying the runtime bundle.

**6.2 Preflight before any GPU time.** Compare source identity, build identity, workload, environment, device assignment, replay cache and runtime bundle between arms; only differences named in allowed_differences (already a ComparisonPlan field via plan_pair) may proceed. This is the core scientific-integrity value of RE12.

**6.3 Reuse the runner.** Extract ab_benchmark._run_arm() into a reusable run_arm_capture(); do not duplicate subprocess execution or statistics; keep using schedule() and block_bootstrap_effect().

**6.4 Immutable raw evidence + one report artifact.** Every arm's stdout, stderr, coverage and parsed result become immutable ArtifactRefs; then publish ONE comparison-report ArtifactRef containing: comparison_plan_id, campaign_plan_id, campaign_run_id, left/right artifact IDs, allowed differences, schedule, raw run artifact IDs, effect estimates, confidence intervals, coverage status, valid, decision_grade.

**6.5 Release-pointer trust boundary.** Replace release-grade use of pointer_from_campaign_result() with pointer_from_comparison_report(): rehydrate the comparison-report; require production provenance; require valid; require release/decision grade; derive campaign IDs FROM THE REPORT (never caller strings); cross-check the report's replay arm against the actual replay result; derive the report hash from the stored bytes. Bump PromotionPointer to schema 3 adding at least report_artifact_id; KEEP reading schema-2 pointers for historical releases. No general release-evidence graph in the pointer — the comparison report already contains it.

**6.6 Required tests:** balanced comparison succeeds from real descriptor-backed fake executables; every raw evidence artifact ID rehydrates; environment mismatch rejects before executable invocation; device mismatch rejects before invocation; source/build mismatch rejects; tampered runtime library rejects; non-exact replay coverage makes the report invalid; a valid report produces a release pointer; a caller cannot substitute a different report/result pairing; schema-2 pointers remain readable.
