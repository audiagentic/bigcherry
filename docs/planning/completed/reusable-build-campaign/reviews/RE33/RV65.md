# Codebase assessment of Vulkan platform identity

## Notes



## Findings

config/recipes.toml still uses targets=["vulkan-stub"], while campaign build identity currently treats platform targets as HIP/AMDGPU configuration. The stock Vulkan build works, but its descriptor cannot express vendor/device/ICD identity. HIP's target list is compile identity, not runtime device identity; Vulkan must not overload targets with raw device indexes.

## Conclusion

Replace the placeholder with typed platform Vulkan identity fields and include a normalized vendor/device class, UUID policy, ICD/driver/API identity, and feature digest in runtime/artifact provenance. Keep open.
