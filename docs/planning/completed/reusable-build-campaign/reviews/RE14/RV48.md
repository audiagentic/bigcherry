# Deep audit of RE03-RE23: five identity/provenance integrity blockers + per-item re-scoping

## Notes

Deep review of active RE03-RE15 and RE20-RE23 against the current implementation, using completed RE16-RE19 as architectural baseline. Conclusion: the plan set mixes (a) old items whose implementation landed but whose docs describe a pre-RE14 world, (b) genuinely unfinished architectural work hidden behind sparse descriptions, and (c) items lacking formal acceptance contracts. Five findings are treated as architectural blockers for treating the canonical build as a production provenance boundary: (1) source materialisation is not content-safe (source_plan_id drops patch/overlay content; cache reuse never revalidates the effective tree); (2) the public lane API silently bypasses the clean-BigCherry check (_materialize_worker hard-codes allow_dirty_bigcherry=True, no execute_campaign_lane override, and cache hits skip the dirty test entirely); (3) raw lane inputs permit provenance laundering (raw Path import stamps current-source provenance without checking the file's own identity); (4) BuildPlan under-identifies compiled bytes (hard-coded SUPPORTED_BUILD_NEEDS, separate inventory_hash/winners_hash instead of a generic input collection, catalog-architecture dimension missing from build identity); (5) the runtime closure is verified but not published as an immutable artifact (only the launcher reaches ArtifactStore).
