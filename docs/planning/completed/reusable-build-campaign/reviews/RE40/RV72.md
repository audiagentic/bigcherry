# Codebase assessment of patch metadata extension

## Notes



## Findings

Catalog metadata already has plan_ids, backends, subsystems, hardware, and option constraints. Patch modules already carry enforced REQUIRES/CONFLICTS consumed by resolve_exact(); duplicating those relationships in catalog metadata would create two sources of truth. The plan should restrict catalog additions to descriptive fields and cross-check module relationships rather than duplicate them.

## Conclusion

Revise RE40 to complete metadata validation/backfill and link checks while keeping module REQUIRES/CONFLICTS authoritative.
