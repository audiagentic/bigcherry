# Codebase assessment of Vulkan eligibility ABI

## Notes



## Findings

vk-autotune-types.h and vk-autotune-replay.h are provisional scaffolding. ggml_vk_hardware_key_v1 intentionally omits capabilities while can_execute and replay lookup receive only that key, so unsupported extension/limit checks cannot be performed. HIP's candidate eligibility path carries the resolved runtime/build identity and fail-closed native fallback; Vulkan needs an immutable capability snapshot rather than a second ad hoc JSON lookup.

## Conclusion

Implement a typed Vulkan capability snapshot/digest passed to preflight, candidate can_execute, and replay lookup. Keep the compact hardware identity separate from the capability payload but bind both through a digest. Keep open.
