# Add explicit campaign-backed release promotion

## Description

Require validated campaign/run/report hashes for promotion pointers while preserving release gates and immutable evidence.

## Steps



## Detailed Solution & Technical Design

FULL INTEGRATION PASS (RV48 audit). VERIFIED: the compatibility probe in release_validate.py still shells out to `python -m bigcherry --llama-root <checkout> legacy-build --recipe <recipe>` against a temporary checkout, and the existing release record still carries legacy concepts such as a mutable-checkout tree_state. That probe becomes an ACTUAL breakage when RE23 deletes legacy-build, so RE13 is an explicit dependency of the final deletion story.

REQUIRED: (1) The new release-support record points at immutable source/build/runtime/campaign/report artifacts instead of a mutable checkout state. (2) A promotion pointer contains: report hash, campaign/run identity, promoted source/build/runtime identities, required architecture evidence, and replay artifact identity (the PromotionPointer builder exists with schema-v2 shape; wire it to real records). (3) Migrate release_validate.probe() to the canonical APIs: for an arbitrary upstream ref it constructs a temporary in-memory source config whose ref is the fully resolved commit and runs the SAME isolated materialisation/build API against a temporary ProjectContext - do NOT reintroduce a general --ref override into canonical production builds just to serve one compatibility probe.

## Notes

RE13 (2026-08-17): migrated release_validate.probe() off legacy-build onto execute_campaign_lane() -- see commit ffa3caa. probe() now: resolves the legacy compat.recipe -> v2 (source, builds, platform) via an explicit mapping (_v2_source_name_for_recipe/_LEGACY_BUILD_ALIASES in release_validate.py, fails closed with ProbeConfigError for a recipe it cannot place); fetches the probed ref into the shared host-local upstream mirror via the new UpstreamRepository.fetch_ref() (workspace.py); builds a temporary in-memory Source (ref replaced with the resolved commit) and calls execute_campaign_lane() directly, once per build in the recipe's build list. LIVE ACCEPTANCE: a real HIP compile (record build, ~400 steps) succeeded end-to-end on Brutus against upstream master through this path -- build_plan_id f3693133ea5c20507c0150bed2963bf2.

CLOSED (commit 10cbe54): the remaining two pieces of RE13's 3-part requirement. (1) promotion.py's PromotionPointer now carries required_architectures and replay_artifact_hash (the replay build's own runtime-bundle closure -- what ships -- not the tune build's binary_hash) alongside the existing campaign/report/source identities. (2) releases.ReleaseRecord gained a `promotion` field holding the persisted pointer document; `validated` can now ONLY be reached through releases.promote(), enforced both at the advance_to() transition (raises if record.promotion is None) and on every validate()/load() (so a record read back from disk with validated+no pointer, or a pointer for the wrong revision, fails closed) -- a bare stage assignment to 'validated' is no longer sufficient, closing the exact gap requirement (1) named ('points at immutable artifacts instead of a mutable checkout state'). promotion.pointer_from_campaign_result() is the real bridge: reads every identity (revision, run_id, source_slice_id, build_plan_id, binary_hash, runtime_bundle content_hash) directly off a genuine CampaignLaneResult, no re-derivation. legacy tree_state field left in place (still written by the not-yet-retired legacy build path) and explicitly documented as such -- its removal is RE23's job, not RE13's, per the plan's own dependency ordering.

Verified end-to-end on real data: test_re13_promotion_wiring.py runs a real execute_campaign_lane() (real git materialize, real BuildPlan identity, real ArtifactStore, only the compiler faked), builds a real pointer from the real result, and promotes a real ReleaseRecord with it. 24/24 new+touched tests pass on Windows and Brutus (Linux); full suite green on both (889 passed locally; 751 on Brutus, same pre-existing pytest-not-installed import errors on 6 unrelated modules as before, not a regression).

All three original RE13 requirements are now implemented and tested. Recommend marking completed.
