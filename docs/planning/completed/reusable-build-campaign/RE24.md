# Extended adversarial cutover matrix for the audit-found integrity failures

## Description

Extend the adversarial cutover test matrix with the integrity failures found by the RV48 deep audit AFTER RE21's flip and RE22's five-check matrix were already closed. This is the end-to-end proof layer for the five architectural blockers tracked in RE04/RE05/RE07/RE08, and it is part of the pre-RE23 deletion bar.

## Detailed Solution & Technical Design

Every test below is an END-TO-END cutover assertion through the canonical build path (CLI or execute_campaign_lane), even where RE04/RE07/RE08 carry their own focused unit tests. This item exists because the audit (RV48) found these failures after RE21's flip and RE22's matrix were both closed - per project doctrine, new work goes on a new item rather than reopening completed ones.

Test set (each maps to a verified defect): (1) PATCH-BYTE/ID SPOOFING: edit a patch module's bytes under its unchanged canonical ID -> the canonical build must not reuse the old source materialisation (RE04 fix). (2) CACHED-TREE TAMPER: modify a file inside an already-cached source worktree -> reuse fails closed (RE04 fix). (3) DIRTY-PROJECT LEAK: dirty BigCherry source -> canonical lane path rejects on BOTH fresh materialisation and cache reuse unless the explicit development override is set; execute_campaign_lane default is clean (RE04 fix). (4) PROVENANCE LAUNDERING: pass a wrong-source inventory as a raw path while building a different source -> rejected, or visibly classified imported-legacy with unprovable v2 provenance (RE08 fix). (5) CATALOG-ARCHITECTURE IDENTITY: change the requested generation architectures with everything else fixed -> different build_plan_id and build dir (RE07 fix). (6) DECLARED-NEED IDENTITY: change any declared build need's bytes -> different build identity, including a correctness-evidence need once HI66 lands on RE07's generic input model (RE07 fix). (7) RUNTIME-BUNDLE INTEGRITY: delete or byte-flip one runtime .so member of a published bundle -> downstream consumption fails closed (RE07 fix). (8) RELEASE-PROBE DECOUPLING: release_validate invokes no command scheduled for RE23 deletion, static + runtime (RE13 migration).

## Notes

Implemented as tools/tests/test_campaign_cutover_audit.py: 10 tests across 8 groups, calling execute_campaign_lane() end-to-end (real git materialize, real patch application, real BuildPlan identity, real ArtifactStore publish/verify; only campaign_workers.subprocess.run faked). All 10 pass locally (Windows) and on real Brutus hardware (Linux, /mnt/vault/development/bc-branch, unittest runner -- no pytest installed there). Item 8 (release-probe decoupling) intentionally asserts the CURRENT pre-RE13-migration state (release_validate.py still invokes legacy-build), not a claim that decoupling is done. Two design notes worth keeping for whoever touches this next: (1) campaign_source.source_plan_for() resolves patch-set SELECTION via patchset.catalog() with no directory override, which defaults to paths.PATCHES (the real project's patches/), not context.patches_root -- unlike workspace.materialize()/resolve_materialization_identity(), which do use context.patches_root explicitly. The test harness works around this by patching bigcherry.paths.PATCHES for the duration of each run; the underlying inconsistency itself was not fixed (out of RE24's scope, could be its own follow-up). (2) CampaignRun.execute() swallows the underlying exception's own message when a stage fails (records only stage state, not the exception text), so CampaignLaneError text alone cannot be used to prove WHICH check caught a given tamper -- RuntimeBundleIntegrityTests asserts closure (CampaignLaneError raised) without pinning the failure to the smoke stage specifically, since a tampered store artifact is actually caught earlier, at the build stage's own re-publish-from-build_dir step, which is a stronger property than the item description assumed.
