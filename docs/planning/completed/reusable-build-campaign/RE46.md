# PatchContext applicability now enforced in the real production build path

## Description

External review (BigCherry_RE30_patch_governance_reassessment_2026-08-20.md) P0-3: patch_catalog.py's PatchContext/applicable()/resolve_for_context() existed and correctly rejected backend mismatches / missing-required-options / forbidden-options-present, but campaign_resolution.py's real production patch-selection path (resolve_lane/resolve_patch_set) never called any of them -- a selected-but-inapplicable patch (e.g. a hip-only patch on a vulkan source) would compile without complaint.

## Steps

[DONE] _MaterializedLaneSource (campaign_lane.py) now carries patch_ids (the exact composed selection resolve_lane already approved), populated from source_plan.patch_ids in _execute_materialize_phase.
[DONE] _execute_build_phase now calls patch_catalog.resolve_for_context(materialized.patch_ids, PatchContext(backend=..., source=..., build=..., platform=..., options=merged_options-keys), catalog_path=context.patches_root/"catalog.toml") right after computing the real backend/merged cmake options, hard-erroring (CampaignLaneError) before generate/build/smoke run.
[DONE] Scoped to the lane's OWN context.patches_root/catalog.toml (matching the patches_root already used for resolve_lane at materialize time), not the real project's global paths.PATCH_CATALOG default -- and skipped entirely when that file does not exist, so an isolated test context or any patches_root with no descriptive catalog layer is unaffected.
[DONE] This only VALIDATES an already-explicitly-selected patch's applicability; it does not auto-select patches by metadata match -- explicit recipe composition (patch-sets/experiments in recipes.toml) remains the sole selection mechanism, per the review's own 'what NOT to do' list.
[DONE] Real end-to-end regression tests added in tools/tests/test_campaign_cutover_audit.py::PatchBackendApplicabilityTests -- a hip-only-cataloged patch on a vulkan-backend source fails closed with a 'backend mismatch' message; the same patch on a hip-backend source still compiles.
