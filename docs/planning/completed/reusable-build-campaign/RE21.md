# Flip `bigcherry build` to the new engine; rename legacy to `legacy-build`

## Description

RE14 step 7: change CLI ownership. `bigcherry build` becomes the new multi-lane planner/runner (RE18) and nothing else -- any request it can't express must fail closed (exit 2) with a message naming `legacy-build` as the explicit compatibility path, never a silent fallback. Today's cmd_build is renamed to an explicitly-named `legacy-build` command. `campaign-build` (added round 18) remains as a low-level single-lane expert entrypoint, unchanged.

## Steps

1. Rename the existing `build` subparser/cmd_build wiring in __main__.py to `legacy-build` (same implementation, new name/help text only).
2. Register a new `build` subparser that parses --recipe/--all/--build in terms the new planner understands (or, if a real recipe-name mapping isn't available yet, in terms of the canonical v2 source/build/platform identities RE19 defines) and calls RE18's run_campaign().
3. Any legacy-only flag (--groups, --states, or a recipe with no canonical v2 equivalent) must be rejected by the new `build` parser with a clear error pointing at `legacy-build`, not silently routed there.
4. Update all help text: `build` no longer says 'legacy'; `legacy-build` clearly says 'compatibility/diagnostic, prefer build'.

## Detailed Solution & Technical Design

gpt-auto-agent design (RE14 round 19): 'Define "default" at the command boundary, not per recipe... bigcherry build = new engine only, for everything it accepts. Unsupported operation = explicit error. bigcherry legacy-build = user explicitly chose compatibility execution. That satisfies "no implicit fallback".'

## Notes

Completed 2026-08-17. Implemented exactly per the recorded design and GPT's round-20 guidance (both preserved above).

`build` is now a canonical-v2-only interface over campaign_planner.plan()/run_campaign(): --profile <name> | --all (= --profile standard) | --lane SOURCE:BUILD:PLATFORM (repeatable) -- exactly one required. --inventory/--winners distribute to whichever planned lanes declare that need via Build.needs. --model runs real runtime-smoke validation on every planned lane. Legacy flags (--recipe/--groups/--states/--variant-set/--force/--target/--dry-run) are simply not defined on this parser -- argparse itself rejects them with exit 2, fail-closed, no silent routing anywhere. Today's cmd_build is unchanged, renamed to the `legacy-build` subcommand (same flags/behavior, keeps accepting --groups/--states during the compat window). campaign-build is unchanged. release_validate.py's own build_command updated to call legacy-build (it uses --recipe).

Exit codes: 2 for invalid/unsupported request syntax (argparse rejection, malformed --lane, both/neither of --profile/--all/--lane, unknown profile), 1 if one or more planned lanes execute and fail, 0 only if every planned lane succeeds.

17 new unit tests (test_build_flip.py). Full suite green (827 passed, 3 skipped), ruff-clean. One real bug caught and fixed during implementation: the initial mutual-exclusion check (`bool(lane) == bool(all or profile)`) didn't reject --all and --profile given together -- fixed to `sum(bool(x) for x in (lane, all, profile)) != 1`, with a dedicated regression test.

Proven for real on Brutus (tuning-code-rebase @ a5b9cc6): `bigcherry build --all --llama-root ... --arch gfx1201 --inventory ... --winners ... --model ... --hip-visible-devices 2` -- the actual production CLI command, unmocked -- ran the full 5-lane standard profile end-to-end on real gfx1201 hardware, all 5 lanes reported 'ok' with correct build_plan_id/workload_id, exit code 0. legacy-build --help confirmed unchanged/intact.

RE22 (fail-closed cutover tests) is next -- pin this behavior with real adversarial tests (poisoned legacy cmd_build, broader unsupported-flag surface, --all lane-set exactness, fault isolation at CLI level, static+runtime no-legacy-checkout-touch check).
