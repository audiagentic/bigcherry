# Add immutable artifact store and provenance v2

## Description

Publish immutable hashed artifacts atomically and define complete source/build/workload/campaign provenance validation.

## Steps



## Detailed Solution & Technical Design

PROVENANCE HALF, SECOND ROUND (RV48 audit). ArtifactStore itself is sound (verified): path confinement, atomic immutable publication, byte verification. The gap: provenance.validate() only requires the five namespaces to EXIST as dicts - each may be {} - which is a useful early-stage shape but not 'complete production provenance'.

REQUIRED: (1) Add ArtifactDescriptor - frozen dataclass(artifact_id, kind, relative_path, content_hash, provenance: ProvenanceV2), serializable independently of process-local Path; ArtifactStore must persist and rehydrate it (RE11's cross-process resume needs exactly this). (2) Kind-specific provenance contracts: runtime bundle requires source slice + source-plan/patch lineage + build plan + effective build + runtime-bundle identity; inventory requires producer source/build identity; promoted-winner/correctness artifact requires producer tune namespace; release report requires campaign/report identities. (3) Raw-path import must be a VALIDATION boundary, not a provenance-creation shortcut - verified laundering path: _resolve_lane_inputs hashes a raw Path, copies it in, and stamps newly invented provenance claiming the current source_slice_id and run_id without checking the file's own identity; an inventory from source A passed as a raw path while building source B acquires source-B provenance at import time. Production code must never say 'the caller supplied this file while building X, therefore it came from X'. For canonical build, prefer persistent artifact IDs/descriptors; a low-level expert campaign-build command may retain an explicit legacy-file import path ONLY if it parses/validates the file's own producer identity and visibly classifies unprovable cases as imported-legacy evidence.

## Notes

Completed 2026-08-17 (RV48 audit fix). Scoped to the verified, concrete laundering defect (item 3 of the audit's required fixes) rather than the broader ArtifactDescriptor/kind-specific-contract design surface (items 1-2) -- see deferral note below.

campaign_lane.py's _resolve_lane_inputs() raw-Path branch used to stamp a freshly-invented provenance document claiming the CURRENT lane's source_slice_id for a file it had no way to prove came from that source. Fixed with a real validation boundary: new _sniff_embedded_provenance() checks whether the raw file's own bytes already carry real provenance-v2 (i.e. it's a byte-for-byte copy of a document this project itself published elsewhere, just handed to us as a path instead of an ArtifactRef) -- if so, that real identity is used untouched. Otherwise the import is visibly classified as imported-legacy evidence (project.provenance_class = 'imported-legacy') rather than silently stamped with an unearned claim. The already-published ArtifactRef branch (verified against its own recorded content_hash) is completely unaffected.

4 new tests (test_re08_provenance_import_boundary.py): plain data file classified imported-legacy not stamped as produced; the exact RV48 wrong-source-inventory laundering scenario caught the same way; a file with genuine embedded provenance has its real identity preserved rather than overwritten; the ArtifactRef branch is unaffected by the fix. Full suite green (851 Windows / 854 Linux), ruff-clean, zero regressions (all pre-existing tests pass unchanged since the fix only adds a marker field and only changes behavior for the previously-never-exercised embedded-provenance case).

Proven for real on Brutus: the actual mtp-inventory.json file used throughout this session's real replay/tune builds, resolved through the real _resolve_lane_inputs() against a real ArtifactStore with a deliberately mismatched source_slice_id (simulating the exact RV48 scenario), came back correctly classified project.provenance_class='imported-legacy' rather than falsely claiming production identity.

DEFERRED (real future hardening, not required to close the verified defect): (1) ArtifactDescriptor -- a frozen, independently-serializable dataclass(artifact_id, kind, relative_path, content_hash, provenance) that ArtifactStore persists/rehydrates, needed for RE11's cross-process resume. (2) Kind-specific provenance contracts (runtime bundle requires source+build+effective-build+runtime-bundle identity; inventory requires producer source/build identity; promoted-winner/correctness artifact requires producer tune namespace; release report requires campaign/report identities) -- today provenance.validate() only requires the five namespaces exist as dicts, which may each be empty. Both are legitimate, separately-scoped follow-up work; the RV48-verified laundering defect itself is fully closed without them.
