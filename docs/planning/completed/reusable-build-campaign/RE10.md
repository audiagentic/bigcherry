## Detailed Solution & Technical Design

### Narrowed scope (locked per RV50 — supersedes the multi-file design above; that design is preserved as history)

PipelineService stays a small PASSIVE stage-boundary checker (verified at 9d55a9b: it already has record/build_inventory/tune/promote/build_replay_full/export_replay_cache/validate_replay methods taking one `expected` dict). Do NOT build the proposed file explosion (lifecycle_specs.py, lifecycle_workers.py, lifecycle_stages.py, runtime_execution.py, replay_validation.py, ggml_types.py). One production module: tools/bigcherry/lifecycle.py — split only if real complexity warrants it.

**Stage surface (exactly what RE15 requires, nothing more):** execute_record_stage(), execute_inventory_stage(), execute_tune_stage(), execute_promotion_stage(), execute_replay_export_stage(), execute_replay_validation_stage(). Each: accepts a typed spec + ArtifactRefs/ArtifactLocators; rehydrates/verifies descriptor-backed inputs (RE25.3 primitives); checks source/build/workload identity; invokes the EXISTING production implementation (no rewrites); publishes outputs through ArtifactStore descriptors; returns a typed result containing ArtifactRefs.
- record: input = record runtime-bundle + workload/model spec → output record-jsonl ref. Runs from the immutable runtime bundle, never the build directory.
- inventory: input = record-jsonl → outputs inventory + dispatch-db (uses RE09's CampaignDatabaseIdentity).
- tune: inputs = tune runtime-bundle + dispatch-db + workload spec → outputs NEW dispatch-db + tuning-measurements. Copy the DB into a run workspace before modification (RE09 4.5); never write into an ArtifactStore object.
- promotion: input = tuning evidence/tuned DB → output promoted-winners, via the EXISTING tune_promotion implementation (it already owns evidence validation incl. the noise-canary protocol) — do not reimplement statistics.
- replay export: inputs = promoted winners/production DB → output replay-cache. Keep replay's portable dispatch identity independent of campaign DB identity (RE09 4.6 test guards this).
- replay validation: inputs = replay runtime-bundle + replay-cache + workload → outputs coverage/validation evidence, reusing ab_benchmark.validate_replay_coverage() — no second coverage validator.

**Minimal PipelineService enhancement (the one real limitation):** run() applies ONE identical expected dict to every input; stages like tune consume different kinds from different producer runs. Add `@dataclass(frozen=True) class ArtifactRequirement: kind: str; expected: Mapping[str, str]; require_promotable: bool = False` plus a `run_contract(...)` path. Not a graph planner.

**CORRECTION to the old RE10 sequence:** old step 'RE10.4 canonical raw-path rejection (allow_legacy_inputs=False by default)' is DROPPED — it contradicts the RV50 non-goal 'keep raw Path as an explicit imported/development boundary'. Raw Path inputs stay legal; RE25.3 turns them into descriptor-backed imported-legacy evidence with sticky taint. No allow_legacy_inputs flag, no rejection.

**Tests (whole-flow, not per-abstraction):** executable fake compiler + fake llama-bench script fixtures (real subprocesses inspecting GGML_HIP_DISPATCH_DB and writing real JSONL — only compile/GPU work faked). Prove: production descriptor chain succeeds; raw-path imported inventory taints all outputs; imported evidence cannot promote; wrong-source production inventory fails BEFORE any GPU/subprocess execution; a modified DB artifact fails before tune; every stage output rehydrates in a fresh ArtifactStore.
