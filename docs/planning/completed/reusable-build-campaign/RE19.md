# Define canonical standard/default campaign profile in v2 config

## Description

Today's `bigcherry build --all` expands to every recipe marked default=true in recipes.toml (a legacy/compat concept). The new planner (RE18) needs its own canonical definition of the 'standard' lane set, expressed directly in terms of v2 source/build/platform identities -- NOT derived by loading compat.recipe.* -- so `build --all` under the new engine means something real rather than silently shrinking to whatever lanes happen to be implemented yet.

## Steps

1. Add a `[campaign.standard]` (or equivalently named) section to the v2 portion of recipes.toml (or a dedicated campaigns.toml) listing the canonical lanes -- e.g. llama-native/stock, bigcherry-native/control, bigcherry/record, bigcherry/tune, bigcherry/replay, each with their platform.
2. Add a config.py loader for this section, producing a tuple of canonical lane identities (not ArtifactRefs -- just the (source,build,platform) selection, which RE18's planner expands into full CampaignLanes).
3. Wire RE18's plan() to accept a --all-equivalent request that expands this canonical profile.

## Detailed Solution & Technical Design

gpt-auto-agent design (RE14 round 19), explicit warning: do NOT let --all silently mean 'all currently new-path-supported lanes' -- that changes what --all means to dodge the cutover requirement rather than actually closing it. The canonical profile must cover the same build roles today's default recipe set covers (stock/control/record/tune/replay or whatever the real production set turns out to be), confirmed against the actual current default=true recipes and their builds before finalizing the list.
