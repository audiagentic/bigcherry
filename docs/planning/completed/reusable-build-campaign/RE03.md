## Detailed Solution & Technical Design

ARCHITECTURAL CONTRACT (backfilled 2026-08-17 per RV48 audit): patch identity and effective source identity are deliberately different things. patch_set_id represents reviewed logical composition and includes module content hashes; source_slice_id represents resulting source bytes. Two different logical compositions may legitimately produce the same effective tree - they share content identity while retaining distinct lineage. Automatic dependency expansion is FORBIDDEN: a declared source/patch set must list its entire dependency closure, and REQUIRES is a validator, not permission for the resolver to silently mutate the requested set (resolve_exact already rejects missing dependencies rather than adding them).

Verified gap (RV48): campaign_resolution computes patch_set_id from exact (patch_id, content_hash) pairs, but production source resolution discards it - campaign_source.source_plan_for passes only module_ids into workspace.SourcePlan, so nothing downstream of resolution carries the content identity. Closing this is RE03's remaining work via the RE04/RE05 fixes.

Current implementation (verified): PatchModule carries canonical ID, ordering, state, upstream provenance, content hash, requires/conflicts; resolve_exact rejects duplicate, unknown, rejected, wrong-state, missing-dependency and conflicting selections. Shipped framework set: 14 validated modules (13 core + validated 1000 upstream-fixes).
