# Decision: no physical patch-folder move — metadata + CLI filtering is sufficient

## Description

Decision: keep patches/ flat and use declarative metadata plus CLI views instead of physically moving files. This has been validated against current discovery, catalog, resolver, and test behavior.

## Steps

Retain flat paths; complete metadata validation through RE40; extend the existing patches CLI through RE43; reconsider only after a measured scale/usability problem.

## Detailed Solution & Technical Design

The functional concerns that folders would address—kind, backend, origin, state, plans, hardware, and relationships—belong in metadata. The code already has recursive discovery and path-independent patch IDs/content hashes, but physical movement would still require broad path/catalog-root changes. Avoid migration churn while the HIP campaign is stable.
