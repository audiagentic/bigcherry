# Consolidate 1243/0840 into ONE production AllReduce dispatch implementation

## Description

RESCOPED 2026-09-02 per explicit operator direction: this plan group's aim is to improve RCCL where it is currently supported, allow RCCL to operate over heterogeneous topologies where the underlying PCIe features it needs are actually available, and provide a safe AND performant fallback where they are not -- not just qualification/documentation of the boundary. Two independent patches (1243, this item's own original implementation, and 0840_hybrid_allreduce_dispatch, written independently) currently exist for the size-adaptive dispatch problem. THIS ITEM'S JOB IS TO END WITH EXACTLY ONE SHIPPED IMPLEMENTATION, not two competing patches.

Direction from gpt-dev-agent's comparative review (2026-09-02): 0840 is the sounder design (correct per-call provider_name/telemetry, threshold derived from the internal pipeline's own real value, forces exact F32 automatically) but has 4 real P1 bugs (missing 0830 dependency; have_internal && !have_nccl large calls wrongly fall to META instead of internal; explicit-override telemetry mislabel; no RCCL admission guard). 1243 is architecturally weaker (independent threshold knob that can drift, manual BF16 handling) but contributed the only real hardware pp/tg evidence so far. Consolidation path: fix 0840's bugs, wire in GP02's admission predicate once it lands, reproduce 1243's real hardware numbers through corrected 0840, THEN retire/delete 1243 entirely -- do not leave both in the tree once 0840 is validated.

EXPLICIT SUCCESS/FAILURE BAR (operator's own words, 2026-09-02): 'if its slower than layer split or meta then we have failed in that scenario.' This applies per-topology, not as one blanket verdict:
- RCCL-viable topologies (PCIe AtomicOps available): dispatch must beat both pure META (-sm layer / butterfly) AND pure internal-only across the full pp/tg range. Already shown directionally true for {0,1} via 1243's numbers; must be reproduced through corrected 0840 with an exact recorded RCCLCompatibilityRevision (1243's numbers have no revision recorded, per GP06 this makes them provisional, not final evidence).
- Device-3 / PCI-atomics-incapable topologies: whatever fallback mechanism ships (see GP09) must be measured faster than META/layer-split for that exact topology, or it must NOT ship -- keep using META there instead. A safe-but-slower special case is itself a failure of this item's aim, not an acceptable compromise.

BASELINE REQUIREMENT (operator's own words): 'baseline is native llamacpp rccl' -- every performance claim in this consolidation must be benchmarked against stock/vanilla llama.cpp's own unpatched RCCL path (not merely against BigCherry's own prior internal-only or META numbers), so it's possible to tell whether BigCherry's dispatch layer is actually adding value over doing nothing.

Root cause chain found during implementation:
1. 2. First real validation showed the rccl branch's guard always failing: comms.size()=0 despite backends.size()=2, so every "rccl" decision silently fell through and produced no measurable change.
3. Root cause: the private scratch source tree used for this work never had patch 1001_hip_internal_allreduce applied. ggml_cuda_ar_pipeline_init() has two implementations in allreduce.cu -- a real CUDA one and a stub gated by `#if !defined(GGML_USE_HIP) && !defined(GGML_USE_MUSA)` that unconditionally returns nullptr on HIP. Patch 1001 flips that guard to `#if !defined(GGML_USE_MUSA)` plus maps pinned-host-memory APIs and swaps __nanosleep for __builtin_amdgcn_s_sleep(4) in vendors/hip.h. Without it, GGML_CUDA_ALLREDUCE=internal was silently falling back to the meta-backend butterfly path the whole session -- so my added secondary-NCCL-init code (inside the `if (ret->ar_pipeline)` branch) never executed at all.
4. Applied patch 1001's exact edits to the scratch tree, rebuilt, reran. Fixed immediately: ar_pipeline_init now returns non-null, secondary ncclCommInitAll succeeds (rc=0, comms.size()=2), rccl branch's guard passes.
