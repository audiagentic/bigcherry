# Rewrite RCCL admission as a shared, reusable fail-closed predicate -- current patch 1225 is not the right design to promote as-is

## Description

SUPERSEDES the original framing of this item per gpt-dev-agent deep review (2026-09-02): the original plan was to promote patch 1225 unchanged into a default patch-set. That is now confirmed WRONG.

Direct code read of patches/1225_hi85_nccl_heterogeneous_arch_guard/patch.py: the guard's actual predicate is raw GPU-architecture inequality (`info.devices[dev_ids[i]].cc != info.devices[dev_ids[0]].cc`) -> GGML_ABORT. It does NOT identify physical device 3 or check PCIe AtomicOps capability at all -- it is a blanket heterogeneous-architecture reject. This means unchanged 1225 would ALSO reject the {0,2}/{1,2} XTX+R9700 topology that HI138/GP06 spent real hardware evidence confirming is safe (excluding the RCCL-version regression GP06 also found). GP01's plan to admit {0,2}/{1,2} to production RCCL is therefore incompatible with shipping 1225 unchanged -- the original GP02 acceptance criteria ('{0,2}/{1,2}/{0,1,2} must remain unaffected by the guard's presence') is IMPOSSIBLE with the guard as currently written.

Separately: 1225 only ever edits the ORIGINAL ggml_backend_cuda_comm_init_nccl() call site. It provides no protection for any OTHER ncclCommInitAll() entry point -- confirmed both 1243 (superseded) and 0840 (patches/0840_hybrid_allreduce_dispatch) each bring up their own independent secondary NCCL communicator with zero awareness of 1225 or any topology qualification list. 'GP02 lands patch 1225' was never going to protect GP03/0840's dispatch path even if 1225's predicate were otherwise correct.

## Steps

1. Design a shared admission function (not a copy-pasted guard per call site) with this predicate, callable from EVERY ncclCommInitAll() entry point in the tree (original comm_init_nccl, 0840's hybrid init, any future one):
   - unknown/unqualified (revision, topology) pair -> DENY (fail closed)
   - known-bad: any topology including physical device 3 -> DENY
   - qualified: topology is in GP01's confirmed-safe set (from a Track-A-pinned RCCLCompatibilityRevision) AND the RCCL library actually loaded matches that qualified revision -> ALLOW
2. Bind the predicate to GP01's qualification data model (RCCLCompatibilityRevision + TopologyIdentityV1), not a standalone architecture-inequality check -- the check must be revision-aware given GP06's finding that revision alone can flip a topology from safe to unsafe.
3. Retire or rewrite patch 1225's actual guard logic to call this shared predicate instead of raw architecture-inequality comparison.
4. Wire the same predicate into 0840's ggml_backend_cuda_comm_init_hybrid() before its ncclCommInitAll() call (this item's real blocking dependency for GP03/0840, not just 'land 1225').
5. Verify: {0,3} (or any device-3-inclusive set) still fails closed with a clear diagnosed error; {0,2}/{1,2} against the pinned known-good RCCL revision now succeeds through both the original init path and 0840's hybrid path.
