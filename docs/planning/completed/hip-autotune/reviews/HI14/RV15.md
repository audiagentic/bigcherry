# Every dual-GPU measurement so far ran without RCCL, on a fallback allreduce

## Notes

Reference invocation used `--lane bigcherry-b10227-hip-mmq-rccl --target rx7900xtx-dual --bench-configs mtp-dual` with repetitions 3 and ctx_size 245760. Note the lane also differs in upstream revision (b10227) and carries `hip-mmq`, so RCCL may not be the only difference; it is the one with a mechanism that explains the magnitude, and the one confirmed present in the logs.

## Findings

The owner supplied reference numbers from the production lane `bigcherry-b10227-hip-mmq-rccl` on `rx7900xtx-dual`, and they are **1.5 to 1.7 times higher than anything measured in this session**:

| | production lane | this session's build |
| --- | --- | --- |
| pp256 | 685.0 | 461.6 |
| pp1024 | 1025.6 | 599.7 |
| pp4096 | 1248.5 | 656.6 |
| **tg128** | **112.7** | 65.9 |
| tg512 | 91.7 | 69.3 |
| tg2048 | 103.4 | 71.2 |

**Cause: `GGML_HIP_RCCL:BOOL=OFF` in every build used here.** The dual-XTX server logs `internal AllReduce init failed (n_devices != 2?); falling back to meta-backend butterfly`. Under `-sm tensor` each layer performs a cross-GPU allreduce, so that fallback sits directly on the critical path. The production lane name ends in `-rccl`; `librccl.so` is installed and `GGML_HIP_RCCL` is a supported option that was simply never set.

**The alternative explanation is ruled out by data already collected.** On this build, native (tg128 69.83), record (67.99) and replay (71.45) all sit within noise of one another. So the gap is not dispatch-layer overhead and not record-mode signature hashing — *native* on this build is ~70 against the lane's 112.7. It is the build.

### What this invalidates, and what it does not

**Not invalidated — the tuning results.** The tuner times individual matmul launches in isolation; allreduce is not inside that measurement. RV13's 7.5% aggregate saving, the `small_k` dominance and the per-candidate medians are statements about kernel selection and stand.

**Invalidated — every end-to-end throughput number for dual-XTX in this session.** That includes the native-versus-replay comparisons and the interleaved A/B, all of which were measured against a baseline crippled by the fallback allreduce. They were already inconclusive on noise grounds (RV11); they are now also measured on the wrong configuration.

**Uncertain — hot-signature ranking.** If the fallback allreduce was consuming a large share of wall time, the relative weight of matmul shapes may look different once it is fast. Standards 7.4 ranking derived from these runs should be treated as provisional until re-recorded on an RCCL build.

**Unaffected — signature capture.** Which signatures execute is determined by the model, context and speculation settings, not by how quickly the two GPUs synchronise. Inventories recorded here remain valid.

## Conclusion

**Confirmed by measurement 2026-08-05.** Built `~/bc-build-rccl` with `GGML_HIP_RCCL=ON` and re-ran at settings matched to the earlier non-RCCL run (`-c 229376`, `--cache-ram 24576`, `-sm tensor -ts 1,1`, draft-mtp n_max 5, q8_0 draft KV), so RCCL is the only variable. The fallback warning is gone — zero occurrences of `AllReduce init failed` / `butterfly`.

| | non-RCCL | RCCL | production lane |
| --- | --- | --- | --- |
| pp256 | 460 | **693.7** | 685.0 |
| pp512 | 568 | 966.3 | — |
| pp1024 | 596 | **1031.7** | 1025.6 |
| pp2048 | 646 | 1180.7 | — |
| pp4096 | 666 | **1254.8** | 1248.5 |
| tg128 | 68.1 | 89.5 | **112.7** |
| tg256 | 66.5 | 90.3 | — |
| tg512 | 67.6 | **89.8** | 91.7 |
| tg2048 | 70.4 | 91.2 | **103.4** |

**Prefill is fully explained.** All three comparable points land within noise of the production lane — 693.7 against 685.0, 1031.7 against 1025.6, 1254.8 against 1248.5. RCCL accounted for the entire prefill gap, a 1.5 to 1.9x improvement.

**Generation is mostly explained.** tg512 matches (89.8 against 91.7). But **tg128 remains 20% short** (89.5 against 112.7) and tg2048 12% short (91.2 against 103.4), so RCCL was the dominant factor and not the only one.

The residual is not attributable from here. Candidates, in rough order of plausibility: the lane is a different upstream revision (b10227 against this tree's 22dc605) and carries `hip-mmq`, which would plausibly affect the small-matmul decode path more than prefill; and the reference ran at `ctx_size 245760` with `cache_ram 0` against 229376 with 24576 here — note `-c 245760` with f16 KV aborts on this build at `ggml-backend-meta.cpp:1520`, so that difference could not be eliminated. The shape of the residual, concentrated at short generation and absent at tg512, points at the speculative-decode path rather than at anything the dispatch layer touches.

**Consequences for this project's measurements are unchanged from the findings above**: tuning results stand, dual-GPU end-to-end numbers from before this need redoing on RCCL, and hot-signature ranking is provisional. The build recipe in HANDOFF has been corrected to set `GGML_HIP_RCCL=ON` with the measured cost of omitting it stated inline.

Still worth doing: have the audit or CMake **warn when a multi-GPU-capable build has RCCL off**. The fallback is correct and near-silent, which is the worst combination — one warning line among hundreds, and a 1.5x performance cliff that no artifact reports.

## Incorporation (2026-08-20, PH01 review triage)
