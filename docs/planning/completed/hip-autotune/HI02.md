# Add CMake options, ABI types, and HIP autotune header infrastructure

## Description

Patch 1 — integrate the proposed CMake options (GGML_HIP_DISPATCH_REPLAY, GGML_HIP_AUTOTUNE, GGML_HIP_AUTOTUNE_VARIANT_SET, etc.) into ggml/CMakeLists.txt; define stable signature/candidate/manifest ABI types in hip-autotune-types.h; create public header ggml-hip-autotune.h; reject FORCE_MMQ/FORCE_CUBLAS combinations at CMake time.

## Steps

- Add GGML_HIP_DISPATCH_REPLAY, GGML_HIP_AUTOTUNE, GGML_HIP_AUTOTUNE_VARIANT_SET, GGML_HIP_AUTOTUNE_SIGNATURE_FILE, GGML_HIP_AUTOTUNE_SQLITE options to ggml/CMakeLists.txt
- Add CMake-time validation: requires GGML_HIP=ON, rejects FORCE_MMQ/FORCE_CUBLAS
- Create ggml/include/ggml-hip-autotune.h with public API declarations
- Create ggml/src/ggml-cuda/hip-autotune-types.h with:
  - `ggml_hip_kernel_family` enum (mmvq, mmq, mmvf, mmf, blas)
  - `ggml_hip_hardware_key_v1` struct (architecture_code, wave_size, compute_units, feature_flags)
  - `ggml_hip_dispatch_signature_v1` struct with `schema_version` field (uint16_t), op, types, M/N/K, ne[]/nb[], flags
  - `ggml_hip_candidate_descriptor` struct (runtime_id as uint32, stable_name, family, implementation_version, architecture_mask as uint64, graph_safe, deterministic, can_execute, launch)
  - `ggml_hip_resolved_dispatch` struct (candidate pointer, prepared_state)
- Define runtime function signatures: `ggml_hip_dispatch_resolve`, `ggml_hip_dispatch_launch`
- Gated all code behind GGML_USE_HIP preprocessor guards
- Verify CMake configuration rejects invalid combinations
