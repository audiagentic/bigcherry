# Generate explicit MMVQ geometry variants

## Description

Patch 7 — refactor MMVQ kernel from implicit constexpr geometry (calc_nwarps, calc_rows_per_block) to explicit template parameters (nwarps, rows_per_block). Generate bounded instances via the catalog. Native wrapper uses existing constexpr policy as explicit candidate.

## Steps

- Refactor mul_mat_vec_q kernel: add nwarps and rows_per_block as template params
- Add `static_assert` bounds matching upstream constraints: `width 1..MMVQ_MAX_BATCH_SIZE (8)`, `nwarps 1..8`, `rows_per_block >= 1`
- Add compile-time eligibility helpers for geometry validity
- Create native wrapper that instantiates existing calc_nwarps/calc_rows_per_block values
- Implement catalog-driven instance generator for bounded matrix (widths 1..8, warps 1/2/4/6/8, rows 1/2)
- Generate mmvq-autotune-instance-*.cu translation units
- Start with Q8_0-only variants first; add Q6_K after Q8_0 passes
- Run full-max as compile audit to discover resource failures

## Notes

**2026-08-05: built, run, verified on hardware, and now measured.** Supersedes the earlier "has not been compiled or run" note.

### Verified

Built `workload-max` against upstream 22dc605 and run on three GPUs across two operating systems — gfx1100 XTX (Linux), gfx1201 (Linux), gfx1100 GRE (Windows/ROCm 7.1). Compiles clean; `nm` confirms `ggml_hip_mmvq_forced` threaded through the mangled native chain and the geometry instances instantiated; the routing executes end to end (`tuner → ggml_hip_mmvq_launch → ggml_cuda_mul_mat_vec_q_variant → ggml_cuda_mul_mat_vec_q → mul_mat_vec_q_switch_type`); full `test-backend-ops -o MUL_MAT` sweeps pass on all three with 0 failures.

### Measured — the geometry matrix earns its place on RDNA3, and only there

Idle GPUs, `SCREEN_SAMPLES=3 FINAL_SAMPLES=15`, full sweep. See review RV07 (closed) for the full table.

**MMVQ explicit geometry wins 24 signatures on gfx1100 at median 16.18%, max 25.32%, 20 of 24 above 10%.** The identical code on gfx1201 wins 5 at ~1–5%. An RDNA4-only reading of this data says the geometry matrix is not worth its 98 compiled instances; that reading is wrong for the hardware this project targets. **Measure per architecture.**

**`mmvq:q8_0:w1:nw4:rpb4:sk1:v1` takes 14 of the 24 wins on its own** — a `small_k` geometry, the dimension `_variant_initialiser` silently dropped so the registry could name it but never request it. The most valuable compiled geometry in the catalog was unreachable until that was fixed. Worth remembering before writing off any similar "naming gap".

Not yet answered: whether this holds for the real Q8_0 27B MTP configuration. Both runs use `test-backend-ops` synthetic shapes. The dominant winner being `w1` sits in the draft-width regime, which is encouraging, but is not evidence.

### One defect found and fixed — review RV01 (closed)

The candidate's src0 type was in every stable name but never in `ggml_hip_variant_params`, so no `can_execute` could check it; candidates were ruled eligible for signatures of other types. It fired the HI09 part-1 abort (`no compiled MMVQ instance for type=q4_0`) and separately made an `mmq:q8_0:j16:...` candidate win an `iq1_s` signature and abort at `mmq.cuh:98`. Fixed across all four families by adding `src0_type` to the variant params and checking it in each predicate.

The part-1 abort earned its keep: it caught this, and the decision that a miss is fatal rather than a silent native fallback is what made it a stack trace instead of a quietly wrong measurement.

Four further defects surfaced behind it (RV02–RV05, closed, against HI12) before a full sweep would complete, and RV06 (closed, against HI09b) narrowed `architecture_mask` to encode capability.

### Earlier notes, still accurate

MMVQ geometry: 56 instances in `workload-max` including `small_k`. Fusion correctly excluded from candidate dimensions (runtime branch inside `mul_mat_vec_q_switch_fusion`, one instance serves both).

- **small_k** is implemented: distinct compiled geometry with `rows_per_block = nwarps`, only for `nwarps > 1`. Occupies a reserved byte in `ggml_hip_variant_params` (struct size unchanged).
- **Fusion excluded**: runtime branch; one compiled instance serves both fused and unfused paths. Including it would double the candidate matrix for no gain.
