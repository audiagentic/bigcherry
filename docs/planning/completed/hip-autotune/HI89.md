# HI67 export-gate follow-ups: orphaned screening reducer, seed-override native validation

## Description

Two small, deliberately-deferred loose ends from HI67's replay-cache export gate slice (2026-08-23), split out so they aren't lost inside a now-closed line of work.

1. `autotune_catalog.read_correctness_evidence()` is now orphaned production code -- its only real caller (`build_manifest()`'s PRODUCTION_VARIANT_SETS gate) was removed when correctness proof moved to `replay_cache.build()`'s dispatch_db gate. It remains directly unit-tested (test_build_descriptor.py) and its docstring now says explicitly 'no current caller treats its output as a correctness gate' -- but nothing else in the pipeline calls it. Decide: keep as a standalone screening/diagnostic reducer someone might wire into a report, or delete it and its test now that it does nothing load-bearing.

2. `replay_cache._load_seed_overrides()` gained optional `hardware`/`native` fields (HI67) so a seed override for a genuinely unseen dispatch can supply the identity the new correctness gate needs. `winner` is validated against the manifest's candidate set; `native` is not -- an operator typo in `native` fails late, inside the correctness-gate's DB lookup (a clear CorrectnessGateError, so it's fail-closed, just not fail-fast with a specific message). Consider validating `native` against the manifest's native_wrapper candidates at seed-load time, matching `winner`'s existing validation, for a clearer error message.
