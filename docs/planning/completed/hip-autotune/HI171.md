# THA15 — Provenance-safe promoted-winner execution and winner-vs-runner-up counterfactual replay audit

## Description

Extend HI171 from execution observation to decision-grade causal validation. For each promoted tuning decision, replay the exact source winner against the exact source runner-up under invariant workload, runtime, environment, build, and hardware. Replay pairs must derive from immutable provenance captured when the production ranking decision was made; never reconstruct or rerank candidates from current Python policy, registries, mutable caches, or current tuner behavior.

## Steps

- Extend the production ranker to persist immutable source top-2 ordering and candidate/config/artifact hashes.
- Bind promotion metadata to selection_id and the immutable source-decision digest without rewriting existing cache semantics.
- Implement strict provenance resolution and fail-closed validation; legacy/incomplete decisions return UNREPLAYABLE_PROVENANCE and require a fresh tune.
- Generate winner control and runner-up counterfactual manifests that differ only at the target dispatch key, with canonical hashes and structural invariant diff.
- Implement paired/interleaved replay with identical workload, binary, device, environment, warmups and iterations; correctness precedes performance and HI166 gates MTP work-equivalence.
- Emit append-only machine-readable results with raw paired samples, effect statistics, confidence metadata, and stable verdict.
- Integrate generated results into THA15 execution-audit and batch operation; coordinate orchestration with HI170 and causal modelling with HI35.
- Add unit, mutation, negative-provenance, integration, and representative RHA04 hardware validation.

## Detailed Solution & Technical Design

The compiled production ranker remains the authority for historical winner/runner-up ordering. Persist schema_version, selection_id/source_run_id, dispatch/signature/cache key, winner and runner_up identities plus complete config or immutable artifact references, per-config SHA-256, candidate-set digest, ranking policy/version/hash and tie-break metadata, source decision digest, git/build/toolchain/runtime identity, hardware key, workload manifest digest, and source cache digest. Resolve selections by immutable binding; rehydrate exact candidates; construct control and counterfactual manifests with exactly one controlled target-key change; canonicalize/hash both and reject any extra difference. Decision-grade requires exact source selection, explicit runner_up, verified digests, target key, cache/workload/runtime/build/hardware provenance, and correctness. Results are append-only and analysis-only; they cannot mutate promotion/source-cache state or be promoted. Exploratory mode is clearly marked and cannot satisfy HI171 acceptance.
