# Real RD07 (Q6_K MMQ sub-scale fold) A/B on the production dense Qwen3.8-27B-AD-Q6_K model

## Description

User downloaded the real production Q6_K quant (/mnt/vault/llm-models/qwen3.8-27b/gguf/mtp/Qwen3.8-27B-AD-Q6_K.gguf) and asked to test whether RD07/RD08 (real external-fork kernel patches for Q6_K, currently `untested` in bigcherry -- patches 1203_rd050607_rdna4_wmma_fa_q6k_mmq / 1204_rd08_q6k_mmvq_vdr2) deliver a real end-to-end win, given HI109's dispatch-tuning approach found none. RD07 (bundled in 1203, applied via `--experiment rd05-07-only`) is the most promising real lead: its fork-reported number is a genuine compute-throughput improvement (Q6_K MMQ 40 -> 58 TFLOPS, prefill), not a dispatch-candidate-selection win -- categorically different from what HI105/HI109 already ruled out.

## Validation

Real 4-round interleaved A/B, real production model/flags, both legs freshly built. Results (t/s):

| round | baseline pp512 | rd07 pp512 | baseline tg256 | rd07 tg256 |
|---|---|---|---|---|
| 1 | 384.54 | 374.82 | 45.06 | 45.51 |
| 2 | 373.88 | 382.04 | 45.61 | 46.16 |
| 3 | 390.72 | 391.59 | 46.03 | 45.99 |
| 4 | 371.86 | 391.45 | 45.97 | 45.32 |

pp512 mean: baseline 380.25, rd07 384.98 (+1.2%) -- round-to-round noise (~7-8 t/s, ~2%) exceeds this delta; not a real signal. tg256 mean: baseline 45.67, rd07 45.75 (+0.16%) -- effectively zero.

**Verdict: net null, same pattern as HI109.** RD07's real, fork-verified kernel-level throughput improvement (40->58 TFLOPS on Q6_K MMQ) does not survive to end-to-end pp512/tg256 on this real production request shape -- consistent with HI107's finding that kernel-level deltas require knowing real time-share before they predict an end-to-end result. A third independent real-hardware null result (MoE dispatch tuning, dense Q8_0 dispatch tuning, dense Q6_K kernel patch) is a real, load-bearing pattern, not noise from one bad measurement.
