# WDDM tuner failure-recovery: soak validation + adjudicate retry/backoff defaults

## Description

HI64's WDDM unblocked-sweep hardening is implemented and hardware-validated: bounded retry (GGML_HIP_TUNE_ELAPSED_RETRY, default 2) + linear backoff (GGML_HIP_TUNE_ELAPSED_RETRY_BACKOFF_US, default 2000us) around the silent non-finite hipEventElapsedTime() branch, plus three more previously-silent hipStatus comparisons routed through hip_ok(). Result: 0/2 clean before -> 5/6 with immediate retry -> 10/10 clean with retry+backoff across independent runs on the real RX 7900 GRE / ROCm 7.1.

What is NOT yet decided: whether the current defaults (2 retries, 2000us backoff) are sufficient, or whether a larger soak sample would justify raising them. Ten clean runs is a real but modest sample for an environmental, probabilistic failure mode; one budget-exhaustion poisoning was observed in the pre-backoff sample (1/6). Both knobs are env-overridable, so no rebuild is needed to experiment.

This is a low-priority measurement-hardening decision, deliberately split out of HI64 (whose cross-device-poison incident and the retry/backoff implementation both closed).

## Steps

- - Run a larger independent unblocked-sweep soak on the Windows/WDDM workstation (target ~20-30 runs, or a run with GGML_HIP_TUNE_TRACE_ATTEMPTS=1 to count real retry events) and record the poisoning rate and the distribution of retry-event counts.
- Decide, from that sample, whether the default retry budget (2) and/or backoff (2000us) should be raised; if a raise is justified, update the defaults in hip-autotune-tuner.cu/.cuh and the source-contract tests, keeping the env overrides.
- If the sample shows the current defaults are sufficient, close this with the decision recorded and no code change.

## Validation

DONE 2026-08-25: 25-run unblocked-sweep soak on the real RX 7900 GRE / ROCm 7.1 (Windows/WDDM), reproducing HI64's exact methodology (GGML_HIP_DISPATCH_MODE=tune, GGML_HIP_TUNE_SCREEN_SAMPLES=3, GGML_HIP_TUNE_FINAL_SAMPLES=15, test-backend-ops.exe test -o MUL_MAT, no HIP_LAUNCH_BLOCKING). Result: 25/25 clean runs, 0 measurement_failure across ~27,600 total measurement results. Retry mechanism (elapsed_time_retry) fired on every single run: 1788 total retry events, per-run range 44-215 (mean ~71.5). No run exhausted the retry budget (GGML_HIP_TUNE_ELAPSED_RETRY=2) or hit the backoff ceiling. This extends HI64's own 10/10 clean sample to 25/25 with zero poisoning and a much larger retry-event population, all self-recovering within the current budget. Decision: current defaults (GGML_HIP_TUNE_ELAPSED_RETRY=2, GGML_HIP_TUNE_ELAPSED_RETRY_BACKOFF_US=2000) are sufficient -- no code change made. Raw per-run journal/trace logs and summary.json retained at build/hi98-soak/runs/ (project-local, gitignored build dir) for this session; run_soak.ps1 is the reproducible harness.
