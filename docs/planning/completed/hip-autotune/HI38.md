# Crash-safe append-only tuning journal

## Description

One self-contained JSON event per line (JSON-lines), each independently checksummed (BLAKE2b-128) and flushed+fsync'd (or _commit on Windows) before the writer returns, so a killed tuning process leaves a prefix of fully-durable, individually verifiable events -- never a torn write presented as complete. Event kinds: start, result, attempt, complete, interrupted. The C++ side (src/ggml/src/ggml-cuda/hip-autotune-journal.{h,cpp}) exposes ggml_hip_journal_open/append_result/append_attempt/close/is_open, wired into the tuner (hip-autotune-tuner.cu) at every time_candidate() call site. The Python side (tools/bigcherry/tune_journal.py) provides JournalWriter, read_current() (detects a truncated/corrupt trailing record and recovers the valid prefix), and compact(); can_compact treats {complete, interrupted, result, start, attempt} as terminal states.

The 'attempt' event kind (append_attempt / trace_launch_attempt, opt-in via GGML_HIP_TUNE_TRACE_ATTEMPTS) was added 2026-08-11 specifically to attribute a device-side crash to the candidate that caused it: a candidate whose kernel corrupts device memory never reaches append_result, so without a pre-launch 'attempt' event the journal's last entry is one candidate short of the truth. This is exactly the tooling that pinned down the EX02 MMQ q6_K/J=112/gfx1100 crash.

Validated on real hardware (2026-08-11/12): the crash-safe recovery behavior was exercised for real during the EX02 investigation (4 tuning attempts, first 3 crashed, the journal correctly reported interrupted/incomplete state each time and the final successful run reported complete:true with 6858 entries).
