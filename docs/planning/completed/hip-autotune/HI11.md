## Notes

### Review update

**Bounded-width array cache** (plan 8.6). The resolver is a hash map on the dispatch digest. For MoE, where width varies per token within one operation, an array indexed by width — bounded at `MMVQ_MAX_BATCH_SIZE = 8` — turns a hash lookup into an array index on the hottest path in the system. Add it beside the digest map, not instead of it. (PACK_REVIEW B5)

**Restart-only cache reload is a deliberate non-goal** (plan 12.5). Captured HIP graphs hold the resolved candidate, so live reload requires graph and binding invalidation that has not been proven. Record it as a non-goal here so it is not added later by someone who has not thought about graph capture. (PACK_REVIEW B8)

**Why this precedes the tuner.** The pack puts manual replay (Phase 3) before the tuning engine (Phase 4) so the whole resolve/bind/fallback/miss path is proven with hand-written winners before any measurement code exists. Keep that order — it means a tuner bug can never be confused with a dispatch bug.
