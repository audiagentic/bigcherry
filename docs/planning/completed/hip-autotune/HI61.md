# Separate supported candidate universe from observed workload coverage

## Description

Make catalog completeness explicit after refactor. Current workload-derived inventories intentionally narrow workload-max generation, but supported quant families and architecture-valid alternatives must remain independently representable and reportable.

## Steps

- Define inventory-observed, workload-max, and production-supported semantics.
- Generate supported candidates independently from observed signatures where the selected mode requires it.
- Add per-quant coverage reporting with observed counts, native/alternative candidates, families, and explicit zero-alternative reasons.
- Make release validation fail when a campaign claims optimization for an uncovered quant family.
- Validate the additive supported_coverage field and preserve workload/replay manifest candidate identity.

## Detailed Solution & Technical Design

Build an unrestricted candidate universe from the same upstream source tables used by full-max, using a synthetic full inventory rather than the observed workload. Keep workload-max, replay-full, and replay-slim candidate selection unchanged. Add supported_coverage as an additive manifest field with sorted supported_types, observed_types, per-type native/alternative counts, alternative families, architecture applicability, and explicit zero-alternative reasons for observed-but-unsupported types. Validate the optional report in the manifest schema and in validated release claims.
