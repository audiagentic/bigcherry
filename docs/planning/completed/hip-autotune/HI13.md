## Notes

### Collection points — all five sites covered (B4)

Patch 0700 (coverage_counters + HI13) instruments all five family entry points:

1. **Dense `ggml_cuda_mul_mat`** — HI04 via `ggml_hip_dispatch_mul_mat`
2. **Dense `ggml_cuda_mul_mat_id`** — HI04 via `ggml_hip_dispatch_mul_mat`
3. **Fused MMVQ graph paths** — patch 0700 via `ggml_hip_dispatch_family` at `ggml_cuda_mul_mat_vec_q` entry
4. **Fused MMVF graph paths** — patch 0700 via `ggml_hip_dispatch_family` at `ggml_cuda_mul_mat_vec_f` entry
5. **Public MMQ/MMF family entry points** — patch 0700 via coverage count + `ggml_hip_dispatch_family` at `ggml_cuda_mul_mat_q` and `ggml_cuda_mul_mat_f` entries (no fusion, so `fusion = nullptr`)

BLAS is excluded from dispatch_family because it's not a fused path and the graph optimiser never calls it directly — only the dense selector reaches BLAS.

### C5 — transposed-vector MMVF path

`ggml_cuda_mul_mat` has a path that swaps `src0`/`src1` and synthesises a `dst` for `ne01 == 1 && ne11 > MMVF_MAX_BATCH_SIZE`. The dispatch layer declines this shape (see `hip-autotune-dispatch.cu`), so the shape is never tuned. This is deliberate — its launch context is not what the signature describes, and modelling it wrongly would be worse than not tuning it.
