# Correctness-evidence mapper only handles non-batched MUL_MAT signatures -- real batched src1 (MTP multi-token verify) signatures are skipped

## Description

HI109 (real dense Qwen3.8-27B/Q8_0 production campaign, 2026-08-24 Brutus): after HI111 fixed quantized-type support in `signature_to_test_file_line()`, 105/113 real hypotheses got correctness evidence. The remaining 7 (of 8) skips were all real MTP-traffic signatures with a batched src1 outer dimension -- `src1=(2,1)`, `(3,1)`, `(4,1)` -- rejected by the same non-batched/contiguous restriction `signature_to_op_filter()` and `signature_to_test_file_line()` both enforce (outer dims must be exactly `(1,1)`). These are almost certainly MTP's multi-draft-token verification batches (spec-draft-n-max=5 in production), not synthetic/rare shapes -- real production traffic routinely produces them.

The 8th skip (`ab456539f62dab531b54d2da08453dfd`, op=GLU) is the already-tracked HI108 gap, not this one.

## Steps

1. Read `test-backend-ops.cpp`'s `test_mul_mat`/`test_generic_op` handling of a batched (bs>1) case to confirm the real byte-layout/broadcast semantics for a batched src1 against a non-batched src0.
2. Extend `signature_to_test_file_line()` (tools/bigcherry/signature_correctness_mapping.py) to accept `ne1` outer dims > (1,1) -- likely still usable with the zero-strides sentinel (same HI111 fix), just needs the outer-dims guard relaxed and validated against a real transcript.
3. Add a unit test using one of HI109's real skipped signatures (e.g. the src1=(2,1) case) as a fixture.
4. Re-run correctness-evidence generation against the HI109 real measurement set (still on Brutus at /tmp/hi109_27b_campaign/) to confirm all 7 now get real evidence instead of skipping.
