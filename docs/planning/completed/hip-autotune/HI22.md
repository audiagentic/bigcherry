# Candidate override for manual testing and seeding

## Description

Mechanisms to manually override the selected candidate for a specific signature or globally.

Three mechanisms:

**A. Environment variable (global force):**
```bash
GGML_HIP_FORCE_CANDIDATE=mmvq:q8_0:w4:nw6:rpb2:sk1:v1 ./test-backend-ops
```
Bypasses resolution and uses that candidate for every eligible signature.

**B. Seed override file (per-signature):**
JSON mapping dispatch_hex → stable_name, applied when building the replay cache:
```bash
python -m bigcherry.replay_cache measurements.jsonl \
    --seed seed-overrides.json --output dispatch.cache
```

**C. Per-signature override file at runtime:**
```bash
GGML_HIP_DISPATCH_OVERRIDE=overrides.json ./llama-bench ...
```
Loaded by the resolver; on cold path, checks the digest against the override map before measuring.
