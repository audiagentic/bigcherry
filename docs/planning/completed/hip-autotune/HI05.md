# Implement canonical signature construction and hardware key

## Description

Create the signature builder (hip-autotune-signature.cpp) that constructs canonical dispatch signatures after device-local slicing. Include hard identity fields, optional refinements, and diagnostics-only fields. Implement hardware key encoding. Stable serialization and 128-bit digest hashing.

## Steps

- Implement ggml_hip_make_signature() with operation, types, precision, M/N/K, ne[], nb[], layout, broadcast, fusion fields
- Exclude diagnostic identity from hash (model name, layer, pointer, request ID, device ordinal)
- Construct signatures after device-local tensor slicing
- Implement refined vs base key separation
- Implement hardware_key_v1 encoding: architecture_code, wave_size, compute_units, feature_flags
- Stable byte serialization and 128-bit digest via `blake2b(digest_size=16)`:
  - Signature: `person=b"llama-hip-tune"`
  - Hardware key: `person=b"llama-hardware"`
- Process deduplication map for identical signatures across different call sites

### Open refinements from PACK_REVIEW B9

**Divisibility class as a refinement** (plan §8.4). The signature has `alignment_class`, `occupancy_bucket`, `offset_modulo` but no divisibility class. MMQ's `fallback` already depends on `ne01 % 128`, which is captured as hard identity — but other divisibility relationships (K against `QK8_1`, N against tile width) are not. Low priority — refinements are opt-in and unpromoted by default.
