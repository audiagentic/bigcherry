DONE (already implemented, found 2026-08-25): this item's real intent -- map a HIP device to a real GPU telemetry source and capture clock/temp/power with absent-not-zero semantics -- was already fully built under HI52/HI60 (src/ggml/src/ggml-cuda/hip-autotune-smi.cpp/.h), not under this item's own ID. Rather than raw /sys/bus/pci parsing (this item's own step-1 sketch), the real implementation dlopen's librocm_smi64.so.1 (never linked, so it degrades cleanly to valid=false on Windows/library-absent hosts rather than breaking the build) and matches the HIP device to an RSMI monitor index by real PCI domain/bus/device (hipGetDeviceProperties + rsmi_dev_pci_id_get), exactly the 'map device -> real sysfs/telemetry source, never guess an index' requirement. Captures sclk/mclk (current, not just supported range), edge/junction temp, socket power (uW), and busy percent. Absent-not-zero is enforced at two levels: a top-level `valid` flag (false whenever the capture is off, unresolved, or any RSMI symbol/init step fails) separate from `identity_valid` (telemetry must not be compared across an unresolved device identity), plus tuner.cu emits an explicit '{}' / 'identity_mismatch' / 'clock_unavailable' status rather than a zeroed struct on any failure path. Gated behind GGML_HIP_TUNE_SMI (off by default). Wired into every measurement's device_state_pre/device_state_post (HI52 part 2, per-signature -- broader than this item's own 'run start/end' framing) and into HI64's per-device poison-scoping (measurement_failure disables further SMI capture on that device only, via g_smi_runtime_disabled). Real coverage confirmed via tools/tests/test_dispatch_safety.py's TestDispatchSafetyContracts (test_device_evidence_has_identity_and_explicit_drift_states, test_device_capture_does_not_emit_zero_state_when_unresolved) plus the HI64 per-device-scoping tests -- both passing locally.
