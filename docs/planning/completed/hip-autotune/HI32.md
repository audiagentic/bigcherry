import sqlite3
import json
from collections import defaultdict

def analyze_gaps(db_path: str, build_id: int, hardware_id: int,
                 min_cluster_size: int = 5, min_total_calls: int = 100):
    """Analyze transform-gap records and propose new transformations."""
    conn = sqlite3.connect(db_path)

    # Query gaps joined with observations for prioritization.
    rows = conn.execute("""
        SELECT g.signature_digest, g.pattern, g.native_family,
               o.calls, o.est_bytes,
               g.transformations_tried
        FROM transform_gap g
        JOIN observation o ON g.signature_digest = o.signature_digest
        WHERE g.build_id = ? AND g.hardware_id = ?
        ORDER BY o.calls * o.est_bytes DESC
    """, (build_id, hardware_id)).fetchall()

    # Cluster by pattern.
    clusters = defaultdict(list)
    for row in rows:
        digest, pattern, family, calls, est_bytes, tried_json = row
        key = extract_pattern_key(pattern)  # e.g., "F32[1xK]xF32[KxN], N>8"
        clusters[key].append({
            'digest': digest,
            'calls': calls,
            'est_bytes': est_bytes,
            'tried': json.loads(tried_json) if tried_json else [],
        })

    # Filter: only actionable clusters.
    proposals = []
    for pattern_key, gaps in clusters.items():
        total_calls = sum(g['calls'] for g in gaps)
        if len(gaps) < min_cluster_size or total_calls < min_total_calls:
            continue

        # Check what transformations were already tried.
        tried_ids = set()
        for g in gaps:
            for t in g.get('tried', []):
                tried_ids.add(t.get('id'))

        # Propose new transformation if no known transform succeeded.
        proposal = propose_transformation(pattern_key, tried_ids, gaps)
        if proposal:
            proposals.append(proposal)

    return proposals

## Architecture

The agent analysis tool reads transform-gap records from SQLite (not JSONL directly — SQLite provides the observation join for prioritization). It clusters gaps by pattern, proposes transformations, and generates code for the most promising candidates.

## Input: SQLite Query

```sql
SELECT g.sig, g.pattern, g.native_family,
       o.calls, o.est_bytes,
       g.transformations_tried
FROM transform_gap g
JOIN observation o ON g.sig = o.signature_digest
WHERE g.build_id = ? AND g.hardware_id = ?
ORDER BY o.calls * o.est_bytes DESC  -- prioritize by impact
LIMIT 50;
```

## Pattern Clustering

Gap records are clustered by:
1. **Type signature**: src0_type + src1_type + dst_type (e.g., F32×F32)
2. **Dimensional pattern**: e.g., `ne0[1]==1` (single row), `ned[1]>MMVF_MAX_BATCH_SIZE` (wide)
3. **Native family**: the family that served it natively (usually BLAS)

Clusters with >5 gaps and total calls > 100 are considered actionable.

## Proposal Generation

For each cluster, generate potential transformations:

| Pattern | Proposed Transform | Target Family |
|---------|-------------------|---------------|
| ne0[1]==1, ned[1]>8, F32 | transpose_weight_for_mmvf | mmvf |
| ned[1]>8, k%2==0, float | batch_for_mmvf | mmvf |
| ne1[1]==1, ned[1]<=8 | (already served by mmvf — no gap expected) | - |
| quantized, ned[1]>MMVQ_MAX | batch_for_mmqq | mmvq |
| F32×F32, small M, large N | row_partition_for_mmf | mmf |

## Validation Pipeline

A proposed transformation goes through:
1. **Mathematical equivalence check**: can the agent prove the transform is equivalent? (e.g., transpose of single-row weight)
2. **Family_can_serve check**: does the transformed signature satisfy the target family's constraints?
3. **Code generation**: emit C++ for can_apply, apply, inverse
4. **Compilation test**: compile the generated code with GGML_HIP_ROUTING_TRANSFORM=ON
5. **Correctness test**: re-run tuner on representative shapes from the cluster, compare_outputs against native
6. **Performance test**: verify improvement >= replacement_threshold_pct

If any step fails, the proposal is rejected and not added to the registry.

This code is written to `hip-autotune-transform-discovered.cu` (separate file from predefined transforms) and registered in the same registry array.

## Integration with Registry

Discovered transforms are added to the registry at init time, same as predefined ones. They carry `source = GGML_HIP_SOURCE_DISCOVERED` and `equivalence_verified = true` (only after passing the validation pipeline).
