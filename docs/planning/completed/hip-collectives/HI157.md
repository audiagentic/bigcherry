# Wire patch 1225 (device-3 RCCL guard) into a default patch-set -- it is currently not shipping

## Description

HI138 (closed 2026-08-29, Outcome B) established that any RCCL communicator including physical device 3 (RX 6900XT) crashes -- a real, permanent hardware limitation (chipset-routed PCIe root port lacks AtomicOps capability). patches/1225_hi85_nccl_heterogeneous_arch_guard.py is the fail-closed guard against this exact condition, and HI138's own closure explicitly relies on it remaining in place ('Patch 1225 remains required and justified by this evidence').

Real gap found during HI138's own investigation, flagged but not fixed: patch 1225 is currently STATE=untested and is NOT included in any default build's patch-set (bigcherry-native's framework patch-set excludes untested-state patches per the project's normal promotion discipline). This means the safety guard every closed investigation assumes is protecting production is not actually shipping in any binary tested so far this project.

## Steps

1. Confirm current state: `bigcherry patch-explain 1225_hi85_nccl_heterogeneous_arch_guard` to see its real state/validation status and which sources/patch-sets (if any) currently include it.
2. Determine what validation is needed to promote it out of untested -- likely just needs its own real-hardware confirmation run (the guard should reject/fail-closed when device 3 is present in an RCCL-bound topology) rather than a fresh design.
3. Once validated, add it to the framework patch-set (or the appropriate source's patch-sets list in config/recipes.toml) so it ships in the default `bigcherry` build.
4. Verify with a real hardware run: attempt the known-crashing {0,1,3} topology with the patched build and confirm it now fails CLOSED (a clear, actionable error) rather than the raw ncclGroupEnd()/hipErrorIllegalState crash this session observed without the guard.
