# Audit production KV format compatibility on ABI43

## Notes

Historical correction, 2026-11-19: this review set the implementation order for the first production lane. User subsequently clarified the bump-wide rule: all existing BigCherry features must be ported. Therefore B16F8/B16I8 are required RUM07 deliverables after plain E4M3; only their order is staged. The earlier word 'deferred' means later stage in this bump, not excluded from the bump.

## Findings

The selected Flash-Next path defaults its served KV format to legacy fp8/E4M3 even when the layout omits a dtype. ABI43 Qwen4exp bring-up refuses kv_fp8_ok; enabling only that probe would still leave no matching Flash-Next H256 dense/QSA attention reader row. Upstream native I8 is not equivalent to the current E4M3 deployment. The production format gate must cover the exact rank geometries, probe, store, paged attention reader, bytes/planner/bindings and shared MTP KV group, with page/split merge behavior. Descriptor-only rad0040/rad0042 work is not production wiring and its assert-only fixture is disabled by NDEBUG.

## Conclusion

The plain E4M3 deployment path remains the first implementation checkpoint. B16F8/B16I8 are also mandatory before RUM07 completion under the user's bump-wide feature-preservation rule; implement them in a separately validated stage and retain their prior semantics.
