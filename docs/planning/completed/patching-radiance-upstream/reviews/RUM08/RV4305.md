## Findings

The exact ABI43 candidate has already replaced rad0013's Qwen pass-replay override, but retirement still needs proof of effective launch arguments. Existing QSA exact-bound and runtime tests cover the selector and keyed bound. Source tracing narrowed the suspected missing-summary collision: BatchBuilder allocates and attaches kv_used_max_h from per-group h_used, and attaches seqused_h; for ordinary resident full-KV decode/verify, every nonempty step has a positive group maximum. If the summary pointer alone is absent, issue.cpp can recompute from seqused_h for a true group operand. The wide QSA verify path above the exactness bound uses private qsa_sequ, so its issue does not match the group operand and uses model-bound fallback in either case. The theoretical collision remains for genuinely missing/invalid summaries on dense full-group decode paths, but that is not an accepted BatchBuilder state. Preserve rad0028 rank-0 proposal agreement and rad0029 per-rank resource bounds. rad0036's long-profile token budget/reservation/order differs from upstream mixed-step timing control; pin interleave and narrowly scope or withhold long profiles.

## Conclusion

No pass-key change is justified from the missing-pointer case alone. Confirm the production decode admission guarantees a positive full-group summary and exercise actual keyed/effective arguments on the selected fixed-depth path. If any accepted dense path can produce a missing or nonpositive summary, fail that launch or add a group-scoped presence bit. Keep rad0013 excluded only after the effective-argument proof; preserve rank-consistent drafts, per-rank bounds, and one explicit scheduler/interleave policy.
