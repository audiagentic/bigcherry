# Repeatable experimental qualification and archival workflow

## Description

Define and document a repeatable, diagnostic-only workflow for exploratory hardware/software experiments before they become formal implementation plans. The process must provide a local run-bundle structure, explicit safety and stop gates, provenance and evidence rules, promotion criteria into planning, and archival guidance. Use RCCL heterogeneous qualification as the motivating example without creating production dispatch or tuner behavior.

## Steps

- Review existing experiment-contract, profiling, evidence, artifact, planning, and ledger conventions.
- Publish a maintained reference runbook for experiment intake, execution, evidence capture, triage, promotion, and archival.
- Add navigation from the documentation and agent onboarding entry points.
- Validate local links and documentation/tooling hygiene.
- Record the documentation change in the release ledger.

## Detailed Solution & Technical Design

Place the durable process in docs/reference/experiments/EXPERIMENTAL_WORKFLOW.md. Keep exploratory code and raw outputs out of production packages: use tools/lab/<topic>/ for temporary drivers, artifacts/<run-id>/ for large machine-local outputs, docs/evidence/<run-id>/ for compact reproducible evidence, and docs/planning/active/<plan>/ for formalized work. Require an experiment contract before hardware execution, one-variable-at-a-time qualification, fresh-process isolation for crash-prone collectives, explicit controls, stop conditions, provenance, promotion criteria, and a final disposition of archive, repeat, promote, or discard.
