# Triage AMD LLM optimization targets

## Description

Classify the gathered primary sources and produce a priority-ordered shortlist of URLs/projects worth technical review.

## Steps

1. Classify each source by hardware/software scope: ROCm, HIP, kernels, inference runtime, quantization, attention, communication, compiler, or deployment.
2. Assess evidence quality, maintenance activity, reproducibility, claimed impact, and fit for this project.
3. Identify duplicates, commentary-only links, and sources with no actionable optimization.
4. Rank remaining targets as high, medium, or low value and state the review question for each.

## Detailed Solution & Technical Design

Priority shortlist for technical review:

HIGH — https://hub.docker.com/r/stilldeadcode/vllm-radiance (source: https://codeberg.org/StillDeadcode/vllm-radiance). It is directly targetable to 2x R9700/gfx1201 and documents actionable runtime choices: R4D attention (reported +14.6% prefill at 64K), MTP/DFlash decoding, drafter unpadding, NUMA binding, and hybrid prefix caching (~3.6x shared-prefix TTFT claim). Review the source, image provenance, exact model/shape limits, benchmark harness, and upstreamability before adoption.

HIGH — https://github.com/stew675/llama-cpp-rdna-boosts. It offers pinned, test-validated, composable llama.cpp patches for ROCm/RDNA, including flash attention, quantized matmul/decode, MoE/SSM fusion and speculative decoding. It explicitly notes numerical trade-offs in the k-quant patch, making it a strong candidate for selective measurement rather than wholesale adoption.

HIGH — https://github.com/kdheeraj-p/bridgespec. Valuable experimental design for RDNA3: HIP MTP/DFlash drafters, external KV state and width-tuned MMVQ verification. Constrained to a Windows RX 7900 XTX, ROCm 7.2 and Qwen3.8-27B; reported results are local rather than cross-machine reproducible. Review concepts and patches, not performance claims alone.

MEDIUM — https://github.com/prcoe1/r9700-serving/blob/main/benchmarks/08_21_qwen3.8-27b_dflash2_bench.md. Useful evidence for an R9700-specific DFlash2 prototype: reported tg32 +12-34%, tg128 +20-25%, and acceptance about 80% vs MTP3. Review alongside the serving source and rerun with comparable hardware/model/version before treating the deltas as portable.

MEDIUM — https://github.com/NetraRuntime/netra-kernel. Promising AOT specialization pattern for MI350X/gfx950 FP8 high-throughput serving, but a different hardware class and deployment model from consumer RDNA. Review architecture/validation methodology as a strategic reference; do not prioritize adoption unless MI350X serving is in scope.

LOW/CONTEXT — full R9700 Reddit tuning report (CPU memory-bandwidth and MoE-offload configuration) and Qwen chat templates. Keep as operational tuning/context sources, not core optimization projects.

NOT AMD PERFORMANCE TARGETS — Prime Agent (duplicate), GenericAgent, NodeTerm, and Parley.
