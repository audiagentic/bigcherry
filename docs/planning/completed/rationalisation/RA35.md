# TR11 Pilot: move release-domain tests into tests/release/

## Description

First TR11 slice (pilot, per explicit scope decision given the risk of reorganizing all 166 flat test files at once): moved the 3 release-domain test files (test_pin_status.py, test_release_validate.py, test_releases.py -- 70 tests) into tools/tests/release/, matching the target tests/ filesystem layout.

## Steps

Discovered two compounding risks specific to test reorganization, beyond the import-depth bug already known from TR10: (1) each moved file's sys.path.insert(0, str(Path(__file__).resolve().parents[N])) needed its depth increased by one, same class of bug as TR10's REPO_ROOT issue; (2) unittest discover -s tools/tests -p 'test*.py' silently DROPPED all 70 tests in the new subdirectory (1746 vs 1816 expected) because it requires an __init__.py to recurse into a directory as a package for pattern-based discovery, even though explicit dotted-path test execution (python -m unittest tools.tests.release.test_x) worked fine without one. Added tools/tests/release/__init__.py; discovery now correctly finds all 1816 tests again. 126 of 166 test files use this same __file__-relative sys.path pattern, so both fixes (path depth + __init__.py) must be applied for every subsequent TR11 domain slice.
