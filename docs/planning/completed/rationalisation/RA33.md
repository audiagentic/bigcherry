# TR10 Move foundation modules into core domain package

## Description

Eighth TR10 domain move: 8 foundation modules (artifacts, config, context, csource, paths, pipeline, provenance, resources) -> tools/bigcherry/core/. True alias shims at all 8 old paths. Deliberately did NOT migrate external callers in this slice -- these foundations have 25-49 callers each across the entire codebase (paths.py alone: ~49 files), and TR13 explicitly treats shim retirement as separate later work; migrating every caller here would be disproportionate for zero functional benefit given the shim is a true module alias with no behavior difference.

## Steps

Found and fixed a real bug class while moving paths.py: several modules (this domain's own paths.py, plus three files from ALREADY-COMMITTED earlier slices -- build/compile_check.py, patch/source.py, patch/validation_campaign.py, tuning/replay.py) compute REPO_ROOT via Path(__file__).resolve() with a fixed parent-count/index, which silently breaks when the file moves one directory deeper into its domain package. Audited the entire tools/bigcherry tree for this __file__-relative pattern and fixed all 5 instances (paths.py parents[2]->3, and the four .parent.parent.parent chains -> one more .parent each). Verified check --quick, which had been silently succeeding on a stale patches/catalog.toml lookup path before the fix, now genuinely passes.
