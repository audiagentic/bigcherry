# TR10 Move release records into release domain package

## Description

First TR10 domain move: relocated tools/bigcherry/releases.py to tools/bigcherry/release/records.py (canonical destination per the target filesystem), leaving a true module-alias compatibility shim at the old path (sys.modules aliasing, not a name-copy) so both import paths resolve to the exact same module object -- including for data attributes like RELEASES_DIR, not just functions/classes. Migrated the three internal production callers (__main__.py, cli/diagnostics.py, cli/source.py) to import from the canonical location directly.

## Steps

Discovered and fixed a real regression along the way: the pin_status.py shim's pattern (globals().update(vars(canonical))) copies name bindings rather than aliasing the module, so a test's mock.patch.object(releases, "RELEASES_DIR", root) patched the shim's copy while the canonical module's own functions kept reading their own module's original global -- silently broke 2 tests. Fixed by switching to a true sys.modules alias.
