## Notes

Findings captured in the referenced doc: (1) llama-bench cannot reliably run this class of model (crashes without -sm tensor; hard argument-parse error if --fit is passed, since llama-bench does not register that flag at all); (2) llama-server needs -sm tensor AND --fit off together (llama.cpp's auto memory-fit feature aborts under SPLIT_MODE_TENSOR); (3) control and subject servers cannot run concurrently for a model this large (each needs ~13GB/GPU under tensor split, two copies exceed 24.5GB/GPU cards -- real cudaMalloc OOM confirmed on hardware) -- fixed via sequential per-request server launches, alternating arms, with any cross-request-state evidence (e.g. cache accumulation) isolated into its own long-lived non-concurrent session; (4) the documented Brutus bench runner (run_bench.py, server-bench mode) is more robust than raw llama-bench, but its server-bench path prints "Extracted Results" not "Aggregated Results" -- parse both headers. See docs/reference/testing/MULTI_GPU_LARGE_MODEL_VALIDATION.md for full detail and a pre-flight checklist.
