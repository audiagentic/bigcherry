# RX 6900 XT tail quad kernel: occupancy-specialised row batches and no padded-row work

## Description

The quad kernel's inner loop computes all RB=16 rows even when an expert has nr < 16 routed rows, wasting dot products, decode and reductions on lightly loaded experts. Both GPT reviews: select the row batch (4/8/16) by rows per expert rather than per request, keeping each valid row's K-fold order unchanged (bit-identical).

## Steps

1. Rows-per-expert histograms from the captures (cold, doc, decode).
2. Templated RB variants selected per expert occupancy (work descriptors per (expert, row tile)), valid rows only.
3. Bitwise sweep + timing on captures; extend captures with doc-text and multi-session prefill.
4. Production adoption with end-to-end A/B.

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

Extract per-expert occupancy histograms from the 40 tail captures, split by gate/up, down, cold prefill, document prefill and decode.Calculate wasted valid/invalid `dot8` operations for each RB=16 tile.Implement only uniform invalid-row arithmetic suppression; replay and profile.If beneficial, test invalid-row staging suppression separately.Profile independently compiled RB=4, 8 and 16 forms on the same per-expert occupancy buckets.Derive a cost-based selector including descriptor generation and additional launch overhead.Add expert-descriptor scheduling only if it beats the simpler guarded kernel.Extend replay with zero-route, one-route, 15/16/17-row, highly skewed and multi-session cases.

## Detailed Solution & Technical Design

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

Split this into two experiments.A. Eliminate invalid-row arithmetic without changing ownership or scheduling. Keep the existing `RB=16` kernel and add uniform guards to the per-row arithmetic:for (uint32\_t r = 0; r < RB; ++r) { if (r \>= nr) continue; // Existing dot8, quad\_sum, K64 and K128 folds. }`nr` is identical for every thread in the CTA, making this a uniform condition. Start with the arithmetic loop, then separately test suppressing invalid activation staging. All valid rows retain their original reduction order.B. Select a measured row-batch implementation per expert. The current `rad46_rows_form()` chooses a form from the total request row count. It cannot choose different compiled kernel templates for individual experts within the current `grid.x = experts()` launch.Therefore, per-expert selection requires either a compact `(expert, row_start, valid_rows, output_tile)` work-descriptor array or separate expert bucket launches for RB 4/8/16. Use measured gate/up and down crossover curves, not a fixed guess that `nr <= 4` always wins.Do not alter the order of rows within each expert or the mapping back to original top-k slots.
