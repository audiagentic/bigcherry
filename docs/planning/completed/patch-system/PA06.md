# Source/patch identity hardening: patch+overlay filesystem containment (L0.1/L0.2)

## Description

External GPT review (BIGCHERRY_SOURCE_PATCH_IDENTITY_HARDENING_REVIEW.md, reviewed HEAD 06ad2373) found patch/apply.py's apply_patch() derives its mutation target as `root / patch.path` with no containment check after resolution -- no rejection of absolute paths, `..` components, or an intermediate/final symlink that redirects a syntactically relative path outside the isolated source root. Verified real: tools/bigcherry/patch/apply.py:181 `target = root / patch.path`, confirmed no resolve/containment check anywhere in apply_patch(). source/workspace.py's materialize() has the analogous overlay-copy gap (destination / relative, no containment check against an upstream symlink in the destination path). Registry-level path validation (patch/registry.py) protects where patch.py definitions live, not the paths those patches write to -- this is a genuinely separate boundary.

## Steps

1. Add resolve_patch_target(root, relative) to patch/apply.py (or a shared source/ helper reused by both call sites, per review's 'do not create separate containment implementations' note): reject empty/absolute paths, reject `..` components, resolve root strictly, walk parent components rejecting symlinks, require final resolved parent under root, reject a final target that is itself a symlink, return the contained path.
2. Call it from apply_patch() before `target = root / patch.path` and from workspace.materialize() before its destination/relative write.
3. Add regression tests per review's list: `../outside.txt` rejected, absolute target rejected, nested traversal rejected, intermediate symlink escape rejected, final symlink target rejected, normal nested target still succeeds, rejection occurs before any file mutation (no partial write on rejection).
