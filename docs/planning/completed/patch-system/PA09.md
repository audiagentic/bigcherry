# Source/patch identity hardening: compile-time source re-attestation (L3.1)

## Description

Review found campaign/workers.py's make_generate_worker()/make_build_worker() re-verify the GENERATED tree at multiple points (hash before/after, store.verify() calls confirmed at lines ~580/678/695) but never re-verify the SOURCE tree the same way. The lane carries a mutable source_root: Path plus a previously-established source_slice_id string, with no live recheck before generate reads it, before CMake configure, after compile, or before publish. Verified real this session: grepped workers.py for verify_source/git_tree_oid/attest/check_dirty/git_revision -- zero hits outside store.verify() (generated-tree only) and one unrelated comment. This is the clearest real gap in the whole review: the binary can be attributed to source_slice_id(A) in provenance while actually compiled from a source_root that was mutated to tree B in between -- breaking the core provenance claim BigCherry's whole measurement/replay/ledger system depends on.

## Steps

1. Define SourceAttestation (upstream_revision, tree_oid, object_format, source_slice_id, allowed_untracked) as a frozen dataclass -- likely in source/identity.py alongside existing tree-hashing primitives.
2. Implement verify_source_attestation(root, expected): checks HEAD, live object format, exact tree OID, untracked policy, ignored-file policy, and re-derives source_slice_id from live facts (never trusts a passed-in string).
3. Call it at all four mandatory sites: immediately before generate reads source_root, immediately before CMake configure, immediately after compile before metadata/publish, and before publishing/reusing any cached build output keyed by source_slice_id.
4. Consider (optional, defense-in-depth per review) marking completed materialized sources read-only after materialization.
