# Source/patch identity hardening: variant transform content-authority (L5.1)

## Description

Review found materialize_source_variant() (patch/source.py) accepts variant_digest: str and apply_variant: Callable[[Path], None] as two independent parameters -- nothing proves the digest actually describes the callable. If the callable's behavior changes while the caller keeps passing the same digest/label, stale source gets reused and the new transform never runs -- for subject/control correctness evidence (the framework-baseline vs RD-enhancement distinction this project cares about, see CLAUDE.md's 'framework vs enhancement' doctrine) this can invalidate attribution silently. NOT yet independently verified against current source this session -- read materialize_source_variant()'s actual signature and call sites before implementing, since the review may be describing the general shape rather than exact current parameter names.

## Steps

1. Prefer a content-addressed SourceTransform object (name, schema_version, operations tuple, with a digest property derived from the exact transform definition) over a free-form caller-supplied digest.
2. If transforms must remain arbitrary Python callables (likely, given how much of this codebase is anchored-edit Python), resolve the callable from a REGISTERED implementation (mirroring patch/registry.py's existing pattern) and digest its exact implementation bytes plus a transform-semantics version -- never accept an unverified caller-provided digest as proof of anything.
