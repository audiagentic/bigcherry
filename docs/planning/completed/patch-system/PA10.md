# Source/patch identity hardening: HI82 output-identity split + ignored-file/schema enforcement (L4.1/L4.2/L4.3)

## Description

Review found patch/source.py's _verify_reuse() compares the live worktree tree against manifest.get('patched_tree') -- a field in the same editable JSON sidecar -- rather than against source_key (which is a materialization-PLAN identity: resolved revision + overlay digest + ordered patch digests + optional variant, not an output-content identity). Verified real this session: read _verify_reuse() directly (patch/source.py:276-317) -- confirms it checks expected_identity keys, then git_head() against manifest['head'], then git_worktree_tree() against manifest['patched_tree'], with NO check that patched_tree is itself bound to source_key. Editing the worktree and editing the manifest's patched_tree field consistently would pass reuse under an identity that never hashed real output. Related, not yet independently verified: L4.2 (git_worktree_tree() uses temporary-index hashing that excludes .gitignore'd files, unlike canonical campaign's git_tree_oid() which rejects ignored files -- an ignored source-side file could exist without changing patched_tree) and L4.3 (manifest writes manifest_schema_version=1 but _verify_reuse() never checks it -- missing/future schema values are silently accepted).

## Steps

1. Split identity per review's Correct split: keep source_key as the materialization PLAN id (cache directory key, used for lookup/scheduling); add a separate source_slice_id computed as H(upstream_revision, live_object_format, actual_output_tree_oid) computed from LIVE Git facts, never persisted-then-trusted.
2. Update manifest schema to carry materialization_plan_id, source_tree_oid, AND source_slice_id explicitly; on reuse, re-derive all three from live Git and treat the manifest purely as an assertion to cross-check, never as the source of truth.
3. L4.2: switch git_worktree_tree() (or add an ignored-file check) to reuse source/identity.py::git_tree_oid()'s existing ignored-file rejection rather than maintaining a weaker duplicate -- 'canonical campaign already rejects ignored files; HI82 should use the same primitive.'
4. L4.3: add a first-line validation in _verify_reuse() (or wherever the manifest is parsed) rejecting any manifest whose manifest_schema_version != MANIFEST_SCHEMA_VERSION -- no default, no compatibility guessing.

## Validation

L4.1: edit worktree + edit manifest tree together => reject; edit worktree + edit manifest source ID consistently => reject if it no longer matches the originally-attested output; two different plans producing byte-identical output trees may have different plan IDs but must share the same source_slice_id. L4.2: add an ignored file inside a materialized HI82 source, require reuse failure. L4.3: missing schema => reject, schema 0 => reject, schema 2 (future) => reject, schema 1 => continue normally.

Do not decide this unilaterally when implementation starts -- raise it.
