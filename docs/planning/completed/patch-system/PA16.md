# Pin-bump rebase validation: patch-rebase-check + known-good quarantine + transaction parity

## Description

The current llama.cpp pin-bump workflow (pull -> audit -> apply -> generate) treats `apply` as all-or-nothing: it gives no per-patch pass/fail visibility when a new upstream revision breaks an anchor, and no path to apply the known-good subset while flagging the rest for external reconciliation. This item tracks building that: a new isolated `patch-rebase-check` probe command producing structured per-patch/per-edit status (CLEAN / NOT_APPLICABLE_BY_DESIGN / FAILED_NEEDS_RECONCILIATION / BLOCKED_BY_DEPENDENCY) with a JSON report and human-readable table, a dependency-aware known-good quarantine algorithm built on the existing `patchset.resolve_exact()` resolver (not the weaker flattening `load_patches()` path), and a follow-on `apply --rebase-report PATH --known-good` mode with strict staleness rejection. Default `apply` stays fail-closed/all-or-nothing.
