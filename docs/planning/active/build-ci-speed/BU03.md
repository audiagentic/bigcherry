# CI speed watch: radiance build on kernel changes, ccache misses, and run-time trend

## Description

Watch CI run times and find build improvements. Measured 2026-11-25 over the last 31 radiance-build runs: mean 25 min, 10 runs over 30 min, max 49 min, min under a minute (docs-only). The 14 min runs have a 96% ccache hit rate (905 of 938 calls); the slow runs are exactly the PRs that change libr3 kernel source (each IQR/K-parallel/head change took 37 to 49 min), because the large libr3 HIP units for gfx1100 miss the cache and recompile. Offline suites are short: core about 2.7 min, patch about 3.2 min, pr-ci gating 25 s typical.

## Steps

1. Resolve the five IQR cold versus shipped resource differences using one exact-source affected HIP unit and actual cache inputs. Until resolved use uncached compilation for new release bundles, retaining verified unchanged-runtime reuse. 2. Use merged RCS20 family targets and RCS25 for changed kernels; full integrated build at release. 3. Reuse existing CI timings and cache statistics to identify slow steps. Remove duplicate full builds only where the existing candidate identity and required proof agree. Tune parallelism only if the measurements justify it.
