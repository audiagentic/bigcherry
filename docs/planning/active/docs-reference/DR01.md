# Migrate docs from hardcoded host facts to environment roles

## Description

The reference docs describe one person's machine rather than the procedure. Measured across docs/: 83 occurrences of the hostname 'brutus' in 40 files, 64 of '/mnt/vault', 39 of '/home/audumla', and 15 hardcoded IP addresses. Moving to a second build host is currently a 40-file edit rather than a config change, and a reader on a different box cannot tell which paths are procedure and which are one host's accident.

The mechanism now exists: config/environment.toml defines hosts by ROLE with hostname, address, repo, cache root, model root, bench harness, share, toolchain, ports and the device inventory; tools/env/bigcherry-env.sh exports them as BC_* variables; docs/reference/ENVIRONMENT.md documents the convention. Verified working: BC_HOST=brutus, BC_MODEL_ROOT=/mnt/vault/llm-models, BC_DEVICES='0:gfx1100 1:gfx1100 2:gfx1201 3:gfx1030'.

What remains is the mechanical pass over the prose.

## Steps

1. Prose: replace 'brutus' with 'the build server' where the sentence is about the ROLE. Keep the literal alias where the sentence is genuinely about that machine's identity (e.g. an ssh config example).
2. Commands: replace literal paths with the exported variables -- $BC_HOST, $BC_MODEL_ROOT, $BC_BENCH_HARNESS, $BC_CACHE, $BC_REPO -- and add `source tools/env/bigcherry-env.sh` where a doc's first command block needs it.
3. Delete hardcoded IP addresses outright. The address belongs in the config so a reader can fix their own ssh config; commands should use the alias.
4. Device indices and VRAM figures: point at BC_DEVICES / environment.toml rather than restating them, so they cannot drift between docs.
5. Ports: replace literal 8080/18400 with BC_PRODUCTION_PORT / BC_BENCH_PORT, so the reason 8080 is dangerous stays attached to the fact.
