# RD19 (1200_rd19) promoted to validated without HI83 evidence

## Description

## Defect (pre-existing, discovered during PA02/RS03 cross_check work)

`1200_rd19_single_gpu_meta_bypass` (rdna-boosts group) is `STATE = validated`, but:
- it is **not** in the HI83 legacy grandfather baseline (`docs/reference/patch-validation-evidence/legacy-baseline.json`, 15 patches, generated when HI83 landed), and
- it has **no** current qualifying HI83 validation record.

## Why it cannot be grandfathered

Timeline proves the promotion post-dates the evidence contract:
- HI83 evidence contract + legacy baseline: commit `5cd10ff`, 2026-08-22.
- RD19 promotion to validated: commit `bc0bb91` ("Audumla"), 2026-08-24 — two days **after** HI83.

So RD19 was promoted to `validated` after the contract required hardware evidence, and was never validated. It correctly cannot be added to the grandfather baseline (that snapshot is a point-in-time migration of the *pre-HI83* validated set; adding a post-HI83 promotion to it would fabricate evidence).

## Impact

Two real-catalog cross-check tests fail:
- `tools/tests/test_patch_catalog.py::TestPatchCatalogCrossCheck::test_cross_check_is_clean_on_the_real_catalog`
- `tools/tests/test_patch_governance.py::CatalogMetadataExtensionTests::test_cross_check_still_clean_with_new_optional_fields`

Both were already failing at the RS00 baseline (before any refactor code) — **not** a PA refactor regression.

## Disposition (per runbook M3)

Quarantined, not fixed: the refactor does not fabricate evidence or revert another actor's committed validated promotion. The two tests tolerate **only** the single tracked RD19 evidence problem (filtered by patch-id prefix) and still fail on any other cross-check finding, so they remain a live regression detector and self-heal to full strictness the moment this gap is resolved.

## Steps

- Confirm RD19's intended validation path with the RD19/rdna-boosts owner (committed by Audumla; RD19 plan item already completed).
- Either (a) produce real HI83 hardware validation evidence for 1200_rd19 via the validation campaign, or (b) if the promotion was premature, transition 1200_rd19 back to a non-validated state deliberately.
- Once resolved, the two cross-check tests pass at full strictness with no test edits required (the quarantine filter becomes a no-op).
- Remove the PA05-specific tolerance comments from the two tests only after the gap is closed and verified.
