# PA10 residual: independently authoritative source output binding (deferred from PA10)

## Description

reviewer-gpt-agent's adversarial follow-up (2026-08-26) confirmed real via a constructed test (xfail: test_tampered_tree_with_fully_self_consistent_forged_manifest_rejected in test_patch_source_isolation.py): HI82's _verify_reuse() compares every live-recomputed fact (actual_head, actual_tree, recomputed source_slice_id) against a field in the SAME mutable manifest.json sidecar. A tamperer who edits the worktree AND updates patched_tree/source_tree_oid/source_slice_id consistently (all three, not just one or two) still passes reuse -- no manifest field is independently authoritative. atomic_write_json(read_only=True) was added as real but partial defense-in-depth (chmod 0o444 after write) -- stops accidental/casual mutation but not a determined tamperer who chmods the file back first.

## Steps

Two reviewer-suggested approaches, pick one:
(a) Write-once audit ledger recorded OUTSIDE the same writable directory the tamperer already has filesystem access to (e.g. a separate append-only log location with stricter permissions, or a location the patch-validation campaign's own execution context controls but the materialized worktree's writer does not).
(b) Deterministic re-materialization comparison on reuse: re-run _add_worktree() + _apply_composition() into a scratch location and diff tree hashes against the live one, instead of trusting any manifest field. Expensive (redoes the whole apply) but fully authoritative -- doesn't rely on ANY value surviving intact from the original write.
Either way: remove the @unittest.expectedFailure decorator from the xfail test once genuinely fixed, and confirm it passes for real.
