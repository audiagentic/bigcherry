# PA20 step 1: prove replay-winner equivalence before any patch reclassification

## Description

First and blocking step of PA20. GPT's explicit warning: 0300-0650 (forced-parameter patches) likely belong in core-serving since production replay executes promoted winners through the same dispatch mechanism (0200) -- moving them to tuning-scaffolding without proof risks silently changing which winner a replay build actually executes. This item exists to get that proof BEFORE any reclassification happens, not after.

## Steps

1. Take a known-real promoted winners.jsonl / replay database from an existing campaign.
2. Build the SAME replay target twice: once with the current full framework patch-set, once with a proposed core-serving-only composition (0200 + 0300-0650 + split-0100's replay half, per PA20's classification).
3. Replay every winner dimension across 0300 (mmq J), 0400 (mmvf block), 0500 (mmf nwarps), 0600 (mmvq geometry), 0650 (mmvq native variant) and confirm byte-identical dispatch decisions and output between the two builds.
4. If ANY winner dimension diverges, that patch must stay in (or move back to) core-serving -- update PA20's classification table with the real finding rather than trusting GPT's a-priori guess.
