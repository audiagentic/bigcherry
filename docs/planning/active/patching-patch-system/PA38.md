# RD12 package prerequisites: bind experiment-contract, add validation.toml producers

## Description

Part of the GPT design (req_ead5338ca09348c5, 2026-09-13) for wiring RD04/RD05/RD06/RD07/RD12 correctness producers into the tracked evidence-binding CLI flow (parent: [[PA35]]).

Confirmed real gap: patches/1205_rd12_paired_mmvq_dual_output/patch.toml currently lacks `experiment-contract = "RD12-PAIRED-MMVQ-DUAL"`. Adding the --run-rd12-contract CLI flag without this binding would create real correctness data that the tracked contract system cannot authoritatively associate with RD12 -- do not wire the CLI flag before this lands.

RD12's contract has expected_effect = "both" (a performance threshold AND controls requirement), so validation.toml needs real performance and controls producers, not just correctness -- GPT explicitly declined to guess those fields without seeing RD12's actual campaign/contract implementation, and so do I; they must be authored from RD12's real bound Experiment Contract (config/experiment-contracts.toml's RD12-PAIRED-MMVQ-DUAL entry) and its existing run_rd12_correctness_check() producer, not invented.

## Steps

1. Add `experiment-contract = "RD12-PAIRED-MMVQ-DUAL"` to patches/1205_rd12_paired_mmvq_dual_output/patch.toml.
2. Read config/experiment-contracts.toml's RD12-PAIRED-MMVQ-DUAL entry in full to determine its real performance/controls thresholds and workload requirements.
3. Author patches/1205_rd12_paired_mmvq_dual_output/validation.toml with: a correctness check using correctness-summary (landed in commit 41ff665a); real performance and controls checks using the benchmark validator, configured to match RD12-PAIRED-MMVQ-DUAL's actual bound thresholds -- do not copy RD04's benchmark-extra-args verbatim, RD12 is a different contract with different flags/workloads.
4. Verify with patch-lint / patch-explain that the new binding resolves cleanly before attempting --run-rd12-contract.
