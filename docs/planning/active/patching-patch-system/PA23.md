# Wire patch-lint to consume the shared gate registry (retire parallel check list)

## Description

Replace cmd_patch_lint's direct validation-policy calls with a repository-static consumer of the PA21 shared gate orchestration. Add an internal GateIntent.LINT (not exposed by the PA22 CLI) whose applicability is exactly G1 SUMMARY and G3 package/performance policy. Preserve patch-lint's existing JSON schema, human stderr text, problem ordering, grandfather reporting, and 0/1 exit semantics byte-for-byte. Explicitly exclude composition, rebase, current-pin evidence, lifecycle, disposition, and production admission paths because lint has no single composition or upstream checkout.

## Steps

1. Capture the current repository-wide patch-lint JSON and human stdout/stderr/exit-code bytes for the acceptance baseline before implementation.
2. Add GateIntent.LINT to the shared applicability matrix with only G1 and G3 active; retain every existing operational intent matrix unchanged and do not expose lint as a PA22 --intent choice.
3. Add a repository-lint result adapter in patch/gates.py. Load the canonical registry once, evaluate SUMMARY through patch.docs, run check_validation_packages() once, and run check_performance_evidence_for_patch() once per descriptor. Project policy results without reimplementing validation rules: preserve PackagePolicyReport.problems and .grandfathered directly.
4. Add a backward-compatible keyword-only check_summaries switch to patch.catalog.cross_check(), defaulting to its current behavior. cmd_patch_lint must call cross_check(..., check_summaries=False) so catalog integrity problems remain first while G1 owns SUMMARY diagnostics exactly once.
5. Make cmd_patch_lint() presentation-only: combine catalog integrity problems with the shared lint report's ordered problems, render the existing JSON/human shape unchanged, and keep policy failures at exit 1 rather than introducing PA22's exit-2 resolution contract.
6. Add focused unit, adapter, catalog, and CLI parity tests, including real deterministic fixtures for current/invalid/not-required/grandfathered/legacy-flat packages and a validated optimization README missing the native baseline marker.
7. Run focused tests, the patch suite, repository checks, and the captured before/after byte comparisons. Update the plan and ledger with the implementation and validation evidence before closing PA23.

## Detailed Solution & Technical Design

Recommended target state (GPT design request req_4ad8e9dfec8b40ea, same session ses_76206cac3e6b4be0, reviewed main@7e06f7ba3d70c6a170999b9121b3bfdbf8a80ddb):

Use GateIntent.LINT = "lint" internally. AUTHOR is insufficient because it applies only G0/G1 and misses G3; VALIDATE incorrectly adds G2 and causes G3's execution-package behavior to reject grandfathered packages that patch-lint currently accepts. LINT applies exactly {G1, G3}:
- G0 composition: excluded; lint has no requested production composition.
- G1 SUMMARY: included; move SUMMARY ownership into the shared gates adapter.
- G2 rebase: excluded; requires a source checkout/report.
- G3 package/performance: included; preserve current static package and optimization README policy.
- G4 evidence: excluded; current-pin evidence belongs to patch verification.
- G5 lifecycle: excluded; promotion-only.
- G6 disposition: excluded; revision/report dependent.
- G7 admission: excluded; production composition/evidence admission.

Keep GateContext strong for operational intents. Do not fabricate composition, pin, backend, or source-root values for repository lint. Add an immutable repository-lint report type in patch/gates.py, for example ScopedGateResult(patch_id, result) and LintGateReport(results, problems, grandfathered). The adapter is orchestration only; policy stays in patch.docs and patch.validation_policy.

The adapter should load the canonical registry once, emit G1 SUMMARY results using check_summary_for_patch(), call check_validation_packages() once with the canonical patches/registry/external-source/grandfather paths, and invoke check_performance_evidence_for_patch(descriptor, root=...) once per registry descriptor. Do not invoke evaluate_package_gate() unchanged: its missing-status BLOCKED behavior is too strict for legacy flat patches, and its not-required early return would skip the separate validated-optimization README marker check. Always use assume_validated=False and never call require_execution_package() for LINT.

Map package statuses without reconstructing policy messages: invalid -> FAIL; current -> PASS unless that descriptor's performance check returns problems; grandfathered -> PASS unless performance problems and retain its ID; not-required -> NA unless performance problems; absent status for a legacy/non-packaged descriptor -> NA. Use PackagePolicyReport.problems directly and preserve PackagePolicyReport.grandfathered directly. The compatibility output order must remain catalog/module integrity problems, SUMMARY problems, package-policy problems, performance-policy problems.

Add check_summaries=True to patch.catalog.cross_check() as a backward-compatible keyword-only option; default preserves existing callers. The PA23 CLI path calls verify_validation_evidence=False, allow_legacy_grandfather=True, check_summaries=False, preventing duplicate SUMMARY diagnostics while leaving the existing catalog-integrity scan in place.

Target call graph:
cmd_patch_lint
  -> patch_catalog.cross_check(verify_validation_evidence=False, allow_legacy_grandfather=True, check_summaries=False)
     -> catalog/module integrity only
  -> patch_gates.evaluate_repository_lint_gates()
     -> patch_registry.load_registry()
     -> G1 -> patch_docs.check_summary_for_patch()
     -> validation_policy.check_validation_packages() once
     -> G3 -> check_performance_evidence_for_patch() per descriptor

No upstream resolution/fetch, source materialization, build, hardware, campaign execution, evidence writes, state promotion, or disposition writes. Keep ownership cli.patch -> patch.gates -> patch domain authorities. Do not add cli.source imports, substantive __main__.py logic, or another compatibility facade. BRC01's remaining cli.patch -> __main__ cmd_apply work is out of scope.

## Effort & Risk

Medium implementation risk despite a small CLI diff. The main risk is accidental semantic drift: choosing AUTHOR/VALIDATE, invoking execution-package or evidence gates, changing missing-status behavior for legacy flat patches, duplicating SUMMARY diagnostics, reordering problems, or changing stderr/exit semantics. The repository-wide byte-parity capture is the primary safeguard. A second risk is over-eager refactoring of patch.gates; keep operational GateContext/evaluator behavior unchanged and isolate the repository-lint adapter.

## Standards

PA21 shared-gate applicability and fail-closed contracts; PATCH_VALIDATION.md's hardware-free/static patch-lint boundary; TOOLING.md ownership rules (cli/ presentation, patch/ policy/orchestration, no second campaign/evidence framework, __main__.py migration boundary); existing validation_policy grandfather and performance-marker semantics; BRC01 source-ownership migration boundaries; ag-ledger event and ag-planning lifecycle requirements.

## Acceptance Criteria

cmd_patch_lint consumes the PA21 shared registry through an internal repository-static LINT intent whose applicability is exactly G1 and G3. G0/G2/G4/G5/G6/G7, current-pin evidence, upstream resolution, hardware, execution-package enforcement, campaign execution, and admission are not invoked.
The command retains exactly the existing passed/problems/grandfathered JSON shape, human stderr wording/routing, problem ordering, grandfather reporting, and 0/1 exit behavior. Repository-wide before/after stdout/stderr/exit captures are byte-identical for both JSON and human modes.
