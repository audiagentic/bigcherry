# Reorganize PATCH_VALIDATION.md around the finalized G0-G7 gate sequence

## Description

Reorganize the sole canonical patch-validation policy around the finalized live gate taxonomy from PA21, PA22, and PA23. The documentation must describe operation-driven applicability accurately: promote = G0-G5; build = G0,G1,G2,G4,G6,G7; rebase = G0,G1,G2,G6; validate = G0-G3; internal lint = G1,G3; internal author = G0,G1. ## Detailed Solution & Technical Design

Use this authoritative matrix in docs/reference/testing/PATCH_VALIDATION.md:

| Gate | Applies to | Requirement | Authoritative implementation |
|---|---|---|---|
| G0 Exact composition | author, validate, promote, rebase, build | Supplied ordered composition re-resolves exactly, including patch IDs/content hashes; rejected, conflicting, or unresolvable composition fails closed | patch.gates.evaluate_composition_gate() -> patch.patchset.resolve_exact() |
| G1 Documentation | author, lint, validate, promote, rebase, build | Focal SUMMARY.md exists and its Status/Plan item header agrees with the canonical descriptor | focal: patch.gates.evaluate_summary_gate() -> patch.docs.check_summary_for_patch(); LINT: patch.gates.evaluate_repository_lint_gates() -> _evaluate_lint_summary() -> summary checks |
| G2 Revision/apply | validate, promote, rebase, build | Rebase report is fresh against live source/BigCherry/overlay/selection/patch identities and focal patch is known-good | patch.gates.evaluate_rebase_gate() -> patch.rebase.require_fresh_report() |
| G3 Validation definition | lint, validate, promote | Static package/ValidationPlan policy passes; focal operational paths may require a real execution package and optimization performance documentation according to the live evaluator; not-required focal operations return NA before those checks | focal: patch.gates.evaluate_package_gate() -> patch.validation_policy.check_validation_packages(), require_execution_package(), check_performance_evidence_for_patch(); LINT: patch.gates.evaluate_repository_lint_gates() -> _evaluate_lint_package() and per-descriptor performance checking |
| G4 Evidence qualification | promote, build | Current qualifying focal evidence satisfies pin/resolved-SHA, identity, architecture/status obligations; malformed/stale evidence fails closed | patch.gates.evaluate_evidence_gate() -> patch.catalog.validation_evidence_statuses() -> patch.evidence |
| G5 Lifecycle promotion | promote | For an untested focal patch, G0-G4 must all PASS; gate only derives eligibility and never edits metadata | patch.gates.evaluate_lifecycle_gate() |
| G6 Disposition coverage | rebase, build | Fresh all-patches report plus exact revision/digest dispositions cover every non-retired patch; recipe-selected failures cannot be waived | patch.gates.evaluate_disposition_gate() -> patch.disposition.compute_coverage() + patch.rebase.require_fresh_report() |
| G7 Production admission | build | Complete ordered production composition passes production admission; inactive/not-ready is BLOCKED at the PA21 gate evaluator, active rejection FAIL, malformed/unknown BLOCKED | patch.gates.evaluate_admission_gate() -> patch_admission.admit(..., mode="production"); distinguish from patch.catalog.resolve_for_context() -> patch_admission.require_admission(), whose current bootstrap not-ready path is admissible=True |

The matrix must be followed by: operation-driven applicability; kind/tag/origin effects inside gate authority (especially G3/G4) without changing the top-level gate_applies matrix; public patch-gates intents exactly validate|promote|build|rebase versus internal AUTHOR/LINT; and shared PASS|FAIL|BLOCKED|NA semantics.

Required final body outline:
- Patch validation policy: retain sole-canonical declaration and TEST.md/PATCH_AUTHORING.md links.
- Before G0: authorities and non-gate prerequisites.
- G0 exact composition identity; cross-link PATCH_SYSTEM.md rather than copying composition mechanics.
- G1 SUMMARY/documentation consistency; document focal gate versus LINT implementation, state that live SUMMARY authority checks Status and Plan item only, and link PATCH_AUTHORING.md for the full SUMMARY template.
- G2 rebase freshness and focal known-good; include live upstream, BigCherry, overlay digest, selector/source identity, exact patch set, implementation digests, dependency/conflict metadata; explain observational isolated-worktree reports.
- G3 validation definition/package; distinguish focal operational evaluation from repository LINT; lint grandfathering is static-only, operational not-required returns NA before require_execution_package()/performance checking, a real new validation campaign still requires require_execution_package(), and optimization three-arm README obligation (native llama.cpp -> BigCherry baseline -> BigCherry+patch) is structurally checked by the applicable descriptor path.
- Evidence production interlude, not a gate.
- G4 persisted evidence qualification; current pin plus resolved SHA, identities, architecture/status; dispatch through validation_evidence_statuses(); stale/missing => failure, malformed/unknown => BLOCKED; not-required is N/A for BUILD while PROMOTE requires evidence; local framework-configuration PROMOTE is currently BLOCKED until the prospective canonical-composition seam exists; verifier commands are read-only while build admission consumes evidence.
- G5 lifecycle promotion; preserve manual transition/review/ledger/re-promotion rules.
- G6 revision-bound dispositions; fresh patch-rebase-check --all, retired exclusions, CLEAN/CLEAN_NOOP/NOT_APPLICABLE_BY_DESIGN, recipe-selected failure cannot be excused, known_broken exact binding.
- G7 complete production admission; BUILD-only full ordered composition, no removal/substitution, evidence reuse and fail-closed gate mappings. Explain that the existing bootstrap production seam currently admits not-ready and is not itself the PA21 G7 blocker.
- Final handoff with PATCH_REFACTOR_RUNBOOK.md companion.

Do not duplicate the full PATCH_AUTHORING.md SUMMARY template, PATCH_SYSTEM.md composition mechanics, or PATCH_REFACTOR_RUNBOOK.md commands.
