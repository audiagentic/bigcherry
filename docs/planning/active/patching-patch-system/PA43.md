# Split validation_campaign.py generic infrastructure into modules

## Description

PA36 migrated the patch-specific code out of `tools/bigcherry/patch/validation_campaign.py`, but the file is still 7,479 lines because the reduction targeted the wrong layer: ~87% of the remaining code is generic infrastructure that was never split into modules. This item splits that infrastructure into a `tools/bigcherry/patch/campaign/` package (build, benchmark, producer-execution, qualification-evidence, trace-probes, contract-gates) so the file stops being a flat monolith. It also retires the two documented-retention code blobs that are self-contained and removable (RD73 legacy CLI, patch1000 lab) once equivalence is confirmed.

## Measured size breakdown (2026-09-22, 7,479 lines)

|---|---|---|
| Generic producer runtime (`_run_validation_producer` 764, `CampaignProducerRuntime` 507, evidence-binding, selectors, device maps) | 1,992 | 27% |

| patch1000 lab experiment (5 functions) | 457 | 6% |
| Benchmark infrastructure (paired llama-bench, device pool, topology) | 433 | 6% |
| Contract/evidence + RD08 | 290 | 4% |

The PA36 reduction worked (only 7 documented-retention patch-specific functions remain: RD73 x4, patch1000 x3; RD58/RD08/RD13/RD26/RD30/RD43/RD50 all migrated to patch-local producers). The file is big because the shared machinery was never modularised, not because it knows all patches.

## Out of scope

- No behaviour change to any validation/evidence contract. This is a pure structural refactor (move + import rewiring), plus the two opt-in retires gated on hardware equivalence.
- No change to evidence files, catalog state, thresholds, or hardware results.
- Does not touch `patch.toml` state or add `--allow-rejected`.

## Steps

1. Baseline: capture the full test-suite pass/fail set (currently 15 failed / 3856 passed) and the `run()`/`_run_validation_producer` behaviour as the regression gate. Every slice must leave the suite at or above this baseline.
2. Create `tools/bigcherry/patch/campaign/__init__.py` and split the six generic subsystems into modules, moving verbatim (no behaviour edits): `build.py` (build infrastructure), `benchmark.py` (paired-bench infrastructure), `producer.py` (producer-execution runtime; distinct from existing `validation_producer.py`), `qualification.py` (qualification evidence), `trace.py` (trace probes), `contract.py` (contract gates / lane effects / eligibility).
3. Rewire `validation_campaign.py` imports to the new package; keep the module as the thin CLI/`run()`/`main()` orchestrator. Verify the full test suite is at-or-above baseline after each module split.
4. Split the 743-line `run()` into stage functions (framework-configuration, performance-benchmark, standard-campaign, contract-evidence, record-persistence) so no single function exceeds ~150 lines.
5. [Optional, hardware-gated] Retire the RD73 legacy CLI path (−997 lines): confirm the generic producer path reproduces the `--run-rd73-contract` evidence on Brutus, then remove the 10 RD73 functions and the `--run-rd73-contract` flag + its structural-baseline entry.
6. [Optional] Move the patch1000 lab functions (−457 lines) to `tools/lab/patch1000/` per the lab/non-package boundary in TOOLING.md.
7. GPT architecture review of the final module layout + full test-suite run; record a ledger change event.

## Detailed Solution & Technical Design

### Guiding principle

Move, don't rewrite. Every function is relocated verbatim into its module; only import paths change. This keeps the regression risk confined to import resolution, which the test suite catches immediately.

### Module ownership

- `campaign/build.py`: `_hip_only`, `_hip_env`, `resolve_selected_device_execution_identity`, `_requested_cmake_args`, `_full_requested_cmake_args`, `_atomic_write_json`, `_configure_request_document`, `_configure_request_matches`, `generate_registry`, `build_tree`, `ensure_stock_baseline`, `_canonical_json`, `_canonical_json_mapping`, `_sha256_file`, `_write_bound_artifact`, `_print`, `PatchCampaignError`, `StandardCampaignScaffold`, `_build_standard_campaign_scaffold`.
- `campaign/benchmark.py`: `PairedBenchmarkOutcome`, `BenchmarkWiring`, `resolve_benchmark_wiring`, `BenchmarkTopology`, `ResolvedBenchmarkModel`, `resolve_benchmark_model`, `resolve_device_pool`, `parse_device_map`, `run_paired_llama_benchmark`, `_paired_llama_bench_command`.
- `campaign/producer.py`: `CampaignProducerRuntime`, `_write_bound_artifact_ref`, `_write_bound_text_artifact_ref`, `ProducerEvidenceBindingContext`, `BoundProducerEvidence`, `_bind_producer_correctness`, `_producer_owned_artifact_ref`, `_bind_producer_trace_evidence`, `_bind_producer_result_evidence`, `ProducerExecution`, `_run_producer_trace_probes`, `execute_validation_producer`, `_parse_validation_producer_selector`, `_parse_producer_inputs`, `_parse_producer_device_map`, `_producer_file_identity`, `_run_validation_producer`.

### `__init__.py` re-export

`campaign/__init__.py` re-exports the public names so existing `from bigcherry.patch.validation_campaign import X` call sites keep working during migration; `validation_campaign.py` becomes the thin CLI layer (`run`, `main`, `_run_framework_configuration`, `_run_performance_benchmark`) importing from the submodules.

### RD73 retire (opt-in, hardware-gated)

Only after the generic producer path is confirmed to reproduce `--run-rd73-contract` evidence on Brutus: remove the 10 RD73 functions (`run_rd73_mtp_server_lane`, `run_rd73_decode_control_lane`, `run_rd73_resource_burst_session`, `run_rd73_contract_qualification`, `parse_rd73_resource_telemetry`, `peak_rd73_resource_result`, `evaluate_rd73_activation_evidence`, `evaluate_rd73_resource_evidence`, `evaluate_rd73_mtp_correctness`, `Rd73CorrectnessError`), the `--run-rd73-contract` `add_argument`, the run() branch, and the structural-baseline entries for these names/flag. Gated on hardware equivalence — offline-only slices must NOT touch this.

## Code Samples & Guidance

No new code is introduced; the split is a verbatim move. The one structural addition is the `__init__.py` re-export layer, which follows the standard Python package pattern:
