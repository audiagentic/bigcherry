# Split validation_campaign.py generic infrastructure into modules

## Description

PA36 migrated the patch-specific code out of `tools/bigcherry/patch/validation_campaign.py`, but the file is still 7,479 lines because the reduction targeted the wrong layer: ~87% of the remaining code is generic infrastructure that was never split into modules. This item splits that infrastructure into a `tools/bigcherry/patch/campaign/` package (build, benchmark, producer-execution, qualification-evidence, trace-probes, contract-gates) so the file stops being a flat monolith. It also retires the two documented-retention code blobs that are self-contained and removable (RD73 legacy CLI, patch1000 lab) once equivalence is confirmed.

|---|---|---|

The PA36 reduction worked (only 7 documented-retention patch-specific functions remain: RD73 x4, patch1000 x3; RD58/RD08/RD13/RD26/RD30/RD43/RD50 all migrated to patch-local producers). The file is big because the shared machinery was never modularised, not because it knows all patches.

## Out of scope

- No behaviour change to any validation/evidence contract. This is a pure structural refactor (move + import rewiring), plus the two opt-in retires gated on hardware equivalence.
- No change to evidence files, catalog state, thresholds, or hardware results.
- Does not touch `patch.toml` state or add `--allow-rejected`.

## Steps

1. Baseline: capture the full test-suite pass/fail set (currently 15 failed / 3856 passed) and the `run()`/`_run_validation_producer` behaviour as the regression gate. Every slice must leave the suite at or above this baseline.
2. Create `tools/bigcherry/patch/campaign/__init__.py` and split the six generic subsystems into modules, moving verbatim (no behaviour edits): `build.py` (build infrastructure), `benchmark.py` (paired-bench infrastructure), `producer.py` (producer-execution runtime; distinct from existing `validation_producer.py`), `qualification.py` (qualification evidence), `trace.py` (trace probes), `contract.py` (contract gates / lane effects / eligibility).
3. Rewire `validation_campaign.py` imports to the new package; keep the module as the thin CLI/`run()`/`main()` orchestrator. Verify the full test suite is at-or-above baseline after each module split.
4. Split the 743-line `run()` into stage functions (framework-configuration, performance-benchmark, standard-campaign, contract-evidence, record-persistence) so no single function exceeds ~150 lines.
5. [Optional, hardware-gated] Retire the RD73 legacy CLI path (−997 lines): confirm the generic producer path reproduces the `--run-rd73-contract` evidence on Brutus, then remove the 10 RD73 functions and the `--run-rd73-contract` flag + its structural-baseline entry.
6. [Optional] Move the patch1000 lab functions (−457 lines) to `tools/lab/patch1000/` per the lab/non-package boundary in TOOLING.md.
7. GPT architecture review of the final module layout + full test-suite run; record a ledger change event.

## Detailed Solution & Technical Design

### Guiding principle

Move, don't rewrite. Every function is relocated verbatim into its module; only import paths change. This keeps the regression risk confined to import resolution, which the test suite catches immediately.

### Module ownership (as landed)

- `campaign/build.py`: `PatchCampaignError`, `_print`, `_hip_only`, `_hip_env`, `resolve_selected_device_execution_identity`, `_requested_cmake_args`, `_full_requested_cmake_args`, `_atomic_write_json`, `_configure_request_document`, `_configure_request_matches`, `generate_registry`, `build_tree`, `ensure_stock_baseline`, `_canonical_json`, `_canonical_json_mapping`, `_sha256_file`, `_write_bound_artifact`.
- `campaign/scaffold.py`: `StandardCampaignScaffold`, `_ScaffoldSources`, `_materialize_scaffold_sources`, `_build_tune_and_replay_trees`, `_build_parity_trees`, `_build_standard_campaign_scaffold`. The standard-campaign scaffold lives here rather than in `build.py` to break the build <-> contract import cycle (it needs `assert_validation_subject_parity` from `contract.py`, which itself imports `build.py`).
- `campaign/benchmark.py`: paired-bench infrastructure (`_paired_llama_bench_command`, `PairedBenchmarkOutcome`, `BenchmarkWiring`, `resolve_benchmark_wiring`, `BenchmarkTopology`, `ResolvedBenchmarkModel`, `resolve_benchmark_model`, `resolve_device_pool`, `parse_device_map`, `run_paired_llama_benchmark`) plus the `--run-performance-benchmark` entry point `_run_performance_benchmark`, split into `_resolve_benchmark_architectures`, `_build_performance_binary_pair` and `_run_performance_cell`.
- `campaign/producer.py`: the producer-execution runtime (`CampaignProducerRuntime`, evidence binding, selectors, device maps, `execute_validation_producer`, `_run_validation_producer`).
- `campaign/trace.py`: `_trace_probe_env`, `_require_real_gpu_execution`, `_run_one_trace_probe`, `run_trace_activation_probes`.
- `campaign/contract.py`: `compute_contract_correctness_gate`, `assert_validation_subject_parity`, `rd08_validation_lane_commands`, `compute_persisted_validation_eligible`, `build_contract_evidence_for_persistence`. (`collect_lane_effect_records` was deleted with the RD73 retire: it had no remaining inputs; `make_record()` now receives `lane_effects=[]` explicitly.)
- `campaign/qualification.py`: **deleted**. A repository-wide search (tools/, patches/, docs code references, tests) found no importer or caller and no tests; only historical README prose names `QualificationEvidenceManifest`.
- `validation_campaign.py` (1,427 lines, down from 7,479): the thin CLI/orchestrator -- framework-configuration stages, the staged legacy `run()` (`_prepare_standard_campaign`, `_run_activation_probe_stage`, `_collect_build_and_correctness_evidence`, `_evaluate_validation_plan`, `_persist_validation_record`), argument builders, `_dispatch_validation_producer`, `main`.

### `__init__.py`

`campaign/__init__.py` is empty apart from a docstring: it re-exports nothing. Every consumer (production, tests, lab scripts) was migrated to import from the owning submodule directly -- no compatibility re-export layer, per the no-legacy doctrine.

### RD73 legacy CLI retired

Done without the hardware-equivalence gate, because the gate no longer applies: patch `1233_rd73_stable_graph_cache_key` is `state=rejected`, so there is no qualification result to reproduce. Removed: `--run-rd73-contract` and `--rd73-corpus`, the run() RD73 contract-evidence stage (`_run_contract_evidence_modes`) and its evidence binder, `run_rd73_mtp_server_lane`, `run_rd73_decode_control_lane`, `run_rd73_resource_burst_session`, `run_rd73_contract_qualification`, `parse_rd73_resource_telemetry`, `peak_rd73_resource_result`, `evaluate_rd73_activation_evidence`, `evaluate_rd73_resource_evidence`, `evaluate_rd73_mtp_correctness`, `Rd73CorrectnessError`, the `_RD73_RESOURCE_*` constants and `collect_lane_effect_records`. The legacy run() path now always runs the generic trace probe, passes `{}` named correctness results to the contract gate and an empty `contract_promotions` (fail-closed: a bound-contract patch is reported ineligible there). The 1233 patch-local producer and its evidence are untouched; its producer tests are kept.

### GPT review fixes (req_44b45662bd314ab4)

- Blocker: the staged run() still read `args.run_rd08_contract` / `args.run_rd08_lanes` after the RD08 flags were retired, so a standard campaign could raise `AttributeError`. Removed (together with the RD73 branches they shared expressions with). Regression test `tools/tests/patch/test_validation_campaign_args_attributes.py` collects every `args.<name>` read in `validation_campaign.py` and `campaign/*.py` via `ast` and asserts each is a dest of the real parser (verified to flag `run_rd08_lanes`/`run_rd08_contract` against the pre-fix source), and that the retired flags are rejected.
- Structural baselines in `test_validation_producer_structure.py` (legacy function names and legacy CLI flags) are now empty.

Removed tests covered only deleted RD73 legacy code (the RD73 classes in `test_patch_validation_campaign_va06c.py`) or the removed RD-mode mutual-exclusion check.
