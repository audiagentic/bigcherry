# One worktree per slice: slice start / lab / finish tooling, main as the only long-lived branch

## Description

Today each machine has one working tree that is switched between slice branches by hand (and once by force). That blocks parallel slices, risks discarding uncommitted work, and keeps `patch-refactor` alive as a second trunk. Target: the primary checkout on every machine stays on `main` and only fast-forwards; every slice in flight has its own git worktree created and removed by tooling; worktrees share the primary checkout's vendor llama.cpp checkout, build caches and work directories. Extends PA46 and docs/reference/build/BRANCHING.md.

## Steps

1. Prerequisite - line endings: verify a fresh `git worktree add` on Windows is clean with the `.gitattributes` from PR #10; renormalise any file still stored with CRLF on main (known: tools/tests/patch/test_1316_node_hash_trace.py). Add a test/CI step that fails if `git ls-files --eol` reports i/crlf for a text=auto file.
2. Prerequisite - shared state: make the vendor checkout, work root and build cache resolvable from a worktree. One setting (config or `BC_PRIMARY_ROOT`, default: `git worktree list` first entry / `git rev-parse --git-common-dir` parent) used by every tool that today assumes they live under the current tree. No copying, no second vendor clone. `patch-rebase-check`, `apply`, `build` must work unchanged from a worktree.
3. `bigcherry slice start <type>/<item>-<topic>`: validate the name against BRANCHING.md, fetch, create the branch from `origin/main`, `git worktree add worktrees/<branch>` (worktrees/ ignored), print the path. Refuses if the branch or worktree exists.
4. `bigcherry slice lab <branch> [--host brutus] -- <script> [args]`: on the lab host, fetch, add a detached worktree at the branch head under the lab work root, run the script through tools/lab/plan-qualification/queue.sh (GPU lock unchanged), remove the worktree on exit (also on failure), print the result. Replaces the hand-written checkout/return steps in chain scripts. The lab primary tree stays on `main`.
5. `bigcherry slice finish <branch>`: require the PR merged or closed (gh), remove the worktree, delete local and remote branch, fast-forward the primary `main`. Refuses on an unmerged open PR or a dirty worktree.
6. `bigcherry slice prune` (exists, PR #10): also list worktrees whose branch is gone or merged, and remove them with `--apply`.
7. `bigcherry slice status`: one table of worktree, branch, PR number/state, ahead/behind main, dirty flag - for humans and agents.
8. Docs: update BRANCHING.md ('Working in parallel', 'Branch clean-up') and CLAUDE/agent instructions: never switch branches in the primary checkout, never force a switch, one agent per worktree, no direct commits to main or to a shared branch.
9. Cut-over: after PR #27 merges, retire `patch-refactor` (delete remote + local, lab tree home branch becomes `main`), delete the stale lab-tree local branches (`bump-b11126-brutus-records`, `planning-refactor`), and move any session still committing to `patch-refactor` onto slices.
10. Admin-only (owner): enable 'Automatically delete head branches' and protection on `main`; record in the item when done.

## Files

tools/bigcherry/release/slice.py (or tools/bigcherry/cli/slice.py, wherever `slice prune` from PR #10 lives), tools/bigcherry/cli/main.py, tools/bigcherry/core (primary-root resolution), tools/tests/release/test_slice*.py, .gitattributes, .gitignore (worktrees/), docs/reference/build/BRANCHING.md, tools/lab/plan-qualification/queue.sh (only if needed for a worktree source root), CLAUDE.md source component for agent rules.

## Validation

Unit tests with temporary git repos: start creates branch+worktree from origin/main and rejects bad names/duplicates; finish refuses unmerged/dirty and removes worktree + branches when merged; prune lists orphaned worktrees; primary-root resolution from inside a worktree returns the primary checkout. Windows: a fresh worktree has an empty `git status` and `patch-rebase-check --source bigcherry` passes from it. Brutus: `slice lab` builds and smokes one slice branch while the primary lab tree stays on `main` with a clean status before and after; a failing script still removes the worktree. Cut-over verified by `git branch -r` showing only main, the release-please branch and open slices.

## Effort & Risk

Medium. Main risk is tools that derive paths from the current working tree (vendor checkout, work/, builds/) silently creating a second copy inside a worktree - fail closed: if the primary root cannot be resolved, error, do not fall back to cwd. Second risk is removing a worktree with uncommitted work: finish/prune never use --force.

## Standards

docs/reference/build/BRANCHING.md; no git stash; no legacy fallback paths (the single-tree checkout/return pattern in lab chain scripts is removed, not kept beside the new command); lab scripts live in tools/lab/<topic>/.
