# Pin bump automation, round 2: close the manual steps found during the b11552 bump

## Description

Owner, 2026-10-11: 'add more to automating the bump for next time'. Method: the b11474 -> b11552 bump is the specification. Every step done by hand or by judgement during it is logged here as it happens, then turned into a phase of `bigcherry pin-bump` (tools/bigcherry/release/pin_bump.py), the bump-llamacpp skill and docs/reference/build/PIN_BUMP.md once the bump is through. Candidates known before starting (confirm or strike each against what actually happened): (1) `pin-bump latest` resolves the newest upstream bNNNNN release tag; (2) `sources check` as the first phase, findings in the report; (3) liveness phase - refuse to start on a tree with live servers, queues or leases; (4) multi-tree phase - push, pull and verify each required tree in turn (the dev campaign tree was behind main at the start: pin-status reported 'mismatch (campaign tree tooling ... != expected ...)'); (5) hardware phase - queue build, runtime smoke and A/B on the lab host and write the evidence file `pin-release --evidence` takes; (6) on a failing recipe patch, run tools/lab/plan-qualification/compose-apply.py's logic and report the edit, file and nearest matching line, so the reconciliation list is concrete; (7) tools/lab/plan-qualification/syntax-check.sh as a phase before any lab-host build; (8) report composition-only collisions separately from failures (PA48: they were mistaken for a bump blocker). Not to automate: reconciling a moved anchor (needs the upstream change read), and the release itself (a deliberate command).

2026-10-12, release pull requests under the main ruleset (found releasing bc-llamacpp 11552.2.1, PR #197):
