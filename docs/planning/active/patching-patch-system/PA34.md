# Make exact selector identity authoritative for experiment/focal-overlay gates and rebase

## Description

Current base confirms the original semantic gap but changes the implementation target. `campaign.resolution.resolve_lane()` already supports named experiments and delegates overlays to `resolve_lane_overlay()`, while `CanonicalSelection` exposes only `source_name`, `source_ref`, `patch_set_id`, and `patch_ids`. `patch.selection.CliPatchSelection` is source-only. `cmd_patch_rebase_check` accepts source/all only, `GateContext` has no expected selector identity, and `cmd_patch_gates` accepts a source or focal dependency closure only.

PA34 must extend the existing canonical resolution/rebase seam. It must not create a second resolver, arbitrary patch-list selector, temporary recipe source, or new gate policy.

## PA34.1: selector identity and rebase authority

1. Extend `campaign.resolution.CanonicalSelection` with ordered `module_hashes`, `selector_kind`, and deterministic `selector_name`. Preserve existing source/ref/patch-set/IDs fields.
2. Extend `resolve_canonical_selection()` with mutually exclusive `experiment` and `focal_overlay_patch_id` inputs.
3. Named experiment delegates to the existing `resolve_lane(..., experiment=...)` path and reports selector name `experiment:<name>`.
4. Focal overlay: resolve the base source, expand the focal dependency closure with `patchset.expand_composition((focal,), directory=...)`, remove IDs already present in the base, then pass only the remaining dependency-complete overlay to `resolve_lane_overlay(..., overlay_name="focal:<patch-id>")`. Do not accept arbitrary user patch lists.
5. Return exact ordered IDs and hashes from the resolved lane. Unknown/rejected/conflicting/ambiguous selectors fail closed.
6. Bump the rebase-report schema and teach `run_rebase_check()`/freshness to persist and re-resolve the exact selector identity. `--all` remains a distinct all-patches coverage selector for G6.
7. Extend `require_fresh_report()` (or a narrowly named sibling) so G2 can require a matching expected selector, not merely a fresh report for the same checkout.
8. Add the expected selector to `GateContext`; `evaluate_rebase_gate()` delegates matching/freshness to `patch.rebase`, not local comparison logic.

Do not change generic `apply --source` semantics in this slice. `patch.selection.CliPatchSelection` may remain the source-only apply/listing projection; avoid broadening mutation surfaces just to satisfy audit/build selectors.

## PA34.2: CLI presentation

1. Add `--experiment` and `--focal-overlay` to `patch-rebase-check` and `patch-gates` using the canonical resolver. They are mutually exclusive; focal-overlay requires a source and uses the command's focal patch as the overlay patch.
2. For patch-gates, represent a focal patch absent from a successfully resolved selector as top-level `selection_status=NOT_EVALUATED` before gate execution. Do not synthesize G7 `NA` or overload GateStatus.
3. JSON must include selector kind/name, source/ref, patch-set ID, ordered IDs/hashes, focal membership status, and gates.
4. G4 stays focal. G7 receives the complete selected ordered composition. G6 `recipe_patch_ids` is the complete selected composition. G2 must consume a selector-matched report.
5. Preserve source-only behavior for existing callers.

## First consumers

PA25 audit contexts: named experiments `hi155-hybrid-allreduce-gate`, `hi18-reduce-probe`, `rd19-only`, `hip-internal-allreduce-only`, plus deterministic focal overlays for 1002/1232. PA33 later consumes the same selector identity for validation execution.

## Acceptance Criteria

One canonical selector authority represents source, named experiment, and deterministic focal overlay; rebase reports/freshness bind exact selector identity; patch-gates and patch-rebase-check expose it without arbitrary lists; G2/G4/G6/G7 retain their existing policy owners; source-only behavior remains compatible; and PA25 can audit the previously unrepresentable prospective contexts without modifying recipes.
