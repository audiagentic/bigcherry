# Support exact experiment and overlay compositions in patch-gates audits

## Description

PA25's GPT validation identified a real semantic gap: patch-gates --intent build requires --source and rejects a focal patch that the selected canonical source does not contain, while G7 is correctly a complete-composition admission verdict. Seven touched/promoted patches therefore cannot receive a prospective per-patch BUILD/G7 result without either misleadingly calling a composition-resolution error a gate result or manufacturing temporary recipe sources. Add an explicit, provenance-preserving composition selection path for audit/build evaluation without adding a second evaluator or permanent compatibility umbrella. GPT validation provenance: dev-gpt-agent, same session ses_76206cac3e6b4be0, request req_d689b6b6ab7e4f14, reviewed pushed 08706ff2.

## Steps

1. Read docs/reference/tooling/TOOLING.md and preserve the canonical CLI owner, existing gate registry, and no-second-framework rule.
2. Trace and reuse campaign_resolution.resolve_canonical_selection(..., experiment=...), which already delegates to resolve_lane(..., experiment=...) and returns source_ref, patch_set_id, and ordered patch IDs. Do not create a new source+experiment resolver.
3. Extend patch-gates to pass args.experiment through that existing selection function. The selection result must carry source name/ref, experiment name, patch_set_id, ordered patch IDs, content hashes, and a deterministic selector identity into composition resolution and JSON.
4. Add the concrete focal-overlay selector --focal-overlay, mutually exclusive with --experiment and requiring --source. Given a resolved base source, expand the focal dependency closure with patchset.expand_composition((focal,)), remove IDs already present in the resolved base while preserving the base/closure order, pass the remaining exact dependency-complete set to resolve_lane_overlay(), and use deterministic overlay identity focal:<patch-id>. Do not claim a registered exact-overlay authority exists and do not accept an arbitrary user patch list. If generic reviewed overlay authority is desired, split it into a separate plan item.
5. Define fail-closed behavior for unknown experiment, unknown/ambiguous overlay, conflicting/rejected patch, focal patch absent from the selected composition, and source/experiment mismatch. For focal absence, return an explicit machine-readable selection_status=NOT_EVALUATED before gate evaluation; never encode it as a GateStatus or G7 NA. Preserve existing source-only exit-2 behavior and extend its CLI tests. Add a test where focal-closure dependencies are split between base and overlay.
6. Extend G2/rebase selector identity, not only patch-gates. patch-rebase-check currently supports only --source or --all; source+experiment/focal-overlay BUILD needs a selector-matched G2 report, not a source-only report or --all report standing in for the exact composition. Persist and revalidate selector kind, source/source-ref, experiment or deterministic-overlay identity, patch_set_id, and ordered IDs/hashes. Keep --all-report solely for G6 coverage.
7. Assert recipe_patch_ids contains the complete source+experiment/overlay composition so G6 cannot waive a selected experimental patch. Keep G4 focal and G7 composition-level.
8. Add hardware-free contract tests for source-only backward compatibility, source+experiment selection, deterministic focal overlay, invalid/focal-absent/rejected/conflicting selections, selector-bound G2 freshness, G6 full-composition coverage, G4/G7 separation, and JSON identity fields. Update canonical testing documentation and CLI help/examples.
9. Use PA25 as the first consumer: validate contexts for hi155-hybrid-allreduce-gate, hi18-reduce-probe, rd19-only, hip-internal-allreduce-only, and deterministic focal overlays for 1002/1232 without changing recipes merely for audit convenience.

## Detailed Solution & Technical Design

Target the existing campaign resolution layer used by build/rebase/campaign commands. patch-gates should pass args.experiment to campaign_resolution.resolve_canonical_selection(..., experiment=...), which already delegates to resolve_lane(..., experiment=...) and returns source_ref, patch_set_id, and ordered patch IDs. Reuse this exact authority rather than inventing another resolver.

The selection request should carry source name, optional experiment name, and the explicit deterministic focal-overlay request. Resolution returns selected ordered patch IDs, content hashes, source/experiment/overlay identity, and the complete composition used by G7. Reuse patchset.expand_composition/resolve_exact and patch_admission.admit; do not move or reimplement those authorities. Keep --source-only behavior unchanged and make new selectors explicit in JSON and receipts.

Focal-overlay implementation is concrete for this item: expose --focal-overlay, mutually exclusive with --experiment and requiring --source. Resolve the base source canonically, expand the focal closure with patchset.expand_composition((focal,)), remove IDs already in the base while preserving the resolved base/closure order, pass the remaining exact dependency-complete set to resolve_lane_overlay(), and use deterministic identity focal:<patch-id>. Because resolve_lane_overlay() is not a registered-overlay authority, this item must not accept arbitrary patch lists or describe a registered overlay. A generic reviewed overlay registry would be a separate plan.

G2 must be bound to the exact selected selector. Extend patch-rebase-check and rebase freshness reports so a source+experiment/focal-overlay BUILD can only consume a matching selector-bound report containing selector kind, source/source-ref, experiment or overlay identity, patch_set_id, ordered IDs/hashes, and resolved pin/BigCherry/overlay identities. --all-report remains a G6 coverage report only. G4 remains focal; G7 receives every patch in the resolved ordered composition. The focal-closure split-dependency test must prove dependencies already in the base are not duplicated and remaining closure dependencies are included.

## Code Samples & Guidance

Expected source+experiment command shape, using the existing resolver:
PYTHONPATH=tools python -m bigcherry --llama-root <audit-llama-root> patch-gates <focal-patch> --intent build --source bigcherry --experiment <experiment-name> --rebase-report <selector-matched-report> --all-report <all-patch-coverage-report> --json

Expected focal-overlay command shape:
PYTHONPATH=tools python -m bigcherry --llama-root <audit-llama-root> patch-gates <focal-patch> --intent build --source bigcherry --focal-overlay --rebase-report <selector-matched-report> --all-report <all-patch-coverage-report> --json

--experiment and --focal-overlay are mutually exclusive; --focal-overlay requires --source. JSON must include selection_status, selector kind, source/source-ref, experiment or deterministic overlay identity focal:<patch-id>, patch_set_id, ordered composition IDs and content hashes, and focal selection status. A focal-absent selection returns selection_status=NOT_EVALUATED before gate results; it must not synthesize G7 NA.

Do not claim production G7 until a real complete composition is evaluated.

## Effort & Risk

M, advanced, P1. Medium risk because selection identity is shared by build/rebase/campaign workflows and a careless shortcut could make an isolated focal patch look like a production composition. Highest risks are duplicate resolution rules, unregistered arbitrary overlays, silent source drift, selector-unbound G2 freshness, and mixing G4 with G7. Keep the change narrow, fail closed, preserve current source-only behavior, and split generic reviewed-overlay authority into another item if needed.

## Acceptance Criteria

Complete only when:
- patch-gates passes args.experiment through the existing campaign_resolution.resolve_canonical_selection(..., experiment=...) authority and exposes --focal-overlay as the explicit deterministic focal-closure mode, mutually exclusive with --experiment and requiring --source;
- focal-overlay expands patchset.expand_composition((focal,)), removes base-overlap IDs while preserving order, passes the remaining exact set to resolve_lane_overlay(), and uses selector identity focal:<patch-id> without accepting arbitrary unregistered patch lists;
- the selected ordered composition and its source/source-ref/experiment or overlay identity/patch_set_id/content hashes are returned in JSON and bound to G0/G7 evaluation;
- selector-bound G2/rebase reports persist and revalidate the same selector identity, while --all-report remains G6 coverage only;
- focal G4 and composition-level G7 remain distinct, with focal absence represented as machine-readable selection_status=NOT_EVALUATED before gates, never as NA/FAIL/BLOCKED or G7 NA;
- source-only behavior remains backward compatible and all invalid/ambiguous/unregistered/rejected/conflicting selections fail closed;
- G6 coverage includes the complete selected source+experiment/overlay composition, including a test where closure dependencies are split between base and overlay;
- no temporary recipe source, permanent framework alias, second evaluator, duplicate patch-selection policy, or arbitrary unvalidated overlay is introduced;
- hardware-free tests and canonical docs are updated, and PA25 can use the path for its real audit contexts once Python and a clean target checkout are available.
