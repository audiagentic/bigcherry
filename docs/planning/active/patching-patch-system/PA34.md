# Support exact experiment and overlay compositions in patch-gates audits

## Description

PA25's GPT validation identified a real semantic gap: patch-gates --intent build requires --source and rejects a focal patch that the selected canonical source does not contain, while G7 is correctly a complete-composition admission verdict. Seven touched/promoted patches therefore cannot receive a prospective per-patch BUILD/G7 result without either misleadingly calling a composition-resolution error a gate result or manufacturing temporary recipe sources. Add an explicit, provenance-preserving composition selection path for audit/build evaluation without adding a second evaluator or permanent compatibility umbrella. GPT validation provenance: dev-gpt-agent, same session ses_76206cac3e6b4be0, request req_d689b6b6ab7e4f14, reviewed pushed 08706ff2.

## Detailed Solution & Technical Design

Target the existing campaign resolution layer used by build/rebase/campaign commands. patch-gates should pass args.experiment to campaign_resolution.resolve_canonical_selection(..., experiment=...), which already delegates to resolve_lane(..., experiment=...) and returns source_ref, patch_set_id, and ordered patch IDs. Reuse this exact authority rather than inventing another resolver.

The selection request should carry source name, optional experiment name, and the explicit deterministic focal-overlay request. Resolution returns selected ordered patch IDs, content hashes, source/experiment/overlay identity, and the complete composition used by G7. Reuse patchset.expand_composition/resolve_exact and patch_admission.admit; do not move or reimplement those authorities. Keep --source-only behavior unchanged and make new selectors explicit in JSON and receipts.

Focal-overlay implementation is concrete for this item: expose --focal-overlay, mutually exclusive with --experiment and requiring --source. Resolve the base source canonically, expand the focal closure with patchset.expand_composition((focal,)), remove IDs already in the base while preserving the resolved base/closure order, pass the remaining exact dependency-complete set to resolve_lane_overlay(), and use deterministic identity focal:<patch-id>. Because resolve_lane_overlay() is not a registered-overlay authority, this item must not accept arbitrary patch lists or describe a registered overlay. A generic reviewed overlay registry would be a separate plan.

G2 must be bound to the exact selected selector. Extend patch-rebase-check and rebase freshness reports so a source+experiment/focal-overlay BUILD can only consume a matching selector-bound report containing selector kind, source/source-ref, experiment or overlay identity, patch_set_id, ordered IDs/hashes, and resolved pin/BigCherry/overlay identities. --all-report remains a G6 coverage report only. G4 remains focal; G7 receives every patch in the resolved ordered composition. The focal-closure split-dependency test must prove dependencies already in the base are not duplicated and remaining closure dependencies are included.

A focal-absent selection returns selection_status=NOT_EVALUATED before gate results; it must not synthesize G7 NA.
