# Support exact experiment and overlay compositions in patch-gates audits

## Description

PA25 GPT review identified a real semantic gap: patch-gates --intent build requires --source and rejects a focal patch that the selected canonical source does not contain, while G7 is correctly a complete-composition admission verdict. Seven touched/promoted patches therefore cannot receive a prospective per-patch BUILD/G7 result without either misleadingly calling a composition-resolution error a gate result or manufacturing temporary recipe sources. Add an explicit, provenance-preserving composition selection path for audit/build evaluation without adding a second evaluator or permanent compatibility umbrella.

## Steps

1. Read docs/reference/tooling/TOOLING.md and preserve the canonical CLI owner, existing gate registry, and no-second-framework rule.
2. Trace campaign_resolution.resolve_lane(..., experiment=...) and resolve_lane_overlay(...) plus the existing source/experiment/overlay contracts; specify which exact selection identity is accepted for a focal build/admission audit.
3. Extend the shared selection seam, not patch-gates with a duplicate resolver, so a command can name a canonical source plus an explicit experiment or exact overlay/composition and receive a fully ordered ResolvedPatchSet with selector identity recorded.
4. Define fail-closed behavior for unknown experiment, focal patch absent from the selected composition, conflicting/rejected patch, ambiguous source/experiment combination, and attempts to use a temporary or unregistered recipe.
5. Keep focal G4 and composition-level G7 separate: focal evidence is evaluated for the requested patch; G7 receives every patch in the resolved ordered composition. Never return G7 NA merely because a focal patch is not selected.
6. Add machine-readable selector/source/experiment/composition identity to patch-gates JSON and preserve the existing --source path's output compatibility.
7. Add hardware-free contract tests for canonical source, source+experiment, exact overlay, rejection and identity binding; update the canonical testing documentation and CLI help/examples.
8. Use PA25 as the first consumer: validate contexts for hi155-hybrid-allreduce-gate, hi18-reduce-probe, rd19-only, hip-internal-allreduce-only, and exact overlays for 1002/1232 without changing recipes merely for audit convenience.

## Detailed Solution & Technical Design

Target the existing campaign resolution layer used by build/rebase/campaign commands and have patch-gates consume its canonical selection result. The selection request should carry source name, optional experiment name, and optional reviewed exact overlay/composition identity; resolution returns selected ordered patch IDs, content hashes, source/experiment/overlay identity, and the complete composition used by G7. Reuse patchset.expand_composition/resolve_exact and patch_admission.admit; do not move or reimplement those authorities. Keep --source-only behavior unchanged and make new selectors explicit in JSON and receipts. A focal patch not in the selected composition is NOT_EVALUATED for that composition, not a GateStatus and not G7 NA. The implementation must not create a permanent framework alias or temporary recipe entry.

## Code Samples & Guidance

Expected command shape to be finalized from the existing parser/resolution APIs, for example:
PYTHONPATH=tools python -m bigcherry --llama-root <audit-llama-root> patch-gates <focal-patch> --intent build --source bigcherry --experiment <experiment-name> --rebase-report <fresh-report> --all-report <fresh-report> --json

If exact overlay is the existing supported contract, expose its canonical name/identity rather than accepting an unregistered arbitrary patch list. JSON must include source, experiment or overlay identity, ordered composition IDs and content hashes, and focal selection status.

## Validation

Hardware-free tests must prove source-only backward compatibility; source+experiment resolves the expected exact ordered set; exact overlay is registered and identity-bound; unknown/ambiguous/focal-absent/rejected/conflicting selections fail closed; G7 invokes patch_admission over the complete resolved set; G4 remains focal; JSON/CLI output is stable and includes selector identity. Run relevant unit tests, docs/link contract tests, ruff/static checks, and the seven PA25 audit invocations when Python and a clean pinned llama.cpp checkout are available. Do not claim production G7 until a real complete composition is evaluated.

## Effort & Risk

M, advanced, P1. Medium risk because selection identity is shared by build/rebase/campaign workflows and a careless shortcut could make an isolated focal patch look like a production composition. Highest risks are duplicate resolution rules, unregistered temporary overlays, silent source drift, and mixing G4 with G7. Keep the change narrow, fail closed, and preserve current source-only behavior.
