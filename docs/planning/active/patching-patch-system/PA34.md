# Make exact selector identity authoritative for experiment/focal-overlay gates and rebase

## Description

Current base confirms the original semantic gap but changes the implementation target. `campaign.resolution.resolve_lane()` already supports named experiments and delegates overlays to `resolve_lane_overlay()`, while `CanonicalSelection` exposes only `source_name`, `source_ref`, `patch_set_id`, and `patch_ids`. `patch.selection.CliPatchSelection` is source-only. `cmd_patch_rebase_check` accepts source/all only, `GateContext` has no expected selector identity, and `cmd_patch_gates` accepts a source or focal dependency closure only.

PA34 must extend the existing canonical resolution/rebase seam. It must not create a second resolver, arbitrary patch-list selector, temporary recipe source, or new gate policy.

## Benefit target

The target is not merely support for two more CLI flags. It is one exact-selection identity model shared unchanged by resolution, rebase freshness, gates, validation, and receipts.

Introduce one immutable `SelectorIdentity` value object owning the complete serializable identity:

- `selector_kind` and deterministic `selector_name`;
- `source_name` and `source_ref` where applicable;
- `patch_set_id` where applicable;
- exact ordered `patch_ids` and corresponding ordered `module_hashes`.

`CanonicalSelection` should carry this object as the single authority rather than duplicate the same identity in parallel fields. Migrate live consumers in this slice; if source-only convenience properties are temporarily required for bounded compatibility, they must be read-only projections of `identity`, never separately stored state.

Measurable targets:

- exactly one canonical serializer/validator for selector identity;
- zero rebase/gates/validation consumers hand-assemble their own selector identity dictionaries;
- exact selector mismatch (kind/name/ref/order/hash) is rejected by one shared comparison path;
- source, named experiment, focal overlay, and all-patches coverage reports use the same identity payload shape, with non-applicable fields explicitly absent/null rather than variant ad-hoc schemas.

## PA34.1: selector identity and rebase authority

1. Add immutable `SelectorIdentity` in `campaign.resolution` (or the narrow existing resolution owner) with canonical construction, validation, `to_payload()`, and exact-match semantics. Validate `patch_ids`/`module_hashes` cardinality and preserve order.
2. Refactor `CanonicalSelection` to carry `identity: SelectorIdentity`; migrate current source/ref/patch-set/ID consumers to the identity object instead of storing a second copy.
3. Extend `resolve_canonical_selection()` with mutually exclusive `experiment` and `focal_overlay_patch_id` inputs.
4. Named experiment delegates to the existing `resolve_lane(..., experiment=...)` path and reports selector name `experiment:<name>`.
5. Focal overlay: resolve the base source, expand the focal dependency closure with `patchset.expand_composition((focal,), directory=...)`, remove IDs already present in the base, then pass only the remaining dependency-complete overlay to `resolve_lane_overlay(..., overlay_name="focal:<patch-id>")`. Do not accept arbitrary user patch lists.
6. Return exact ordered IDs and hashes from the resolved lane through `SelectorIdentity`. Unknown/rejected/conflicting/ambiguous selectors fail closed.
7. Represent `--all` rebase coverage with the same payload type using a distinct `all-patches` selector kind. It remains coverage identity, not a claim that mutually conflicting patches form one production composition.
8. Bump the rebase-report schema and teach `run_rebase_check()`/freshness to persist and re-resolve the exact selector identity object rather than serializing its own `selection` dictionary.
9. Extend `require_fresh_report()` (or a narrowly named sibling) so G2 can require an exact expected `SelectorIdentity`, not merely a fresh report for the same checkout.
10. Add the expected selector identity to `GateContext`; `evaluate_rebase_gate()` delegates matching/freshness to `patch.rebase`, not local comparison logic.

Do not change generic `apply --source` semantics in this slice. `patch.selection.CliPatchSelection` may remain the source-only mutation projection; avoid broadening mutation surfaces just to satisfy audit/build selectors.

## PA34.2: CLI presentation

1. Add `--experiment` and `--focal-overlay` to `patch-rebase-check` and `patch-gates` using the canonical resolver. They are mutually exclusive; focal-overlay requires a source and uses the command's focal patch as the overlay patch.
2. For patch-gates, represent a focal patch absent from a successfully resolved selector as top-level `selection_status=NOT_EVALUATED` before gate execution. Do not synthesize G7 `NA` or overload GateStatus.
3. JSON embeds `SelectorIdentity.to_payload()` plus focal membership status and gates. Do not duplicate selector fields beside the canonical payload.
4. G4 stays focal. G7 receives the complete selected ordered composition. G6 `recipe_patch_ids` is the complete selected composition. G2 must consume a selector-matched report.
