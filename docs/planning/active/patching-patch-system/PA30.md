# Run final semantic-equivalence gates before deleting old framework/native names

## Description

Verification gate after PA29 and before PA31. Compare old and migrated roles while both names still resolve. This item validates semantics, not merely that the new config parses.

## Gates

1. **Serving control equivalence:** old `bigcherry-native` vs new `bigcherry-serving-base` under the same serving/replay build profile and generated inputs. Compare correctness, replay decisions, and representative performance.
2. **Release equivalence:** pre-cutover `source.bigcherry` composition vs migrated `source.bigcherry` serving-core composition plus the same upstream-fixes/validated-enhancements. Differences caused by intentionally removing campaign/qualification patch surface must be enumerated and shown not to alter serving behavior.
3. **Replay-winner equivalence:** re-run PA26 against the final migrated serving source, not only the PA27 candidate.
4. **Tuning smoke:** one real record -> inventory/generate -> tune -> promote/replay smoke through `bigcherry-tuning`, with durable build/generated/winner identities.
5. **Qualification smoke:** exercise 0830 telemetry and 1100 direct-op evidence through `bigcherry-qualification`; prove required artifacts are still produced.
6. **Patch-system gates:** selector-matched G2 plus G0/G4/G6/G7 as applicable, patch-lint, and all-patches rebase/disposition coverage. Use PA34 selector identity; `--all` remains a G6 coverage report, not a substitute for exact G2.

## Files

Verification artifacts/receipts only unless a discovered defect requires a separately reviewed fix.

## Validation

Use the same resolved llama.cpp commit, BigCherry revision, model/workload hashes, GPU/device mapping, build profile, generated registry, and winner database for each paired comparison. Balanced/rotated performance runs are required for any claimed parity/regression conclusion; a single llama-bench sample is only a smoke signal.

## Acceptance Criteria

All six gates pass or have an explicitly reviewed intentional difference with evidence. No BLOCKED/unknown selector/report is treated as PASS. The final receipt is sufficient for PA31 to delete old names without relying on compatibility fallbacks.
