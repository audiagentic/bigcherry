# Add semantic patch-sets and transitional sources without moving live consumers

## Description

Create the PA20 taxonomy after PA27 and PA26 pass. This step is additive only: old `patch-set.framework`, `source.bigcherry-native`, and the current `source.bigcherry` behavior remain available until PA29 performs the cutover.

## Steps

1. Add `patch-set.serving-core` from the PA26-confirmed serving classification.
2. Add `patch-set.campaign-support` for the PA27 tune/record half plus 0700, 0800, 0810, 0820, 0900.
3. Add `patch-set.qualification-support` for 0830 and 1100.
4. Keep `patch-set.upstream-fixes` and `patch-set.validated-enhancements` independent.
5. Add an explicit serving control source (`bigcherry-serving-base`) = serving-core + upstream-fixes.
6. Add `bigcherry-tuning` = serving-core + campaign-support + upstream-fixes. Enhancements/experiments remain explicit overlays rather than implicit additions.
7. Add `bigcherry-qualification` = serving-core + qualification-support + upstream-fixes; campaigns that also need campaign-support must request the composition explicitly.
8. Do not rename the canonical release source: `source.bigcherry` remains the production release owner and is cut over to serving-core only in PA29 after migration inventory is complete.

## Detailed Solution & Technical Design

All identities must come from existing `campaign.resolution.resolve_patch_set()/resolve_lane()/resolve_canonical_selection()`. Do not create a second recipe resolver. Add tests over ordered module IDs/hashes and `patch_set_id`, not only set membership.

During this coexistence phase, the old and new names may intentionally resolve to overlapping module sets. That is temporary migration scaffolding, not a permanent compatibility layer; PA31 removes the old framework/native names after PA30.

## Files

`config/recipes.toml`; resolution/config contract tests; source/build documentation that enumerates canonical source purposes.

## Validation

Resolve every new source and record source ref, patch-set ID, ordered module hashes, required-state policy, backend, and overlay flag. Build one representative profile for each new source. Assert 0800 and 1100 are not orphaned.

## Acceptance Criteria

New semantic sets/sources resolve deterministically and build, the current live consumers are unchanged, `source.bigcherry` has not yet been behaviorally cut over, and every old framework patch has exactly one documented semantic owner for the final taxonomy.
