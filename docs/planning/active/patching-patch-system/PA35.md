# Corrective follow-up for 0300/1000/1002 evidence gaps; recover or re-establish missing raw artifacts for 0840/1224

## Description

An independent agent audit of framework-package hardware-validation evidence found the registry's blanket claim that framework patches are 'equally hardware-validated' does not hold up. Findings (verbatim from the audit):

- 1001: genuine three-arm comparison against native llama.cpp; +10.8% versus native and +17.8% versus the BigCherry RCCL baseline for decode, with the known prefill regression documented. Strong record.
- 0840: real production MTP results, multiple RCCL versions, two- and three-GPU topology coverage, and heterogeneous-topology fail-closed checks. Strong record, BUT raw artifact directory not present in this checkout.
- 1200: causal single-GPU performance evidence, graph call-count proof, graph-capture confirmation, two-GPU preservation, and later exact-PPL confirmation. Strong record.
- 1224: 540/540 real-hardware correctness passes across 10 production signatures and 3 providers, limited to D=2. Strong record, BUT raw artifact directory not present in this checkout.
- 1225: direct safety/admission evidence across four devices and mixed topologies, but only single-repetition scope -- weaker.
- 1232: deterministic Windows/gfx1100 compile-command evidence, not runtime performance evidence -- a different, narrower claim than the others.
- 1000, 1002, 0300: flagged as needing corrective follow-up before being treated as fully evidence-closed (specifics not detailed in the audit summary -- needs a fresh look at each patch's own README/evidence to determine exactly what's missing or wrong).

Bottom line from the audit: retain registry states for framework packages as implementation/configuration validation, but stop describing all of them as equally hardware-validated.

## Steps

1. For 1000_rdna4_mmq_q2k_q6k_fix, 1002_hip_unsafe_math_opt_in, 0300_mmq_forced_j: read each patch's current README/evidence, identify the specific gap the audit is pointing at, and either gather the missing real evidence or correct any overstated claim in the README.
2. For 0840 and 1224: locate or regenerate the raw artifact directories their README/plan/ledger records reference; if they cannot be recovered, note in each patch's README that the summary record is not independently re-inspectable and why.
3. Do not weaken any patch's lifecycle state based on this audit alone -- this is an evidence-quality/documentation-accuracy pass, not a new correctness finding; follow bigcherry-patch-lifecycle's axis discipline if any state change does turn out to be warranted.
