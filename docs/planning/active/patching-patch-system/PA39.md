# CLI wiring: --run-rd04-contract / --run-rd050607-contract / --run-rd12-contract evidence-binding flags

## Description

Part of the GPT design (req_ead5338ca09348c5, 2026-09-13) for wiring RD04/RD05/RD06/RD07/RD12 correctness producers into the tracked evidence-binding CLI flow (parent: [[PA35]]). This is the core CLI/main() engineering work; depends on [[PA37]] (RD1203 prerequisites) and [[PA38]] (RD12 prerequisites) for the flags that touch those patches.

Real structural facts confirmed this session (verified against actual tools/bigcherry/patch/validation_campaign.py source, not assumed):
- make_record() requires TWO disjoint, mandatory build-identity domains: build_identities (role set must be exactly {tune, replay, stock} -- the standard S1-S7 campaign domain) and validation_build_identities (role set must be exactly {control, subject} -- the actual patch validation domain). No lighter path exists; a correctness-only script cannot bind evidence in isolation.
- For the DEFAULT (non-RD58) path, validation_build_identities already comes from control_build_evidence/validation_subject_build_evidence -- generic builds main()/run() already produces for every invocation. RD73's branch reuses these directly rather than building separately.
- RD04 needs llama-perplexity built fat (gfx1100;gfx1201;gfx1030); the standard flow only builds llama-server/llama-bench for a single args.amdgpu_targets architecture -- the new branches need their own build_tree() call(s) for the additional target/fat scope, reusing the already-materialized control_src/patched_src trees (cheap: build_tree() cache-reuses when the configure request is unchanged, so adding a target to an existing build dir just compiles the new target).

## Steps

1. Add CLI flags --run-rd04-contract, --run-rd050607-contract, --run-rd12-contract (store_true), plus --correctness-corpus (Path, for RD04/1203's PPL producers). Wire mutual exclusivity (with each other, with --run-performance-benchmark, with existing legacy RD flags) and require --device-map when any of the three specialized modes is set.
2. Define specialized_evidence_mode = any(...) including the three new flags alongside the existing run_rd08_contract/run_rd04_benchmark/run_rd58_state_restore/run_rd73_contract set; use it to gate the generic trace-probe and generic S1-S7 campaign execution the same way the existing specialized modes already do.
3. For each new mode: build the required fat/extended binaries (see facts above), call the existing correctness producer(s) (run_rd04_contract_correctness(), the RD1203 aggregator from [[PA37]], run_rd12_correctness_check()), capture validation_build_evidence (the actual CompletedBuildEvidence pair used), and thread results into a common {named_results_by_contract, per_arch_results, artifacts, gpu_architectures, validation_build_evidence} shape.
4. Replace the current single-contract ternary (contract_correctness_gate = ...) with plural gate evaluation: build named_results_by_contract from ALL specialized sources (rd08/rd58/rd73/the new three), evaluate compute_contract_correctness_gate() per contract in load_contracts_for_descriptor(descriptor), and emit _contract_correctness_gate (singular, back-compat) when exactly one contract is bound or _contract_correctness_gates (plural) when more than one is (1203's case).
5. Fix the pre-existing validation_plan.contract singular-access bug that will break 1203 (which binds 3 contracts): use validation_context_contract = validation_plan.contracts[0] if len(validation_plan.contracts) == 1 else None when constructing ValidationContext, never validation_plan.contract directly for a multi-contract patch.
6. Wire the terminal make_record() call: gpu_architectures=record_gpu_architectures (the actual architectures executed, which may be the fat list, not args.amdgpu_targets), validation_build_identities from the new modes' captured validation_build_evidence when set, falling back to the existing rd58/default logic otherwise.
7. These flags must NOT populate contract_promotions -- they produce current-pin tracked CORRECTNESS evidence only; they must not silently qualify performance/activation/promotion claims or change patch tracked state. eligible_for_validated_state stays gated by all OTHER declared checks as before.
8. Add the raw new artifact paths (rd04-correctness-<arch>.json, rd050607-correctness-<arch>.json, rd12-correctness-<arch>.json) to evidence.py::_artifact_refs() so their hashes are captured into the tracked record.
9. Hardware-free tests: build_tree() never called inside the per-device loop; --device-map missing an architecture fails closed; ROCR_VISIBLE_DEVICES is excluded/stripped; one failed architecture fails the aggregate; RD05/RD06 consume gfx1201 only while RD07 requires all three; multi-contract gate serialization (singular vs plural key); external --correctness-evidence ambiguity rejection extended to the three new flags; specialized-mode exclusions include the three new flags; validation-build identities actually reaching make_record(); write_record() receiving full current-pin/contract identities.
