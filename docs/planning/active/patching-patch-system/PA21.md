# gates.py: orchestration layer composing existing validation/evidence/admission checks

## Description

Authoritative PA19 G0-G7 policy evaluator. Compose existing validation policy, evidence, lifecycle/disposition and patch-admission authorities behind one typed evaluator; do not duplicate or replace those authorities. PA21 is the first implementation slice and PA22/PA23 consume it.

## Steps

1. Define immutable GateContext containing resolved patch descriptor, complete resolved production composition, upstream pin, operation intent, evidence roots and canonical platform/build context.
2. Define GateResult(id,status PASS|FAIL|BLOCKED|NA,phase,authority,detail) and stable status/error mapping.
3. Implement evaluate_patch_gates() by composing validation_policy.check_validation_packages(), require_execution_package(), check_performance_evidence(), evidence/HI83 record verification, patch_admission.admit(), and disposition lookups.
4. Evaluate G0-G7 with applicability by operation intent, patch kind, tags, origin and scope. G7 must evaluate the complete resolved production composition, not just the focal patch.
5. Map admission status not-ready with gate_active=false to BLOCKED, never PASS. Unknown, malformed or unresolved authority data fails closed.
6. Add hardware-free tests for positive, negative, blocked and non-applicable paths across framework, diagnostic, upstream-backport and enhancement descriptors.

## Detailed Solution & Technical Design

Implement immutable GateId, GateStatus, GateIntent, GateResult, and GateContext using the existing PatchContext and ResolvedPatchSet types. Compose G0-G7 with explicit applicability by intent. G7 must admit the complete ordered composition, never only the focal descriptor. Map not-ready/inactive/unknown or malformed authority results fail-closed to BLOCKED; negative evaluated verdicts are FAIL. For PROMOTE, pass an opt-in assumed target state only through catalog.validation_evidence_statuses(), preserving default behavior for all existing callers.

Framework PROMOTE requires an authority-preserving prospective-state seam below catalog.py: verify_framework_configuration_patch currently reloads the physical registry and resolves the bigcherry-native lane, whose [patch-set.framework] required-state is validated. Add an opt-in target-state/state overlay to the existing composition-resolution authority used by that verifier, defaulting to current physical-state behavior; do not reimplement lane resolution in gates.py. Until that seam exists, framework PROMOTE must return BLOCKED. Keep catalog assume_validated restricted to untested modules.
