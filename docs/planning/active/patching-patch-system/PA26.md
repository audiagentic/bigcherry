# Prove serving replay equivalence after the PA27 mechanical split

## Description

Evidence gate between PA27 and PA28. PA27 is allowed to mechanically split 0100 while preserving the aggregate composition; PA26 then proves that the candidate `serving-core` composition produces the same replay decisions and outputs as the current framework for a fixed promoted-winner database.

This is not a source-inspection proof and not a prerequisite to creating the split. It is the behavioral gate that decides which 0100 functionality is truly serving-critical.

## Steps

1. Select a known-real promoted winners/replay database and record hashes for winners, model, generated registry, source ref, BigCherry revision, build profile, GPU identity, and relevant environment.
2. Build the current aggregate arm and the PA27 serving-core candidate from the same resolved source/ref and generated inputs.
3. Replay every winner dimension exercised by 0300/0400/0500/0600/0650 and compare resolved signature, chosen candidate/configuration, dispatch outcome, and output/correctness artifact.
4. Include negative fixtures that intentionally remove or alter one serving dependency and prove the equivalence test detects the divergence.
5. If a real dimension diverges, reclassify the responsible functionality into serving-core before PA28. Do not waive the difference because throughput is similar.

## Files

A reusable equivalence test under `tools/tests/campaign/` or the existing replay test owner; PA27 split outputs; immutable test receipt/artifacts. Do not add a second replay implementation.

## Validation

The test must resolve both arms through the same `campaign.resolution` and build/generate path used by production. Compare ordered patch/module hashes and build identities before comparing dispatch results so a stale or accidentally different arm cannot pass.

## Acceptance Criteria

A reproducible positive receipt proves current aggregate vs serving-core replay equivalence for the declared winner corpus, negative fixtures prove the oracle is sensitive to real differences, and any discovered serving dependency is reflected in PA20/PA27 before PA28 creates public taxonomy.

## Notes

Authoritative sequence is PA27 -> PA26 -> PA28. Older text implying PA26 had to precede the mechanical extraction is superseded.
