# Adopt the branching standard: slice branches, gated pull requests, automatic versions

## Description

Owner request 2026-10-08: merge the current branch and from now on do each slice of work on its own branch, as a production-like workflow, formalised as a standard. The standard is docs/reference/build/BRANCHING.md (trunk-based, short-lived branches, squash-merged pull requests with conventional titles, required checks, release-please versions, protection on main). This item makes the repository and the tooling enforce it.

## Steps

1. Done with the standard: BRANCHING.md, the pull request template, main fast-forwarded to patch-refactor (the last direct update of main).
2. CI on pull requests: patch-offline-validation.yml, jobs-service-validation.yml and rcd-slurm-validation.yml trigger on `pull_request` to main (and on push to main) instead of on pushes to patch-refactor; changed-patch detection uses the merge base.
3. Title check: a small workflow that fails a pull request whose title is not a conventional commit of an allowed type.
4. Tooling to the new flow: `bigcherry pin-release` releases from main (the bump is a `bump/<tag>` pull request; the release phase merges release-please's pull request) and no longer fast-forwards main itself; `patch-promote` (PA45) ends by opening the promotion pull request; a `bigcherry slice start <type> <item> <topic>` / `slice pr` pair that names the branch, rebases it on main and opens the pull request from the template.
5. Lab: `tools/lab/plan-qualification` helper that checks a slice branch out in the Brutus tree under the queue lock, runs the given job list and returns the tree to main; the completion gate compares trees against main.
6. Protection on main (repository settings, via `gh api`): pull request required with one approval, required checks from step 2 and 3, linear history, no force push, no deletion. Applied only after steps 2-4 are merged, otherwise the release command and the agents are locked out.
7. Retire patch-refactor after the slices in flight on it have merged; update the trees' configured branch (config [[trees]]), CLAUDE.md's source-control doctrine through its owning component, and the bump and patch skills.
8. release-please: confirm that squash-merged `feat(patch):` / `fix(patch):` titles raise minor / patch without a Release-As footer, and that a pin bump still releases as <build>.0.0.
