# 1005: physical-clear A/B diagnostic for hybrid/recurrent state reset on checkpoint invalidation

## Description

Real, unresolved finding from patch 1005's live multi-turn server validation (2026-09-12, gfx1100, lfm2.5-8B). A real squash defect (deleted n_past reassignment) was found and fixed in patches/1005_prompt_cache_checkpoint_selection/patch.py, but the live test STILL fails after the fix: checkpoint invalidation and full 37-token prompt reprocessing happen correctly (confirmed via verbose server trace -- checkpoint restore is NOT the active path in this reproducer), yet generation still produces garbled output and stops after only 8 tokens instead of matching a cold-reference completion of the identical prompt.

GPT review (dev-gpt-agent, session ses_3adef4de3bc249b2, req_59b2012bc3934ae6) is explicit: do not record 'recurrent state is not reset on checkpoint invalidation' as a confirmed finding -- the code path SHOULD reset it (b10705's hybrid memory routes seq_rm() through both recurrent and attention memory, and build_rs explicitly zeroes a freshly-allocated recurrent-state row before use). A physical-clear A/B is the concrete, cheap next diagnostic that converts this from hypothesis to a real result.

## Steps

1. In the exact do-reset/no-valid-checkpoint path (server-context.cpp, the branch that fires when no checkpoint is selected), temporarily add a call to `llama_memory_clear(llama_get_memory(ctx_tgt), true)` (the data=true form, clears both metadata and backing buffers) plus `llama_synchronize(ctx_tgt)` before re-evaluating the prompt.
2. Rebuild and re-run the exact A/B/C live-server sequence documented in patches/1005_prompt_cache_checkpoint_selection/README.md (turn A primes a checkpoint, turn C shares only a shorter common prefix, compare turn C's output against a cold/fresh-process reference of the identical prompt).
3. If turn C now matches the cold reference: this confirms a real defect in llama.cpp's own logical seq_rm() -> fresh recurrent-state reconstruction (tail/rs_idx/rs_zero/graph reuse in llama-memory-recurrent.cpp) -- open a dedicated upstream-level investigation, separate from patch 1005's own scope (server-side checkpoint/cache selection only).
4. If turn C still garbles/hits early EOS even with the physical clear: stale recurrent state is effectively ruled out as the cause. Next target: warm-vs-cold graph/sampler/runtime state divergence, starting with a first-token logits comparison between the warm and cold paths.
5. Remove the temporary diagnostic instrumentation once the discriminator result is recorded, regardless of outcome.
