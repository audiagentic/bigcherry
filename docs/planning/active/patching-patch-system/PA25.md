## Detailed Solution & Technical Design

GPT final-validation provenance: dev-gpt-agent, same session ses_76206cac3e6b4be0, request req_7aad71bd36ba4e28, terminal success at 2026-09-12T17:56:31Z. GPT inspected main 650237068b43d82593945a4ecd38d5192d4a1f3c and required separate G4 evaluation state from GateResult.

For 1225 and 1232, patch-verify-evidence is the correct focal evidence authority route because their local-framework PROMOTE path deliberately blocks before normal evidence evaluation. Its output is not a G4 GateResult. Preserve the raw authority status/detail as evidence-authority output, set G4 evaluation to NOT_EVALUATED, and set G4 GateResult to none unless evaluate_evidence_gate() actually runs. The five non-framework PROMOTE projections may provide a real G4 GateResult; read that field, not the overall PROMOTE verdict.

G4 semantics: focal evidence is evaluated against current b10901, its resolved SHA, current patch/validation identity, and declared architecture obligations. Missing/stale qualifying evidence is FAIL; malformed/unknown authority output is BLOCKED; not-required is NA. Historical README evidence and the separate validation-package grandfather for 1200 (G3 structural grandfather) are not G4 evidence. G7 semantics: patch_admission.admit(mode=production) receives the complete ordered resolved composition; active admitted is PASS, active rejection is FAIL, inactive/not-ready is BLOCKED at the PA21 evaluator. Keep the existing bootstrap require_admission distinction documented.

Environment semantics: Python/launcher inability is NOT_RUN. BLOCKED may be recorded only when the live gate evaluator returns BLOCKED. A focal patch absent from the selected composition or a deliberately uninvoked G4 path is NOT_EVALUATED, not NA/FAIL/BLOCKED. Record the actual pin-resolution source used by patch-verify-evidence through ProjectContext or paths.llama_root() and its resolved SHA; do not imply that command consumed the patch-gates --llama-root argument.
