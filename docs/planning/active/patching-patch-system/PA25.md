# Audit current focal G4 and composition-level G7 status for the seven promoted/touched patches

## Description

Step 5 of PA19, after PA21/PA22/PA23/PA24 landed. This is a current-state evidence and admission audit, not a promotion shortcut. It must report each patch's focal G4 status from the live evidence authority against the configured b10901 pin and separately report one complete production-composition G7 result. The existing CLI cannot produce a prospective per-patch BUILD/G7 result for these seven: --intent build requires --source, and source.bigcherry/source.bigcherry-native do not select them. Do not modify recipes to manufacture temporary audit sources. Historical README/SUMMARY/manual hardware evidence remains historical provenance and is not silently converted into current G4 evidence.

## Steps

1. Establish identities before execution: record the full BigCherry revision, configured pin b10901, resolved pin SHA, audit llama.cpp HEAD, and clean/dirty status. Use a dedicated clean detached audit checkout at the resolved pin; the shared vendor tree is dirty and is not authoritative. If only the current Windows host with an unavailable Python launcher is available, record NOT_RUN as an environmental blocker and do not claim GateStatus.
2. Generate fresh all-patches and production-source rebase reports with the exact audit checkout:
   PYTHONPATH=tools python -m bigcherry --llama-root <audit-llama-root> patch-rebase-check --all --json artifacts/patch-gates/PA25/rebase-all.json
   PYTHONPATH=tools python -m bigcherry --llama-root <audit-llama-root> patch-rebase-check --source bigcherry --json artifacts/patch-gates/PA25/rebase-bigcherry.json
3. For every listed patch, run patch-verify-evidence <patch-id> --no-legacy-grandfather --json and capture the authority output. This is the focal audit route for 1225_hi85_nccl_heterogeneous_arch_guard and 1232_hi81_windows_cxx_hipcc_flags_reach_compile.
4. For 0840_hybrid_allreduce_dispatch, 1224_hi18_reduce_correctness_probe, 1200_rd19_single_gpu_meta_bypass, 1001_hip_internal_allreduce, and 1002_hip_unsafe_math_opt_in, run patch-gates --intent promote with rebase-all.json and --no-legacy-grandfather, then record the G4 field rather than the overall PROMOTE result. Do not use this PROMOTE projection for 1225/1232 because their local-framework special case intentionally blocks before ordinary evidence resolution.
5. Run actual G7 once at composition scope using a selected focal patch from source.bigcherry, for example 0100_cmake_options, with rebase-bigcherry.json and --all-report rebase-all.json. G7 must receive the complete ordered resolved source composition. Do not run one of the seven with --source bigcherry and call the composition-resolution error a G7 result.
6. Append a dated PA25 receipt block to each existing README's Known limitations without rewriting or invalidating historical evidence. Record exact G4 status/detail, G7 status and exact composition or NOT_EVALUATED, full revisions, clean audit-root identity, receipt path, and follow-up ID. Use NOT_RUN for environment inability and NOT_EVALUATED for a focal patch absent from a selected composition; neither is NA, BLOCKED, or FAIL.
7. For true missing/stale/malformed evidence, create an owner-specific follow-up through ag-planning. Use PA items for gate/composition tooling; PGC items for shared-collective qualification; PRBE items for RD19/1200; and the actual build/configuration owner for 1002/1232 unless the gap is tooling. Each follow-up must retain the patch ID, PA25 provenance, exact gate detail, full revisions/pin/resolved SHA, OS/architecture/topology, existing historical evidence, missing producer/identity, and explicit unblock condition.

G4 semantics: focal evidence is evaluated against current b10901, its resolved SHA, current patch/validation identity, and declared architecture obligations. Missing/stale qualifying evidence is FAIL; malformed/unknown authority output is BLOCKED; not-required is NA. Historical README evidence and the separate validation-package grandfather for 1200 (G3 structural grandfather) are not G4 evidence. G7 semantics: patch_admission.admit(mode=production) receives the complete ordered resolved composition; active admitted is PASS, active rejection is FAIL, inactive/not-ready is BLOCKED at the PA21 evaluator. Keep the existing bootstrap require_admission distinction documented.

Architecture is derived from metadata, not a patch-gates argument: 1200 declares gfx1100/gfx1201/gfx1030; 1232 declares gfx1100; other listed patches have no explicit architecture list and G7 supplies its default gfx1100 obligation.

Create a separate PA follow-up for prospective patch-gates composition support, using the existing campaign_resolution.resolve_lane(..., experiment=...) / resolve_lane_overlay(...) seam. Do not add a second evaluator, temporary source, or permanent framework compatibility umbrella.
