# Core types for sig-to-sig routing transformations

## Description

Define the data structures and registry that represent a routing transformation — a mapping from one launch context to another. This is the foundation for cross-family tuning via operand manipulation (like PR #26171's transpose+swap). Must be behind a compile-time flag so the whole feature can be toggled on/off.

## Steps

- Add GGML_HIP_ROUTING_TRANSFORM CMake option in vendor/llama.cpp/ggml/src/ggml-cuda/CMakeLists.txt, default OFF
- Add enum ggml_hip_transform_id and enum ggml_hip_transform_source to hip-autotune-types.h inside #ifdef GGML_HIP_ROUTING_TRANSFORM block
- Add function pointer typedefs (can_apply_fn, apply_fn, inverse_fn) to hip-autotune-types.h
- Define struct ggml_hip_routing_transformation in hip-autotune-types.h with id, name, source, equivalence_verified, overhead_bytes, can_apply, apply, inverse
- Create hip-autotune-transform.cuh with ggml_hip_transform_find() and ggml_hip_transform_count() declarations
- Verify build: OFF (default) produces no symbols; ON produces transform registry

## Detailed Solution & Technical Design

## Architecture

A routing transformation takes a signature that would fall to BLAS (or other single-family result) and produces an **alternative launch context** — different tensor pointers, reshaped dimensions, or batch decomposition — such that a non-BLAS family can serve it.

### Core Model

```
original_sig  --[transform]-->  transformed_sig  --[tuner]-->  winner
       |                                                       |
       +-- record gap (if no transform works)                  +-- record attempt
```

A transformation is a **pure function**: given a `ggml_hip_dispatch_signature_v1` and a `ggml_hip_launch_context`, it produces either:
- Nothing (can_apply returned false), or
- A new signature + launch context pair that the tuner can measure normally.

### Data Structures

**Transform descriptor** — registered once at init, immutable:
```c
enum ggml_hip_transform_id {
    GGML_HIP_TRANSFORM_NONE = 0,
    GGML_HIP_TRANSFORM_TRANSPOSE_WEIGHT_FOR_MMVF = 1,
    GGML_HIP_TRANSFORM_BATCH_FOR_MMVF = 2,
    // Next available: 3. Leave room for DISCOVERED transforms (16+).
};

enum ggml_hip_transform_source {
    GGML_HIP_SOURCE_PREDEFINED = 0,   // hand-written, equivalence_verified=true
    GGML_HIP_SOURCE_DISCOVERED = 1,   // agent-proposed, must pass validation
};

typedef bool (*ggml_hip_transform_can_apply_fn)(
    const ggml_hip_dispatch_signature_v1 & sig);

typedef int (*ggml_hip_transform_apply_fn)(
    const ggml_hip_dispatch_signature_v1 & orig_sig,
    ggml_hip_dispatch_signature_v1 * out_sig,   // transformed signature
    ggml_hip_launch_context * out_lc,           // transformed launch context
    void ** out_inverse_ctx);                    // opaque: inverse writeback data

typedef bool (*ggml_hip_transform_inverse_fn)(
    const ggml_hip_dispatch_signature_v1 & orig_sig,
    const ggml_hip_launch_context & orig_lc,
    void * inverse_ctx);

struct ggml_hip_routing_transformation {
    ggml_hip_transform_id id;
    const char * name;                 // e.g. "transpose_weight_for_mmvf"
    ggml_hip_transform_source source;  // PREDEFINED or DISCOVERED
    bool equivalence_verified;         // mathematically guaranteed equivalent

    // Cost estimate: extra bytes beyond the candidate's own workspace.
    // BATCH_FOR_MMVF needs temporary pointers; TRANSPOSE_WEIGHT needs none.
    size_t overhead_bytes(const ggml_hip_dispatch_signature_v1 & sig);

    ggml_hip_transform_can_apply_fn can_apply;
    ggml_hip_transform_apply_fn     apply;
    ggml_hip_transform_inverse_fn   inverse;   // null if no writeback needed
};
```

**Transform registry** — flat array, size macro:
```c
#ifdef GGML_HIP_ROUTING_TRANSFORM
extern const ggml_hip_routing_transformation g_routing_transforms[];
extern const int g_routing_transform_count;
#endif
```

### Launch Context Modification

A transformation does NOT modify the original signature or launch context. It produces new instances:
- `out_sig` — a copy of orig_sig with dimensions/pointers modified so that `family_can_serve` returns true for the target family.
- `out_lc` — a copy of lc_in with src0/src1/dst pointers reshaped.
- `out_inverse_ctx` — opaque data the dispatch layer needs later to write back results.

For TRANSPOSE_WEIGHT_FOR_MMVF, the transformation swaps src0↔src1 and reshapes dst from [N×1] to [1×N]. The inverse is identity because mmvf writes to the same memory with different stride interpretation — the consumer reads `ned` from the original signature.

For BATCH_FOR_MMVF, the transformation splits into ceil(N/8) launch contexts. Each has sliced src1 and dst pointers. The inverse writes back from the batch slices to the original dst layout (also identity in practice because the slices partition the contiguous dst exactly).

### Flag Gate

Every file that includes this machinery is wrapped:
```c
#ifdef GGML_HIP_ROUTING_TRANSFORM
// all transform code here
#endif
```

CMake option `GGML_HIP_ROUTING_TRANSFORM` defaults OFF. When OFF, the preprocessor eliminates all symbols — zero symbols in .cu files, zero runtime cost.

### CMake Integration

In `vendor/llama.cpp/ggml/src/ggml-cuda/CMakeLists.txt` (or the parent):```cmake
option(GGML_HIP_ROUTING_TRANSFORM "Enable sig-to-sig routing transformations" OFF)
if(GGML_HIP_ROUTING_TRANSFORM AND GGML_HIP_DISPATCH)
    set_source_files_properties(hip-autotune-transform.cu PROPERTIES
        COMPILE_DEFINITIONS "GGML_HIP_ROUTING_TRANSFORM")
endif()```
