### 2026-08-12: bc_requested_size fix re-applied to patches/0900_pool_workspace_metrics.py

Added `bc_requested_size` member to `ggml_cuda_pool_alloc<T>`, set it at `alloc()` time to `size * sizeof(T)`, switched both `note_alloc`/`note_free` accounting calls to read it instead of `actual_size` (the real `pool->free(ptr, actual_size)` call is untouched). Verified all four patch anchors match the current pinned vendor tree.

**Historical discovery:** the patch was initially not applied to builds because it
had no `STATE` declaration, and the tuner-side wiring was absent. That finding
explains the original gate; it is no longer the current tree state.

The patch is now marked `STATE = "validated"` for patchset selection, and the
tuner reads the counters at isolated candidate measurements. The combined chain
still must be proven against real hardware before workspace-informed ranking is
treated as production evidence; only then should the final validation gate be
closed.

The former wiring gap is closed: `hip-autotune-tuner.cu` now has an explicit
isolated measurement path, calls the pool clear/reset/peak hooks, checks return
to baseline, and emits `measurement.pool_peak_bytes`. HI54's exact protocol and
the hardware validation gate remain outstanding.

Remaining scope: validate the now-wired clear/reset/rebase protocol on HIP
hardware, capture isolated versus interleaved evidence, run the historical
discrepancy corpus, and decide from measured overhead whether cache clearing can
be reduced. Do not close this item or enable workspace-based ranking solely from
source-level wiring and offline tests.
