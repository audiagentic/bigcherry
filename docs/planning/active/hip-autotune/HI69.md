# Profile-gated exact on-device correctness reduction for candidate screening

## Description

On-device exact correctness reduction for screening (F4, P2): replace the full device-to-host output copy + host NMSE compare per eligible candidate with an exact on-device scalar reduction, but only if profiling shows it material - and never by subsampling or deferring correctness.

## Steps



## Detailed Solution & Technical Design

DESIGN (GPT-adjudicated in RV49): profile first - if the screening copies are a material portion of tune time, implement an EXACT device-side reduction over the COMPLETE output that computes sum((C-N)^2), sum(N^2), max(abs(C-N)) and any_nan_or_inf, copying only those scalars to the host. DO NOT strided-subsample correctness and do NOT defer correctness until after finalist selection - both trade a hard correctness property for cold-path speed, and are rejected by design. Sequenced AFTER HI67 (F1) because F1 changes what the reference actually needs to be (CPU reference R, not just native N) - build the reduction against the final reference semantics in one pass rather than twice. Note the verified correction: the determinism recheck does the D2H copy only twice and only for the selected winner, not for all finalists - the bulk cost is the per-eligible-candidate screening pass.
