# Make campaign workflows unattended across models and GPU topologies

## Description

Follow-up to HI168. Add one thin validated matrix entrypoint over existing BigCherry campaign workflows so selectable registered models, GPU sets/topologies and runtime configurations can run unattended with reproducible provenance. tune-campaign, ab-benchmark, ServerRunner and existing admission/evidence machinery remain authoritative; this item covers outer resolution, serialization, delegation and aggregation only.

## Steps

1. Define/finish one declarative e2e-build-matrix configuration selecting model registry ID, physical GPU set/topology, runtime profile, workflow, stock/native/replay identities and replay cache.\n2. Preflight-expand the entire requested matrix before launching GPU work, resolving models.toml, environment.toml/BC_*, recipes.toml identities and replay compatibility.\n3. Materialize immutable resolved cell descriptors containing model, GPUs/visibility, topology, runtime arguments, build/binary identities, cache evidence and benchmark configuration.\n4. Execute GPU cells serially with explicit visibility and clean teardown; stop on residual process/device state or uncertain visibility.\n5. Delegate tuning to tune-campaign and performance cells to ab-benchmark/ServerRunner using maintained server-bench.\n6. Write per-cell/per-GPU manifests and a run-level summary, propagating child verdicts unchanged.\n7. Add fail-closed tests and reusable dual-GPU and single-GPU examples.

## Detailed Solution & Technical Design

Expose exactly one matrix runner over existing campaign configuration (for example, bigcherry campaign-run --matrix <name>). Resolve and validate every cell before hardware execution. Reject unresolved models, unavailable or duplicate GPUs, topology mismatch, invalid profiles, missing build identities, incompatible caches or required evidence failures. Never auto-select, regenerate, retune or silently fall back from a rejected replay cache. Keep production replay timing and diagnostic evidence separate; the matrix layer cannot upgrade admission. Use write-once cell artifacts and deterministic ordering.

## Validation

Unknown model, GPU, topology, runtime, build or cache fails before execution. Tests prove deterministic order, zero overlapping GPU workloads, explicit effective visibility, teardown gating, stable resolved identity digest, child failure/non-admission propagation and complete manifests. Real smoke uses maintained server-bench for representative dual-XTX/27B and single-gfx1030/9B lanes.

## Effort & Risk

M effort and risk. Existing execution/admission primitives exist; primary hazards are GPU visibility leakage, contention, identity drift and diagnostic evidence being confused with production timing. Mitigate with full preflight, serialization, immutable descriptors and strict delegation.

## Standards

Fail closed; canonical models.toml, environment.toml/BC_* and recipes.toml only; maintained server-bench only; no duplicate campaign engine or admission policy; no concurrent GPU workloads; production and diagnostic roles distinct; preserve raw evidence and never upgrade verdicts.

## Acceptance Criteria

One matrix entrypoint runs another supported model/topology/configuration by configuration change only. The full matrix is resolved before GPU execution; workloads never overlap; visibility is explicit and recorded. Stock/native/replay identities and cache evidence are retained. Existing workflows perform execution and admission. Per-cell and aggregate provenance is emitted. Invalid inputs fail closed and cannot produce an admitted result.
