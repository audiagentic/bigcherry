# RD73 measures as a ~2% REGRESSION on the workload it was promoted on

## Description

1233_rd73_stable_graph_cache_key is the only patch in [patch-set.validated-enhancements] -- the release enhancement set -- promoted 2026-09-05 on 6 pre-registered sessions claiming +1.8886% end-to-end, 95% CI [1.4754, 2.3523], 0.0% control regression, bit-identical output, contract RD73-STABLE-GRAPH-CACHE-KEY hash 8827bd6d.

An order-balanced 4-arm comparison on the SAME workload, model and architecture the contract was measured on (MTP speculative decode, tierL-qwen27b-q8, gfx1100 x2, -sm tensor) measures it as a REGRESSION:

  arm            tg128     tg512     tg2048    pp1024    pp4096
  bcnative       102.02    100.34    106.95    987.36    1236.73
  bcrd73         100.02     99.09    106.32    980.52    1229.26
  delta          -1.96%    -1.24%    -0.59%    -0.69%    -0.60%

tg128, tg512 and pp1024 show COMPLETE SEPARATION at n=8 per arm -- every bcrd73 sample worse than every bcnative sample -- which is Mann-Whitney p = 2/C(16,8) = 0.00016 per metric. tg128 ranges do not come close to touching: [99.21-100.51] against [101.58-102.31].

Both claims cannot be true. The gap is a sign flip of roughly 3.9 percentage points on the headline metric.

The run also isolates two things RD73 is NOT being confused with. Framework overhead is zero: llama-native vs bigcherry-native is -0.11%/-0.17%/-0.12%/+0.09%/-0.26%, all overlapping. And the GGML_HIP_DISPATCH_REPLAY build flag is nearly free: replayflag vs bcrd73, on BYTE-IDENTICAL source trees, is -0.36%/-0.12%/-0.08%/-0.29%/-0.19%, all overlapping. Earlier in this session I attributed the deficit first to the 19 tuned winners and then to the replay build variant. Both attributions were wrong; this is RD73.
