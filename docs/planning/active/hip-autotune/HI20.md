# Load tuning measurements JSONL into SQLite database

## Description

After a tuning run, all per-candidate metrics (median_us, p95_us, nmse, workspace, etc.) are only in the `.measurements.jsonl` file. The schema already has `measurement` and `winner` tables with the right columns. Need to load them.

The existing `inventory.py` loads record-mode JSONL into SQLite but doesn't handle tuning-mode measurements. The tuner writes results with per-candidate measurement data that needs to populate: `build`, `candidate`, `measurement`, and `winner` tables.

## Steps

- Add `build_tuning_database()` function to `tools/bigcherry/inventory.py` that reads `.measurements.jsonl` and populates SQLite
- Parse the header line for build info (source_revision, manifest_hash, schema versions)
- For each result: insert candidate rows from the catalog, measurement rows per candidate, winner row
- Extend the `bigcherry inventory` CLI to accept tuning-mode JSONL (detect by presence of `kind: result` vs `kind: observation`)
- Handle both fresh database and appending to an existing database that already has build/hardware/signature/observation from record mode
- Write unit test with a small measurements.jsonl fixture

## Notes

The measurements.jsonl doesn't include hardware key or signature canonical JSON directly — only the dispatch digest. To link back to signature rows, we need either: (a) append measurement/winner as a separate step after the record-mode DB is built, or (b) accept that measurement rows reference by dispatch_digest only. Option (a) requires the signature_digest column in measurement table; option (b) is simpler and more accurate since the dispatch_digest IS the lookup key.
