# Windows/WDDM measurement hardening — unblocked sweeps poison on transient fatal failures

## Description

On the local Windows workstation (WDDM), full unblocked HIP tuning sweeps hit transient fatal measurement failures that poison the whole experiment: both an ON and a matched OFF run of Slice A died at different random stages with identical failure modes, proving the flake is environmental, not caused by the double-native twin. Evidence collection therefore had to use HIP_LAUNCH_BLOCKING=1, which serializes launches and makes blocked-run timings non-authoritative (accepted for Slice A's local gate; production-architecture validation on Brutus/Linux remains the unblocked evidence gate).

The failure is a SUSPECTED transient WDDM/TDR-class measurement error inside hipEvent timing — classification against the actual driver error code is step 1 of this item, not an assumption. The current policy treats any launch/timing failure as global poison, which is correct in principle but means one transient driver hiccup discards an entire multi-hour sweep with no retry or quarantine of the affected signature.

## Steps

- Reproduce unblocked: run a full sweep without HIP_LAUNCH_BLOCKING=1 on the workstation and capture the fatal-failure class (TDR/event error code) from the log.
- Classify transient vs permanent failure modes at the hipEvent/launch layer.
- Add bounded retry with backoff for the transient class only; permanent failures keep poisoning (standards: a wrong measurement is worse than no measurement).
- Record the retry/recovery in the journal JSONL so poisoned-vs-recovered runs are distinguishable in artifacts.
- Verify: an unblocked sweep completes on the workstation, or fails with a classified permanent error, and the OFF/ON parity still holds under verify_slice_a.py.

Current state (verified): a single failed HIP timing transaction anywhere calls disable_smi_after_measurement_failure(), which sets g_tuner_poisoned AND g_smi_runtime_disabled as PROCESS-GLOBAL PERMANENT flags - one WDDM flake disables all tuning for the rest of the process lifetime, and every later unseen signature records 'tuning disabled after fatal measurement failure'. Required per GPT: (1) poison state keyed by HIP device + context generation, not process-global - a failure poisons further tuning on that device/context only, other GPUs keep tuning; (2) NO time-based auto-clear and no clear-after-one-successful-operation; (3) the tuner must never call hipDeviceReset() itself (could invalidate allocations owned by llama.cpp); (4) recovery only when the surrounding backend can PROVE the HIP context/device execution generation was recreated - this item supplies that generation/reset signal to the tuner; (5) make SMI-disable state and the cached host-sync-overhead device-local too, or a per-device poison flag leaves process-global collateral behind. The WDDM transient-fatal hardening originally described in this item and the F6 refactor share the same recovery-signal mechanism - do them as one design.
