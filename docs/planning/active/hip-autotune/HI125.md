# HI121 close-out step 4: C++-authoritative canonical signature digest verification (RV84 P0-4)

## Description

RV84 P0-4, confirmed real by dev-gpt-agent's independent investigation (2026-08-26), NOT actually closed by round-3's repeat-sighting check: inventory._resolve_signature() now rejects a LATER canonical JSON differing from the first one stored for a digest (real corruption detection), but the FIRST (digest, canonical_json) pair for any digest is still accepted on faith -- no proof the real C++ signature hash actually produces that digest. signature_capabilities.py deliberately does NOT reimplement the C++ canonical serializer/hash in Python (correct decision, reaffirmed by both reviews), but the underlying invariant -- digest D really does correspond to canonical content C -- currently has NO verification mechanism at all. A poisoned first record establishes digest D -> harmless-looking canonical C, and C becomes semantic authority for all future compatibility decisions built on it (M4's capability-gating).
