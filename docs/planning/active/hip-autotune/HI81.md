# CMAKE_HIP_FLAGS does not propagate to compile commands on Windows Ninja+Clang HIP builds

## Description

Found while validating patch 1002_hip_unsafe_math_opt_in: CMAKE_HIP_FLAGS-based options (GGML_HIP_UNSAFE_MATH, and the pre-existing GGML_HIP_EXPORT_METRICS -- same mechanism, same gap) set the CMake cache variable correctly but the flag never reaches the actual per-file compile command on Windows (`ninja -t commands` shows no trace of it, tested both -funsafe-math-optimizations and -Rpass-analysis=kernel-resource-usage). Confirmed working correctly on Linux/Brutus (same cmake invocation, same patch, flag present in the real compile command when ON). Likely a Windows-Ninja-generator-specific CMake HIP-language quirk (CMAKE_HIP_FLAGS may need to route through CMAKE_HIP_FLAGS_INIT or a per-target COMPILE_OPTIONS on this generator instead). Low urgency (Windows is a dev workstation platform, not where BigCherry ships) but means any CMAKE_HIP_FLAGS-gated option is silently a no-op on Windows today.
