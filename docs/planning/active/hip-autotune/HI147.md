# RCCL admission gate: implement level-2 per-call candidate binding

## Description

Implementation slice split from HI145 (design item). Adds exact qualified-candidate binding at patch 0830's existing per-call GGML_HIP_REDUCE_PLAN seam: once level-1 (HI146) admits a topology as RCCL-eligible, this level confirms the SPECIFIC candidate (algorithm/protocol/channel combination) being used matches one HI142's RQ08/RQ10 evidence actually qualified for that exact topology -- e.g. Ring/Simple and Tree/Simple are qualified for {0,2}/{1,2}/{0,1,2} at the real production signature; Ring/LL128 and Tree/LL128 are not (RQ08 found them UNSUPPORTED); Ring/LL is admissible-but-should-not-be-promoted (RQ10 found it ~20-30x slower, a performance exclusion not a safety one -- keep that distinction, do not conflate 'unsupported' with 'slow'). Depends on HI145's design decision and HI146's level-1 gate being in place first.

## Steps

1. Define the exact qualification key per HI142/P2.3: RCCLCompatibilityRevision + ReductionOperationSignatureV1 + TopologyIdentityV1 + candidate (algorithm/protocol/channels).
2. Implement the per-call check inside patch 0830's existing seam: before actually dispatching via RCCL, confirm the resolved candidate is qualified for the current topology+signature; if not, fail closed (do not silently fall back, per the user's original HI85 requirement -- an unqualified per-call candidate should behave the same way an unqualified topology does).
3. Encode HI142's actual RQ08/RQ10 findings as the initial qualified-candidate set for {0,2}/{1,2}/{0,1,2}: Ring/Simple and Tree/Simple qualified; Ring/LL128, Tree/LL128 not qualified (unsupported); Ring/LL technically admissible but excluded from promotion on performance grounds (a separate, explicit exclusion list, not conflated with the safety gate).
4. Tests: qualified candidate on a qualified topology passes; unqualified candidate (even on an otherwise-qualified topology) fails closed; qualified candidate on an unqualified topology never reaches this check at all (level-1 already blocked it).
5. Full patch test suite must stay green.
6. Real hardware validation: confirm the qualified candidates (Ring/Simple, Tree/Simple) actually dispatch via RCCL end-to-end on {0,2}/{1,2}/{0,1,2}, and an unqualified candidate is correctly rejected.
