# Reconcile HI29 runtime transform-record JSONL schema with the HI33 offline loader/analyze stack (producer/consumer field mismatch)

## Description

HI29's runtime writer (vendor/llama.cpp/ggml/src/ggml-cuda/hip-autotune-tuner.cu, in ggml_hip_tuner_flush()) emits `.transforms.jsonl` rows in a FLAT schema: transform-attempt `{original_sig, hardware, transformation_id (int), transformation_name, source, original_native_family, result, rejection_reason, transformed_winner, original_us, transformed_us, improvement_pct, nmse, max_abs_error}`; transform-gap `{sig, hardware, native_family, est_bytes, transformations_tried:[{id, reason}]}`.

But the offline analysis stack built under HI33 (tools/bigcherry/transform_records.py -> load_transform_records, consumed by BOTH transform_loader.py:load_transforms AND analyze_gaps.py) REQUIRES a NESTED schema: `hardware_provenance` (object), `build_provenance` (object), `source_signature` (HEX32), `evidence_references` (non-empty list), `transformation` (object {id, name, source}), `outcome` (success|rejected), `reason`; gap rows need `source_signature` + non-empty `transformations_tried`.

Running REAL HI29 output through either load_transforms() or analyze_gaps() therefore raises TransformRecordError (missing hardware_provenance/build_provenance/evidence_references/source_signature, `transformation` is not an object, `outcome` missing). The record->SQLite and record->agent-analysis pipelines are NOT demonstrated end-to-end against real runtime artifacts, even though both halves pass their own offline tests. The audit (BigCherry_active_plan_audit_2026-08-23) and both cards missed this: HI29's stale note calls the loader 'still-unlisted/uncreated' (HI33 completed 2026-08-13, a week before HI29's runtime work), and neither noticed the schema divergence.

## Steps

- Decide the authoritative schema (likely the nested provenance one, since the offline stack + its 11 tests already target it; but first confirm whether the runtime flush can actually supply build/hardware provenance + evidence_references at flush time).
- Either (a) extend the runtime writer to emit the nested provenance schema, or (b) add a normalizing adapter in transform_records.py that maps the flat runtime schema to the nested one. Prefer whichever keeps the runtime flush simple and leaves exactly ONE authoritative schema.
- Add an end-to-end test: a fixture .transforms.jsonl in the REAL runtime (flat) shape is ingested by load_transforms() AND analyze_gaps() without TransformRecordError, producing the expected transform_attempt/transform_gap rows.
