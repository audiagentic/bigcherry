# Tuner config X-macro: single source of truth for env overrides + header emission (HI96A)

## Description

Split out of HI96 (2026-08-23, plan-hygiene, audit §5.10 HI96A). This is the real correctness/provenance improvement of the three concerns and must not be blocked on the optional telemetry or cache-UX concerns.

Scope: GGML_HIP_TUNER_CONFIG_FIELDS X-macro generating BOTH the env-override block and the header emission from one field list, so a new tuning knob cannot be added without being recorded. This closes the specific failure mode that invalidated RV01-RV05 and recurred when the `compiler` knob was dropped for weeks.

Key design constraint (reassessed 2026-08-23): this is a real, careful refactor, not a mechanical drop-in. The ~20 existing env-override lambdas each carry bespoke per-field min/max validation bounds (e.g. FINAL_SAMPLES 2..100000, ALPHA 0.0..1.0, NOISE_PCT 0.0..max), which a simplified F(type,name,env) macro sketch does not account for. Design the macro to carry bounds too (e.g. F(type, name, env, min, max)) BEFORE attempting the mechanical rewrite of every existing call site.

## Steps

- Design the X-macro to carry per-field bounds: F(type, name, env, min, max), covering all ~20 existing bespoke bounds.
- Generate both the env-override block and the header emission from the single field list.
- Mechanically rewrite every existing env-override call site against the macro.
- Add a test asserting the header's config key set equals the macro's field set, so the omission class that recurred with `compiler` is caught mechanically.
