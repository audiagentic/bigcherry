# Diagnostics are not zero-cost: enabled() does an atomic RMW on every call

## Description

dispatch_counters_enabled() and native_select_timing_enabled() both execute `checked.exchange(true)` on EVERY invocation, not only the first. exchange is an unconditional atomic read-modify-write, i.e. a WRITE to a shared cache line, so every call from every thread takes exclusive ownership of that line -- purely to discover that diagnostics are disabled. They are called several times per dispatch (native_select, make_hardware_key, dispatch_resolve, both sampling checks).

The comment above DispatchCounters claims 'Zero cost when disabled: every increment site below is guarded by dispatch_counters_enabled(), never unconditional'. The guard is real; the claim that it is zero-cost is false, and it is false in the specific way that matters most -- a contended write rather than a read.

Found by dev-gpt-agent (req_6075d7c2055c4aa2) while auditing production hot-path overhead; it rates this above the coverage atomics and well above the make_signature memset as the thing to fix first.

Separately, ggml_hip_coverage_count_executed/dispatched do two relaxed fetch_adds per dispatch on contiguous per-family atomics (false-sharing candidate) and are NOT gated at all -- GGML_HIP_DISPATCH_COVERAGE only controls whether a report is written. These cannot explain the replay-vs-control delta (both arms pay them) and the framework-vs-stock measurement of ~0.0% argues they are not costing 2% on this workload, but they are diagnostics and should compile out when unused.

## Steps

1. Replace the checked/enabled atomic pair in both enabled() functions with a function-local static const bool initialised from a lambda -- a magic static is initialised exactly once, thread-safely, and afterwards costs a guard load, not an RMW.
2. Audit every other *_enabled()/should_sample_* helper in the dispatch and tuner translation units for the same pattern.
3. Fix the false 'Zero cost when disabled' comment to say what is actually true.
4. Make coverage counting compile out when the build does not want it, rather than always-on.
5. Measure: this is a host-side CPU change, so tg (decode, dispatch-bound) is where it can show. Use the balanced harness; do not claim a win from the counter change alone.
