# bigcherry profile-campaign: rocprofv3-based repeatable GPU/runtime deep-profiling command

## Description

Add `bigcherry profile-campaign`: a real, repeatable deep-profiling orchestrator built on rocprofv3 (--sys-trace --rccl-trace), following the exact tune-campaign/patch_validation_campaign architecture (CampaignRequest -> plan() -> run_campaign() for the real build, ServerRunner for real server lifecycle). CPU call-graph profiling via perf is deliberately out of scope here (see HI133) -- the report always includes a `cpu: unavailable` field rather than failing.

## Steps

1. ServerRunner gains `command_prefix` so a profiler (rocprofv3, later perf) can wrap the real server launch without duplicating lifecycle/health/shutdown handling.
2. profiling/schema.py: typed ControlBlock/KernelStat/GpuProfilePass/CpuProfilePass/ProfileReceipt/ProfileReport dataclasses.
3. profiling/rocprof.py: real rocprofv3 command-prefix builder + CSV parser (kernel_trace.csv -> aggregated KernelStat rows) + multi-GPU/RCCL capture validation, failing closed to `incomplete_multi_gpu_capture` rather than silently PASSing a partial capture.
4. profiling/control.py: unprofiled control blocks (real wall-clock tokens/sec measurement against a real running server, no dependency on the server's own /completion timings field shape).
5. profiling/workflow.py: the real orchestrator -- build lane -> control A -> GPU pass 1 -> control B -> control C (CPU-1 slot, unavailable) -> control D (CPU-2 slot, unavailable) -> GPU pass 2 -> control E -> environment-drift check (>5% spread across control means marks the run `environment_stable=False` -- profiling artifacts stay usable diagnostically, but no comparative conclusion is drawn) -> profile-receipt.json/profile-report.json/profile-report.md.
6. cli/profiling.py + main.py wiring: `bigcherry profile-campaign --platform ... --model ... --devices ... --runtime-profile ... [--control-reps 10] [--profile-passes 2]`.
7. Offline tests: CSV parsing (real column layout confirmed against a real rocprofv3 run on Brutus this session), multi-GPU/RCCL capture-status logic, report rendering, control-block wall-clock math -- 14 new tests, all passing, no GPU required.

## Notes

Design settled via an aggressive gpt negotiation (session ses_fec603fc33ee4089, req_c3ff203a1d4b40c5 round 1 + req_8d0cd9d969314e31 round 2, 2026-08-27) -- round 1's recommendation (rocprofv3 + perf, --repeats 3) was pushed back on with real, VERIFIED gaps (perf is actually broken on Brutus: kernel/package mismatch, confirmed via direct `perf --version`; repeats=3 wasn't justified against this project's own measured noise floor). Round 2 corrected itself where the pushback was itself wrong (perf_event_paranoid=2 does NOT need a system-wide change for our use case -- gpt caught this, not me) and landed the final settled design: rocprofv3 mandatory, perf reserved as HI133, `--control-reps 10`/`--profile-passes 2` (statistically justified against the session's own established floor, not arbitrary), interleaved controls around every profiler pass, never running two profilers in the same launch.

First real validation target identified (not yet run): the CPU-sampler-serialization question from earlier this session (does `llama_synchronize()` + CPU-side MTP sampling serialize meaningful decode time under `-sm tensor`). rocprofv3's own HIP-runtime timestamps can show WHETHER a host-only gap exists around sync calls even without perf; only the WHAT-is-running-during-the-gap attribution needs HI133.
