# Emit intrinsically-complete nested provenance from the C++ runtime transform writer (retire the flat adapter)

## Description

HI97 (completed, be9590f + 023951e, reviewed by the GPT dev agent) landed an explicit adapter (load_runtime_transform_records / load_artifact_records header dispatch) so the flat runtime .transforms.jsonl the C++ tuner writes can ingest without fabricated identity. The agreed design treated this as acceptable-but-transitional: the flat schema cannot carry architecture or build_descriptor_hash, so flat records run with provenance_complete=False and SQLite ingestion must resolve build identity from the DB (failing closed on zero or ambiguous matches).

The permanent fix is on the writer side: make the runtime emit the nested, intrinsically-complete schema (header + per-record hardware_provenance including architecture, build_provenance including build_descriptor_hash, evidence_references) so every record is self-describing and the DB-identity-resolution path becomes unnecessary. The build descriptor hash is computable at runtime (it is part of the manifest the tuner already loads); the architecture is the device string the tuner already formats; evidence references can start as a per-flush artifact reference.

## Steps

- Compute/verify the build descriptor hash at the tuner flush site (cross-checked against the offline manifest computation on a shared fixture).
- Switch the transforms flush to the nested layout (header transform_schema_version; per-record hardware/build provenance incl. architecture + build_descriptor_hash; evidence references starting as a per-flush artifact reference).
- Offline test: nested runtime-shaped artifact ingests via load_transforms() and analyze_gaps() with provenance_complete=True.
- Ship the writer change with hardware validation on a real device; ingest a real nested artifact.
- Separate follow-up: retire the flat adapter once no flat artifacts can exist (fail-closed rejection of the old flat header until then).

## Detailed Solution & Technical Design

1. In the C++ tuner's transforms flush (hip-autotune-tuner.cu, the fprintf block that writes header/transform-attempt/transform-gap), switch to the nested layout the offline stack already treats as authoritative: header with transform_schema_version; per-record hardware_provenance {digest, architecture} and build_provenance {source_revision, manifest_hash, build_descriptor_hash}.
2. Compute the build descriptor hash from the same manifest inputs the portable cache uses (keep the two identities byte-identical so a build recorded by either artifact binds to the same DB build row).
3. Extend the offline test fixtures: a nested runtime-shaped artifact (runtime origin, complete provenance) ingests through load_transforms() and analyze_gaps() with provenance_complete=True.
4. Only after the writer change ships and at least one real nested runtime artifact has ingested cleanly, retire the flat adapter (load_runtime_transform_records, the flat branches in _resolve_build_id, runtime-flat-v1 handling) in a separate item, keeping a version-fail-closed rejection of the old flat header until artifacts with it can no longer exist.
