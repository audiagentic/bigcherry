# Dispatch integration — use transformed winner at runtime with zero overhead when no transform applies

## Description

At dispatch time, if a stored binding includes a transformation (from HI30's tuning result), apply the transformation before launching. The binding carries: candidate + variant + transform_id + inverse writeback mapping.

The dispatch flow:
1. ggml_hip_dispatch_mul_mat() receives original launch context
2. Look up binding — if it includes a transformation, apply it to produce transformed launch context
3. Launch the candidate with transformed launch context
4. If inverse writeback is needed (e.g., batch_for_mmvf writes to sliced dst), apply it after launch

Key constraint: the transformation must be applied at dispatch time with zero overhead when no transform applies — this means the fast path (no transform) is unchanged, and only signatures with stored transformed bindings go through the transform path.

// hip-autotune-dispatch.cu — extended dispatch launch:
void ggml_hip_dispatch_launch(const ggml_hip_resolved_dispatch & bound,
                              const ggml_hip_launch_context & lc_in) {
    GGML_ASSERT(bound.candidate != nullptr);
    GGML_ASSERT(bound.candidate->launch != nullptr);

#ifdef GGML_HIP_ROUTING_TRANSFORM
    if (bound.transform_id != GGML_HIP_TRANSFORM_NONE) {
        const auto * xform = ggml_hip_transform_find(bound.transform_id);
        GGML_ASSERT(xform != nullptr);

        // Re-derive signature from current tensors.
        auto sig = ggml_hip_make_signature(lc_in.src0, lc_in.src1,
                                           lc_in.ids, lc_in.dst, nullptr);

        ggml_hip_dispatch_signature_v1 trans_sig = {};
        ggml_hip_launch_context trans_lc;
        void * inverse_ctx = nullptr;

        int rc = xform->apply(sig, &trans_sig, &trans_lc, &inverse_ctx);
        if (rc != 0) {
            static std::once_flag once;
            std::call_once(once, [&bound]() {
                GGML_LOG_WARN("bigcherry: transform %d failed at dispatch "
                              "for candidate %s — falling back to native\n",
                              bound.transform_id,
                              bound.candidate->stable_name);
            });
            // Fall back: launch with original context.
            // We need the native candidate — but we only have the transformed one.
            // For safety, re-resolve from scratch (cold path).
            return;  // caller handles fallback
        }

        if (xform->id == GGML_HIP_TRANSFORM_BATCH_FOR_MMVF) {
            // Batch iteration dispatch.
            auto * bctx = reinterpret_cast<batch_inverse_ctx *>(
                bound.inverse_ctx ? bound.inverse_ctx : inverse_ctx);
            for (int batch = 0; batch < bctx->num_batches; ++batch) {
                int64_t start = batch * bctx->batch_size;
                int64_t end = std::min(start + bctx->batch_size, bctx->total_n);

                ggml_hip_launch_context batch_lc = trans_lc;
                // Offset src1 and dst pointers by 'start' columns.
                // ... (pointer arithmetic based on strides)
                bound.candidate->launch(bound.candidate, batch_lc);
            }
        } else {
            bound.candidate->launch(bound.candidate, trans_lc);
        }

        if (xform->inverse && inverse_ctx) {
            xform->inverse(sig, lc_in, inverse_ctx);
        }
        return;
    }
#endif

    // Fast path: no transform.
    bound.candidate->launch(bound.candidate, lc_in);
}

## The Problem

When the tuner installs a transformed winner, the binding stored in `g_bindings` must carry enough information for dispatch to:
1. Apply the transformation at runtime (produce the transformed launch context)
2. Launch the candidate with that context
3. Write back results if needed (inverse)
4. Fall back to native if something goes wrong at runtime

## Binding Extension

The existing `Binding` struct is minimal — it just holds a candidate + variant. We need to add transform information.

**Approach: versioned binding.** We extend the struct with new fields that are null/zero when no transform applies. The process cache key (dispatch_digest) doesn't change — we're storing a different value under the same key, not a new key.

```c
struct Binding {
    const ggml_hip_candidate_descriptor * candidate;
    ggml_hip_variant_params               variant;
    bool                                  from_cache;

#ifdef GGML_HIP_ROUTING_TRANSFORM
    // Transform info — null/zero when no transform applies (fast path).
    ggml_hip_transform_id                 transform_id;   // 0 = none
    const ggml_hip_routing_transformation * transform;    // pointer to registry entry
    void *                                inverse_ctx;    // opaque writeback data
#endif
};
```

When `transform_id == 0`, the fast path skips all transform logic — zero overhead.

## Dispatch Flow

In `ggml_hip_dispatch_resolve()`, when a cached binding is found, the dispatch layer checks:
1. If `binding.transform_id != 0`: apply transformation before launch
2. If `binding.transform_id == 0`: fast path — launch normally

```c
void ggml_hip_dispatch_launch(const ggml_hip_resolved_dispatch & bound,
                              const ggml_hip_launch_context & lc_in) {
    GGML_ASSERT(bound.candidate != nullptr);

#ifdef GGML_HIP_ROUTING_TRANSFORM
    if (bound.transform_id != GGML_HIP_TRANSFORM_NONE) {
        // Apply transformation.
        ggml_hip_dispatch_signature_v1 trans_sig = {};
        ggml_hip_launch_context trans_lc;
        void * inverse_ctx = nullptr;

        const auto * xform = ggml_hip_transform_find(bound.transform_id);
        GGML_ASSERT(xform != nullptr); // if we got here, it should exist

        // Re-derive the signature from the current tensors.
        auto sig = ggml_hip_make_signature(lc_in.src0, lc_in.src1,
                                           lc_in.ids, lc_in.dst, nullptr);

        int rc = xform->apply(sig, &trans_sig, &trans_lc, &inverse_ctx);
        if (rc != 0) {
            // Transform failed at runtime — fall back to native.
            // This should not happen for PREDEFINED transforms,
            // but DISCOVERED transforms might have edge cases.
            GGML_LOG_WARN("bigcherry: transform %d failed at dispatch, "
                          "falling back to native\n", bound.transform_id);
            // Launch with original context and native candidate.
            bound.candidate->launch(bound.candidate, lc_in);
            return;
        }

        // Launch the transformed path.
        bound.candidate->launch(bound.candidate, trans_lc);

        // Inverse writeback if needed.
        if (xform->inverse && inverse_ctx) {
            xform->inverse(sig, lc_in, inverse_ctx);
        }

        // Clean up inverse_ctx if it was allocated.
        if (bound.inverse_ctx) {
            delete reinterpret_cast<batch_inverse_ctx *>(bound.inverse_ctx);
        }
        return;
    }
#endif

    // Fast path: no transform.
    bound.candidate->launch(bound.candidate, lc_in);
}
```

## Correctness Fallback at Runtime

If `can_execute` fails at dispatch time (shape changed, device mismatch), the fallback is:
1. Log a one-shot warning
2. Launch with the native candidate instead
3. The binding remains cached — next time, same thing happens
4. If this is a persistent issue (wrong transform for this shape), the user needs to re-tune

This is **not** a re-tuning trigger — re-tuning only happens in tune mode.

## Cache Serialization

The process cache (`g_bindings`) is an in-process `unordered_map`. It doesn't survive process restart. The replay cache (binary file) is separate and managed by HI31's replay module — that also needs to store transform_id.

**Replay cache format change:** The replay cache stores `(dispatch_digest → candidate, variant)` pairs. With transforms, it needs `(dispatch_digest → candidate, variant, transform_id)`. This requires a version bump in the replay cache format and backward compat handling (old caches without transform_id are read with transform_id=0).

## Workspace Considerations

The transform's `overhead_bytes` is included in workspace calculation. The tuner already checks `max_workspace_bytes` against candidate workspace — we add the transform overhead:
```c
m.workspace_bytes = candidate->workspace(c, trans_sig)
                  + xform->overhead_bytes(trans_sig);
```

This ensures batch transforms that need extra workspace are properly bounded.
