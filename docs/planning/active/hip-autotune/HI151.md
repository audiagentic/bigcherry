# tree-activity lease/maintenance-lock protocol

## Description

Foundational for HI150 (pin-bump orchestrator). New host-local liveness protocol under ProjectContext.work_root so pin-bump can refuse to touch a tree that's actively in use by another process/session, closing the real gap found during the b10502->b10680 bump test (Brutus's configured campaign tree had clean-enough git state but two active experiment log tails from a concurrent session -- git status alone would not have caught this).

Design (converged with gpt, see HI150 notes):
- `<work_root>/tree-activity/<hash(project_root)>/maintenance.lock` -- exclusive; pin-bump (or any maintenance operation) acquires this only if no live leases exist.
- `<work_root>/tree-activity/<hash(project_root)>/leases/<uuid>.json` -- one file per active long-running operation: {pid, hostname, command, run_id, project_root, started_at}.
- Long-running runners (build, campaign-build, tune-campaign, profile-campaign, experiment/validation runners) create a lease on start and remove it on exit (including on crash via atexit/finally where feasible).
- New long-running work refuses to start while maintenance.lock is held.
- Staleness is decided ONLY by real PID liveness on that host (os.kill(pid, 0) / psutil-equivalent) -- never silently break an apparently-live lease just because it looks old.
- Transition period: not every runner will be lease-aware immediately. Provide a diagnostic-only (never authoritative) fallback that scans /proc/*/cwd and /proc/*/cmdline on Linux for other processes whose cwd/cmdline references the configured tree path, excluding the calling process's own ancestry -- surfaced as a warning, not a hard gate, until lease adoption is complete.

## Steps

1. Add tools/bigcherry/core/tree_activity.py: acquire_maintenance_lock(project_root), Lease context manager (write on enter, remove on exit, handles crash via try/finally), list_active_leases(project_root) with real PID-liveness filtering of stale entries, and the /proc-scan diagnostic helper (Linux-only, no-op elsewhere).
2. Wire Lease acquisition into the existing long-running entry points (campaign/build.py, campaign/lane.py's run paths, tune-campaign, profile-campaign) -- minimal: acquire on start, release in a finally block.
3. Unit tests: lease written/removed correctly, maintenance lock refuses acquisition with a live lease present, stale (dead-PID) leases are ignored/cleaned up, live leases are never overridden.
4. Do NOT block on 100% runner adoption -- ship the protocol and wire the highest-value entry points first (build/campaign-build, tune-campaign), track remaining adoption as follow-up.
