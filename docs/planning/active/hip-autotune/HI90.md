# Graph-lifecycle trace markers (patch 1231) invisible below llama-server -lv 4

## Description

Real-hardware finding from HI14's 2026-08-23 capture-lifecycle closure run, split out so the fix doesn't get lost inside HI14's own long history.

patches/1231_hi14_graph_capture_lifecycle_evidence.py emits its BIGCHERRY_GRAPH_LIFECYCLE stage=... markers via raw GGML_LOG_INFO(...) calls in ggml-cuda.cu. Traced through vendor/llama.cpp/common/log.cpp: llama-server's common_get_verbosity() maps a raw ggml GGML_LOG_LEVEL_INFO message to LOG_LEVEL_TRACE (4), and common_log_default_callback() drops it unless the server's verbosity threshold is >= 4 (i.e. `-lv 4` or higher). Default server verbosity is 3. So at any normal production verbosity, these markers are silently invisible -- confirmed on real hardware: a genuine graph-capturing run at default verbosity produced zero BIGCHERRY_GRAPH_LIFECYCLE log lines even though the server's own 'graphs reused = N' counters proved graphs were actually captured and replayed; the identical run at `-lv 4` produced all four expected markers cleanly.

This is not a functional bug (graphs work fine; the counters prove it) -- it's an observability gap in evidence-collection tooling that was written to be checked, and would otherwise require anyone reproducing this evidence to already know to pass -lv 4, which is undocumented anywhere in HI14's design notes or the patch itself.

## Steps

- Decide the right fix: switch the markers to GGML_LOG_WARN (visible at default verbosity, same as the pre-existing NCCL heterogeneous-arch guard's warnings) even though these aren't warnings semantically, OR keep GGML_LOG_INFO but document -lv 4 as a hard requirement everywhere this evidence-collection procedure is described (this item's own description, HI14's notes, any operator runbook), OR add a llama-server-independent sink (e.g. a distinct env-gated file writer) that doesn't route through llama-server's verbosity-filtered logger at all.
- Whichever fix is chosen, re-verify on real hardware that markers appear reliably without needing to raise verbosity, or that the -lv 4 requirement is clearly documented at every place this procedure could be repeated.
