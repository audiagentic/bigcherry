# Complete release gate and architecture-specific coverage validation

## Description

Replace overclaimed release validation with an explicit state-machine gate and close architecture-specific catalog/build coverage for gfx1030, gfx1100, and gfx1201.

## Steps

- Define prepare/validate states for audit, patch, generate, build descriptor, record/tune/promote/replay, and coverage evidence.
- Keep compatibility probing separate from the full production release gate.
- Add architecture mapping and CMake target-set tests for all shipped targets.
- Run the gate against a bounded Brutus artifact and record each failure class.
- Produce real record/tune/promote/replay coverage for gfx1030, gfx1100, and gfx1201 before closure.

## Detailed Solution & Technical Design

Validated claims now carry production_gate with a required architecture set and ordered stage map. Each stage progresses pending -> prepared -> validated (or failed), requires ok=true and non-empty evidence references when validated, and later stages cannot be validated after an incomplete earlier stage. Compatibility probe records remain compatible-only and do not enter this gate.
