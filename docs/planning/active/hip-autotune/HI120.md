# Harden signature coverage for RD12 dst_gate and RD17 x_scale_channel_dst fusion modes

## Description

dev-gpt-agent deep review of HI118 (2026-08-25, commit 2ef2dfa) found two real, non-blocking gaps in the fusion-field presence flags HI118 added, both specific to experimental non-default patches rather than the upstream GLU-fusion case HI118/HI119 actually target:

1. RD12 (patches/rd/1205_rd12_paired_mmvq_dual_output) adds a `dst_gate` field to ggml_cuda_mm_fusion_args_host and a real fused dispatch mode (gate set, dst_gate set, glu_op == GGML_GLU_OP_NONE) that DOES reach ggml_hip_dispatch_mul_mat/family and gets signed today. It is not silently aliased with a real GLU signature (GLU's own glu_op is never NONE), but the signature currently distinguishes it only via the implicit invariant 'fusion == GATE with glu_op == NONE means RD12' rather than an explicit flag -- fragile if a second glu_op==NONE fusion mode is ever added.

2. RD17 (patches/1207_rd17_moe_topk_down_fold.py) changes x_scale's real semantics via an `x_scale_channel_dst` mode: scale length becomes dst->ne[1] (not the upstream NVFP4-only n_expert/1 sizing), can apply to non-NVFP4 types, and is indexed by destination channel instead of expert. HI118's GGML_HIP_SIG_FUSION_X_SCALE flag only records presence, not which semantic mode is active -- a real repo-wide completeness gap if RD17 is ever promoted out of untested/experimental status.

## Steps

1. If/when RD12 is promoted toward production use: add an explicit GGML_HIP_SIG_FUSION_DST_GATE-equivalent flag (patch-conditional, only compiled when RD12 is applied -- see hip-autotune-signature.cpp's existing pattern for handling patch-conditional fusion fields) rather than relying on the GATE+NONE inference.
2. If/when RD17 is promoted toward production use: add a flag or field distinguishing x_scale_channel_dst mode from the upstream NVFP4 n_expert/1 sizing, and record dst->ne[1] (or the field needed to reconstruct the real scale array length) for that mode.
3. Neither is needed for HI119's initial upstream-GLU-fusion-only scope -- do not block HI119 on this item.
