### gpt design round complete + independently verified (2026-08-29)

gpt agreed with the two-level split, with real refinements. Verified two of its factual claims myself against real source/hardware (both checked out):

1. **GGML_CUDA_P2P/cudaDeviceCanAccessPeer already exists in the pinned source** (ggml-cuda.cu lines 417/425, 647-667) -- confirmed by direct grep. Peer-access querying is cheap but not currently cached for admission-gate use.

Strong empirical validation for the whole gate design.

**Real, honest gap gpt also caught**: HI142's P2.6 correctness proof ran `test-hip-reduce --plan rccl` WITHOUT setting RCCL_OVERRIDE_ALGO/RCCL_OVERRIDE_PROTO -- so it used RCCL's own auto-selected algorithm, not an explicitly forced Ring/Simple candidate. The correctness evidence should be described as 'RCCL's auto-selected algorithm for this signature/topology is proven correct', NOT 'Ring/Simple is proven correct' -- HI147 (level-2 candidate binding) must not encode Ring/Simple as verified-correct without re-running P2.6 with that specific candidate explicitly forced, or re-deriving which algorithm RCCL actually chose during the original P2.6 runs (check the result JSON's -M1-equivalent fields / NCCL_DEBUG=INFO output if re-derivable from existing artifacts, before assuming).

### Settled design (record for HI146/HI147/HI148 to consume)

**TopologyIdentityV1 (MVP, deliberately minimal)**:
- participant_count
- per-node: {arch_class (from ggml_cuda_info().devices[id].cc), host_native_atomic_supported (from hipDeviceAttributeHostNativeAtomicSupported, NEWLY QUERIED -- not currently cached anywhere)}
- directed edges: {peer_access} (from cudaDeviceCanAccessPeer, already queried elsewhere in the source under GGML_CUDA_P2P but not currently reused for this purpose)
- Do NOT reuse rccl_qualify.py's RcclTopology.topology_id as-is -- it's only ordered architecture strings, lacks the atomic/peer facts.
- Do NOT invent a full PCIe root/NUMA transport class -- not currently available anywhere in ggml_cuda_info()/comm_ctx; add only if real evidence later requires it.

**Admission mechanism: runtime-loaded qualification manifest, NOT a static source allowlist.** Static allowlists would turn Brutus-only evidence into global compiled policy and require rebuilds per box. Env var path: GGML_HIP_RCCL_QUALIFICATION_MANIFEST=/path/to/manifest.json. Minimal schema (schema_version, rccl_compatibility_id, communicator_admissions[] keyed by topology_id, bindings[] keyed by topology_id+operation+candidate) -- see gpt's full JSON example in this round's response. Keep topology and operation identity structurally separate even though telemetry has a convenience combined signature key.

**Gate placement confirmed correct, with one important semantic fix to 1225's CURRENT behavior**:
- Level 1 (HI146): at ggml_backend_cuda_comm_init_nccl(), immediately before ncclCommInitAll(). BUT: an unqualified communicator should NOT necessarily hard-abort -- it should mark RCCL unavailable and preserve the safe META/internal path. Then plan=meta -> safe META; plan=auto -> safe fallback; plan=rccl (explicit force) -> fail-closed error. This fixes a real flaw in 1225's CURRENT behavior: even an explicit GGML_HIP_REDUCE_PLAN=meta deployment can be killed by 1225's blunt abort before the per-call selector ever runs -- worth confirming this is genuinely how current 1225 behaves before HI146 assumes it as the bug to fix.
- Level 2 (HI147): per-call, immediately before ggml_backend_cuda_comm_allreduce_nccl(), at/adjacent to patch 0830's existing GGML_HIP_REDUCE_PLAN seam -- this is the only place exact operation signature (dtype/count/shape) is actually available. Candidate binding cannot live at comm-init.
- Compatibility identity needs NEW plumbing -- current init context has no RCCL source SHA/build-config identity at all. Manifest admission must fail if the qualified RCCL compatibility revision can't be matched, not just topology.

**Minimum honestly-shippable v1 slice (gpt's explicit scope-down, adopted)**:
- Replace 1225's raw abort with: host-native-atomic prerequisite + cached topology identity + exact manifest lookup for heterogeneous admission; preserve existing homogeneous behavior unchanged.
- Extend 0830's seam: exact operation match + exact candidate match, only then call RCCL; missing binding -> auto falls to META, forced rccl fails closed.
- Support ONLY the currently-proven dimensions: allreduce/sum/f32, the exact production shape/count, algorithm+protocol (channels=null, chunk_size=null -- rccl_qualify.py's own channels field isn't even applied by build_command() today, confirmed).
- Explicitly OUT of v1 scope: tuner plugin, fuzzy matching, cross-box universal allowlist, PlacementIdentityV1, richer PCI topology discovery.

**Two blockers before HI146/HI147 write any code** (per gpt, both now partially addressed):
1. Validate hostNativeAtomicSupported on Brutus -- DONE, confirmed above (0/1/2=1, device3=0).
2. Bind the existing P2.6 correctness evidence to its ACTUAL algorithm/protocol candidate -- NOT DONE, real open item (see the honest gap noted above). HI147 must resolve this before encoding any specific candidate as 'verified'.
