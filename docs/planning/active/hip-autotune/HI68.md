# Canary retry becomes a stability probe; one fresh complete finalist block is the sole ranking dataset

## Description

Canary retry must not replace final-stage statistics (F2, P0): the noise-canary retry self-selectively swaps native's and twin's ranking statistics to a fresh draw while other finalists keep original-block stats, mixing two measurement blocks in one decision. Fix with a stability-probe + one fresh complete finalist block.

## Steps

1. Extract the canary transition logic into a GPU-free, host-compilable header `hip-autotune-canary.h` (pure `(stage, native_us, twin_us, threshold, retries) -> verdict`; no hip/ggml include).
2. Define the three-stage state machine: INITIAL -> (pass) RANK | (fail + budget) PROBE | (fail, no budget / unmeasurable) UNRESOLVED; PROBE -> (pass) FRESH | (fail) UNRESOLVED; FRESH -> (pass) RANK(retried_pass) | (fail) UNRESOLVED. The FRESH stage has NO retry branch by construction.
3. In the tuner, replace the old `for (attempt ...)` retry loop: on a failed initial canary run ONE pair-only stability probe whose statistics are DISCARDED; only if it passes, re-measure one complete finalist block via the extracted `measure_finalist_block` unit (same interleaving/counterbalance/retime as the normal final stage).
4. Extract the post-block scrutiny (E4 noisy + native-baseline checks) into `post_block_reject_reason` and run it after EVERY block that becomes the ranking dataset, including the fresh one.
5. Record `canary_fresh_block` on the result and serialize it in the result JSON so offline readers know which measurement window covers the ranked medians.
6. Pin the behavior with a real host-compiled C++ transition-table test plus source contract tests.

## Detailed Solution & Technical Design

DEFECT (verified in ggml_hip_tuner_resolve, canary block): when the first native-vs-twin canary check exceeds noise_canary_pct and retries remain, the pair is re-measured and native's AND twin's median_us/mad_us/p95_us/host_median_us/samples are OVERWRITTEN with retry-only statistics, while their final_gpu_us arrays are NOT replaced. Downstream policy ranking then uses retry-only effective_us for the pair but original-block effective_us for every other finalist, and paired_sign_test still reads the original final-stage arrays - two different measurement blocks inside one decision, triggered self-selectively because things looked noisy.

REQUIRED FLOW (GPT-adjudicated in RV49; neither replace-pair nor pool-pair): (1) measure the complete finalist block normally; (2) evaluate its canary; (3) if it fails, run the pair-only retry STRICTLY as a stability probe; (4) if the probe still fails: UNRESOLVED, retain native; (5) if the probe passes: perform ONE fresh COMPLETE finalist block containing every finalist - that fresh block is the SOLE ranking dataset, its canary evaluated once with NO further retry (do not retry it until quiet). The QC-failed original block is discarded for ranking. Rationale: pooling only native+twin would give them more observations over a different time window than other finalists; pooling the whole original block is defensible but that block is precisely the one whose QC failed. Confirmation is independent (fresh rounds) so it is not directly contaminated, but this fix changes WHICH candidate reaches confirmation - exactly the quantity HI65-style experiments measure.

EXTRACTION (F5 per RV49): make the canary transition logic a CPU-testable function over a FinalRoundBlock/CanaryOutcome type so this behavior is pinned by direct unit tests, not Python source-text contract tests. Avoid one giant mutable RunState - extract semantically closed units only.

## Code Samples & Guidance

Transition header (GPU-free, `src/ggml/src/ggml-cuda/hip-autotune-canary.h`):

```cpp
inline ggml_hip_canary_verdict ggml_hip_canary_transition(
        ggml_hip_canary_stage stage, double native_us, double twin_us,
        double threshold_pct, int retries_allowed) {
    ggml_hip_canary_verdict v;
    v.pct = ggml_hip_canary_divergence_pct(native_us, twin_us);
    v.passed = (v.pct >= 0.0) && (v.pct <= threshold_pct);
    switch (stage) {
        case GGML_HIP_CANARY_STAGE_INITIAL:
            if (v.passed)                v.next = GGML_HIP_CANARY_RANK;
            else if (v.pct < 0.0)        v.next = GGML_HIP_CANARY_STOP_UNRESOLVED; // unmeasurable: fail closed
            else if (retries_allowed > 0) v.next = GGML_HIP_CANARY_RUN_PROBE;
            else                          v.next = GGML_HIP_CANARY_STOP_UNRESOLVED;
            break;
        case GGML_HIP_CANARY_STAGE_PROBE:
            v.next = v.passed ? GGML_HIP_CANARY_RUN_FRESH : GGML_HIP_CANARY_STOP_UNRESOLVED;
            break;
        case GGML_HIP_CANARY_STAGE_FRESH:
            // Terminal by construction: no retry-until-quiet branch exists.
            v.next = v.passed ? GGML_HIP_CANARY_RANK : GGML_HIP_CANARY_STOP_UNRESOLVED;
            break;
    }
    return v;
}
```

In-tuner fresh-block path (abridged): the probe pushes only local `probe_native/probe_twin` vectors (never writes back into any `Measurement`); on `RUN_FRESH` it calls `measure_finalist_block()`, re-runs `post_block_reject_reason()`, then evaluates the canary once on the fresh medians with a zero budget and sets `result.canary_fresh_block = true`.

## Evidence-Integration Fix Record (GPT follow-up, RV49/F2)

GPT's adjudication of the HI68 implementation: **RV49/F2 (the ranking-safety defect) is CLOSED** - the core three-stage flow (stability probe + one fresh complete finalist block as the sole ranking dataset) is correct. Two P1 evidence-integration gaps had to be fixed before full closure:

1. **P1 - promotion validator re-encoded the old protocol assumption.** `tools/bigcherry/tune_promotion.py::validate_adaptive_evidence` still carried `canary_state == "unresolved" and retries < 1: raise`, which rejects a state HI68 now makes legal: an initial canary failure with `noise_canary_retries=0` goes straight to UNRESOLVED with `retries=0`. The old line encodes the pre-HI68 belief that "unresolved implies a retry happened". Fixed by replacing it with the producer's **legal terminal-state matrix** over the `(canary_state, canary_retries, canary_fresh_block)` triple - the same transition table the C++ state machine implements:
   - legal: `not_available/0/false`, `pass/0/false`, `unresolved/0/false` (probe disabled by config), `unresolved/1/false` (probe failed, original block retained diagnostically), `retried_pass/1/true` (fresh complete block ranked), `unresolved/1/true` (fresh block canary failed, terminal, native retained);
   - legacy: a pre-HI68 row lacking the `canary_fresh_block` field with state `retried_pass` is accepted on that basis only (the old pair-replacement semantics); any other triple raises.
   The flag is also type-guarded to bool when present, so a non-bool cannot sneak past.

2. **P1/P2-evidence - provenance set too late on fresh-block early-return paths.** In the tuner, `canary_fresh_block` and the terminal `canary_state` were assigned *after* the E4 post-block scrutiny (`post_block_reject_reason`) on the fresh-block path. A row rejected by that scrutiny therefore serialized **fresh statistics but `fresh_block=false` / `state=not_available`** - contradictory provenance: an offline reader could not tell which measurement window the medians in that row cover. Fixed with **pessimistic terminal-state ordering** in `ggml_hip_tuner_resolve`:
   - on entering `GGML_HIP_CANARY_RUN_PROBE`, set `canary_state = UNRESOLVED` up front (every path below - probe failure, fresh-block rejection, fresh canary failure - ends UNRESOLVED; only a passed fresh canary upgrades it to `RETRIED_PASS`);
   - set `canary_fresh_block = true` **after** `measure_finalist_block()` completes (the window has replaced every finalist's statistics) but **before** `post_block_reject_reason()`, so a row rejected on that scrutiny still authoritatively says its evidence is the fresh block's. `canary_fresh_block` is now an authoritative measurement-window marker, not an "everything passed" flag.
   - The doc comment on `Result.canary_fresh_block` was updated to state these invariants exactly.
