# Audit remote-MoE engine lifetime and collective failure cleanup

## Notes



## Findings

The plan needs to cover two current lifetime hazards in addition to moving callback policy into an engine generation. moe_remote_hook.cpp still owns process-global HookState and DSO-static registration; RTLD_LOCAL does not make these state per Engine. Normal stop currently interrupts the ledger and aborts the barrier before joins, which prevents a clean close-admission/cancel/drain path for bound ahead work. Candidate r4d_ar_entry.hip also builds rank allocations in locals and only publishes them after all allocations; build/acquire failure deletes the instance without the normal release cleanup, leaking pinned/VRAM resources. Audit the direct mailbox-device and owner-generation entry points as well as plugin callbacks.

## Conclusion

Add explicit bind/open and stop/detach with opaque engine-generation context, clean-stop drain distinct from fault interruption, and failed-init allocation cleanup that preserves peer pointer lifetime until all ranks unwind. Include direct owner-generation/mailbox APIs and failure/reuse tests.
