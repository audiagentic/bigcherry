# Correct attn_gate tensor-parallel split granularity

## Description

Future correctness patch from ed89854 that aligns attn_gate tensor-parallel split granularity with attn_q.

## Steps

1. [DONE 2026-08-19] Verbatim port to patches/1201_rd20_attn_gate_tp_split.py (GROUP=rdna-boosts, STATE=untested); anchor and applied-region byte-identity vs fork commit 3b200b259 verified; idempotent re-apply verified.
2. Correctness bench (correctness-first, per the item's standard): two-GPU tensor-split run on the two FREE Brutus devices (device 2 gfx1201 + device 3 gfx1030; do NOT take the XTX pair -- held by llama-server). The pre-patch bug is an abort on 3+ GPU layouts where the head-aligned split rounds a device's attn_gate share to zero, so a 3-GPU layout is the true regression; if only 2-GPU is feasible, record that explicitly.
3. Known risk: Brutus multi-GPU RCCL/allreduce had an independent failure mode before this item -- if 2-GPU TP itself cannot run, fall back to: (a) single-GPU no-op proof (patch must not change single-GPU behavior at all), (b) static proof that the post-patch attn_gate split granularity equals the attn_q granularity for the layouts that previously aborted, and keep the item OPEN naming the hardware gap rather than claiming validation from single-GPU runs (the item's own standard forbids that).
4. Decide and record: pass -> flip 1201 STATE + update external-sources.toml; partial (fallback 3) -> record partial evidence and the gap; fail -> record and set registry status.
