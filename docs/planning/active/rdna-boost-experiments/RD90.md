# RD50: require a full multi-target compile before isolated benching (translation-unit fold risk)

## Description

Filed as a standalone tracking item because two attempts to append this finding directly to RD50's own notes were silently lost by the planning tool's concurrent-write race (confirmed live, 2026-08-20 -- re-read RD50 immediately after each write and found the original content unchanged both times). The finding itself: patch 1221_rd50_gdn_chunked_recurrence.py folds two upstream files (gated_delta_net_chunked.cu/.cuh) into the existing gated_delta_net.cu, since BigCherry's patcher has no new-file-creation primitive. GPT review (req_1be17a9750a44a4c) only saw the docstring + edit list, not the full 651-line patch body, and flagged that folding translation units can change macro lifetime/leakage, include ordering, and symbol visibility even when the source uses well-prefixed names (the upstream code does use strongly prefixed gdn_*/ggml_cuda_gdn_chunked_* names, which reduces but doesn't eliminate the risk).

## Steps

Before RD50's isolated bench run, compile the patched gated_delta_net.cu (and the whole tree) across every supported HIP target (gfx1100/gfx1201/gfx1030 at minimum), not just a successful `bigcherry apply --dry-run` (which only proves the regex anchors matched text, not that the resulting C++ is valid/correctly-scoped). If it compiles clean on all targets, that's real evidence the fold preserved compilation semantics; if it doesn't, the fold needs rework, not a suppressed anchor.
