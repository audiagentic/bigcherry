# AMD-MMQ-001: RDNA MMQ tile-width reduction for LDS occupancy

## Description

Backend: HIP, gfx1100/gfx1151/gfx1201. Source: AMD PR Set 2/downstream #32 (llama.cpp discussions #26349). Source status: Recheck before port. Prerequisites: none. Q8_0 relevance: High.

## Steps



## Detailed Solution & Technical Design

Hypothesis: Reducing MMQ X tile width for LDS-limited shapes increases resident workgroups and improves prefill throughput.

What/why: Wide tiles reduce scheduling overhead but can consume enough LDS/VGPRs to collapse occupancy; AMD's gfx11 work retunes MMQ geometry rather than assuming CUDA-derived values transfer.

Where: ggml-cuda MMQ config/launch selection. Port only the tile-selection change, not the whole #32 bundle.

## Code Samples & Guidance

Trigger: high-cost dense/MoE MMQ signatures from Qwen3.6-27B and 35B-A3B; gfx1100/gfx1201 independently, gfx1151 if hardware available.

Controls: small matrices already at high occupancy; quant types not targeted; non-MMQ family winners (routing still selects BLAS/MMVQ where appropriate).

Boundary: mmq_x candidates around native winner; physical M/ubatch 64,128,256,512,1024,2048,4096; record LDS/workgroup/VGPRs/waves-per-SIMD/occupancy.
