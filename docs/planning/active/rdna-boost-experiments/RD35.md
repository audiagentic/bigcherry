# AMD-GEMM-001: 128-byte row padding for cache-set aliasing

## Description

Backend: HIP, gfx1100/gfx1201. Source: AMD PR Set 5/#57 (discussions #26379). Source status: Recheck before port. Prerequisites: none. Q8_0 relevance: Low direct, high if combined with dequantized shadows (RD36-RD38).

## Steps



## Detailed Solution & Technical Design

Hypothesis: Adding one cache line when a float-weight row stride is a multiple of 2048B breaks LLC cache-set aliasing and improves GEMM prefill.

What/why: AMD split this originally as #34, later folded into #57; independent from the F16-shadow optimization, must be tested separately.

Where: weight allocation/layout; consumers must honor nb[1].

## Code Samples & Guidance

Trigger: captured float/BF16/F16 GEMM tensors with aliasing row bytes; Qwen dense projection shapes known to hit 2048B stride multiples.

Controls: non-aliasing strides; quantized representations whose packed rows aren't affected.

Boundary: padding 0,64,128,256 bytes where legal, grouped by row_bytes mod cache geometry.
