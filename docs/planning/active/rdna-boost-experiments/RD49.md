# AMD-SSM-001: Channels-major SSM_CONV input mode

## Description

Backend: CPU+HIP support required. Source: AMD PR Set 6/#52 (discussions #26380). Source status: Recheck before port. Prerequisites: none. Q8_0 relevance: High.

## Steps

1. Recheck AMD PR #52 (merge f6ea7bced112) against the current pinned llama.cpp graph/SSM APIs.
2. Separate API/layout semantics from architecture-specific performance.
3. Implement CPU reference support first (or in the same atomic slice as the op/layout enum) so every new graph remains executable on a reference backend.
4. Implement HIP/CUDA kernel support for both short- and long-token paths.
5. Switch only DeltaNet/Qwen graph construction that is proven channels-major; preserve existing time-major callers unchanged (bit-identical).
6. Validate interaction with RD50 chunked GDN and any RD27 SSM-concat work.
7. Validate meta/tensor-parallel split propagation in a real multi-device run.
8. Measure ubatch-sensitive prefill improvement; decode must stay neutral.

## Detailed Solution & Technical Design

Hypothesis: Allowing SSM convolution to consume channels-major input eliminates a per-layer physical transpose in DeltaNet models.

What/why: AMD reports -29% total prefill at ub4096 in the favorable case; changes shared ggml semantics, so backend fallback/correctness must be strong.

Where: ggml_ssm_conv API/op and CPU/HIP implementations.

## Code Samples & Guidance

Trigger: Qwen3.6 hybrid/GDN model prefill.

Controls: existing time-major callers must remain bit-identical; backends without implementation must cleanly fall back.

Boundary: ubatch 256/512/1024/2048/4096; sequence lengths.

## Validation

Correctness (direct op): both layouts; d_conv {3,4,9}; representative d_inner values; short and long token paths; single and multi sequence. AMD PR #52: 90/90 direct SSM_CONV layout cases passed against CPU.

Model: qwen35 dense; qwen35moe / Qwen3.6; qwen3next; PPL or deterministic output parity (AMD reports bit-identical PPL on tested qwen35/qwen35moe/qwen3next).

Composition: RD49 alone; RD50 alone; RD49 + RD50; any active RD27 SSM-concat patch if materialized. Do NOT combine RD49 SSM layout work with RD50 chunked-GDN in one code commit.

Tensor parallel / meta: actual multi-device/meta execution, not source inspection only. AMD explicitly left TP/meta split handling coded-but-unexercised -- that gap is in BigCherry's acceptance criteria.

Performance: ubatch 256/512/1024/2048/4096 where feasible; report CONCAT/CONT/SSM_CONV/GDN op time and total prefill. AMD gfx1151 measured: pp512 +5.3%, pp1024 +4.3%, pp512@depth512 +5.2%, pp1024@depth1024 +6.8%, decode ~neutral, extreme ubatch=4096 total prefill 3825ms -> 2717ms. Do NOT reproduce the -29% headline as the acceptance bar -- that was an extreme favorable ubatch case; accept on stable improvement in BigCherry's real workload envelope, correctness and composition first.

Acceptance: adopt layout mode only if API stays backward-compatible and at least HIP+CPU are correct.
