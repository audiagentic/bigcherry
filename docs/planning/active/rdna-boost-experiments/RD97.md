# P0: audit AMD PR #75 MMQ tile-reuse barrier race against the pinned tree (structural audit: hazard absent at b10502)

## Description

P0 correctness audit from the 2026-08-23 AMD follow-up handoff: determine whether BigCherry's pinned/materialized llama.cpp contains the shared-tile lifetime hazard AMD fixed in PR #75 (merged 812a47a89991, head 4ea5f294f821). AMD's in-fork evidence: 115/1568 tested MMQ configurations produced nondeterministic wrong results when load_tiles() overwrote shared tile_x while another warp could still be executing the previous iteration's vec_dot; fixed by replacing the elidable mmq_hip_tile_barrier with a full __syncthreads() at both loop sites. AMD reports ~1.3% cost at mmq_x=16, effectively none above 32. The PR's RDNA3.5 tile-width tuning is a SEPARATE performance change and is out of scope for this item.

STRUCTURAL AUDIT ALREADY DONE at baseline d76bdc2 (pin b10502 + patches, vendor + patch inspection):
- No mmq_hip* symbols anywhere in vendor/llama.cpp/ggml/src/ggml-cuda or in any patch -- the fork's elidable barrier does not exist in the materialized tree.
- The only mul_mat_q_process_tile K loop (ggml/src/ggml-cuda/mmq.cuh ~line 899-937) is: load_tiles(x, tile_x, ...) -> tile_y write -> __syncthreads() -> vec_dot(..,0) -> __syncthreads() -> tile_y write -> __syncthreads() -> vec_dot(..,MMQ_TILE_NE_K) -> __syncthreads(). The final full-block __syncthreads() at every iteration end means no warp can reach the next iteration's load_tiles before all warps have passed the last vec_dot. The hazard requires an elidable barrier; upstream's is not elidable.
- Patches touching mmq* files (0300 forced_J, 0700 counters, 1000, 1100, 1203, 1204) do not edit the process_tile K loop; 1203's mmq.cuh edit is the J_max env override only.

Working conclusion: ALREADY FIXED / NOT APPLICABLE at the current pin. Expected disposition: close as baseline/already-fixed with this structural record after the materialized-build confirmation below. If the materialized build contradicts the structural audit (e.g. a patch changes the barrier at build time in a way the text inspection missed), materialize a barrier-only patch as patches/1233_rd97_mmq_tile_reuse_barrier.py (1233 is free at d76bdc2 -- re-list first) with the exact anchor regenerated from the materialized source.
