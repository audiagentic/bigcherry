# Hardware-eligibility needs device traits beyond architecture (integrated/UMA/P2P/driver/GPU-count)

## Description

External review (2026-08-20): RD22 (patch 1209, integrated-GPU host-buffer backout) is not really a 'gfx1151 optimization' -- it's a HIP integrated/UMA host-buffer correctness workaround under specific async execution conditions; the patch itself explicitly states discrete devices are unaffected. Contracts and RD items currently key eligibility on architecture strings (gfx1151, gfx1100, etc), but this class of fix really needs first-class device traits (integrated=true/false, uma, peer_access, gpu_count, driver) -- keying eligibility on architecture alone risks BigCherry's own generalisation engine learning the wrong abstraction (e.g. 'this helps gfx1151' when the real rule is 'this helps any integrated/UMA device').

## Steps

Add device-trait fields (integrated, uma, peer_access, gpu_count, driver) to the hardware-eligibility model used by Experiment Contracts and/or the underlying autotune hardware key, separate from architecture. Audit existing hardware-scoped items (RD22 at minimum) for whether their real eligibility condition is architecture-keyed or trait-keyed, and correct the contract/scope if it's currently mis-keyed.
