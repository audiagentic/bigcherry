# Bake-in rule: port RD21/RD24/RD15 kernel regions from branch-tip (post-fix) state

## Description

Port snapshot-v2 commit 8cdf1ab081384aa1786bfff3a45e0ec341f9fd52 'cuda : fix MTP batch-vs-seq consistency for fused kernels and gfx1151 mmvq' (mmvq.cu, +77/-27). CORRECTNESS, not performance: the frozen RD12 (paired mmvq) and RD21 (gfx1151 mmvq) commits are known to have an MTP batch-vs-seq inconsistency that this commit fixes. Porting RD12 or RD21 WITHOUT this fix would ship known-broken kernels -- this item is a hard prerequisite of both, and RD08 should be audited against it.

## Steps

1. [DONE 2026-08-19] Triaged: no standalone patch exists; converted to a port-sequencing rule (see Notes).

4. When RD15 is ported: take shexp_down_gated_q8_0 from tip state (includes the same restructure).
5. Validate the specific scenario the commit message names -- fused decode bit-identical to unfused verify -- as a regression test of each ported item, not as a separate bench.

## Notes

NOT A STANDALONE PORT (verified 2026-08-19 against the branch-tip diff): all 7 hunks of 8cdf1ab08 anchor ONLY on code that does not exist in our pinned+framework base -- the gfx1151 nwarps=2 table in calc_nwarps (introduced by RD21), ssm_gate_beta_fused_q8_0 / ssm_conv_l2_gatebeta_fused (RD14/RD24's SSM kernels), and shexp_down_gated_q8_0 (RD15). It therefore has no patch of its own. BAKE-IN RULE: when RD21, RD24, or RD15 is ported, extract those kernel/table regions from the BRANCH-TIP (9e46e1fd) state rather than from the individual pre-fix commit diff, so the broken pre-fix state never exists in the tree. This supersedes the RV51 framing of RD25 as a prerequisite to 'port first' -- porting it first is impossible, and unnecessary if the tip state is used. RD26 commits 10b83d6b2 (19 references into the fixed regions) and 6cdf5aff9 (1) touch the same post-fix code and must also port from tip state. RD12/RD08 are NOT touched by this commit and have no such requirement (corrects the RV51 assumption that RD12 is gated by it -- RD12's only relationship is mmvq.cu co-tenancy with RD08/RD21).
