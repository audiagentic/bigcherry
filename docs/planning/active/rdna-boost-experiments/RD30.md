# AMD-MOE-001: MoE-aware MMQ tile sizing from average expert occupancy

## Description

Backend: HIP, gfx1100/gfx1201, gfx1151 source evidence. Source: #39 (discussions #26349). Source status: Recheck before port. Prerequisites: none. Q8_0 relevance: High. PRIORITY P0.

## Steps



## Detailed Solution & Technical Design

Hypothesis: Selecting MMQ tile width from expected/average tokens-per-expert reduces empty work and improves MoE prefill vs worst-case ncols_max sizing.

What/why: Real routing rarely sends every token to one expert; worst-case sizing over-widens tiles. Source reports large pp128/pp1024 gains on Qwen3.6-35B-A3B.

Where: MUL_MAT_ID MMQ host-side tile selector.

## Code Samples & Guidance

Trigger: Qwen3.6-35B-A3B Q8_0 and Q4_K_M; natural + synthetic routing captures.

Controls: dense Qwen3.6-27B; highly skewed single-expert routing (where mean-based sizing can become wrong); alternative MoE family (Gemma/DeepSeek) if available.

Boundary: ubatch 128,256,512,1024,2048,4096; routing uniform/captured/mild skew/Zipf/concentrated/single-hot; record mean/p95/max tokens-per-expert.
