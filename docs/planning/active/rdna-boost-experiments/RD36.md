# AMD-GEMM-002: Persistent F16 shadow of quantized dense weights

## Description

Backend: HIP, gfx1100/gfx1201. Source: #57. Source status: Recheck before port. Prerequisites: none. Q8_0 relevance: Very high. Prerequisite of AMD-GEMM-003/004 (RD37/RD38).

## Steps



## Detailed Solution & Technical Design

Hypothesis: For large-batch prefill, paying a one-time Q->F16 expansion at load can beat repeated quantized MMQ execution.

What/why: Trades VRAM for faster dense GEMM; Q8 especially interesting since expansion ratio is only ~2x vs ~4x from Q4.

Where: model load/device buffer path; create F16 shadow only for eligible dense weights.

## Code Samples & Guidance

Trigger: Qwen3.6-27B Q8_0 primary; Q4_K/Q6_K as controls/alternative economics.

Controls: decode-only workloads; VRAM-constrained configs; MoE expert weights (shadowing them could explode memory).

Boundary: shadow selected tensors only vs all eligible dense tensors; M/ubatch 64..4096; track VRAM.
