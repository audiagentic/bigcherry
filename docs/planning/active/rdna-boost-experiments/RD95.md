# Repin advisory ancestry/redundancy report: exact-tracked-commit baseline detection (equivalent-detection half in RD99)

## Description

External review (2026-08-20): external source commits that later land upstream (or become ancestral to the current pin) should be automatically caught and the corresponding RD item moved to baseline/retired, not left as an active 'optimization' plan indefinitely. This project already does this kind of check manually/ad hoc -- this session found RD85/RD86 needed a real ancestry check (initial assumption they were likely already-baseline turned out wrong, confirmed via real SSH ancestry check against Brutus), and RD68a/RD68b turned out non-ancestral to the b10502 pin despite an initial assumption they probably were.

## Steps

Shipped as a routine, automated REPIN ADVISORY report (not a hard pre-bump gate, and not blocking): at the END of cmd_repin, for every tracked external-source commit in config/external-sources.toml, check whether its EXACT tracked.commit is now ancestral to the candidate pin, and REPORT the now-baseline commits + their plan-items. Fail-closed: only verdict=="ancestral" is reported; not-ancestral and unknown (an unfetched pin, or a fork SHA absent from the local upstream checkout) are never asserted redundant. Non-mutating: it names candidates but never transitions planning cards (MCP single-writer domain); a report failure never invalidates the RE48 transition.

The "(or an equivalent)" upstream-equivalence half -- a FORK commit that landed in upstream under a DIFFERENT (rebased) SHA -- is deliberately out of scope for this item and is carried in RD99 (phase 1: optional `upstream-equivalent` registry field + OR in the ancestry check, manual annotation; phase 2: deferred auto-matching). The requirement is preserved there, not dropped.
