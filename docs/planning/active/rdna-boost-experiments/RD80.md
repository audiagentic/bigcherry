## Description

Backend: AMD proprietary/AMDVLK. Source: discussion #21043. Source status: Recheck before port. Prerequisites: none. Q8_0 relevance: High.

## Detailed Solution & Technical Design

Hypothesis: Some dense RDNA4 shapes run faster on conventional shaders than proprietary-driver coopmat codegen.

What/why: Source reported dense prefill improvement when coopmat disabled, RADV behaved differently.

Where: Vulkan coopmat route/override.

PR #27952 strengthens the hypothesis that coopmat choice is workload/type/driver dependent, especially on RDNA4: retain the possibility that conventional shaders win dense shapes while CM1 wins selected MoE or quantized shapes. Do not infer a global coopmat-off policy. Compare route choices only after device identity and driver/ICD fingerprinting are available, and keep PR implementation/qualification in RO19-RO22.
