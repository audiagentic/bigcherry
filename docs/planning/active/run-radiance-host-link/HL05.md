# Host-memory all-reduce via CPU relay push for tensor-parallel layouts (27B on two XTX)

## Description

**Separate TP2 owner:** optional CPU relay between *two* XTX tensor-parallel ranks, preserving their existing exact/WHT6 wire semantics and accumulation protocol. Reuse HL02's matched contention/push curves and RAD50's DMA-BUF publication and safety proofs; do not duplicate HL02 or VTP38's three-rank CPU host reduction. Only this item can justify TP2 managed libr3 integration after qwen27b-2xtx end-to-end A/B. A WHT6 payload relay is byte-exact relative to WHT6, not mathematically identical to exact BF16. Original TP2 motivation follows.

**History — original scope:**

TP layouts exchange through host memory (each card writes its half, then pulls its peer's): 22-29% of flashnext-tp2xtx prefill, and the pull is exactly the traffic XTX 0 contention halves. A CPU relay pushing each half into the peer's VRAM (RAD50 DMA-BUF path) avoids the contended pull. Relevant to qwen27b-2xtx and any engine spanning two cards; not to flashnext-4gpu.

## Detailed Solution & Technical Design

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

Keep the existing all-reduce arithmetic and exchanged wire bytes unchanged. Replace only the destination delivery mechanism.Existing conceptual path:`Rank A GPU -> shared host memory -> Rank B GPU pull
Rank B GPU -> shared host memory -> Rank A GPU pull`Proposed path:`Rank A GPU -> shared host memory -> CPU relay -> Rank B VRAM
Rank B GPU -> shared host memory -> CPU relay -> Rank A VRAM`A producer GPU must publish completion of its host-memory writes before the relay reads those bytes. The relay must finish and make its GPU-local output visible before the peer's consumer proceeds. Use separate sequence numbers for direction and generation; distinguish rank 0→1 from rank 1→0 explicitly.Export each receiving rank's GPU-local buffer as a DMA-BUF, retain the FD and mapping across steps, and use a persistent relay instead of process creation per exchange.The main comparison must include the existing exact-BF16 transport and the existing WHT6 transport. An exact-byte relay of WHT6 data is lossless relative to the original WHT6 wire, but WHT6 itself is not equivalent to the exact-BF16 wire.Do not change the existing all-reduce accumulation order or rank-count logic. In particular, an all-reduce result must not be added twice because both the old host-read path and new relay path become visible.
