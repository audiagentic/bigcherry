# CPU-push the helpers' activation copies instead of each helper pulling them (prefill activation round)

## Description

RAD40: a 5.4 MB activation round to each helper at once finishes XTX 0 662 us, XTX 1 853 us (651 uncontended), tail 1,601; CPU-pushing XTX 0's copy instead cut the heads' makespan 853 -> 683 us (-20%). In flashnext-4gpu prefill every MoE layer step does this round, so it is a per-layer gain, a different application of the RAD50 push than the result combine.

## Steps

1. Model: per-layer prefill critical path with the measured activation round (trace contract from RAD40's review).
2. Lab: CPU push of activations into helper VRAM (DMA-BUF) with per-chunk ready generations, vs today's helper pull; bit-exact payload.
3. Only if the lab clears RAD40's stop/go (>= 15% transfer makespan or >= 0.3 ms off a layer step): opt-in moe-remote transport behind a manifest setting, A/B on prefill and decode separately.

## Detailed Solution & Technical Design

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

Treat the activation relay as two stages:The R9700 publishes the exact E4M3 activation codes and FP32 group scales into the existing shared-host staging area.After those stores are visible, a persistent CPU relay writes the relevant activation data into a DMA-BUF exported from the destination helper GPU.The initial R9700-to-host publication remains necessary. CPU push replaces the helper's subsequent host read; it does not create GPU P2P.The helper must not consume the DMA-BUF until its exact generation and data range are ready. Reuse the current request identity: rank, layer, sequence, placement epoch, generation slot and activation layout. Do not reuse a generation from a prior layer or another helper.Two transport shapes should be compared:Full activation plane, simplest protocol and direct comparison to the RAD40 activation-round test.Routed-row payload, carrying only the actual expert-relevant rows, if the measured sparse reduction pays for its metadata and compaction costs.A host relay may use the same generation-aware chunk machinery as RAD50. However, unlike the result-add kernel, the expert GEMM consumes sorted rows by expert; it cannot safely start on arbitrary token chunks before all operands for the scheduled expert tile are present.Thus, full-plane ready before compute should be the first implementation. Expert-tile pipelining is a separate optimisation with substantially higher complexity.-

RAD40 measured a 5.4 MB activation round in which XTX 0 and XTX 1 completed at approximately 662 and 853 µs. It does not establish a whole-layer gain, because the RX 6900 XT tail can still be the straggler and because the actual helper kernel sparsely copies only routed activations.The latter is important: `moe_remote_gpu.h:644–675` and `moe_lane_front.h:74–116` already implement sparse activation preparation. A dense CPU push could transfer many rows that the helper would never consume.-
