# Prefill on gfx1100: lane-owns-a-row MXFP4 GEMM with bf16 activations

## Description

radiance's prefill MXFP4 GEMMs (r4d_gemm_mxfp4a8_nt_m64, r4d_gemm_mxfp4a8_tiled, and the DTM form of the decode unit for M <= 128) stage E4M3 in shared memory and call the gfx12 fp8 x fp8 WMMA. Through libr3 that is software fp8 conversion plus 12 cross-lane moves a call, or with the first native form 2 x 16 conversions a lane a step. hipfire's gfx1100 prefill (gemm_mq4g256v2_residual_wmma_gfx11_bt.hip) uses the gfx11 fragment as it is: one wave a block, a lane owns one weight row, reads its 16 codes (8 bytes) for a K step, dequantises them to f16 in registers once and reuses the fragment across B = 4, 6 or 8 batch tiles with independent accumulators; the activation fragment is a plain 32-byte load of one token's 16 values. No conversion in the loop, no shared memory, no cross-lane move, and the accumulator is written out in the gfx11 interleaved layout.

## Detailed Solution & Technical Design

Kernel gemm_mxfp4a8_bt_gfx11, libr3-owned. A operand of the gfx11 WMMA = weight: lane l (row n0 + (l & 15)) holds W[n, k0..k0+15]; with radiance's fragment-order slots a lane's row is split over the two halves' dwords (k 0-7 in lane l, k 8-15 in lane l+16), so either each lane loads both dwords (two 4-byte loads) or the layout hook writes a row-major 8-byte slot for libr3 (decide by measurement; start with two loads). Codes to bf16 through the E2M1 table with the block exponent folded as r4d_mxfp4_fold_d does, giving the bf16 bits directly (a 16-entry table of bf16 magnitudes per exponent offset; no E4M3 step). B operand = activations: lane (token m0 + 16b + (l & 15)) holds A[m, k0..k0+15] as bf16. radiance hands the kernel fp8 activations with f32 scales: widen fp8 to bf16 once per launch into the op's scratch ([M,K] bf16, 512 x 17408 x 2 = 17.8 MiB worst case) with a small pre-pass kernel, then every K step is a 32-byte load. Where the graph has the bf16 activation before quant_act_fp8, taking it directly is a later step (needs a graph-level change; not in this item). Accumulators: BT independent v8f per lane, D[n][m] with the lane's column = m; rescale at 128 boundaries for the (row, 128) grid as mxd_rescale does, per column. Epilogue: apply Wref exponent and row scale, write bf16 C[m][n] from the gfx11 layout (rows 2e + half) without the gfx12 repack. Grid [ceil(N/16), ceil(M/(16 BT))], block 32 threads, launch bounds as hipfire's (32, 2). Second variant for wide N and many blocks reading the same activations: 8 waves share a staged activation group in shared memory, tile-major layout to keep bank conflicts four-way (hipfire gemm_hfq4g256_residual_wmma_gfx1100_muse_lds_g256.hip).

## Effort & Risk

Large, advanced. Risks: scratch for the widened activations (17.8 MiB) must come from the op's scratch hook, which the core sizes from a per-row callback, so the row needs its own scratch hook; occupancy at one wave a block with 8 accumulators (VGPR pressure); the fragment-order weight layout costs two loads a step until a row-major layout is produced by the hook.
