# ROCm 10.1 RDNA3 optimization, quantization and KV-cache qualification

## Description

Investigate ROCm Core SDK 10.1.0 as an **opt-in build and benchmark toolchain** for standalone Radiance's gfx1100 kernel library (`libr3`) on Brutus's two RX 7900 XTX GPUs. Compare it against the proven ROCm 7.2.4 lab baseline; do **not** replace the production driver/toolchain or silently change llama.cpp builds.

Parent: RR01 (RDNA3 `libr3` portability and model support); active survey branch `feat/radiance-rdna3-survey`, draft PR #109. This item is parallel research and optimization **after** RR01's fail-closed build, registry, and `rad-kbench` correctness gates. Its results must not block a working gfx1100 baseline on ROCm 7.2.4.

ROCm 10.1.0 (2026-10-05) supports gfx1100 and includes LLVM 24, HIP 10.1, rocWMMA 2.2.1, Composable Kernel 1.3, RCCL 2.30.7 and rocSHMEM 3.7. ROCm 10 does **not** confer gfx12-only FP8 WMMA, gfx12 fragment layouts or `global_load_tr_b128` instructions upon RDNA3 hardware. Quantized **storage** and matrix **compute** must be treated separately.

## Steps

1. **RR02-A: isolate the toolchains / prove runtime compatibility.**
   - Preserve the ROCm 7.2.4 toolchain and the lab's existing runtime. Stage ROCm Core SDK 10.1.0 separately (documented default prefix: `/opt/rocm/core-10.1`) or in a container/toolchain prefix; no system-wide switch, ACS/IOMMU changes, or unreviewed kernel-driver upgrade.
   - Select only the two verified gfx1100 devices; record GPU BDF, ROCm-visible indexes, topology/peer capability, firmware/driver, host kernel, compiler/HIP/LLVM/rocWMMA/CK/RCCL/rocSHMEM versions, Radiance source SHA, exact build flags and `libr3` SHA.
   - Rebuild **the same** Radiance revision (initially RR01's 1.3.0 / `89cee7c`) and `libr3` for gfx1100 under separate clean build directories. Check the AQL-backed `hipLaunchKernel` interception, fatbinary registration and plugin ABI. Fail on missing device rows, errors or unsupported kernel capabilities; log rather than discard failures.
   - Require identical fixture, weights, layout, batch shapes, compiler flags where equivalent, and GPU clock/power context for comparisons. Capture generated gfx1100 ISA/disassembly for any claimed code-generation improvement.

2. **RR02-B: gfx11-native matrix backends and weight quants.**
   - Compare gfx1100 **BF16/F16 WMMA** against rocWMMA 2.2.1 and Composable Kernel 1.3 reference kernels for `gemm_nt`, including M=1 decode, skinny M<=64 and M=512 prefill. Respect gfx11 wave32 operand replication, accumulator mapping, LDS staging and precision; never lower to gfx12 intrinsics.
   - Compare native gfx11 **signed INT8 WMMA** for `w8a8` and `w4a8` (unpack int4 to the required i8 fragment) before attempting an FP8-equivalent fast path. Test `w4a8_asym` separately; exact zero-point and scale semantics are required. Benchmark whole producer+GEMM chains, not kernel time alone.
   - For **FP8 E4M3** checkpoint weights (`fp8a16`, `fp8a8`), retain packed OCP bytes and scales in VRAM; unpack/convert **per tile** into BF16/F16 WMMA fragments (or validate an integer alternative), not a permanent 2x BF16 weight image. The existing fp8 software conversion alone is not native FP8 matrix support.
   - For **MXFP4 E2M1 plus E8M0 per-32** scales, retain checkpoint encoding; test per-fragment unpack, scale/exponent handling, BF16/F16 WMMA and numerical fidelity. A re-quantized i8 representation is a separate candidate with an explicit accuracy gate, never a transparent substitution.
   - Differential test against Radiance `libref` / `rad-kbench`: asymmetric tiles, all E4M3 codes, signed zero, subnormals, infinities/NaNs where defined, conversion midpoints, accumulation error, red zones, shape boundaries and representative model layers. Keep a coverage matrix `op x dtype x shape x kernel x ROCm version`.

3. **RR02-C: KV-cache dtype/attention trade-offs.**
   - Use **BF16 KV** as the correctness baseline, then benchmark Radiance's existing **FP8 E4M3 KV** with correct per-head/sequence K/V descales. FP8 KV uses software conversion on gfx1100; it remains worth measuring for halved cache bandwidth/capacity. Do not claim an unimplemented KV format is supported.
   - Cover GQA/head-width/block/window variants actually used by MiniCPM5-2B, Qwen3.8-27B, Flash-Next QSA and DFlash2; compare prefill, single-stream decode, concurrency, cache footprint and long-context stability.
   - Measure representative 8K/24K/98K contexts and larger contexts only when verified to fit; report prompt TPS, decode TPS, p50/p95 latency, memory GiB, conversion overhead, context ceiling and accuracy drift. Greedy *identity* applies only to like-for-like format/model comparisons; BF16 versus FP8 KV needs numeric/top-1/quality checks, not assumed bit identity.
   - Evaluate native gfx11-friendly plain loads + LDS/lane shuffle as the substitute for gfx12 `global_load_tr_b128`, with correctness probes that reveal transposed K/V elements.

4. **RR02-D: dual-XTX transport under ROCm 10.1.**
   - Keep **exact host-staged** two-rank collective as control; compare conditional RCCL 2.30.7 (`NCCL_PROTO=Simple`) and rocSHMEM 3.7 IPC/tile-reduction variants **only after Brutus confirms the required P2P capabilities**. Unsupported P2P must fail closed rather than hang or select a peer-spin scheme.
   - Independently A/B HIP `hipMemLocationTypeHostNuma` VMM and ROCr host-pool VMM for pinned NUMA-local host staging when supported; no new transport is presumed faster than the control.
   - Test tiny/medium/large payloads, two-way asymmetry, exact rank agreement, graph capture/replay, bounded watchdog/timeouts, reset/recovery and repeated long runs. Never enable peer spin polling, override ACS or disable IOMMU automatically.
   - ROCm Systems Profiler / ROCprofiler-SDK may help diagnose HIP, HSA, RCCL and rocSHMEM. First prove that tracing sees Radiance's custom AQL dispatch; absence of tracing is not evidence of no GPU work.

5. **RR02-E: ABBA comparison, disposition, and integration.**
   - Use isolated lab queue runs and fixed model/context/quant, matched compiler/ROCm binaries per arm, at least two interleaved ABBA repeats, warmed runs and reproducible fixtures. Record complete source/environment matrix and confidence/variance, not only the fastest time.
   - Triage improvements as `gfx1100 ISA change`, `ROCm compiler/runtime change`, `format/layout change` or `transport change` to avoid attributing all differences to ROCm 10.
   - Promote separate, hardware-proven changes only; preserve ROCm 7.2.4 fallback and keep inference production recipes unaffected pending independent promotion approval.
