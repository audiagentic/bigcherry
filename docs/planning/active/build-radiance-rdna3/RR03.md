# Radiance drafter on a separate card: R9700 first, then the RX 6900 XT

## Description

Owner direction 2026-10-09: run radiance's drafter on a card that is not one of the trunk's ranks, as BigCherry does in llama.cpp (MTP drafter on the RX 6900 XT). Start with the R9700 as the draft card, because it is gfx1201 and radiance's own kernel library (libr4d) already runs the drafter kernels there; no new kernel library is needed for the first version. The trunk runs on the two RX 7900 XTX through libr3 (RR01).

What radiance does today (1.3.0, 89cee7c, read 2026-10-09): `core/engine_bringup.cpp` `usable_devices` keeps only the discrete cards that share the first card's architecture; every rank is one card holding a share of every weight; the drafter (`core/engine_draft.cpp`, `core/sched/draft.cpp`) runs as extra passes on the same ranks after the trunk step is sampled and committed, in the shape the architecture plugin declared (`rad_declare_drafter`: serial or block).

## Steps

0. Prerequisite: RR01 serving a model on two XTX (trunk) so there is something to draft for.
1. Read `engine_draft.cpp`, `sched/draft.cpp`, the rank/device structures and kernel resolution, and write down: what state the drafter reads from the trunk each step (hidden rows, KV, sampled ids), where it is allocated, and whether kernel selection is per engine or per device.
2. Device selection: allow one extra card of another architecture as a draft device, named explicitly (a flag such as --draft-device), never picked up implicitly. The rank set stays one architecture.
3. Kernel resolution per device: the draft device resolves its ops against the libraries that have code for it (libr4d on gfx1201), the ranks against theirs (libr3 on gfx1100).
4. Run the drafter passes on the draft device: its weights and buffers allocated there, the rows it needs staged from rank 0 through pinned host memory each step, drafted ids returned the same way. Exact, no lossy wire.
5. Measure against the drafter on the ranks: decode t/s, acceptance, VRAM on each card, greedy text identical with the drafter on either placement.
6. Second target: the RX 6900 XT (gfx1030). It has no matrix-multiply instructions, so it needs its own kernels for the drafter's ops; only after 1-5 work on the R9700.
