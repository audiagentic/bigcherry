# RDNA3 (gfx1100) kernel library for standalone radiance

## Description

Radiance's device kernel library (libr4d) is built for gfx12 only: wave32, the gfx12 WMMA fragment layouts and gfx12-only instructions. On the two RX 7900 XTX (gfx1100) the engine starts but has no device kernels. Owner decision 2026-10-09: build an RDNA3-compatible version; PR #86 (libr11, two kernels, never compiled) is a guide only.

Radiance 1.3.0 (commit 89cee7c on Brutus) gives three things to build on: the plugin ABI (docs/PLUGIN.md, abi/), libref (every conventional op on the host, the specification and oracle), and rad-kbench (replays recorded fixtures and checks every kernel a library supplies against libref, with red zones and a completeness matrix).

## Steps

1. Survey (no code of ours): compile libr4d's units for gfx1100 out of tree and list which fail and why (gfx12-only builtins, WMMA layouts); rad-info --plugins and rad-kbench with libref on an XTX to confirm the harness runs there.
2. For the units that compile, run rad-kbench against libref on gfx1100: correct, wrong, or skipped, per kernel. Units that are correct unchanged need no port.
3. Port the failing groups in order of what a model needs first: bf16 elementwise / norm / embedding / rotary / sampler, bf16 GEMM with the gfx11 WMMA layout, paged attention, GDN, then exact two-rank collectives (host-staged twin first, P2P only if the peer probe allows it).
4. First model: MiniCPM5-2B bf16 on one XTX, then two (TP2). Then Qwen3.8-27B (fp8 or mxfp4), then Flash-Next.
5. Packaging: an out-of-tree plugin under engines/radiance/, built by the lab build script, listed in engine.toml.
