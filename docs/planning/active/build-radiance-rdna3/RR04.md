# gfx1100 native kernel optimization: FP8 GEMM, quantized WMMA, paged KV and TP2

## Description

Replace **slow, correct-enough compatibility-path hot kernels** in standalone Radiance 1.3.0 with
independent, native RDNA3 (`gfx1100`) candidates, selected only after real-card correctness and
repeatable performance evidence. Scope: the two RX 7900 XTX on Brutus, with the R9700
(`gfx1201`) as an architectural *comparison*, not a same-hardware performance control.

This is an **execution plan** following RR01's functional `libr3` port. RR02 owns the optional
ROCm 10.1 compiler/runtime and quant/KV cross-version comparison. RR03 owns placing the drafter
on a separate card. Do not bundle an SDK upgrade, model integration or mixed-arch drafter work
into a kernel optimization PR. Parallel independent `libr11` candidates (PR #86, stacked PR
#110) are references/contenders, not replacements for `libr3` until checked by the same harness.

### Starting evidence, not a performance promise

Pinned Radiance 1.3.0 source `89cee7c`, ROCm 7.2.4, one gfx1100.
The recorded `libr3-b4` run (code base `8f0cf127`, documented on PR #86, commit
`c66a610f`) compiled 62 discovered libr4d device translation units; registered 201
device-kernel rows. `rad-kbench` recorded **2,083 passed, 0 failed**, 27 skipped,
7 diverged and 32 capped. Only **37 rows exercised; 164 were not exercised**.
Compilation and a passed recorded FP8 fixture **do not validate all rows**, especially
INT8, INT4, MXFP4 and MoE.

Measured *geometric means over the recorded fixture*, **not per-layer serving latency**:

| `libr3` compatibility entrypoint | Cases | Current gfx1100 |
|---|---:|---:|
| `gemm_fp8a8_nt_m16` | 72 | 808.3 us |
| `gemm_fp8a8_gated_nt_m16` | 7 | 1502.1 us |
| `gemm_fp8a8_tiled` | 28 | 9410.9 us |
| `gemm_bf16_nt_m16` (earlier b3) | 30 | 16.5 us |
| `gemm_bf16_nt_m64` (earlier b3) | 26 | 19.0 us |
| `attn_decode_h256_gqa6_fp8kv` (earlier b3) | 16 | 191.7 us |
| `attn_prefill_h256_gqa6_fp8kv` (earlier b3) | 8 | 1295.9 us |

The current `r3_compat.h` routes gfx12 WMMA into gfx11 instructions **with input fragment
lane permutation, product accumulator repacking, and a separate FP32 add**.
FP8 additionally widens E4M3 to BF16 in software on every WMMA invocation. Gfx12
transposed loads are simulated with numerous cross-lane `ds_bpermute` operations.
These are direct, testable optimization hypotheses; do not assume they alone explain
all measured latency. The newer `r4d-baseline.sh` allows a same-fixture run on
`gfx1201`, but **R9700 / XTX ratios conflate different GPUs with different kernels**.

   `seen = built + intentionally_excluded` in tooling. A regex silently skipping units is

**Acceptance:** full truthful unit manifest; benchmark failure exits nonzero; all
unexercised rows explicitly visible; both device baselines pinned; prior numeric
and invocation behavior unchanged.

### RR04-B: Native gfx11 BF16/F16 WMMA foundation (independent candidate slice)

1. Implement a `gfx1100` WMMA policy with **wave32**, `16x16x16` K tiles and
   `v16short/v16half` input per lane. Replicate A/B fragments across lanes
   0–15 and 16–31. Store FP32 accumulators as row
   `2*register_index + floor(lane/16)`, col `lane%16`.
   Never use gfx12's `8*floor(lane/16)+register_index` store mapping.
2. For direct K loops, **accumulate into the same native gfx11 FP32 fragment**
   rather than round-tripping every product via `r3_frag_12_to_11` /
   `r3_acc_11_to_12`, `ds_bpermute` and a separate vector add.
   Test byte-exact identical replay *against the same new kernel*, and numeric
   agreement to `libref` / existing `libr3` (different reduction trees may
   prevent bit identity). Use asymmetrical nonidentity matrices.
3. Benchmark a skinny one-wave/row-tile launch against multiwave LDS K staging
   for `gemm_nt` `M=1..16` and `M=17..64`, then tiled prefill
   `M>=65`. Vary split K {1,2,4,8}, contiguous A/B vector width
   {2,4,8,16} BF16 and number of K tiles staged ahead {0,1,2}.
   Measure occupancy, register spill and LDS bank conflicts (pad or XOR
   swizzle the staging stride when needed).
4. Treat PR #86's independent scalar/WMMA `libr11/gemm_bf16.hip` as an oracle
   and contender, not a reason to copy unvalidated code. Preserve
   `RadKernelInfo` shape, `RadStream` and native Radiance AQL-dispatch contracts.

**Acceptance:** `gemm_nt` real-shape numeric/red-zone coverage plus same-card
latency comparison; no spurious selected-row launch rejection or output layout
difference. Admit a new winning dispatch band only on measured evidence.

### RR04-C: FP8 E4M3 skinny decode and fused gated projections (top measured bottleneck)

**Source to model:** `libr4d/r4d_gemm_fp8a8.hip`,
`libr4d/r4d_fp8_wmma.h`, `r3_compat.h` and the
`Comfy-Org/comfy-kitchen` gfx11 `mma.h` FP8-to-BF16 compute policy.

1. Keep Qwen3.8-27B **OCP E4M3 weight bytes** and BF16
   `weight_scale_inv[ceil(N/128),ceil(K/128)]` on-device; do **not**
   dequantize the checkpoint to a full BF16 weight matrix. Honor
   `fp8a16` versus `fp8a8` activation and its per-block scale
   (`R4D_FP8_BLOCK=128` as upstream). Test signed zero, E4M3 subnormals,
   single NaN code, saturation/midpoint, and **all 256 input codes**.
2. Decode packed E4M3 **directly into gfx11 BF16 WMMA fragment order**:
   compare scalar bit decode, byte-permute/vector decode, and small LUT
   variants. Finite E4M3 values fit exactly into BF16; handle NaNs
   explicitly. No gfx12 `fp8_fp8_w32_gfx12` intrinsic.
3. Load contiguous/coalesced packed weights (and activation fragments) with
   layout pre-transformed at model conversion **only when** the container
   already permits an alternative reversible packed layout; otherwise
   transform locally in LDS with pad/XOR bank swizzle. Both inputs must
   share the **same K permutation**. Zero-pad tails and test asymmetric
   patterns; do not silently reinterpret source scale/group boundaries.
4. For `M<=16`, test fused producer+GEMM and split-K within one workgroup
   against the existing scratch-reduce path; apply the BF16 block scale
   at the exact `128x128` block boundary. Maintain FP32 accumulation,
   explicit ordering and bounded scratch. Measure launch count and total
   quantize+matmul+gated epilogue cost, not only inner WMMA cycles.
5. Add a gated `gemm_nt_q_gated` candidate only after plain FP8 passes.
   Compare `gemm_fp8a8_gated_nt_m16` (1,502.1 us baseline) with a
   dedicated fused gate/up + activation quantizer store; reject a fusion
   unless the Radiance `replaces` equivalence gate passes.

**Acceptance:** measured `gemm_fp8a8_nt_m16` and gated bands on the same XTX,
complete scale/reference and red-zone checks, real decode-model acceptance/greedy
quality, and no extra full dequantized VRAM weight copy. A correct but slower
candidate remains an experiment, not a dispatch rule.

### RR04-D: FP8 prefill tiled GEMM and LDS pipeline (other top bottleneck)

1. Implement a native gfx11 `128x64`, `128x128` and slimmer
   `64x64` tiled `gemm_fp8a8_tiled` candidate using the same
   FP8 packing/scales and BF16 FP32 WMMA policy. Separate
   `block_M,block_N,block_K`, `waves_per_CU`, register `MTxNT`
   (cap by physical VGPRs), LDS pitch and split-K as constrained tunables.
2. Stage one K tile ahead using double-buffered LDS or registers;
   compare 0/1/2 prefetch depth, wave assignment, global coalescing,
   `s_waitcnt` placement and gfx11-supported barriers. Unlike gfx12,
   gfx1100 has no `global_load_tr_b128` and does not gain it from a
   compiler upgrade. Benchmark direct loads versus explicit
   LDS transpose; preserve K labels and both operand fragment order.
3. Choose LDS swizzle/padding analytically:
   bank `(byte_address/4)%32`; avoid repeated same-bank accesses for
   16- and 32-bit lanes. Save disassembly, occupancy/VGPR and
   `ds_*` bank behavior. Never claim fewer transactions by counting
   instructions alone.
4. Benchmark against `libr3`'s measured 9,410.9 us geometric mean using
   the exact original **28** prefill cases and new `M=128..1024` cases.
   Also time `quant_act_fp8 -> gemm_nt_q -> output` as a chain;
   a fast GEMM that adds new conversion/copy launches may lose end-to-end.

**Acceptance:** no numeric regression beyond established `libref` tolerances,
same-card repeated A/B per shape, tolerable scratch/VRAM, and improved
real-model prefill before promoting a tiled dispatch band.

### RR04-E: INT8, INT4, MXFP4 and routed-MoE native formats (parallel after RR04-A/B)

1. **W8A8:** use gfx11
   `__builtin_amdgcn_wmma_i32_16x16x16_iu8_w32`, inputs as
   four 32-bit VGPRs/lane, explicit signedness and INT32 accumulator;
   preserve per-128 group scales, output RNE and producer's INT8 packing.
   Separate `M<=64` from tiled prefill. Verify reduction order,
   rounders and scale application.
2. **W4A8 / W4A8H / asymmetric grids:** use gfx11 native
   `__builtin_amdgcn_wmma_i32_16x16x16_iu4_w32` **K=16**;
   gfx12's corresponding iu4 K=32 must be split into two gfx11 calls,
   with correct nibble order, `a_neg/b_neg` and zero points.
   A mixed `W4A8H` weight requires its original Hadamard/activation
   pairing; never swap in symmetric W4A8. Compare INT4 hardware
   against widening nibbles to INT8 for the same packed checkpoint.
3. **MXFP4:** preserve OCP E2M1 nibbles and per-32 E8M0 exponents,
   with the exact optional per-output `b_ref` reference exponent.
   Test table-driven 4-bit->BF16 decode + native gfx11 BF16 WMMA
   against INT8 re-quantized candidate **only with a separately
   recorded quality/accuracy gate**. An 8-bit rewrite is a changed
   model representation, not a transparent kernel optimization.
4. **MoE:** create a routed-MoE fixture with actual route masks,
   per-expert `M`, top-k, padded empty experts, group-scales and
   permutation. Measure expert dispatch/reorder+GEMM as a complete
   chain; do not assume a dense GEMM winner also wins small,
   irregular expert batches.

**Acceptance:** nonzero tested cases per promised `w8a8`,
`w4a8`, `w4a8_asym`, `w4a8h`, `mxfp4a8` and `moe_gemm_q`
row before enabling it; every layout/repack is round-trip verified
against upstream `r4d_layout.cpp` and `libref`. Missing fixtures
remain marked NOT COVERED.

### RR04-F: Paged attention, QSA/GDN and KV memory bandwidth (parallel after RR04-A)

1. Establish correct baseline **BF16 KV vs FP8 E4M3 KV** for the
   actual `attn_paged` schema; preserve K/V descales and block-table
   semantics. Start with the measured `head_dim=256,gqa=6,
   block_size=16` decode/prefill. Include `h256,gqa=12` (QSA),
   `h128,gqa=4` (drafter/window), `gqa=8` and relevant
   sliding-window variants only when that geometry exists in the
   running architecture.
2. Replace `r3_global_load_tr_b128_v8i16` cross-lane emulation
   with coalesced global loads plus **LDS transpose** or lane-shuffle
   transpose. Compare to direct loads for decode. Retain the exact
   K/V fragment permutation and mask semantics (padded slots,
   causal/window and ragged batch).
3. Tune number of split-KV workgroups, tiles, prefetch (0/1/2/4)
   and workspace layout separately for decode and prefill.
   Measure latency versus sequence count (1/2/4/8), 8K/24K/98K
   and available longer contexts. Avoid excess scratch and
   zero-work blocks; test graph replay/AQL ordering.
4. FP8 KV may save **cache capacity/bandwidth** even though gfx1100
   decodes it in software. Benchmark conversion cost against saved
   traffic; report output rel-L2/top-1 drift and long-context behavior.
   Do not claim bit identity between different KV storage formats.
5. For GDN/QSA, start from the already-passing gfx11 ports and
   BigCherry patch `1253_nro04_gfx1100_bf16_chunked_gdn`.
   Remove gfx12 fragment-shuffle wrappers from chunk scan /
   KKT solve / QSA score only after bit/numeric and state rollback
   checks. Measure the fused recurrent/decode path and BF16/f16
   partial-state layouts, not only the inner WMMA instruction.

**Acceptance:** exact masked/ragged/long-context attention cases,
BF16 and FP8 KV comparison with memory accounting, GDN recurrent
state acceptance/rollback equivalence, and sustained decode speedup
against the same XTX/Radiance `libr3` baseline.

### RR04-G: TP2 transport, full-model inference and automatic dispatch (dependent on RR01 serving)

1. Two-XTX: first confirm device identity and
   `hipDeviceCanAccessPeer`/topology. Keep exact host-staged
   collectives as the control. Never use unsupported direct-P2P
   spin/poll all-reduce, change ACS/IOMMU globally, or infer

2. Validate deterministic greedy output for like-for-like

   recovery. No CPU-host reference fallback in a production pass.
3. Capture model-level throughput at `M`/prompt sizes
   1, 8K, 24K and 98K (only when model/context fits) and
   decode at 1/2/4/8 concurrent streams, per-card VRAM and

4. Promotion is *per validated row band*: enable native kernels

no unsupported peer transport, independent prefill+decode wins,

### ABI, specialization and performance methodology

- Use exactly the running Radiance `RAD_ABI_VERSION` and parameter/opd
  contract; pre-validate rows and strides before launch.
  Callbacks (`shape`, `scratch`, `layout`, `relayout`, `describe`,
  `launch`) must be real, not unresolved-stub placeholders.
  Preserve AQL/RadStream semantics and out-of-tree `libr11`/kdev comparisons.
- Maintain three contenders on the **same RX 7900 XTX** per op:
  `libr3` compatibility, independent `libr11`/kdev new candidate,
  `libref` oracle. Run `libr4d` on `gfx1201` only as
  additional cross-hardware context; the RDNA3 delta cannot be isolated
  from cross-card ratios.
- Compile each candidate at fixed `gfx1100`, C++/HIP ABI, `-O3`
  and FP contraction policy compatible with the reference. Inspect
  `llvm-objdump`/disassembly for native WMMA count, unnecessary
  `ds_bpermute`, VGPR spills, unexpected f32 upcasts, LDS accesses,
  synchronization and occupancy. Expose one knob at a time.
- Benchmark at least two **interleaved ABBA** sequences per candidate,
  warmed and with controlled card sharing. Write complete raw
  `rad-kbench` markdown/JSON/log, stdout/stderr, fixture digest,
  compiler/driver/device/binary hash and sampled clocks/VRAM.
  Report median/us, p95, variance, per-shape ratio, geometric mean
  and whole-model prompt/decode. Never overwrite a run folder.
- Admission thresholds to be used as **pre-registered decision rules**,
  not predicted outcomes: no unexplained correctness change; no
  missed/unsupported previously served shape; no OOB/red-zone writes;
  measured speedup with effect exceeding the ABBA variance
  (target >=5% model/chain latency improvement for a P1 promotion);
  no >3% repeatable regression in an important supported band
  without an explicit dispatch guard; bounded extra VRAM/scratch
  with a documented capacity impact. A microbenchmark win alone
  never enables a production row.

### Tests that expose silently wrong ports

1. `gfx11` accumulator and duplicate input mapping: non-square,
   non-symmetric tile values; K permutation applied to A *and* B;
   test M/N tails and both lane halves; negative/NaN handling.
2. FP8: all E4M3 codes including subnormals/NaN; BF16
   weight-scale bytes for every `128x128` block; `K=127/128/129`
   only when supported by the real row's shape contract.
3. INT8/INT4: per-lane packed-byte/nibble mapping including
   `K=16/32` hardware steps, signed/unsigned flags, zero points,
   odd rows, nontrivial scales and exact Hadamard rotation.
4. MXFP4: all E2M1 magnitudes/signs, per-32 E8M0 exponent
   bounds, absent/present `b_ref`, row-reference-exponent
   construction and round-trip packing.
5. Attention: K/V block table OOB guards, negative slots,
   causal/window boundaries, partial blocks, extreme GQA and
   sequence concurrency, matching cache dtype descales.
6. GDN/MoE: long recurrence, acceptance rollback and split-state,
   routed zero-token experts and precision of residual accumulations.
7. Runtime: mixed architecture visible-device masking,
   single/dual-XTX, graph replay, AQL descriptor compatibility,
   TP2 all-reduce exactness and graceful unsupported transport.

## Code Samples & Guidance

Native gfx11 WMMA *policy sketch* (not a drop-in port of any gfx12 fragment):

```cpp
// One wave32 -> output 16x16 tile; 16 BF16 A/B values per lane.
// A and B fragments are duplicated across wave halves.
using v16bf = short __attribute__((ext_vector_type(16)));
using v8f   = float __attribute__((ext_vector_type(8)));
v8f accum = {};
for (int k = 0; k < K; k += 16) {
    v16bf a = load_gfx11_A(lane % 16, k);
    v16bf b = load_gfx11_B(lane % 16, k);
    accum = __builtin_amdgcn_wmma_f32_16x16x16_bf16_w32(a, b, accum);
}
for (int j = 0; j < 8; ++j)
    store_if_in_bounds(row=2*j+lane/16, col=lane%16, accum[j]);
```

In `libr3`'s generic `r3_wmma_f32_16x16x16_bf16_w32_gfx12`,
the old path uses `r3_frag_12_to_11`, native gfx11 WMMA from
a *zero* accumulator, `r3_acc_11_to_12`, and a separate
`c + product` on **each K iteration**. The direct policy above
eliminates these conversions only when the entire consumer
kernel is rewritten to use gfx11 accumulator order.

## Effort & Risk

**XL, parallelizable.** The core risks are false-positive fixture
coverage (164 untested rows), silent gfx11/gfx12 fragment permutations,
extra FP8 rounding / invalid block scale lookup, wrong per-32 MXFP4
exponents, native packed-int4 signedness, excessive VGPR/LDS occupancy,
unavailable peer topology, and prematurely promoting microbenchmarks
while end-to-end serving is still blocked.

This is performance work, not a replacement for the
RR01 requirement to **serve a real model on gfx1100**. Correctness,
kernel coverage and model bring-up outrank speed.
