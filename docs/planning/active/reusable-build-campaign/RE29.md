# re15_acceptance_run stage H never passed -m to llama-bench, so both comparison arms tried to load the default placeholder model path

## Description

First real-hardware run to ever reach RE15 stage H (balanced tune-vs-replay comparison) -- possible only after the RE27/RE28 fixes let the harness clear stages A-G -- failed immediately: both benchmark arms exited with `llama_bench: error: failed to load model 'models/7B/ggml-model-q4_0.gguf'` (llama-bench's built-in default when no -m is given), so no coverage.json was ever written and comparisons.py's artifact publish step crashed on the missing file with a confusing FileNotFoundError far from the real cause.

## Steps



## Detailed Solution & Technical Design

re15_acceptance_run.py's stage H call to comparisons.run_comparison() passed `model_args=["-p", "512", "-n", "128", "-r", "3", "-o", "json"]` -- never `-m <model>`, even though `args.model` (the same GGUF path used for every earlier stage) was available in scope. Fixed by prepending `["-m", args.model]`.
