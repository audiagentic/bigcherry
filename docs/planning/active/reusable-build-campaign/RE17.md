# Generalize lane stage inputs and graph shape beyond inventory-only tune

## Description

CampaignStageExecutor._run_generate() currently hard-requires an inventory_ref and fails without one; make_generate_worker() likewise expects exactly one inventory input. This makes the execution contract inventory-specific at the API level, not just at argparse -- an outer loop over multiple builds cannot work until stages accept the canonical need-set (none / inventory / inventory+promoted-winners) and the graph shape varies by build kind (stock: materialize->build; control/record: materialize->generate->build; tune: materialize->generate(inventory)->build; replay: explicit inventory+promoted-winners dependencies). Runtime-smoke must become optional validation (validation=None|RuntimeSmokeSpec), not mandatory on every build -- legacy `build` is fundamentally a build command, not always a smoke-tested one.

## Steps

1. Replace the single inventory_ref parameter threaded through CampaignStageExecutor/make_generate_worker with a needs-driven input contract (e.g. a LaneInputs dataclass or Mapping[str, ArtifactRef], validated against the build's declared config.Build.needs frozenset).
2. Make the generate stage conditional -- builds with no variant_set skip it entirely (stock/control-without-generation cases).
3. Add promoted-winners as a first-class ArtifactRef input for replay-shaped builds, feeding build/compile-input identity exactly the way inventory already does -- do NOT let it become an untracked filesystem path (that is precisely the class of hole rounds 13-14 closed for inventory/generated-tree; reintroducing it for winners would be a regression).
4. Make runtime-smoke an optional stage: LaneExecutionSpec.validation: RuntimeSmokeSpec | None, wired so a lane with validation=None skips smoke and doesn't require --model at all.
5. Extend campaign_plan.py's stage-graph builders to produce the right graph shape per build kind rather than the current fixed generate->build->smoke shape.

## Detailed Solution & Technical Design

gpt-auto-agent design (RE14 round 19). The canonical need-set model already exists in config.py's v2 Build.needs (frozenset[str]); this item is about making the EXECUTION path (CampaignStageExecutor, campaign_workers, campaign_plan) actually consume that set-valued model instead of the current single-inventory assumption baked in since round 6.
