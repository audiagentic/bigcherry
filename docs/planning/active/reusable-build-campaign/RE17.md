# Generalize lane stage inputs and graph shape beyond inventory-only tune

## Description

CampaignStageExecutor._run_generate() currently hard-requires an inventory_ref and fails without one; make_generate_worker() likewise expects exactly one inventory input. This makes the execution contract inventory-specific at the API level, not just at argparse -- an outer loop over multiple builds cannot work until stages accept the canonical need-set (none / inventory / inventory+promoted-winners) and the graph shape varies by build kind (stock: materialize->build; control/record: materialize->generate->build; tune: materialize->generate(inventory)->build; replay: explicit inventory+promoted-winners dependencies). Runtime-smoke must become optional validation (validation=None|RuntimeSmokeSpec), not mandatory on every build -- legacy `build` is fundamentally a build command, not always a smoke-tested one.

## Steps

1. Replace the single inventory_ref parameter threaded through CampaignStageExecutor/make_generate_worker with a needs-driven input contract (e.g. a LaneInputs dataclass or Mapping[str, ArtifactRef], validated against the build's declared config.Build.needs frozenset).
2. Make the generate stage conditional -- builds with no variant_set skip it entirely (stock/control-without-generation cases).
3. Add promoted-winners as a first-class ArtifactRef input for replay-shaped builds, feeding build/compile-input identity exactly the way inventory already does -- do NOT let it become an untracked filesystem path (that is precisely the class of hole rounds 13-14 closed for inventory/generated-tree; reintroducing it for winners would be a regression).
4. Make runtime-smoke an optional stage: LaneExecutionSpec.validation: RuntimeSmokeSpec | None, wired so a lane with validation=None skips smoke and doesn't require --model at all.
5. Extend campaign_plan.py's stage-graph builders to produce the right graph shape per build kind rather than the current fixed generate->build->smoke shape.

## Detailed Solution & Technical Design

gpt-auto-agent design (RE14 round 19). The canonical need-set model already exists in config.py's v2 Build.needs (frozenset[str]); this item is about making the EXECUTION path (CampaignStageExecutor, campaign_workers, campaign_plan) actually consume that set-valued model instead of the current single-inventory assumption baked in since round 6.

## Code Samples & Guidance

gpt-auto-agent's exact RE17 design (verified against source before implementing: autotune_catalog.build_manifest already accepts inventory: Inventory | None, winners: set[str] | None, correctness_source: Path | None; autotune_catalog.read_winners(measurements: Path) -> set[str] exists; builds.BuildPlan already has both inventory_hash and winners_hash fields).

KEY PRINCIPLE: config.Build.needs (frozenset[str]) is the single authority for what a lane requires -- no second typed inventory/winners schema alongside it. Two HIDDEN generalizations beyond the plan's original 5 bullets: workload_id must become Optional (stock has no workload at all), and manifest_ref/generated_tree_ref must become Optional (stock has no generate stage) -- _run_workload_scoped's existing `if not self.workload_id: raise` would make stock impossible even after removing the inventory-specific requirement.

1. CampaignLaneExecutionSpec.inputs becomes a generic keyed collection, NOT named optional fields (that just moves the hardcoded schema one level out):
   inputs: tuple[tuple[str, Path | ArtifactRef], ...] = ()  # keys must equal cfg.builds[name].needs exactly
   validation: RuntimeSmokeSpec | None = None
   Supports both a raw Path (CLI importing a file) and an already-published ArtifactRef (future canonical-lane caller) -- both normalize to ArtifactRef before any stage runs. Fail closed on any need name outside {'inventory','promoted-winners'} for now -- BuildPlan has no generic identity slot for an unknown need kind yet.

2. _resolve_lane_inputs(spec, *, build, store, source_slice_id, run_id) -> dict[str,ArtifactRef]: exact-set-equality check (provided == build.needs, not subset) with missing/unexpected named in the error; for Path inputs, content-address into the store at inputs/<need-name>/<sha256> (generalizes _publish_inventory); for ArtifactRef inputs, verify ref.kind==name and re-verify store bytes. inventory_hash/winners_hash on BuildPlan set independently from whichever refs are present; workload_id = inventory ref's content_hash if present, else None -- NEVER a hash of inventory+winners combined, since winners already has its own BuildPlan.winners_hash slot.

3. CampaignStageExecutor: replace inventory_ref param with generate_inputs: Mapping[str,ArtifactRef] + generate_needs: frozenset[str]. _run_generate validates frozenset(generate_inputs)==generate_needs (not just non-empty), passes a By-kind dict to the generate worker. Generate worker result DROPS "workload_id" entirely -- the lane already knows it before graph construction; generate discovering it was always backwards. Generate's PipelineService.expected() envelope stays narrow (source_expected only) for ALL generated builds including needs=[] -- inventory/winners may legitimately come from a different build_plan/campaign/run, so build/campaign identity must not become an invariant across the generate boundary just because the need set happens to be empty.

4. make_generate_worker(..., required_needs: frozenset[str]) -> Callable[[Mapping[str,ArtifactRef]], dict]: validates inputs against required_needs, extracts inventory_ref/winners_ref by key (each optional), calls build_manifest with inventory=(Inventory.from_json(...) if present else None), winners=(read_winners(...) if present else None), correctness_source=(winners_ref.path if present else None) -- winners feed BOTH the winners= filtering param AND correctness_source=, matching what the current CLI already does; don't assume winners only matters for replay-slim filtering.

5. campaign_plan.build_stage_graph(..., include_generate: bool, include_runtime_smoke: bool, ...) -- ONE flexible function, conditionally appending the generate/runtime-smoke StageNodes and adjusting the build node's dependencies tuple, NOT four named per-build-kind graph builders (config.Build has no kind enum; stock/control/record/tune/replay are just names, not architecture). include_generate = build_cfg.variant_set is not None; include_runtime_smoke = spec.validation is not None. materialize stays its own separate graph (source_slice_id identity-resolution boundary, unchanged).

6. make_build_worker(..., lane_inputs: Mapping[str,ArtifactRef], has_generate_stage: bool, ...): when has_generate_stage is False, expects ZERO stage inputs (not a fabricated empty generated-tree) and skips generated_root/generated_tree.verify_tree entirely; cmake_configure_args already tolerates generated_root=None/inventory=None via its existing `if X is not None` guards -- confirmed, no change needed there. metadata['generated_compile_inputs_hash'] becomes None for non-generated builds; reuse check becomes None==None (correctly reusable) rather than needing special-casing.

7. _run_workload_scoped (rename _run_build_scoped) drops its `if not self.workload_id: raise` entirely; gains execution_expected(source_slice_id, build_plan_id, run_id, workload_id) that omits the workload.workload_id key entirely when workload_id is None (not an empty-string placeholder).

8. Runtime-smoke: construct make_smoke_worker only when spec.validation is not None; its factory also gains workload_id: str | None, emitting an empty workload provenance namespace when absent. CampaignLaneResult: workload_id, manifest_ref, generated_tree_ref, smoke_ref ALL become Optional; input_refs: tuple[tuple[str,ArtifactRef],...] added. Extraction keyed off graph node membership (`if generate_stage_id in build_graph.nodes: ... else: None`), not a fixed-shape assumption.

9. REAL TRAP flagged, not in the original 5 bullets: run-scoped filesystem/store paths (work/runs/<run_id>/generate/generated/, runs/<run_id>/generate/... in the store) are NOT lane-scoped -- if RE18's multi-lane runner passes one shared run_id to multiple lanes, two generate lanes collide even though their stage_ids differ. Must be resolved (unique run_id per lane call, or path namespacing by a stable lane_id) BEFORE RE18, not discovered by it.

Regression matrix (the RE17 acceptance gate): stock (no generate, no inputs, workload=None, smoke optional), control/record/audit (generate with {} inputs, workload=None, smoke optional), tune (generate with {inventory}, workload=inventory hash, smoke optional -- must remain byte-for-byte equivalent to today's proven path), replay (generate with {inventory,promoted-winners}, workload=inventory hash, winners_hash feeds build_plan_id, smoke optional). Plus negative cases: missing/unexpected input names, kind-mismatched ArtifactRef, tampered incoming artifact bytes, artifact from outside the shared store, artifact whose source provenance disagrees with the materialized source, stock never touching the generate worker or generated-tree filesystem at all, validation=None never calling make_smoke_worker.

Implementation order: (1) generic spec.inputs + resolution/publication, (2) BuildPlan winners_hash wiring + optional workload_id, (3) executor generate-inputs generalization + drop worker-established workload_id, (4) make_generate_worker generalization, (5) build worker generalization for no-generate builds, (6) build/smoke provenance optional-workload generalization, (7) build_stage_graph structurally conditional, (8) result refs optional, (9) CLI/validation optional, (10) the regression matrix tests.
