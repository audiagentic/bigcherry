# Structurally enforce work-root/checkout non-overlap, not just default-topology safety

## Description

Make ProjectContext reject any explicit work-root/upstream-checkout overlap. Default topology is safe today, but explicit misconfiguration can still alias campaign writes into the upstream checkout.

## Steps

Resolve both paths; reject equality, work_root inside upstream_repo, and upstream_repo inside work_root; use os.path.commonpath/path.resolve semantics rather than string prefixes; preserve allowed sibling paths; add clear error text and tests.

## Detailed Solution & Technical Design

Put the guard at ProjectContext.resolve() after absolute normalization, before constructing derived roots. This protects every HIP and future Vulkan lane centrally and avoids per-backend checks. Keep project_root distinct from work_root and retain existing default behavior.

## Code Samples & Guidance

```python
# context.py, after work/upstream are resolved
try:
    common = os.path.commonpath((str(work), str(upstream)))
except ValueError:
    common = None  # different Windows drives are disjoint
if common is not None and Path(common) in (work, upstream):
    raise ValueError(
        f"work_root and upstream_repo must be disjoint: {work} vs {upstream}"
    )
```
Prefer a helper `_paths_overlap(a, b)` using resolved Paths and `commonpath`; do not use string `startswith`, which misclassifies siblings such as `work` and `work-old`.

Tests should cover equal paths, work under upstream, upstream under work, sibling paths, Windows different-drive paths, and symlink-resolved aliases. Assert the error occurs during ProjectContext.resolve(), before any directory creation.
