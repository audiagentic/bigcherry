# Structurally enforce work-root/checkout non-overlap, not just default-topology safety

## Description

GPT review (RV57 on RE23) found test_new_campaign_work_root_never_overlaps_legacy_checkout_root (test_campaign_build_flip.py) proves the DEFAULT topology is safe, not that overlap is structurally prevented. ProjectContext.resolve() does not reject a BIGCHERRY_WORK_ROOT explicitly set to overlap the vendor checkout (e.g. set to a path under or equal to the upstream checkout root). This is pre-existing resolver behavior, not a regression introduced by RE23 -- it would require a deliberately adversarial or careless BIGCHERRY_WORK_ROOT misconfiguration to trigger, not something this project's actual operational pattern does today.

## Steps

Add an explicit rejection in ProjectContext.resolve() (or wherever work_root is finally settled) for: work_root == upstream_repo; work_root nested below upstream_repo; upstream_repo nested below work_root. Add a real test proving each of these three cases fails closed with a clear error, not just that the default case is disjoint.
