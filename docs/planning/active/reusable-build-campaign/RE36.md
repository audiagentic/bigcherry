# Vulkan experiment execution adapter: forceable selector interface + route telemetry

## Description

External review (2026-08-20): HIP has mature forced-candidate/replay/generalisation machinery (forced MMVQ geometry aborts loudly rather than silently falling back to native -- confirmed real this session, patch 0650). Vulkan RD plans (matmul routing, coopmat, FA routing, submission batching) have no equivalent way to force a specific selector/shader and prove it actually fired. Without this, Vulkan RD plans remain sophisticated manual runbooks rather than reproducible experiments -- the planning model is backend-neutral (EC16's target.kind already handles this), but the EXECUTION machinery still isn't.

## Steps

Build a Vulkan equivalent of the forced-candidate interface: force selector X, force shader family Y, set specific pipeline params (rm_kq, coopmat on/off, small-N route, submission cap, output device), then prove the selected path actually fired via route telemetry -- same fail-loud-not-silent-fallback discipline HIP's 0650 already establishes.
