# Vulkan experiment execution adapter: forceable selector interface + route telemetry

## Description

Add a Vulkan-native forced execution and route-observation contract after RE30's dispatch hook exists. This is the Vulkan analogue of HIP's forced variant machinery, not a shared candidate ABI.

## Steps

Define force selector/shader/pipeline parameter inputs; validate them before dispatch; refuse unsupported or unknown forced requests rather than silently selecting native; emit selected route, requested route, fallback reason, candidate/recipe digest, and device identity; expose bounded logs/coverage suitable for campaign evidence.

## Detailed Solution & Technical Design

Mirror HIP's fail-loud GGML_HIP_DISPATCH_MODE/forced candidate behavior and route telemetry at the contract level. Implement Vulkan-specific recipe selectors and a native fallback path for non-forced/replay misses. Keep forced diagnostics non-promotable unless correctness/timing evidence explicitly qualifies them.

## Code Samples & Guidance

HIP-aligned Vulkan environment contract, but Vulkan-native names:
```text
GGML_VK_DISPATCH_MODE=native|record|tune|replay
GGML_VK_FORCE_RECIPE=<stable recipe id>
GGML_VK_FORCE_PIPELINE=<pipeline id>
GGML_VK_ROUTE_LOG=<bounded jsonl path>
```
A forced request must return an explicit `unsupported`/`invalid` result and never silently fall back while claiming the forced route fired. Normal replay misses may fall back to native, but must emit `miss_reason` and `fallback=native`.

## Validation

Test valid force, unknown force, capability rejection, device-lost/timestamp failure, native mode, replay hit/miss, bounded route log, and correctness parity. Keep forced diagnostics non-promotable until the evidence contract says otherwise.
