# Migrate dispatch DB and tuning artifacts to campaign identities

## Description

Add explicit DB schema v3 migration and carry source/build/workload/campaign identities through inventory, measurements, promotion, replay, and bundles.

## Steps



## Detailed Solution & Technical Design


### Schema-4 design (locked per RV50; code claims verified 2026-08-17)

Verified state at start: CURRENT_DB_SCHEMA_VERSION="3" (inventory.py), only sql/migrations/0003_campaign_identity.sql exists, and the build table in sql/dispatch-db.sql still carries the legacy `UNIQUE(source_revision, manifest_hash, signature_schema, hardware_schema, variant_set, build_descriptor_hash)` while campaign-identity columns (source_slice_id, build_plan_id, effective_build_id, campaign_run_id, workload_id) sit nullable on top. The schema's row identity does not match the identity model — wrong DB identity can corrupt tuning evidence.

**4.1 Naming: `identity_scope`, NOT `provenance_class`.** Artifact provenance already uses production/imported-legacy/development/diagnostic; a same-named DB column with values like campaign/legacy-imported invites accidental semantic mixing. So: `identity_scope TEXT NOT NULL CHECK(identity_scope IN ('campaign','legacy-imported'))`.

**4.2 Real unique identity, per scope (partial indexes on rebuilt table):**
- `CREATE UNIQUE INDEX build_campaign_identity_uq ON build(source_slice_id, build_plan_id, effective_build_id) WHERE identity_scope='campaign'`
- `CREATE UNIQUE INDEX build_legacy_identity_uq ON build(source_revision, manifest_hash, signature_schema, hardware_schema, variant_set, build_descriptor_hash) WHERE identity_scope='legacy-imported'` (the old table-level UNIQUE moves here and applies to legacy rows only)
- SQLite cannot conditional NOT NULL, so add: `CHECK(identity_scope='legacy-imported' OR (source_slice_id IS NOT NULL AND build_plan_id IS NOT NULL AND effective_build_id IS NOT NULL))`.

**4.3 Migration safety (sql/migrations/0004_build_campaign_identity.sql).** SQLite needs a full table rebuild to drop the table-level UNIQUE: PRAGMA foreign_keys=OFF outside the transaction; BEGIN; CREATE TABLE build_v4 (all existing fields + identity_scope + both CHECKs); copy every row deriving identity_scope — ONLY rows carrying the COMPLETE campaign identity (source_slice_id AND build_plan_id AND effective_build_id all non-null) become 'campaign', everything else 'legacy-imported' (never silently relabel partial rows as campaign evidence; observation/measurement/winner/replay_miss FK children move with their build row); DROP TABLE build; ALTER TABLE build_v4 RENAME TO build; recreate all indexes incl. the two partial uniques + existing campaign-identity indexes; UPDATE schema_meta SET value='4'; COMMIT; PRAGMA foreign_keys=ON; PRAGMA foreign_key_check must come back clean.

**4.4 CampaignDatabaseIdentity dataclass replaces five loose string args:**
`@dataclass(frozen=True) class CampaignDatabaseIdentity: source_slice_id: str; build_plan_id: str; effective_build_id: str; campaign_run_id: str; workload_id: str`. Used in build_database(), load_measurements(), and the DB update/import paths. identity=None means diagnostic/imported-legacy. effective_build_id is available from CampaignLaneResult.effective_build_id (added in RE25.2) without reparsing runtime manifests.

**4.5 Never mutate immutable DB artifacts.** Tune flow: published inventory DB → copy into the run workspace → tuner modifies the working copy → publish the resulting DB as a NEW dispatch-db artifact. No SQLite writes directly against an existing ArtifactStore object, ever.

**4.6 Required tests:** two campaign builds sharing the legacy key but differing in campaign identity coexist; identical campaign build identity reuses one row; a legacy and a campaign row can share the old legacy key; schema-3→4 migration with child FK rows survives and foreign_key_check is clean; production campaign rows have non-null build identity; legacy-imported rows remain visibly legacy; portable replay-cache bytes do NOT change solely because campaign DB identity changed. RE15 supplies the real-hardware integration proof (acceptance criterion 2); this item closes on its own tests.
