# ArtifactDescriptor persistence + kind-specific provenance contracts

## Description

RE08's remaining RV48-required work, split out because RE08's core verified defect (raw-path provenance laundering) is closed and doesn't need to wait for this broader design surface. Add ArtifactDescriptor -- a frozen, independently-serializable dataclass(artifact_id, kind, relative_path, content_hash, provenance: ProvenanceV2) -- that ArtifactStore can persist and rehydrate (RE11's cross-process resume needs exactly this: today CampaignRun.records is process memory only). Add kind-specific provenance contracts so provenance.validate() stops accepting all-five-namespaces-empty as sufficient for production artifact kinds.

## Steps

1. Design ArtifactDescriptor as a frozen dataclass, JSON-serializable (no Path objects -- relative_path as a string), with a stable artifact_id derivation.
2. Add ArtifactStore.persist_descriptor()/rehydrate_descriptor() (or equivalent) so a descriptor round-trips: persist, rehydrate, byte-verify against the store.
3. Define kind-specific provenance contracts: runtime-bundle requires source slice + source-plan/patch lineage + build plan + effective build + runtime-bundle identity; inventory requires producer source/build identity; promoted-winner/correctness artifact requires producer tune namespace; release report requires campaign/report identities.
4. Wire contract validation into provenance.validate() (or a new provenance.validate_for_kind()) so a document missing its kind's required fields is rejected, not silently accepted because the five namespaces merely exist as (possibly empty) dicts.
5. Migrate real producers (campaign_workers.py's generate/build/smoke workers, campaign_lane.py's materialize/input-resolution) to populate the now-required fields per kind.

## Detailed Solution & Technical Design

GPT-auto-agent full implementation plan (2026-08-17, verified against d9b393c). Key architectural rule for RE25/RE10/RE09/RE12/RE11 together: bytes, descriptor identity, provenance, and campaign execution state remain SEPARATE layers -- never collapse them into one hash or one SQLite record.

Sequence within RE25 (land as separate commits): RE25.1 typed ProvenanceV2 + ArtifactDescriptor + ArtifactRef.artifact_id + descriptor store/rehydration. RE25.2 campaign materialize/generate/build/smoke produce descriptors with full lineage. RE25.3 sticky imported/development taint + kind-specific promotion contracts (resolves the RE25a/RE25b ordering question already on this item: taint propagation via derived_provenance_class()/derive() makes raw-path rejection safe without needing full descriptor rehydration everywhere first -- an imported-legacy artifact can flow through the pipeline, get built, but never become promotable).

FULL DESIGN (see code_samples for exact signatures):

1. Move ArtifactRef into artifacts.py (currently in pipeline.py); keep a compat re-export. Add ArtifactLocator(artifact_id: str) as a third LaneInputValue variant alongside Path/ArtifactRef.

2. Replace provenance.py's dict-shaped documents with frozen typed ProvenanceV2 (project/source/build/workload/campaign namespaces as their own frozen dataclasses, not raw dicts). document()/from_document() strict round-trip, reject unknown fields.

3. Sticky taint: derived_provenance_class(parents, local_class) -- an artifact derived from any imported-legacy/development/diagnostic parent inherits that class even if the current stage is otherwise 'production'. derive() builds a full ProvenanceV2 from parents + local identity. This is what makes it safe to keep accepting raw-Path cross-run inputs (the real record->tune/replay workflow needs them) while guaranteeing they can never silently become promotable evidence.

4. Kind-specific production contracts: validate_for_kind()/require_promotable() check a fixed required-field list per artifact kind (source-metadata, manifest, generated-tree, binary, runtime-bundle, record-jsonl, inventory, dispatch-db, tuning-measurements, promoted-winners, replay-cache, comparison-report). require_promotable additionally requires project.provenance_class=='production'.

5. ArtifactDescriptor(schema_version, artifact_id, kind, relative_path, content_hash, provenance: ProvenanceV2) -- artifact_id = blake2b digest of the descriptor body (excluding artifact_id itself). Stored under <store>/.descriptors/v1/<id[:2]>/<id>.json -- a CENTRAL descriptor namespace, NOT one sidecar per byte path, because one immutable build byte object can legitimately participate in several later campaign runs with different provenance chains.

6. ArtifactStore gains persist_descriptor()/load_descriptor()/rehydrate(artifact_id, expected_kind=, require_promotable=)/publish_bytes_ref()/publish_file_ref()/publish_json_ref(). rehydrate() re-verifies: parse descriptor -> recompute artifact_id -> validate provenance for kind -> path stays inside store -> rehash actual bytes -> compare content_hash -> return ArtifactRef. A tampered descriptor OR tampered bytes both fail closed.

7. new tools/bigcherry/runtime_bundle.py centralizes runtime-bundle manifest parsing/verification (currently duplicated ad hoc in make_smoke_worker) -- RE10/RE12 both need the same operation.

8. Real call-site migration: workspace.bigcherry_revision(), CampaignStageExecutor gets project_revision/local_provenance_class/source_provenance threaded through; _run_materialize constructs real SourceProvenance from materialize_source()'s own returned metadata (already has everything post-RE04/RE05 fixes); generate/build/smoke construct BuildProvenance from real BuildPlan + lane_inputs; _resolve_lane_inputs's raw-Path branch now publishes via publish_bytes_ref with imported-legacy provenance (no more manual provenance dict construction).

9. CampaignLaneResult gains effective_build_id: str (populated from runtime_bundle_ref.provenance.build.effective_build_id) so RE09 doesn't have to re-parse JSON for it.

Tests (real git fixtures + fake-compiler-only pattern, matching test_campaign_cutover_audit.py): descriptor round-trip across a NEW ArtifactStore instance; artifact-byte tamper fails; descriptor tamper (provenance/hash edited, same filename) fails; path-traversal descriptor fails; two descriptors sharing one byte object with different campaign.run_id both coexist with distinct artifact_ids; incomplete production runtime-bundle rejected by require_promotable; same incomplete provenance persists fine as imported-legacy but stays non-promotable; dirty materialization (allow_dirty_bigcherry=True) always produces 'development' class, never 'production'; raw inventory taint propagates end-to-end through a REAL execute_campaign_lane() run to the final runtime bundle; a second ArtifactStore instance + second execute_campaign_lane() call rehydrates a still-production inventory; wrong-source production inventory rejects rather than silently passing as unknown-legacy.

RE25 is done when: a process can terminate, a second process given only (store root, artifact_id) can recover a byte-verified, kind-validated, provenance-complete ArtifactRef.

## Validation

An ArtifactDescriptor round-trips through the store (persist, rehydrate, byte-verify). Each kind-specific contract rejects a document missing its required fields. Existing empty-namespace test fixtures either get real fields or are explicitly grandfathered as non-production kinds -- audit however deliberately calls out empty namespaces as 'a useful early-stage shape but not complete production provenance', so production kinds must fail without real fields.

## Effort & Risk

M -- touches provenance.py's validation contract, a shared primitive multiple producers depend on; must not silently break the real hardware-proven RE16-RE22 provenance flow while tightening it.
