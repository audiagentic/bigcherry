# Vulkan-aware device-visibility wiring for build's runtime smoke path

## Description

RE30's real end-to-end verification (Vulkan stock lane, bigcherry build producing a working llama-server) had to work around a real gap: smoke_environment_for_hip_devices() in campaign_lane.py is HIP-only -- it only knows how to set HIP_VISIBLE_DEVICES. Passing --model to `bigcherry build` for a Vulkan lane today would try to set a HIP-shaped device-visibility env var, not the Vulkan-correct GGML_VK_VISIBLE_DEVICES, so the built-in runtime smoke path silently does the wrong thing (or nothing) for Vulkan lanes. This session's verification started/tested the server manually instead of through build's own --model smoke path.

## Steps

Add a Vulkan-aware counterpart (e.g. smoke_environment_for_vk_devices) or generalize the existing helper to take a backend parameter and emit the correct env var name per backend. Thread it through cmd_build_new the same way the HIP one is threaded today. Real-hardware test: bigcherry build --lane vulkan-stock:vulkan-stock:vulkan-linux --model <path> should smoke-test the built server automatically, restricted to the confirmed-safe devices (GGML_VK_VISIBLE_DEVICES must be set explicitly -- it defaults to ALL dedicated GPUs if unset, verified this session).
