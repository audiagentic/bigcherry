# Evaluate adding Vulkan as a tunable build line (patchable, campaign/tune/replay-capable like HIP)

## Description

User asked (2026-08-20) whether Vulkan can be included as a patchable build stream with the same campaign tune/replay machinery BigCherry runs for HIP, so Vulkan-side patches/kernels could be added later. Not started -- this item exists to scope and track the decision, not to implement anything yet.

## Detailed Solution & Technical Design

Two distinct asks were identified when this came up in conversation, and they have very different cost:

1. **Compile llama.cpp's stock Vulkan backend alongside HIP.** Cheap. `GGML_VULKAN=ON` is just another upstream cmake flag; a `[build.vulkan]` variant with no BigCherry dispatch/autotune layer attached would build as a plain `stock`-style lane (no patches, no tuning). No architectural work needed beyond a recipes.toml entry.

2. **Give Vulkan kernels the same autotune/dispatch/replay/tune campaign treatment HIP gets** (candidate registry, can_execute/launch function pointers, the tuner, the replay cache, RE15-style acceptance chain). This is the expensive one and is what the user actually asked about. BigCherry's entire dispatch layer (hip-autotune-dispatch.cuh, candidate descriptors, launch function-pointer typedefs, the replay cache binary format) is HIP-specific by construction -- compiled only under GGML_USE_HIP, with candidate launch signatures tied to HIP calling conventions (__global__ launches, dim3 grid/block, HIP stream types). None of it carries over to Vulkan's dispatch model (pipeline objects, descriptor sets, command buffers -- no __global__ launch shape at all). None of the 11 RD-prefixed experimental patches or the candidate-registry model would carry over either.

Realistic scope for (2): a parallel dispatch/candidate abstraction with its own launch-function typedef, its own replay cache format (or a generalized one both backends implement), its own tuner integration point, and campaign_workers.py/campaign_build.py changes to build/tune/replay a Vulkan-flavored lane the way the HIP lanes work today. This is architecturally closer to a second implementation of RE01-RE13's foundational work than an extension of it.
