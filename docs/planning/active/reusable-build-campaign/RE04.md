# Add host-local upstream repository and isolated source materialisation

## Description

Materialise an exact, immutable source-input specification into a detached worktree and reuse it only after BOTH its requested materialisation inputs AND its resulting effective tree have been revalidated (revised objective per RV48 audit - this item needs a correction, not just documentation).

## Steps



## Detailed Solution & Technical Design

VERIFIED DEFECTS (RV48, all against current code): (1) campaign_source.source_plan_id hashes only upstream_revision / overlay_enabled / sorted patch IDs / required_state - no patch content, no overlay content; an in-place edit of a patch module under its canonical ID reuses the old materialisation. (2) materialize_source's cache-hit path compares exactly those same ID-level fields and returns the stored metadata without recomputing anything - the cached worktree is never re-hashed against the stored source_tree_oid/source_slice_id, so a modified cached source dir is another false reuse. (3) The clean-BigCherry check lives only inside workspace.materialize (fresh-creation path); a cache hit returns before it ever runs. (4) campaign_lane._materialize_worker hard-codes allow_dirty_bigcherry=True and execute_campaign_lane exposes no override - dirty-tree execution is implicit in the public lane API, contradicting RE16's design that it be an explicit development/harness escape hatch only.

REQUIRED FIXES: (a) Introduce a materialisation-plan identity containing the fully resolved upstream commit, overlay content identity, patch_set_id with ordered module IDs + content hashes, and required state; key the destination directory by THAT identity. Do not make source_slice_id carry these labels - it remains resulting-content identity (see RE05). (b) On a cache hit, recompute the effective source tree and require equality with the stored source_tree_oid/source_slice_id before reuse; a modified cached worktree fails closed rather than compiling stale bytes. (c) Move the clean-project check so it surrounds BOTH fresh creation and cache reuse: unless an explicit development override is set, dirty BigCherry source rejects either path. (d) execute_campaign_lane defaults to allow_dirty_bigcherry=False with an explicit argument; only the RE14 harness passes True.

Preserve what already works: detached-worktree semantics, temporary-index effective-tree computation, allowed-untracked overlay identity, exact patch application.
