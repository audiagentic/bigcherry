# Extend patch_catalog.py metadata: PLAN_IDS, BACKENDS, SUBSYSTEMS, REQUIRES, CONFLICTS, HARDWARE

## Description

Complete declarative patch metadata and validation without creating duplicate relationship authorities. Catalog already carries kind/origin/backend/state plus plan_ids/backends/subsystems/hardware/options; patch modules already own and enforce REQUIRES/CONFLICTS.

## Steps

Validate catalog/module 1:1 coverage and state agreement; validate plural fields and plan IDs; add catalog references for descriptive plan/backend/subsystem/hardware data; cross-check catalog backend/options against PatchContext; expose module REQUIRES/CONFLICTS through snapshot/CLI rather than duplicating them; add provenance/retirement link checks against external-sources.toml.

## Detailed Solution & Technical Design

Keep patchset.py module constants authoritative for executable dependency/conflict resolution, as HIP's exact resolver already enforces them. Keep catalog.toml authoritative for descriptive classification and lane applicability metadata. If a relationship needs to become declarative, migrate it deliberately with one source of truth; never read two optional requires/conflicts fields. Include canonical metadata in future identity only when the identity contract is versioned and tested.

## Code Samples & Guidance

Catalog records may evolve additively:
```toml
[[patch]]
id = "1207_rd17_moe_topk_down_fold"
kind = "enhancement"
origin = "external-fork"
backend = "hip"
backends = ["hip"]
plan-ids = ["RD17", "HI73"]
subsystems = ["moe", "mmvq"]
hardware = ["gfx1100", "gfx1201"]
external-source = "stew675-rdna-boosts"
```
Do not add `requires` or `conflicts` here while module constants remain executable authority. Add `CatalogEntry.plan_ids_for()` compatibility that returns plural values or falls back to singular `plan_item`.

## Validation

Add fixtures for missing/duplicate IDs, invalid backend/kind/state, singular/plural disagreement, missing external source, and module state mismatch. Cross-check every module's `REQUIRES`/`CONFLICTS` through PatchModule, not a second catalog field.
