# Add explicit campaign-backed release promotion

## Description

Require validated campaign/run/report hashes for promotion pointers while preserving release gates and immutable evidence.

## Steps



## Detailed Solution & Technical Design

FULL INTEGRATION PASS (RV48 audit). VERIFIED: the compatibility probe in release_validate.py still shells out to `python -m bigcherry --llama-root <checkout> legacy-build --recipe <recipe>` against a temporary checkout, and the existing release record still carries legacy concepts such as a mutable-checkout tree_state. That probe becomes an ACTUAL breakage when RE23 deletes legacy-build, so RE13 is an explicit dependency of the final deletion story.

REQUIRED: (1) The new release-support record points at immutable source/build/runtime/campaign/report artifacts instead of a mutable checkout state. (2) A promotion pointer contains: report hash, campaign/run identity, promoted source/build/runtime identities, required architecture evidence, and replay artifact identity (the PromotionPointer builder exists with schema-v2 shape; wire it to real records). (3) Migrate release_validate.probe() to the canonical APIs: for an arbitrary upstream ref it constructs a temporary in-memory source config whose ref is the fully resolved commit and runs the SAME isolated materialisation/build API against a temporary ProjectContext - do NOT reintroduce a general --ref override into canonical production builds just to serve one compatibility probe.
