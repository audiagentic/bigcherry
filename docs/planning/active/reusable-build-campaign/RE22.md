# Fail-closed cutover tests for the multi-lane build flip

## Description

The tests that actually prove RE14's acceptance criterion ('the default campaign path contains no implicit fallback to legacy') holds after the RE21 flip. Without these, the flip is just an assertion, not evidence.

## Steps

1. Poison/mock legacy cmd_build (e.g. monkeypatch it to raise if called) and confirm `bigcherry build` for every canonical-profile lane still succeeds without ever invoking it.
2. Confirm an unsupported legacy-only option (--groups, --states) passed to `build` fails closed with exit 2 and a message naming `legacy-build`, performing zero work -- not a silent redirect.
3. Confirm `build --all` produces exactly the canonical lane set from RE19, no more, no fewer.
4. Confirm one lane failing (fault-injected) does not corrupt or misidentify a sibling lane's result (extends RE18's own test with a real CLI-level check).
5. Confirm no lane's execution path references _ensure_tree_state, _reset_tree, or legacy _build_dir -- a static/grep-based check plus a runtime assertion that the new path's work_root never overlaps the legacy checkout path.

## Detailed Solution & Technical Design

gpt-auto-agent design (RE14 round 19): 'Then step 7 is legitimately closed' once these pass -- named as the explicit acceptance bar for the flip, not optional hardening after it.
