## Detailed Solution & Technical Design


### Execution order (locked per RV50 — one complete release evidence chain, the single integration finish line)

Dependencies: RE25.3 closed + RE09 + RE10-min + RE12-min green. After this runs, stop adding architecture.

Use a clean production-class BigCherry checkout and a fresh acceptance store.

A. Source/build — materialize; build the record lane; verify source/runtime-bundle descriptors rehydrate; record ALL artifact IDs in an acceptance manifest.
B. Record — run the representative workload through the RECORD runtime bundle (immutable, never the build dir); publish record-jsonl.
C. Inventory — consume that record descriptor; produce production inventory + schema-4 dispatch-db; query the DB and assert non-null campaign identity columns.
D. Tune — build/use the tune runtime bundle; copy the dispatch DB to a working run location; run tuning; publish the resulting DB + tuning evidence as NEW immutable artifacts.
E. Promotion — run the existing promotion policy; publish promoted-winners; require promotable provenance.
F. Replay — build replay-full from descriptor-backed production inventory/winners; verify its runtime bundle is still production; export + publish the replay-cache descriptor.
G. Runtime validation — run the replay workload from the immutable runtime bundle; verify EXACT replay coverage (no misses, incompatibles, candidate-unavailable or rerun-required outcomes).
H. Balanced performance evidence — construct artifact-backed comparison arms; run the RE12 balanced comparison; produce the immutable comparison-report; confirm valid + decision-grade.
I. Release pointer — build the promotion pointer from the STORED report (never caller booleans); persist the release promotion; reload and validate pointer/report/artifacts independently.
J. Negative evidence — deliberate tamper rejection for at least THREE distinct stages, each on a DISPOSABLE copy of the acceptance store (never corrupt the canonical evidence): flip an inventory byte → downstream tune must refuse; flip a replay-cache/runtime member → validation/comparison must refuse; flip the comparison-report or its descriptor → release promotion must refuse.
K. Legacy absence — capture the exact commands/code paths used; verify no legacy-build, mutable checkout, _reset_tree, _ensure_tree_state or old _build_dir participated (static + runtime check per acceptance criterion 8).
L. Platform verification — full Windows suite; full Brutus/Linux suite; relevant RE24 adversarial matrix; one current-head real GPU run.
