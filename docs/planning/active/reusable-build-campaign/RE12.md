# Implement explicit balanced comparison planner and campaign reports

## Description

Preserve A/B statistics while adding identity-aware arms, intentional-difference policies, pairwise comparisons, and report generation.

## Steps



## Detailed Solution & Technical Design

CONNECT THE TWO HALVES (RV48 audit). The identity-aware pair planner (comparisons.py) and ab_benchmark's real balanced/interleaved schedules + statistical machinery exist but are still two halves rather than one production flow.

REQUIRED: (1) Benchmark arms must be built from immutable campaign artifacts - a production arm identifies at least the runtime bundle, source slice, build plan, effective build, workload, replay-cache identity where applicable, execution environment and hardware/device assignment. (2) The planner explicitly enumerates the ALLOWED causal differences before launching runs; any undeclared difference rejects the comparison (the existing fail-closed difference check generalises to this). (3) ab_benchmark executes the balanced schedule and emits an immutable COMPARISON-REPORT artifact linking all arm descriptors, raw run logs, validity checks, effect estimates and confidence intervals. (4) That report is the thing RE13 may promote; manual executable paths remain diagnostic input, not release-grade comparison evidence.
