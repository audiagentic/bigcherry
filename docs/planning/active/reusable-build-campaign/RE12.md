## Description

Preserve A/B statistics while adding identity-aware arms, intentional-difference policies, pairwise comparisons, and report generation.

## Steps



## Detailed Solution & Technical Design

GPT-auto-agent full implementation plan (2026-08-17), fourth priority after RE25/RE10/RE09. Depends on RE25 (comparison-report artifact kind + provenance) and benefits from RE10 (real lifecycle stage results to compare). New tools/bigcherry/campaign_compare.py.

campaign_planner.plan() gains a real CampaignPlan(schema_version,profile_name,lanes,provenance_class) with a real campaign_plan_id property (hash of source/build/platform names, generation architectures, input artifact IDs, binary path, compiler overrides, smoke model hash+settings+env, profile name -- NEVER local filesystem paths). If any input is still a raw Path, provenance_class='imported-legacy' and the plan cannot produce a promotable comparison report.

comparisons.py gains real typed BenchmarkArm (runtime_bundle_artifact_id, binary_artifact_id, replay_cache_artifact_id, source_slice_id, build_plan_id, effective_build_id, workload_id, environment, devices: DeviceAssignment) replacing path-carrying arms; ComparisonPlan(left,right,execution: BenchmarkExecutionSpec,allowed_differences,label) with comparison_plan_id. Allowed-difference checking runs BEFORE any GPU process, comparing runtime_bundle/binary/replay_cache/source_slice/build_plan/effective_build/workload/environment/device identity.

ab_benchmark.py: extract run_arm_capture() (real subprocess execution + metric parsing) as a reusable primitive the CLI's existing _run_arm() becomes a thin wrapper around -- production comparison calls the SAME statistics functions (schedule/block_bootstrap_effect) rather than duplicating them.

New ComparisonReport(schema_version,comparison_plan_id,campaign_plan_id,campaign_run_id,label,left,right,allowed_differences,schedule,runs: tuple[BenchmarkRunEvidence,...],effects: tuple[MetricEffect,...],required_architectures,decision_grade,valid) -- an immutable comparison-report artifact kind (RE25's contract list already reserves this kind). run_comparison() rehydrates both arms via ArtifactStore, requires production provenance, verifies runtime bundles, THEN launches runs; publishes every raw stdout/stderr/coverage log as its own ArtifactRef so the report is fully self-contained evidence.

promotion.py gains pointer_from_comparison_report() replacing the caller-trusted pointer_from_campaign_result() for release-grade promotion: rehydrates the report, requires report.valid AND report.decision_grade, cross-checks the replay arm's runtime-bundle/source/build identity against the actual CampaignLaneResult, derives campaign_plan_id/campaign_run_id/architectures from the REPORT not from caller arguments. PromotionPointer bumps to schema 3 (adds report_artifact_id/source_metadata_artifact_id/binary_artifact_id/replay_artifact_id alongside the existing hash fields) while from_document() keeps accepting persisted schema-2 pointers with the new fields defaulted to None -- pointer_from_campaign_result() stays as a diagnostic/back-compat API only, not used by release-grade callers after this lands.

Tests (test_re12_campaign_comparison.py): two real CampaignLaneResults via execute_campaign_lane() with a REAL executable fake-compiler-produced benchmark script (not mocked); real balanced comparison run + report rehydration; every report log/coverage artifact ID resolves; undeclared source/build/environment/device difference rejects before any executable runs; tampered runtime .so rejects before run; one non-exact replay-coverage outcome makes report invalid; pointer_from_comparison_report() obtains plan/run/report identity from the report alone, and rejects a report pointing at a different replay runtime bundle; schema-2 pointers still load.
