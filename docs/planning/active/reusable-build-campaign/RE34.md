# Restore an independent build-comparison oracle for future toolchain/RDNA-target changes

## Description

Keep an independent build-comparison oracle dormant until a real toolchain, recipe, or RDNA-target change triggers it. Do not resurrect the deleted mutable-checkout legacy path.

## Steps

When triggered, define a second construction path independent of campaign planning; publish both arms through ArtifactStore; compare build/source/runtime identities and selected configuration with check_parity(); record common-mode limitations and residual risk.

## Detailed Solution & Technical Design

Reuse HIP's existing balanced comparison, ArtifactDescriptor, BuildPlan, runtime bundle, and check_parity() infrastructure. Independence means a documented manual/CMake invocation, alternate toolchain, or separately implemented planner—not two campaign arms sharing the same planner/config generation.

## Code Samples & Guidance

Trigger-time recipe:
```text
1. Freeze campaign BuildPlan/ArtifactRef A.
2. Construct B from documented independent CMake/toolchain invocation.
3. Publish B through the same ArtifactStore descriptor validator.
4. check_parity(A, B) plus explicit option/source/toolchain diff.
5. Add one negative test where both arms omit the same required option.
```
Do not add a permanent second planner. Store the independent command, tool versions, environment digest, and manual rationale in the comparison evidence bundle.
