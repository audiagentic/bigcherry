# Restore an independent build-comparison oracle for future toolchain/RDNA-target changes

## Description

RE23 deleted tools/bigcherry/re14_parity_run.py (the legacy-vs-new build comparison harness) once the legacy build path itself was retired. GPT review (RV57 on RE23) found a real, not-yet-acted-on gap: that harness's own docstring said it was meant to be rerun for future toolchain changes, recipe edits, and new RDNA targets, not just the one-time RE14 cutover gate. The rewritten test_parity_loaders.py tests now compare two independently-published new-path arms against each other -- this still exercises check_parity()'s fail-closed logic well (binary_hash divergence, descriptor divergence), but cannot catch a common-mode bug shared by both new-path builds (e.g. both silently omitting the same CMake option). check_parity() itself is untouched and still callable against any two real arms.

## Steps

When a real toolchain change, recipe edit, or new RDNA target actually comes up (not speculatively before one does), build a genuinely independent second construction path to compare against -- e.g. a from-scratch manual build following documented steps, or a build from a different, deliberately-isolated code path -- and run check_parity() against it. Do not resurrect the deleted legacy mutable-checkout mechanics to do this; that mechanism is gone for good reasons (RE14's whole point). This item stays open/low-priority until a concrete triggering change actually happens.
