# Replace platform.vulkan-linux's targets placeholder with real device/ICD identity

## Description

config/recipes.toml's [platform.vulkan-linux] entry currently has targets = ["vulkan-stub"] -- an explicit placeholder, not real device/ICD identity, because the legacy recipes.py loader requires a non-empty targets list for every platform regardless of backend even though cmake_configure_args(backend="vulkan") ignores platform.targets entirely today. Now that a real Vulkan stock build has been verified end-to-end on real hardware (RE30), this placeholder should be replaced with something that actually encodes real device/ICD identity for build/artifact provenance -- right now a Vulkan build's descriptor carries no real device-class information the way a HIP build's AMDGPU_TARGETS does.

## Steps

Design what Vulkan device/ICD identity should look like in build provenance (vendor/device ID class, not raw index -- same discipline as the vk_hardware table's device_class field, RE30 phase 2). Update platform.vulkan-linux (and any future Vulkan platform entries) to carry it for real, and make sure it flows into build descriptor/provenance the way platform.targets does for HIP today, rather than being silently ignored.
