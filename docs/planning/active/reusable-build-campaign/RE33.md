# Replace platform.vulkan-linux's targets placeholder with real device/ICD identity

## Description

Replace platform.vulkan-linux's targets placeholder with typed runtime device/ICD identity without pretending Vulkan runtime identity is a compile target list.

## Steps

Define Vulkan platform identity fields; normalize vendor/device class, stable UUID policy, ICD/driver/API and feature identity; include them in platform/build/runtime provenance; preserve targets only for legacy loader compatibility or remove its semantic use for Vulkan; add descriptor and mismatch tests.

## Detailed Solution & Technical Design

HIP AMDGPU_TARGETS remains compile identity. Vulkan platform identity is a runtime capability/provenance object and must be captured separately from CMake options. Use vendor_id/device_id/device_class, stable device UUID when available, ICD name/version, Vulkan API version, driver version, and capability/shader digest. Raw device indexes belong only in evidence/runtime selection, not reusable artifact identity.

## Code Samples & Guidance

Proposed v2 config shape:
```toml
[platform.vulkan-linux]
backend = "vulkan"
targets = [] # legacy compatibility only; not runtime identity
vendor-id = 4098
device-classes = ["rdna3", "rdna4"]
icd = "auto"
require-vulkan-api = "1.3"
```
Prefer recording actual runtime identity in the platform/device snapshot rather than hard-coding one Brutus ordinal. `targets` must either be optional for Vulkan or explicitly excluded from Vulkan build identity.
