# Generated q1_0 MMVQ timing failure poisons HIP context during tuning

## Description

During the post-HI60 full SMI tuning matrix on Brutus gfx1201, the q1_0 signature m=16,n=1,k=256,bs=[3,2],nr=[1,1] records a launch_failed timing result, then the subsequent correctness execution aborts in quantize_row_q8_1. The same q1_0 filter passes 45/45 in the native Brutus build, so this is a tuning-sweep/generated-candidate context-poisoning path rather than a stock native failure.

## Steps

1. Reproduce with GGML_HIP_TUNE_TRACE_ATTEMPTS=1 and the exact q1_0 shape filter.\n2. Identify the generated candidate and launch stage that causes the illegal HIP access.\n3. Add a narrowly scoped eligibility/quarantine or lifecycle recovery fix only after candidate identity and faulting instruction are known.\n4. Rebuild the pristine Brutus overlay and prove native and tune q1_0 correctness plus the full matrix completion.\n5. Remove any temporary quarantine once a real kernel fix is verified.
