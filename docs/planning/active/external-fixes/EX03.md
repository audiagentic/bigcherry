# Generated q1_0 MMVQ timing failure poisons HIP context during tuning

## Description

During the post-HI60 full SMI tuning matrix on Brutus gfx1201, the q1_0 signature m=16,n=1,k=256,bs=[3,2],nr=[1,1] records a launch_failed timing result, then the subsequent correctness execution aborts in quantize_row_q8_1. The same q1_0 filter passes 45/45 in the native Brutus build, so this is a tuning-sweep/generated-candidate context-poisoning path rather than a stock native failure.

## Steps

1. [x] Reproduce the exact q1_0 signature m=16,n=1,k=256,bs=[3,2],nr=[1,1] with GGML_HIP_TUNE_TRACE_ATTEMPTS=1 in a fresh gfx1201 process; the exact case passed 1/1.
2. [x] Run the q1_0 m=16,n=1,k=256 family with HIP_LAUNCH_BLOCKING=1 and attempt tracing; 14/14 passed, the journal contained 888 durable candidate-attempt events and 12 result events, and no launch/assertion/ROCm/HSA error occurred.
3. [ ] Identify a generated candidate and launch stage that reproduces the illegal HIP access, then identify the faulting instruction before changing eligibility.
4. [ ] Rebuild the pristine Brutus overlay and prove native and tune q1_0 correctness plus the full matrix completion after any verified fix.
5. [ ] Remove any temporary quarantine once a real kernel fix is verified.
6. [ ] Repeat cold full-matrix runs if needed to capture the intermittent sequence while preserving the passing recovery evidence.

## Validation

Historical evidence remains one full SMI tuning run where the q1_0 exact m=16,n=1,k=256,bs=[3,2],nr=[1,1] launch_failed timing result was followed by a quantize_row_q8_1 HIP abort; native q1_0 passed 45/45.

Fresh instrumented Brutus evidence on gfx1201: the exact target filter passed 1/1 with GGML_HIP_TUNE_TRACE_ATTEMPTS=1. A fresh q1_0 m=16,n=1,k=256 family run with HIP_LAUNCH_BLOCKING=1 and attempt tracing passed 14/14; its durable journal contained 901 lines, including 888 attempt events and 12 result events. The run reported zero launch_failed, GGML_ASSERT, illegal-memory, ROCm, HSA, or fatal errors. Candidate attempts included mmq:native:v1 and mmvq:native:v1, and the target shape completed with mmvq:native:v1.

The first candidate of a fresh journal is intentionally not traceable until the first result opens the journal; this is documented by the source and explains why the one-case run has no attempt event. The family run provides subsequent candidate identity and launch-stage evidence for any future reproduction. No candidate-level fault identity or corrective patch has been established.
