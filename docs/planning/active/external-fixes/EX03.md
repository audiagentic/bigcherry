# Generated q1_0 MMVQ timing failure poisons HIP context during tuning

## Description

During the post-HI60 full SMI tuning matrix on Brutus gfx1201, the q1_0 signature m=16,n=1,k=256,bs=[3,2],nr=[1,1] records a launch_failed timing result, then the subsequent correctness execution aborts in quantize_row_q8_1. The same q1_0 filter passes 45/45 in the native Brutus build, so this is a tuning-sweep/generated-candidate context-poisoning path rather than a stock native failure.

## Steps

1. [x] Reproduce the exact q1_0 signature m=16,n=1,k=256,bs=[3,2],nr=[1,1] with GGML_HIP_TUNE_TRACE_ATTEMPTS=1 in a fresh gfx1201 process; the exact case passed 1/1.
2. [x] Run the q1_0 m=16,n=1,k=256 family with HIP_LAUNCH_BLOCKING=1 and attempt tracing; 14/14 passed, the journal contained 888 durable candidate-attempt events and 12 result events, and no launch/assertion/ROCm/HSA error occurred.
3. [x] Make a failed HIP measurement poison the tuning experiment: suppress later candidate launches, correctness copies, final rounds, determinism checks, and SMI queries; preserve the terminal result as non-promotable evidence.
4. [x] Open the diagnostic journal at cold-path entry after signature/hardware digests are available, so the first attempt records candidate, signature, and protocol stage durably.
5. [ ] Identify a generated candidate and launch stage that reproduces the illegal HIP access, then identify the faulting instruction before changing eligibility.
6. [ ] Rebuild the pristine Brutus overlay and prove native and tune q1_0 correctness plus the full matrix completion after any verified fix.
7. [ ] Remove any temporary quarantine once a real kernel fix is verified.
8. [ ] Repeat cold full-matrix runs if needed to capture the intermittent sequence while preserving the passing recovery evidence.

## Validation

Historical evidence remains one full SMI tuning run where the q1_0 exact m=16,n=1,k=256,bs=[3,2],nr=[1,1] launch_failed timing result was followed by a quantize_row_q8_1 HIP abort; native q1_0 passed 45/45.

Fresh instrumented Brutus evidence on gfx1201: the exact target filter passed 1/1 with GGML_HIP_TUNE_TRACE_ATTEMPTS=1. A fresh q1_0 m=16,n=1,k=256 family run with HIP_LAUNCH_BLOCKING=1 and attempt tracing passed 14/14; its durable journal contained 901 lines, including 888 attempt events and 12 result events. The run reported zero launch_failed, GGML_ASSERT, illegal-memory, ROCm, HSA, or fatal errors. Candidate attempts included mmq:native:v1 and mmvq:native:v1, and the target shape completed with mmvq:native:v1.

Post-`2e8728c` clean-overlay validation on Brutus gfx1201 rebuilt the vendor
tree from the pushed source and ran the native and tune q1_0 filters. Native
mode passed 26/26. Tune mode passed 26/26 with
`HIP_LAUNCH_BLOCKING=1`, graphs disabled, and the minimum valid reduced sample
configuration; it wrote 24 durable result records and 1,082 durable attempt
events across 1,107 journal lines. The first attempt payload contained the
signature digest and `stage=isolated_workspace`, proving the cold-path journal
opening and attribution change is present in the hardware binary. The run had
zero launch-failure, assertion, illegal-memory, ROCm, HSA, or fatal matches.
This is recovery/non-reproduction evidence, not candidate-level root-cause
evidence. The source-level fail-closed guard is covered by focused
dispatch-safety and replay-promotion tests. HIP event timing,
correctness-copy, and stream synchronization failures now share the terminal
poison path, and failed native rows cannot enter a replay cache. Real Brutus
fault-injection and candidate-level fault identity remain open.

Before this slice, the first candidate of a fresh journal was not traceable until
the first result opened the journal. The cold-path journal open now removes that
observability hole: future attempts carry candidate, signature digest, and
protocol stage before risky GPU work. No candidate-level fault identity or
corrective patch has been established.

## Notes

EX03 remains open as an intermittent investigation. The exact target and a blocking/attempt-traced q1_0 family run now pass with durable candidate-attempt evidence, but this is recovery/non-reproduction rather than root-cause closure. Do not add a broad eligibility quarantine without candidate-level evidence. Close only after the generated candidate and faulting instruction are identified, or supersede with an explicitly accepted quarantine/monitoring decision.

The poison guard is scoped to the tuner measurement protocol. It suppresses
new uncached tuning work and prevents failed rows from replay export; it does
not retroactively invalidate dispatcher bindings already cached before the
failure, nor does it attempt to reset a potentially poisoned HIP context.
That broader dispatcher quarantine remains a separate decision pending a
reproduced candidate-level fault.
