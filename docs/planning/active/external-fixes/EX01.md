# 1005_prompt_cache_checkpoint_selection anchors broken -- need re-derivation against real source

## Description

patches/1005_prompt_cache_checkpoint_selection.py (an upstream backport of a squashed 4-commit fix for hybrid/recurrent memory checkpoint selection and prompt-cache entry selection, PR #24055 + follow-ups) was reconstructed from a session transcript after an external `git reset --hard` wiped uncommitted work on 2026-08-11/12. It parses and loads fine, but a dry-run `patcher.apply_all()` against the real pinned vendor tree (b10362) shows all 4 edits in `tools/server/server-context.cpp` and `tools/server/server-task.cpp` fail to match: `anchor ... matched 0 time(s), expected 1`.

Root cause confirmed by reading patcher.py's own module docstring: 'No anchoring into comments. Anchors are matched against a noise-stripped copy of the file with comments and string literals blanked out.' The failing anchors in 1005 include full `//` comment lines (e.g. `// n_tokens_cur: the number of tokens added...`, `// evict checkpoints within min-step...`) and `SLT_TRC(slot, "...")` string-literal log text as part of the regex match text -- both categories are blanked in the stripped copy the patcher actually matches against, so these anchors can structurally never match, regardless of whether the real source still has the described code. This is not a source-drift issue; it's a design/reconstruction defect in the anchor text itself (contrast with 1002_hip_unsafe_math_opt_in.py, which explicitly documents avoiding this exact mistake).

Verified directly: `sed -n '2354,2358p' vendor/llama.cpp/tools/server/server-context.cpp` shows the described `create_checkpoint` code is present, byte-identical to what the docstring/comments in 1005 describe -- so the underlying fix content and rationale in the docstring are sound. Only the anchor regexes need to be redone to key off non-comment, non-string code tokens (following the pattern already used successfully in 1002 and the other 10 core patches).

Other 4 recovered patch files in this batch (0900_pool_workspace_metrics, 1000_rdna4_mmq_q2k_q6k_fix, 1002_hip_unsafe_math_opt_in, 1003_quantized_cpy_thread_block_fix) all apply cleanly (dry-run verified) against the pinned b10362 vendor tree.
