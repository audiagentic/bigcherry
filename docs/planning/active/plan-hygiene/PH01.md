# HI active-plan triage audit (gated on RE14 close)

## Description

Single audit pass over docs/planning/active/hip-autotune/ — the directory still contains many HI items from multiple project generations, and 'active' must not be read as 'the current engineering queue'. Classify each active HI item:
- Measurement-integrity defect that could change winner selection → keep active / highest priority
- Runtime correctness/crash/data-corruption defect → keep active
- Concrete performance hypothesis with evidence → keep as experiment queue
- Architecture-specific qualification not currently targeted → defer
- Already implemented but plan state stale → close
- Superseded by a later HI item → close/supersede
- General refactor/telemetry nice-to-have → backlog
- Old experiment whose question is already answered → close

Key test: could this item materially change whether a candidate is correct, whether we measured it fairly, or which candidate we choose? Yes → ahead of performance tuning. No → it must not block tuning.

## Steps

- Enumerate all active HI items with state
- For each: read the item + check code/ledger for evidence it was implemented or superseded
- Classify per the table above; apply plan_set_state / plan_delete_item accordingly with a review record for findings-driven corrections
- Leave the surviving set as the true tuning-priority queue
