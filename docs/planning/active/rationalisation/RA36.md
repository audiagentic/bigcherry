# TR11 Continue: classify and move remaining tests by domain

## Description

Continue TR11 test reorganization after the RA35 pilot (release-domain, 3 files/70 tests, done and validated). 163 of 166 tools/tests/*.py files remain flat and unclassified, needing to move into tools/tests/{source,build,patch,campaign,tuning,core,analysis,integration,hardware,fixtures}/ per the target filesystem. Unlike TR10 (which had an explicit file->domain mapping from the run sheet), classifying these requires reading each file to determine what it actually tests -- a heavier analysis task than the mechanical moves themselves.

## Steps

- For each remaining domain (source, build, patch, campaign, tuning, core, analysis are the clearest; integration/hardware/fixtures need their own criteria per the run sheet: hardware tests explicit and not part of normal discovery, generic C/C++/CUDA fixtures under fixtures/<domain>/, patch-specific durable fixtures stay package-local not here).
- Classify by content (imports/what's under test), not just filename pattern -- filenames don't reliably indicate domain (e.g. test_cli_tooling_surface.py, test_recipes.py touch multiple domains).
- For every moved file: increment its sys.path.insert(0, str(Path(__file__).resolve().parents[N])) depth by one (126 of 166 files use this pattern) -- same bug class as TR10's REPO_ROOT issue.
- Add tools/tests/<domain>/__init__.py for every new subdirectory -- unittest discover -s tools/tests -p 'test*.py' silently drops tests in a subdirectory with no __init__.py (confirmed: pattern-based discovery requires it even though explicit dotted-path execution doesn't).
- After each domain slice: full unittest discover must find the same total test count as before the slice (currently 1816, only the pre-existing Windows symlink error as a known failure) -- a dropped count means a missing __init__.py, not a real test loss.
- Do not rename thousands of test functions merely to remove HI/RD/RE history (run sheet TR11 rule) -- only the file's directory location changes, not test names/content.
- Recommend doing this as several more domain-sized slices (source domain next, similar size to release), each with its own plan item + ledger event + commit, same discipline as the TR10 domain moves.
