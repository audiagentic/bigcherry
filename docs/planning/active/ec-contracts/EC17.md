# Separate typed source-evidence from BigCherry acceptance-metric semantics

## Description

External review (2026-08-20) found that Experiment Contracts risk conflating a source-reported number (which might be pp512, tg128, end-to-end throughput, measured on hardware BigCherry doesn't own) with BigCherry's own acceptance threshold, as if they were the same metric. A source-reported +7.4% is a reason to investigate an optimization, not a logical requirement that BigCherry reproduce exactly +7.4% on its own hardware with its own measurement methodology.

## Steps

Split the schema: add an explicit [source-evidence] section (metric name, value_pct, hardware, workload -- what the EXTERNAL source actually reported) kept separate from [acceptance] (BigCherry's own required minimum gain / regression budget). [acceptance] should not just parrot the source's number without re-deriving what's actually being measured on BigCherry's own hardware and methodology.
