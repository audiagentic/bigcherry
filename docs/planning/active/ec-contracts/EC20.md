# CI link-audit: source -> plan -> patch/action -> contract must be mechanically valid

## Description

External review (2026-08-20): there are four graphs that should stay consistent -- external source, RD/EX plan item, patch/environment action, experiment contract -- and they are not necessarily 1:1 (e.g. one source commit maps to RD05+RD06+RD07 maps to one patch 1203 maps to three logical contracts; RD39-42 maps to one coupled materialization 1215 maps to one contract). That flexibility is good but dangerous without an audit: nothing currently prevents a retired plan from appearing in a production patch set, a hardware-deferred contract from being promoted, or a partial-cluster contract (like RD26/1210) from closing its parent plan.

## Steps

Add a real CI check (not a manual review habit) asserting: every external patch has real source provenance (external-sources.toml entry); every external patch maps to >=1 plan item; every materialized plan has >=1 contract once contracted; every contract references a valid, existing plan item; every prerequisite resolves; active source IDs referenced by tracked entries still exist in the registry; retired plans cannot appear in production patch sets; hardware-deferred contracts cannot be marked promoted; partial-cluster contracts (composition-gated, like RD26's 1210) cannot close their parent plan item's state.
