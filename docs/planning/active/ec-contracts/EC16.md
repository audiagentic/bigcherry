# Generalise Experiment Contract target classification beyond the 5-family matmul enum

## Description

EC02's backfill pass found the hypothesis.family field is a closed 5-value matmul-dispatch enum (mmvq/mmq/mmvf/mmf/blas, imported from autotune_schema.FAMILIES, correctly never redefined) -- but 10 of the 15 materialized RD-prefixed patches (RD19/RD20/RD04/RD05/RD06/RD13/RD22/RD26/RD39-44/RD50) are flash-attention, graph-fusion, TP-topology, SSM/GDN, or dispatch-scheduling work that is genuinely outside that enum. EC02 correctly refused to force-fit them with a wrong family value, backfilling only the 5 that actually fit. Per GPT review (see RV56 on EC02): this is real progress but should not be read as complete coverage -- the guide's own mission is to express every imported optimization as a contract.

## Steps

Introduce an orthogonal experiment-target classification (e.g. target.kind = "kernel_family" | "attention" | "graph_fusion" | "tp_topology" | "ssm_gdn" | "dispatch_scheduling", with target.family populated only when target.kind == "kernel_family") decoupled from the existing 5 runtime kernel families -- do NOT add non-matmul values to autotune_schema.FAMILIES itself, that enum must stay the 5 runtime kernel families only. Once the schema change lands, backfill contracts for the remaining 10 materialized patches using the same harvest-don't-duplicate discipline EC02 used for the first 5.
