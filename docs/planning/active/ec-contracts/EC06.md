# A/B aggregation: per-contract target gains and control regressions

## Description

`ab_benchmark.py`/comparisons aggregate target gains and control regressions per contract -- rolling up the per-lane balanced-comparison results EC03's positive/control/boundary lanes produce into the contract-level acceptance numbers (`target_kernel_gain_pct`, `end_to_end_gain_pct`, `max_control_regression_pct`) EC01's schema declares.

Full source: docs/reference/BigCherry_Experiment_Contract_Implementation_Guide.md (§7 EC06 row, §4 acceptance fields, §12 steps 3-6).

## Detailed Solution & Technical Design

## Relevant steps from the test workflow (guide §12)
3. Run positive model/workload lanes and capture canonical signatures.
4. Filter/identify the exact signatures the hypothesis intends to improve.
5. Benchmark native plus eligible candidate alternatives using existing tuner/A-B machinery.
6. Probe boundary values around the claimed trigger, not only the expected winning point.

This item is where those four steps' RAW per-lane results get aggregated into the three acceptance numbers EC01's schema requires: target_kernel_gain_pct (the isolated-candidate speedup on the exact triggering signatures), end_to_end_gain_pct (the whole-workload effect, which can be much smaller than the kernel-level gain if the affected op is a small fraction of total time -- this is exactly the RE15 stage H balanced-comparison machinery this session already exercised for the b10502 repin), and max_control_regression_pct (the worst regression observed across every control lane, not an average -- a contract that wins on average while quietly regressing one control model is not a pass).

## Validation

Aggregation tests: a contract's target_kernel_gain_pct is computed only from positive-role lanes' isolated-candidate measurements, never control-role lanes; max_control_regression_pct takes the WORST (not average) regression across all control lanes; a contract with zero control lanes fails validation rather than silently reporting max_control_regression_pct=0 (undefined is not the same as zero regression).
