## Detailed Solution & Technical Design

Consolidated test list (each maps to a specific EC item's own validation section -- this item's job is making sure the full set actually exists and stays green, not inventing new test categories beyond what EC01-EC11 already specified):

- Schema (EC01): closed-schema rejection of unknown fields, required-section enforcement.
- Hash stability (EC01): contract identity/hash stable across reloads of identical content, changes on semantic edit.
- Dependency cycles (EC02): prerequisite cycle detection and rejection.
- Campaign expansion (EC03): N positive + M control + K boundary -> exactly N+M+K lanes, no cross-product explosion.
- Identity separation (EC04/EC05): contract metadata never perturbs build_plan_id/effective_build_id/source_slice_id or runtime signature/dispatch identity -- the single most safety-critical test category per guide §2's non-negotiable architecture, deserves the most scrutiny of any item here.
- Negative controls (EC06): max_control_regression_pct is the WORST not average regression; a contract with zero control lanes fails rather than reporting a false zero.
- Boundary expansion (EC03/EC06): full swept-dimension results captured, not just the winning point.
- Evidence completeness (EC07/EC09): promotion blocked when contract-declared-required evidence (correctness, generalisation) is missing, regardless of performance evidence quality.
- Promotion rejection (EC09): a contract that fails ANY declared gate cannot promote, even with otherwise-strong evidence; correctness-only contracts (RD20/RD22/RD26-style) can still promote on correctness alone.
- Report output (EC10): all nine report sections populate even for a rejected contract; no report field without a schema source, no schema section without a report rendering.
