# Mandatory trigger-proof requirement for performance contracts

## Description

External review (2026-08-20) found that a performance contract can pass merely because a benchmark completed, without proving the candidate code path was actually exercised. A benchmark run against a model/workload that never triggers the target signature can look like legitimate neutral (or even passing) evidence, when it's actually meaningless -- especially dangerous for narrow-eligibility optimizations (tiny-M Q8, specific head sizes, specific MoE density, BF16 KV, gfx1151-only, hybrid/GDN graph shapes).

## Steps

Every performance contract needs a machine-checkable 'this code path was actually exercised' assertion (e.g. candidate kernel launches > 0, expected route selected > 0, mean-occupancy selector selected > 0), consumed from BigCherry's existing coverage/telemetry instrumentation (0700 coverage_counters, 0810 replay_hit_diagnostics, 0820 measurement_signature_shapes, 0830 split_reduce_telemetry -- all already built and validated, per this project's own framework patch series). Missing trigger evidence should make a contract report INVALID, a third state distinct from pass/fail, not silently treated as a neutral/passing result.
