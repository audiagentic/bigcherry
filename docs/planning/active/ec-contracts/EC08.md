# Generalisation handoff: feed exact winning signatures to generalise.py

## Description

Feed exact winning signatures (from EC06's aggregation) to existing `generalise.py`; do not invent hand-coded dispatch envelopes first. Holdout proof determines whether a broader dispatch rule is safe to generalize from a contract's exact-signature wins.

## Detailed Solution & Technical Design

## Generalisation policy (guide §13, verified against tools/bigcherry/generalise.py's real constants 2026-08-20)
Reuse the existing generalized-key proof. Current policy defaults require:
- at least 3 exact signatures
- min_holdout_calls = 100
- min_added_coverage_pct = 5.0
- max_median_regret_pct = 0.5
- max_upper_regret_pct = 1.0
- max_exact_regression_pct = 0.5

Do not weaken these globally to make a patch pass; a contract may be stricter than the defaults, never looser. This item's job is purely the HANDOFF -- taking a contract's exact winning signatures (the boundary-swept, positive-lane-proven set from EC03/EC06) and feeding them into generalise.py's existing holdout machinery in the shape it already expects, not reimplementing regret/coverage math.

## Validation
