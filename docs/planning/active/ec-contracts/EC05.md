# Evidence binding: contract identity/hash into bundles and reports

## Description

Bind contract identity/hash into experiment bundles and reports without contaminating runtime signature identity -- the same separation principle as EC04, applied to the evidence layer (`experiment_bundle.py`, `provenance.py`) instead of the campaign-lane layer.

Full source: docs/reference/BigCherry_Experiment_Contract_Implementation_Guide.md (§7 EC05 row, §2).

## Steps



## Detailed Solution & Technical Design

Guide §2's non-negotiable architecture: "Keep runtime candidate identity separate from source provenance and from experiment identity." This item is where that separation is enforced at the evidence layer specifically -- an experiment bundle or report can and should SAY which contract produced it (contract_id + contract content-hash, both immutable per EC01), but the underlying tuning/replay/dispatch identity (signature digest, dispatch digest, manifest hash, build_plan_id) must never be derived from or perturbed by contract identity. Reuses `experiment_bundle.py`/`provenance.py`/`source_identity.py` as-is per guide §3 ("Reuse") -- this item adds contract-aware fields to their existing documents, it does not replace their identity model.

## Validation

Two lanes built from different contracts but otherwise byte-identical source/build/campaign inputs produce byte-identical runtime signature/dispatch identity in their bundles, differing ONLY in the contract_id/contract_hash provenance fields -- the direct test of the separation invariant.
