# Validate META SPLIT_REDUCE correctness for D=3/D=4 heterogeneous topologies

## Description

Qualify META collective correctness for the current heterogeneous D=3/D=4 device sets. This is configuration-scoped evidence work, not a timeless claim about Brutus, not a stock RCCL campaign, and not a new production collective implementation.

## Steps

1. Capture kernel/build, IOMMU/ACS/P2PDMA, ROCm/HIP, device BDF/order, architecture vector, and directed peer matrix. 2. Preserve August no-P2P results as historical configuration-scoped evidence. 3. Use forced META for heterogeneous groups; do not repeat known RCCL crash paths unless HI138 changes admissibility. 4. Qualify D=3 META correctness, permutations, and the non-power-of-two fold/copy-back path. 5. Qualify D=4 META correctness only after D=3 passes. 6. Record evidence and disposition; correctness evidence is not a performance-promotion claim.

## Detailed Solution & Technical Design

Key mechanics (GPT-designed, only the D=2 subset independently source-verified so far):

- Split-state callback only needs to describe the 2 static leaf tensors (A, B) as GGML_BACKEND_SPLIT_AXIS_0 with 1 element per rank; META derives the compute tensor (MUL_MAT output)'s PARTIAL/MIRRORED state itself from the real handle_mul_mat() rule (verified: ggml-backend-meta.cpp:578-594, axis0+axis0 -> PARTIAL pre-sync / MIRRORED post-sync) and the subgraph partitioner terminates on PARTIAL (verified: line 1962). Do NOT hand-encode PARTIAL in the callback -- that would manufacture the answer instead of exercising production partitioning.
- Static tensors go through ggml_backend_meta_alloc_ctx_tensors_from_buft with USAGE_WEIGHTS; compute tensors (partial, out) get scheduler-allocated with USAGE_COMPUTE via ggml_backend_sched -- NOT the same buffer, because META's callback-invocation decision depends on buffer usage state at tensor-init time.
- Per-rank readback for a MIRRORED tensor via the ordinary ggml_backend_tensor_get only returns simple-backend-0's copy (verified pattern at ggml-backend-meta.cpp's MIRRORED case, 'TODO other simple backend may be better') -- this is why per-device output must come from the existing HI58 nodes-capture telemetry hook (the tensor array 0830 already keeps alive across the provider/fallback boundary), not a new generic accessor.
- device_ids[] / devices[] pairing with rank position is part of the evidence contract -- for permutation testing, rank-N.f32 input files stay attached to logical rank position while physical device assignment varies across the run (device order (2,0,1) means rank-0.f32 -> physical device 2, etc), specifically to catch rank/device-mapping bugs.
- Analytical error bound (gamma=(D-1)*u/(1-(D-1)*u)) is already D-generic in reduce_correctness.py and deliberately conservative enough to tolerate different valid reduction-tree rounding orders at D=3/D=4 (sequential vs pairwise summation can legitimately differ bitwise) -- do not tighten it or promote bitwise agreement to a hard gate for D>2; record cross_device_digest_equal as a diagnostic signal only.
- D=3 is higher priority than D=4: it is the only device count that exercises allreduce_fallback's non-power-of-two fold-excess-ranks-then-copy-back logic (ggml-backend-meta.cpp ~2146-2198); D=2 and D=4 (a pure power of 2) cannot reach that branch at all.
