# Size-adaptive internal/RCCL AllReduce provider dispatch

## Description

1001_hip_internal_allreduce (validated 2026-08-31) enables an internal, non-RCCL AllReduce path on HIP that is a real, large win for decode (+17.33% TPS on MTP completion-bench, +6.88% t/s on plain tg128 llama-bench, both dual RX 7900 XTX gfx1100) but a severe regression for prefill (-32% to -34% t/s on pp512/pp2048/pp4096, same hardware, same tensor-split config). b10687's ggml-cuda.cu currently selects one AllReduce provider once at communicator init (a single stored try_allreduce function pointer for the whole session) via GGML_CUDA_ALLREDUCE -- there is no per-call, size-aware selection. Shipping GGML_CUDA_ALLREDUCE=internal as a blanket default or production config would regress every prefill-heavy request by ~a third, so the patch's SUMMARY.md currently scopes its recommendation to decode-only workloads with an explicit warning against blanket adoption.

## Steps

1. Instrument or reuse patches/0830_split_reduce_telemetry's existing provider/reduction-bytes telemetry to record per-call reduction size at the real dispatch site.
2. Confirm the crossover point between the two llama-bench-measured regimes (pp512 already shows -33.66%, tg128 already shows +6.88%) with a finer sweep of intermediate reduction sizes if needed to locate roughly where internal stops winning.
3. Implement per-call size-based provider selection in ggml_backend_cuda_comm_try_reduce_plan (or the try_allreduce dispatch path it feeds) as a new BigCherry patch: `if (n_backends == 2 && bytes < crossover) internal; else rccl;` -- gpt-dev-agent's proposed shape.
4. Validate with the same 3-arm methodology already used for 1001 (correctness via the HI18 SPLIT_REDUCE probe, performance via paired completion-bench for decode + llama-bench pp/tg sweep for prefill) to confirm the adaptive dispatch wins (or ties) across the whole size range, not just at the two tested extremes.
5. Only then consider promoting GGML_CUDA_ALLREDUCE=internal-adaptive (or equivalent) into a production runtime-profile.
