# Backend stack probing and canonical identity

## Description

Add HIP/Vulkan probes, ProviderIdentity/ResolvedBackendStack, capability probing, canonical JSON, and deterministic stack fingerprints.

Define the canonical resolved software/provider stack identity and separate it from capability snapshots and provenance. HIP and Vulkan use one versioned identity envelope without conflating physical hardware with software identity.

## Detailed Solution & Technical Design

Define ProviderIdentity and ResolvedBackendStack with canonical sorted serialization and blake2b bigcherry/backend-stack/v1 fingerprint. Reuse existing compiler/ROCm discovery. HIP captures HIP/rocBLAS/hipBLASLt/CK identities and capabilities; Vulkan captures loader/device/driver/ICD/extensions/features/limits/subgroups/cooperative matrices/shader compiler/pipeline UUID.

ResolvedStackIdentity represents semantic software/provider implementation identity. CapabilitySnapshot represents device/architecture/runtime capabilities and is separately hashed or referenced when required. Provenance retains paths and diagnostic details without defining semantic equality.
