# Runtime stack attestation

## Description

Capture actually loaded HIP/Vulkan providers at runtime, emit reports/fingerprints, and fail workflow stages on build/runtime mismatch.

Define and enforce actual runtime stack attestation for every evidence-producing execution. The attestation must report what the loader/provider runtime actually used, not merely the requested stack or environment variables.

## Steps

Depends on: RO04

Execute only after prerequisites are complete. Preserve existing tuning architecture, fail-closed safety, stack/provider identity, and exact evidence lineage.

Define Vulkan adapter output using the same schema under RO17. 4. Collect attestation after backend/provider initialization and before timed work. 5. Reject missing, malformed, substituted, or lazy-loaded provider identities before evidence is accepted. 6. Thread attestation into workflow receipts and RO06 run persistence.

## Detailed Solution & Technical Design

Emit actual loaded HIP/rocBLAS/hipBLASLt/CK module identity through ggml_hip_runtime_stack_json/fingerprint/write report. GGML_HIP_STACK_REPORT writes once at initialization/first dispatch. Record, tune, verifier, correctness, replay smoke/profile set the path, read report, and fail on build/runtime mismatch. Keep software stack out of hardware key.

RO05 owns the protocol, comparator, and HIP implementation. RO03 supplies expected semantic identity; RO04 supplies expected build-stack identity; RO06 persists per-run actual identity. Do not infer loaded DSOs from PATH, ROCM_PATH, LD_LIBRARY_PATH, or ICD selectors.
