# Integrate CM1 shader generation and Vulkan capability gating

## Description

Integrate the PR's int8 coopmat1 shader and host pipeline support as an available-but-not-selected Vulkan candidate, with complete shader generation, capability checks, and native fallback.

## Steps

1. Add the CM1 shader/function sources and register all supported generator variants.
2. Verify host-side generated symbols, pipeline declarations, specialization constants, and S/M/L/K tile variants.
3. Extend the RE32 capability snapshot with cooperative-matrix integer/type/shape support, subgroup properties, subgroup-size-control, shared-memory limits, ballot requirements, FP4 support, device/driver/ICD identity, and shader/toolchain digest.
4. Implement host shared-memory eligibility matching the GLSL allocation for each quant/op path.
5. Gate RDNA3/RDNA3.5/RDNA4 behavior without relying on vendor-only or unstable enum-ordinal heuristics.
6. Keep the normal native path behavior-equivalent when the candidate is disabled or unavailable.

Before adapting the PR, inspect the current pin's `vk_device_architecture`, architecture detection, device capability fields, cooperative-matrix discovery, subgroup-size-control, MMQ shared-memory helpers, warptile definitions, shader loading, pipeline creation/storage, Q8_1 preparation/`quantize_y`, and MUL_MAT_ID structures. Then adapt the four PR files to the current APIs rather than copying historical hunks blindly.

## Detailed Solution & Technical Design

CM1 is not just a new shader file. The candidate depends on F32 activation preparation to Q8_1, quant-specific unpack/scale/LUT paths, cooperative-matrix fragment access, subgroup width, S/M/L pipeline construction, and optional split-K/reduction. Expose availability through Vulkan-native recipe metadata, not HIP candidate types. Treat upstream RDNA4 detection and quant exclusions as initial compatibility hints only; capability and later measurement decide actual execution. Add an invariant preventing duplicated architecture enum ordinals between C++ and GLSL/generator code.

Host integration must cover RDNA classification, integer CM1 eligibility, wave32 preference only when subgroup-size-control supports it, CM1 normal/K tile definitions, pipeline creation, Q8_1 activation preparation, empty-pipeline fallback, and proprietary/open AMD cooperative-matrix handling. Replace or mechanically guard any host/shader architecture enum ordinal coupling; prefer an explicit CM1 layout specialization. Keep upstream RDNA4 performance exclusions out of capability semantics: `can_execute` answers correctness/capability, while auto-selection policy remains separate.

RO20 implements the source patch and capability code but does not itself establish a performance qualification. Keep static capability/generator tests separate from Experiment Contract claims. Any custom validation must use the locked `check(ctx)` interface inside the patch package and only when genuinely necessary; prefer built-in validators.

## Code Samples & Guidance

Capability minimums include: integer cooperative support; cooperative matrix M/N/K and operand/accumulator types; subgroup current/min/max and subgroup-size-control; subgroup ballot for MUL_MAT_ID; max shared memory; FP4 extensions; driver/API/ICD; device class/UUID; glslc/SPIR-V/source digest.

Audit the shader interfaces against the pinned `types.glsl` and MMQ helpers: buffer bindings, push constants, specialization indexes, `block_q8_1_x4_packed128`, `mul_mm_id_funcs.glsl`, cooperative-matrix signatures, output/split-K offsets, batch/broadcast, row IDs, and subgroup ballots. Expected generator coverage is 12 quant types × dense/MUL_MAT_ID × f32acc/f16acc = 48 intended variants; q2_k must have no generated symbol. Host shared-memory accounting must match shader declarations, including `BK=32`, `BK_STEP=4` for MUL_MAT and `2` for MUL_MAT_ID, `QPITCH`, `KSCALES`, per-quant scales/LUTs, row IDs, ballots, and NVFP4 tables. Add a deterministic generated-symbol audit rather than relying on grep.

## Validation

Build every expected CM1 SPIR-V variant and verify matching host data/length symbols. Test all twelve supported types independently: q4_0, q4_1, q5_0, q5_1, q8_0, iq4_nl, mxfp4, q3_k, q4_k, q5_k, q6_k, nvfp4. Verify q2_k remains unavailable. Test no cooperative support, wrong subgroup, insufficient shared memory, missing FP4, unsupported driver, and pipeline creation failure all produce non-executable native fallback.

Run `PYTHONPATH=tools python -m bigcherry check --full`, `sources check`, `patch-lint`, `patch-rebase-check --all`, then configure/build a pristine materialization with `GGML_VULKAN=ON`, tests/tools enabled, and targets `ggml-vulkan`, `test-backend-ops`, and `llama-bench`. Verify all 48 expected symbols, q2_k absence, host/shader specialization agreement, LDS byte agreement, architecture classification, insufficient-LDS rejection, and native fallback.

Use package/source checks for generator completeness, build, and capability rejection. Do not put scientific thresholds in validation.toml or README. If a CM1 contract requires named correctness/activation/performance/control checks, each named check needs its own real producer and PASS; one generic correctness PASS is insufficient. Until that executor exists, the patch remains unvalidated even if compile and unit tests pass.

[ ] Four vendor files compile against the current pin. [ ] Intended CM1 symbol set is complete and q2_k is absent. [ ] Host and shader LDS accounting agree. [ ] Unsupported capability, subgroup, FP4, or shared-memory cases are non-executable. [ ] Disabled/native mode remains behavior-equivalent. [ ] Architecture layout does not silently depend on an unchecked enum ordinal. [ ] No unresolved RE32 capability ambiguity remains.

[ ] Static and build checks are clearly distinguished from contract qualification. [ ] No validation adapter duplicates contract thresholds or hypotheses. [ ] Unknown validators fail closed. [ ] Any custom validator is package-contained and exactly `check(ctx)`. [ ] CM1 qualification is blocked rather than falsely promoted while the executor is absent.

## Notes

This item establishes availability and compile correctness only; it does not select CM1 by default or claim performance.

Critical shader risks are RDNA4 fragment row mapping, quant-specific scale/min/LUT handling, NVFP4 conversion, and MUL_MAT_ID row-ID/ballot paths. Treat the fragment layout as hardware/driver ABI requiring correctness evidence, not as an ordinary optimization.

The current real contract-execution implementation is RD08-specific. RO20 must not copy RD08's executor as a generic CM1 framework; extend the existing experiment/validation architecture deliberately and record a new plan/review if a generalization is needed.
