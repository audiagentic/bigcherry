# Expose CM1 as a forceable Vulkan recipe candidate

## Description

Connect the integrated CM1 path to RE30 record/candidate machinery and RE36's Vulkan-native force selector, proving forced execution, telemetry, correctness, and native fallback before tuning.

## Steps

1. Define a complete CM1 recipe spanning activation preparation/Q8_1, main CM1 pipeline, and optional split-K/reduction.
2. Add candidate identity fields for operation, quant, accumulator, S/M/L/tile class, subgroup, device/architecture, driver/ICD, shader digest, and recipe stages.
3. Implement Vulkan-native can_execute and route selection.
4. Expose force requests through RE36 and emit requested route, actual route, rejection/fallback reason, and recipe digest.
5. Run native-versus-CM1 correctness checks for MUL_MAT and MUL_MAT_ID before allowing measurement.
6. Ensure forced unsupported requests fail explicitly, while ordinary replay/candidate misses fall back to native with visible telemetry.

Create `patches/1247_ro21_vulkan_cm1_force_telemetry/` as a separate BigCherry-local framework patch. Add the CM1 recipe registry/identity, Vulkan-native strict force selector, actual-route telemetry, and correctness adapter. Keep it separate from 1246 so upstream retirement does not remove BigCherry observability.

## Detailed Solution & Technical Design

A CM1 candidate is a complete Vulkan pipeline recipe, not a shader pointer or HIP launcher. The dispatch hook belongs around Vulkan native recipe selection and must not be placed in generic dispatch. Create pipelines outside timed regions, preserve descriptors/push constants/scratch/reduction state, and make route telemetry truthful: a fallback must never be reported as CM1 firing.

A CM1 candidate is a complete recipe: activation preparation/Q8_1, CM1 main dispatch, and optional split-K/reduction. Candidate identity must include backend, recipe ID, upstream snapshot/patch ID, vendor revision, build identity, shader/SPIR-V digest, physical device, driver/API/ICD, dispatch signature, operation, quant, accumulator, tile class, subgroup, and split-K. Separate `can_execute` from `auto_eligible`; strict force never silently falls back, while auto/replay misses may select native with a reason.

`1247_ro21_vulkan_cm1_force_telemetry` is also package-only with mandatory `patch.toml` and `patch.py`. Treat it as BigCherry framework/instrumentation unless and until it has a separate scientific Experiment Contract. Do not bind it to the CM1 performance contract merely because it is composed with 1246; multi-contract patch validation is not supported.
