# Decode launch census and prefill/decode baselines (Flash-Next, 2x gfx1100 + gfx1201)

## Notes

Scripts: tools/lab/flash-next/long-ctx-profile.sh (full|decode|perf|timing), graphs-ab.sh. Census script logic: kernel_trace rows within the final predicted_n/predicted_per_second window, grouped by op family per Agent_Id, divided by steps = predicted_n - draft_n_accepted.

## Findings

Config: -ts 2,2,3, 192K, q8_0 KV, ub512, MTP3 draft on gfx1030, --allreduce cpu-root, patches 1291 (+1292 for later runs).
Decode at ~80K cached (rocprof decode window, flashnext-long-ctx-decode-3): ~4176 kernel launches per MTP step per tensor-split GPU (draft GPU 547). Per step per GPU: allreduce 192 launches / 6-12 ms (mostly consume spin), dense mmvq 480 / 5.2-6.5 ms, attention 32 / 3.5-4.7 ms, MoE mm 96 / 2.8-4.5 ms, f32 matvec 275 / 2.5-2.8 ms, elementwise 1283 / 2.1-2.4 ms, activation quantize 640 / 1.4-1.6 ms, copies 347 / 0.5 ms, HC pre/post 192 / 0.4-0.5 ms, QSA top-k 132 / 0.55 ms, GDN 72 / 0.3 ms. GPUs 20-24% busy under rocprof; rocprof overhead is large (unprofiled 80K decode 38 t/s pre-1292, ~45 t/s with 1292, vs 27.8 profiled).
Prefill 47K (flashnext-long-ctx-profile-1): RCCL 30.3% of summed kernel time (~1.34 ms per 3.3 MB AR), flash_attn_ext_f16 8%, quantized matmuls ~25%, f32 rocBLAS ~11%, same-GPU D2D copies 7.6 s (276/GPU, bimodal 0.35 ms vs 20-40 ms on gfx1201, source not attributed), H2D 4.7 s.
Host (perf): O(n_ctx) kpool rebuild per MTP step fixed by 1292 (-14% ms/step at 80K). After 1292 no libllama symbol above ~0.5%.
In progress: HIP graphs on/off ABBA (GGML_CUDA_DISABLE_GRAPHS=1) to establish whether per-rank subgraphs are graph-captured under the meta backend.

## Conclusion

Decode is launch-bound: the launch count is the primary RNX target. Gate RNX03/04/08/10 ordering on launch reduction per step; next low-level profiling: HIP API trace (hipGraphLaunch vs hipLaunchKernel counts, per-launch CPU cost) and attribution of the 20-40 ms D2D spikes.
