# HIP API trace: decode is host-synchronization bound (465 stream syncs per MTP step)

## Notes

tools/lab/flash-next/long-ctx-profile.sh apitrace mode; graphs-ab.sh.

## Findings

HIP graphs ARE active under the meta backend: graphs-off ABBA costs ~3 ms/step (50.2 vs 53.3 ms/step at 10K, acceptance equal; flashnext-graphs-ab-1). rocprofv3 --hip-runtime-trace over 256-token decode at 10K (flashnext-apitrace-1, 82 steps): hipStreamSynchronize 465 calls/step = 44.2 ms/step (95 us/call); hipGraphLaunch 285/step = 9.9 ms (34.7 us/call, ~96 PARTIAL boundaries x 3 ranks); hipLaunchKernel 1143/step outside graphs (2.25 us/call); hipMemcpyAsync 182/step; hipGraphExecUpdate ~8/step and Instantiate ~1/step (graphs re-captured each step). Host thread 82% of wall time inside the HIP API. Scheduler splits = 2, and meta graph_compute is async, so the syncs most likely come from ggml-cuda buffer set_tensor/get_tensor (cudaMemcpyAsync on cudaStreamPerThread + cudaStreamSynchronize) for graph inputs on every meta rank, per decode call (draft steps + verify), plus output reads.

## Conclusion

Top decode lever is host synchronization, ahead of kernel fusion: (1) async per-rank input upload for the meta backend (one sync per decode instead of per input per rank), (2) stop per-step graph re-capture, (3) then launch-count fusions (RNX10/04/08).
