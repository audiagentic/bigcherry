# HC weights are Q8_0; the f32 GEMMs are router/inject/GDN projections

## Notes

Verified with gguf-py GGUFReader on Brutus.

## Findings

GGUF (Qwen3.8-Flash-Next-UD-IQ4_XS) tensor types: hc_*_down/up Q8_0 [10240x320 / 320x10240] -> already MMQ/MMVQ; hc_*_inject F32 [10240x4]; hc_*_norm F32; ffn_gate_inp (router) F32 [2560x512]; ffn_gate_inp_shexp F32 [2560]; ssm_alpha/beta F32 [2560x48]. So the ~11% f32 rocBLAS prefill share and the 275 f32 matvec launches / ~2.5-2.8 ms per decode step per GPU come from router + inject + shared gate + GDN alpha/beta, not HC down/up. HC pre/post kernels are 192 launches / ~0.45 ms per step per GPU.

## Conclusion

Re-scope 1304: HC fusion value is launch count (192/step) plus the f32 inject matvecs, not a precision change to HC GEMMs. Router f32 matvec (2560x512 x48 layers per token) is a bandwidth item; any bf16/f16 conversion changes routing numerics and is out of scope per this item's own rule.
