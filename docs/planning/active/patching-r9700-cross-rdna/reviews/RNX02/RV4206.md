# Attention/QSA decode costs and a QSA top-k determinism defect

## Notes

GPT inline request req_df43e605c032406e (deterministic tie-break) pending. Runs: flashnext-determinism-1/2, flashnext-kpool-parity-1.

## Findings

Decode at 80K: attention 32 launches / 3.5-4.7 ms per step per GPU, including ~1 ms/token of q8_0->f16 KV dequant (dequantize_block_q8_0_f16) on the MTP-verify flash_attn_tile path; QSA top-k 132 launches / ~0.55 ms per step. Determinism: greedy output differs across server starts at 32K and 80K (identical at 10K; decode within one server is deterministic; RCCL, cpu-root and host AllReduce all show it), localized to the cache-fill prefill. Mechanism: QSA scores are sums of ReLU (many exact 0.0); once n_pool > top_k/kpool the cut falls in a tie and ggml-cuda radix TOP_K (top-k.cu, atomicAdd on equal_count) picks tied columns in arrival order, so the selected KV blocks vary run to run (selection is converted to a mask, so only membership matters).

## Conclusion

Add to 1301 scope (or a separate small patch): deterministic lowest-index tie-break in the radix select's equal branch, with env disable; validate with tools/lab/flash-next/determinism.sh (cross-start greedy identity at 32K/80K). For 1300, the verify-width path with quantized KV (tile + full dequant) is a better target than QSA scoring.
