# R9X03 — GDN short-prefill, MTP, and conv/recurrence fusion

Status: planned
Proposed patch: `1302_r9x_gdn_short_prefill_fusion`
Depends on: R9X01
External source: `kernels/r9k_gdn.hip`, `r9700_vllm/models/gdn.py`; tests `tests/test_gdn_decode_r9k.py`, `tests/test_gdn_prefill_r9k.py`
Existing BigCherry owners: `1221_rd50_gdn_chunked_recurrence`, `1253_nro04_gfx1100_bf16_chunked_gdn`, `1254_nro05_gdn_mtp_prefix_tail`, `1255_nro06_adaptive_mtp_depth`
Primary llama.cpp target: `ggml/src/ggml-cuda/gated_delta_net.cu`; graph/shape checks in Qwen4Exp path as needed.

## Goal

Port only the r9700 GDN work that is not already represented by BigCherry's chunked recurrence and MTP-prefix work: short-sequence/MTP specialization, causal-conv staging, recurrence fusion, or launch-count reduction. Avoid a second chunked GDN implementation.

## Required overlap review

`1221` already folds an external chunked GDN kernel into `gated_delta_net.cu`; `1253` adds gfx1100 BF16 chunked behavior; `1254` owns GDN MTP prefix/tail behavior; `1255` owns adaptive MTP depth. Build a symbol-level comparison before coding. If r9k's win is only another chunk size/tile for the same recurrence, feed it into the existing selector/ablation rather than creating 1302.

## Implementation

1. Census GDN launches for decode, MTP depth 1..N, pp32/128/512/4096. Identify conv, gate/decay, recurrence, and state-update launch boundaries.
2. Compare `r9k_gdn_decode_mtp`, sequence path, and conv path to current `gated_delta_net.cu` semantics: state layout, BF16/F32 accumulation, keep/reset state, scalar/KDA gate cases.
3. Choose the smallest new unit: ideally a short-sequence dispatcher that reuses existing helpers and fuses only the proven launch chain. Keep long-prefill chunked path owned by 1221/1253.
4. Gate on exact head/state dimensions and token-range measured to win. Add env disable/trace for A/B.
5. If causal conv has reusable transpose/layout work, keep it inside 1302 only when the fusion is inseparable; otherwise hand the transpose microkernel to R9X08.

## RDNA adaptation

RDNA4: reproduce r9k scheduling first, including any wave32/LDS assumptions, but use BigCherry's existing GDN types/state buffers.
RDNA3: highest-priority port because current production includes gfx1100; preserve 1253's BF16 path and retune occupancy/LDS. Never let the new selector bypass a better existing chunked path.
RDNA2: reuse short-token fusion/state locality if supported by available instructions; cap LDS/register usage and fall back if occupancy collapses. No gfx12 builtin in common templates.

## Validation/acceptance

Run recurrent-state/output parity over long sequences, reset/continuation boundaries, MTP accept/reject paths, and tensor split. Include adversarial short lengths around every dispatch threshold. Benchmark isolated GDN and E2E decode/MTP/prefill with trace-confirmed path selection.

Promote only if 1302 is demonstrably additive to 1221/1253/1254, falls through exactly outside eligibility, and improves the target short-sequence regime without regressing long prefill. If the source idea is subsumed by existing BigCherry patches, close R9X03 as `already-owned` and record the evidence instead of creating code.
