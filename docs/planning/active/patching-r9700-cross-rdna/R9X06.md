# R9X06 — Routed-expert residency cache and pinned-host backing

Status: planned / feasibility-gated
Proposed patch: `1307_r9x_moe_expert_cache`
Depends on: R9X01; routing census from 1279
External source: `r9700_vllm/moe/cache.py`, `kernels/third_party/davetha/r4d_lru.hip`, `tuning/lru_gather_bench.py`
Related BigCherry memory work: 1235, 1280, 1286, 1292

## Goal

Evaluate a llama.cpp-native VRAM hot-expert cache backed by pinned system memory, using r9700-stack's LRU residency design as a reference. This is a conceptual transplant, not a direct kernel port: vLLM owns weights/routing differently from ggml and BigCherry must preserve tensor ownership, quant layout, split-mode semantics and allocator lifetime.

## Source behavior to preserve conceptually

The r9700 cache keeps every routed expert in pinned host memory (UVA), a per-layer VRAM arena holds S resident experts, routing drives deterministic LRU replacement, missed experts are gathered host→VRAM, then resident/cold work is executed with maps. The vendored `r4d_lru.hip` is Apache-2.0; if code is adapted, record that provenance explicitly.

## Mapping gate — mandatory before 1307

Trace Qwen4Exp expert weights from `src/models/qwen4exp.cpp` graph construction through tensor loading, backend buffer placement, MUL_MAT_ID/MMQ dispatch and meta/tensor-split ownership. Identify the narrowest existing abstraction that can represent `backing tensor + resident slots + expert map` without mutating GGUF tensors in unsafe ways.

Review `patches/1235_rd09_q81_activation_cache_foundation`, `1280_qwen4exp_mtp_kpool_alloc`, `1286_draft_local_shared_tensors`, and `1292_kpool_tail_truncate` for allocation/lifetime patterns, but do not confuse K-pool/activation caching with expert-weight caching.

Expected implementation surfaces after mapping: `src/models/qwen4exp.cpp` or generic model loading for policy, the ggml backend buffer/allocation layer for pinned/UVA backing, and `ggml/src/ggml-cuda/mmq.cuh`/MUL_MAT_ID launch path for expert indirection. R9X01 must replace these expectations with exact symbols before code.

## Design requirements

- Cache per layer and per owning rank; no cross-rank implicit sharing.
- Deterministic replacement given identical route stream; no eviction of experts used by the current dispatch.
- Explicit capacity and disable control; zero capacity reproduces baseline exactly.
- Copy on backend stream with correct dependency before GEMM; overlap only after correctness.
- Quantized expert representation stays native; no hot/cold precision mismatch.
- Collect hit/miss, bytes copied, eviction, and cold-compute counters.
- Support a static-frequency baseline before LRU; LRU must beat simpler placement to justify complexity.

## RDNA implications

This idea is mostly `common`; its benefit is governed by PCIe/system-memory bandwidth and cache hit rate more than ISA. RDNA4/RDNA3/RDNA2 kernels need only consume the same resident mapping. Tune gather/copy geometry per generation, but keep cache policy shared. On systems with poor mapped-host access, never execute cold GEMM directly from UVA unless measured; staged DMA may be superior.

## Validation/acceptance

First use `1279_moe_routing_dump` to measure per-layer working-set/hit-rate curves and simulate LRU capacities offline. Reject 1307 early if realistic capacities cannot remove enough host traffic. Then test exact logits/tokens under forced hits/misses/evictions, all-zero/one-hot/Zipf/uniform routes, context reset, MTP, and tensor split. Benchmark PCIe bytes/token and E2E, not cache-manager kernel time alone.

Promotion requires an E2E win at a documented VRAM budget and no allocator/lifetime corruption. If a static top-N placement gives the same result, prefer the simpler design.
