# Structured evidence capture for ad-hoc real-hardware verification runs (non-patch)

## Description

Current-source review at BigCherry `7e690088df137321b00d92e7f1b2bb6142081133` resolves the architecture question without adding a new evidence engine.

Canonical ownership already exists:

- `docs/evidence/<run-id>/` is the tracked compact evidence store.
- `artifacts/<run-id>/` is the ignored large/raw store.
- `tools/bigcherry/core/provenance.py` owns common provenance-v2 identity.
- campaign/tuning workflows already write their own artifacts/provenance.
- `tools/bigcherry/patch/evidence.py` is patch-specific and must remain patch-specific.

The bounded implementation is therefore a documented non-patch bundle contract in `docs/evidence/README.md`, not a generalized patch validator and not a third campaign/evidence subsystem.

## Current-source disposition

- **Mechanism choice: DONE.** Reuse `docs/evidence` + `artifacts` + provenance-v2. A new CLI is unnecessary for the acceptance requirement because the structured store already exists.
- **Bundle contract: DONE.** `docs/evidence/README.md` now defines the minimum README/manifest/checksum envelope and explicitly forbids fabricating incomplete historical provenance.
- **Historical retrofit: BLOCKED.** The four original runs (HI16, HI24, HI37, RD87) are still prose/history rather than complete immutable bundles. GitHub source alone does not contain enough original raw output/toolchain identity/checksums to reconstruct all four honestly.

## Blocked prerequisite

Recover the original compact/raw outputs and exact execution identities from the host/session artifacts, or rerun each check on the relevant hardware. Do not promote plan prose or commit-message summaries into synthetic evidence.

For each of HI16, HI24, HI37, and RD87:

```bash
RUN_ID=<YYYY-MM-DD>-<plan-id>-<slug>
mkdir -p "docs/evidence/$RUN_ID" "artifacts/$RUN_ID"
git rev-parse HEAD
# Recover or rerun the exact documented verification, keeping raw output in artifacts/$RUN_ID/.
# Create README.md + manifest.json per docs/evidence/README.md.
sha256sum docs/evidence/$RUN_ID/<payload> > "docs/evidence/$RUN_ID/SHA256SUMS"
```

The manifest/README must name the actual project/source/build/toolchain/device identity and exact command from the recovered/rerun execution. If those facts cannot be recovered, mark the historical record incomplete and rerun it; do not guess.

### Smallest closure rerun

Do not rebuild an evidence engine for these four historical checks. For each
missing bundle, rerun the narrowest existing verifier/provenance-producing
command under the same checkpoint and configuration, and capture the following
fields before accepting the result: plan/variant, exact command, source
revision and checkpoint/input identity, build/tuning configuration, UTC start
and end/run identity, relevant result, host/GPU/toolchain identity, and links
to the tracked provenance and raw artifact files. A legacy log may be retained
as context, but it cannot be promoted by repackaging if any of those material
fields are absent.

## Validation

From a fresh checkout, a contributor can discover the non-patch evidence convention in `docs/evidence/README.md` and locate bundles under `docs/evidence/<run-id>/`. Final TO02 validation additionally requires complete bundles for all four named historical checks.
