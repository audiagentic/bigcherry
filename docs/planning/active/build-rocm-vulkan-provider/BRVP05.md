# Host roles in env settings: no machine names, paths or device ids in scripts or code

## Description

Owner 2026-10-26: hosts are addressed by role (build server, test/bench server, lab, workstation) resolved from environment settings; roles may be one machine today and separate machines later. Today the same machine appears as build-server / brutus-lab (this PC) and dev (Brutus); the three environment.local.toml copies have drifted (old key names, stale mount paths, legacy keys, wrong rocm-sdks); slice worktrees do not find the primary checkout's config; ~60 hard-coded host values in ~25 tracked files (mostly tools/lab: ROCm install paths, work-root mount paths, literal PCI addresses, ROCR_VISIBLE_DEVICES=N).

## Steps

1. Environment schema: [roles] maps build, test, lab, workstation (extensible) to [host.<name>] entries; each host has addresses, roots, rocm-sdks (BRVP04), and a device table with roles per device (e.g. engine, helper) instead of positional indices; one shared file content per deployment, each machine selects its own host by hostname match.
2. tools/env exports role-resolved values (BC_BUILD_HOST, BC_TEST_HOST, BC_LAB_HOST, roots, device selectors) for shell; Python tooling resolves roles through core/environment.
3. slice worktrees and slice lab resolve config from the primary checkout (BC_PRIMARY_ROOT) automatically; no BIGCHERRY_ENVIRONMENT/--host hand-setting.
4. Migrate every script and tool to roles and device roles; remove hard-coded hosts, paths, BDFs and indices (no fallbacks).
5. CI lint: forbidden-term check extended to host names, mount paths, BDFs and literal device indices in tracked scripts (config/forbidden table already exists).
6. Reconcile the deployed environment.local.toml files on both machines to the new schema (backups kept).
