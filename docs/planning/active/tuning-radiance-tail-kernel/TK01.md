# RX 6900 XT tail quad kernel: register-permute W4 decoder instead of the LDS table (bit-identical)

## Description

The gfx1030 tail's accurate rows kernel (lane_moe_rows_w4_quaddpp, moe_lane_gemm.h ~834) is 71% of the tail's GPU time on cold/varied prompts; the tail bounds flashnext-4gpu cold-prompt TTFT (11.4 s on 27k synthetic prompts, tail busy ~73%). It decodes W4NL nibbles through an LDS lookup table. The GEMV already decodes the same levels with register byte permutes (w4nl_to_h2x2), producing the exact same f16 bits in the same element order. Swap the decoder (both GPT reviews' first bit-identical idea).

## Steps

1. Replay form `quad_perm` (OPT bit 0) beside production (branch exp/rad49-tail-quad-perm, worktree ${BC_WORK_ROOT}/wt-tail-quadperm).

3. rocprofv3 timing, alternating forms, gate/up and down separately (runs/rad49-tail-quadperm).
4. If faster: make it the production decoder (no switch left behind), KL + cold/doc/long-fill A/B.
