# Experimental branch: INT8 dot4 tail kernel (W4NL codebook as int8, activations re-quantised) under its own quality gate

## Description

RDNA2 has V_DOT4_I32_I8; llama.cpp decodes IQ4_NL to int8 and uses Q8_1 activations (mmq.cuh, vecdotq.cuh vec_dot_iq4_nl_q8_1, OpenCL gemm_noshuffle_iq4_nl_q8_1_dp4a.cl; Vulkan PR #31764: +34% matmul, +20% pp512 on RX 6600M, mean KL 0.00072, 98.73% same top token). Our levels x8 (9..176) do not fit one int8 codebook exactly and E4M3 -> int8 activations is lossy, so this is NOT bit-identical. ExLlamaV3 disables its INT8 GEMV on RDNA (fp16 dot2 faster). Ranked last by both reviews.

## Steps

1. Offline error study on captures: codebook approximation and activation re-quantisation, gate/up and down separately.
2. Only if the error is acceptable: prototype kernel, timing incl. conversion.
3. Full-model KL against reference AND against the current helper baseline at identical batching.

Extract real W4NL codes, E4M3 activations and scales from the captured gate/up and down workloads.Build CPU reference oracles for the accurate FP16-dot2 path and each integer representation.Measure codebook-only, activation-only and combined error independently.Reject candidate representations that cannot satisfy the declared quality budget.Prototype the best surviving representation using `v_dot4_i32_i8` on gfx1030.Profile all conversion, launch, reduction and rescaling costs.Test representative small-expert and large-prefill occupancy.Only then run full-model KL, against both the recorded reference and current accurate helper output.Keep the integer implementation experimental and opt-in until separately authorised.

## Detailed Solution & Technical Design

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

Begin with a completely offline representation study before writing an integer kernel.Evaluate exact and approximate codebook representations separately:Approximate one-pass signed-INT8 levels with a measurable quantisation error.A two-component representation, using multiple integer dot products or a correction term, to represent the signed W4NL levels exactly before scaling.Activation quantisation using independently measured per-group scales, matching the existing grouping as closely as possible.Existing `moe_lane_gemm.h:32` defines the nonlinear codebook. Its code-level expansion, K64 weight scale and K128 activation scale must be included in the oracle.For an approximate approach:`qW = encode_integer_codebook(W4NL)
qA, scaleA = quantise_E4M3_activation(A)

integer_dot = dot4(qW, qA)

output = rescale(integer_dot, weight_scale, scaleA)`This sketch is intentionally not presented as numerically equivalent to the current FP16-dot2 implementation. Compare the two-component exact-weight approach with the approximate one to isolate error caused by weights from error caused by activations.The prototype must preserve separate measurement of codebook decode, activation quantisation, integer-dot execution, scale restoration and final BF16 conversion.
