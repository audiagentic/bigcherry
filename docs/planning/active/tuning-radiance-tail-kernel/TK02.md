# RX 6900 XT tail quad kernel: fold the quad DPP broadcasts into v_add_f32_dpp (bit-identical)

## Description

The quad reduction does 3x (v_mov_b32_dpp + v_add_f32) per row per K64 group (~640 reductions per 16-row gate/up batch per column). gfx1030 DPP16 supports v_add_f32_dpp, so each pair becomes one instruction with the same operands in swapped order (exact for an fp32 add). Gateway GPT's top-ranked idea (est. 5-15% kernel, very low KL risk).

## Steps

1. Replay forms `quad_dppadd` (OPT bit 1) and `quad_perm_dppadd` (bits 0+1) on exp/rad49-tail-quad-perm.
2. Inspect the gfx1030 ISA: three v_add_f32_dpp, no reassociation or extra moves.
3. Bitwise sweep + alternating timing on the 40 captures (runs/rad49-tail-quadopt).
4. Adopt the fastest bit-identical combination as the production form; end-to-end A/B as TK01.

## Detailed Solution & Technical Design

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

Replace the six-instruction broadcast/reduce sequence in `moe_lane_gemm.h:881–905` with three ordered DPP additions:float sum; asm volatile( "v\_add\_f32\_dpp %0, %1, %1 "  "quad\_perm:\[1,1,1,1\] row\_mask:0xf bank\_mask:0xf\\n\\t"  "v\_add\_f32\_dpp %0, %1, %0 "  "quad\_perm:\[2,2,2,2\] row\_mask:0xf bank\_mask:0xf\\n\\t"  "v\_add\_f32\_dpp %0, %1, %0 "  "quad\_perm:\[3,3,3,3\] row\_mask:0xf bank\_mask:0xf"  : "=&v"(sum) : "v"(partial));Each lane's accumulation remains, in order, `partial + lane1`, then `+ lane2`, then `+ lane3`.The DPP source/destination operand distinction matters. This is not an ordinary warp reduction and must not be replaced by a butterfly sum or compiler-generated reassociation. Preserve full-lane participation and the existing `#pragma clang fp contract(off)` and `reassociate(off)` safeguards.
