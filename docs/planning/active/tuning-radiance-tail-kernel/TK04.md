# RX 6900 XT tail quad kernel: stage each activation row once per expert, not once per N-tile CTA

## Description

Every N-tile CTA re-stages and software-converts the same E4M3 activation rows to f16 (24 CTAs per expert for gate/up, 80 for down). Options: wider N per CTA (N=64, two columns per lane), or pre-converted activation tiles shared across CTAs. Must keep arithmetic order; register pressure decides.

## Steps

1. Measure the staging share of kernel time (ISA counters / variant with staging only).
2. N=64 variant; pre-converted f16 activation plane variant.
3. Bitwise sweep + timing; adopt only if faster on cold and doc captures.

Correct the plan's CTA counts to 40 gate/up and 80 down.Quantify stage conversion instructions, LDS traffic, barriers, wave occupancy and register pressure with the current TK01+TK02 kernel.Implement a staging-only diagnostic that preserves traffic and synchronization, clearly marking invalid numerical output.Test vectorised widening in the existing N=32 CTA.Prototype N=64 and inspect disassembly before full replay.If still promising, build a pre-converted-row experiment with a measured scratch-memory budget.Compare complete producer-plus-GEMM time, not GEMM alone.Remove temporary buffers and modes for any unsuccessful form.

## Detailed Solution & Technical Design

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

Compare two independent approaches.A. Wider N-tile CTA. A 128-thread CTA currently computes 32 output columns, with four lanes cooperating on each column. An N=64 variant could process two output columns per quad group and reuse one staged activation tile, while maintaining separate `acc[RB]` arrays and each output's original K order. The important trade-off is doubled or longer-lived accumulators and weight state.B. Pre-converted activation plane. Convert the E4M3 codes into their exact FP16 widening once per unique activation row. Keep activation scales separately in FP32. The GEMM must still apply scales at the original K128 fold; applying the scale during pre-conversion changes rounding and violates bit-identical arithmetic.Candidate design:// One-time preparation, for unique routed rows. half\_act\[token\]\[k\] = exact\_f16(e4m3\_act\[token\]\[k\]); // Existing quad GEMM: // read half\_act, read original float activation scales, // retain original dot8 and K-fold operations.A full 2,560-element activation row requires 5,120 bytes in FP16, compared with 2,560 E4M3 bytes plus scale storage. Account for scratch VRAM, preparation kernels, additional reads and the possibility that repeated staging is largely hidden by weight processing.A third, cheaper experiment is vectorised E4M3 widening inside the existing CTA without altering N tiling. This should precede an extra intermediate buffer.

GPT seed (gateway reviewer, 2026-11-10; full text runs/rad49-gpt-review/seed/):

- Assessment: The repeated staging is verified; the assumed CTA count needs correcting. With the confirmed intermediate width of 640 and `kQuadDppN=32`, gate/up has `2×640/32 = 40` output-tile CTAs per expert, not 24. Down has `2560/32 = 80`.
