# Review privacy and measurement boundaries for automatic benchmark export

## Notes



## Findings

P1: Use a closed schema with controlled identifiers; raw reports, receipt digests, error strings and free-form labels can leak or expose local provenance. P1: Compare serving identity around the benchmark; aggregate engine counters during shared traffic are not attributable. P2: Commit local evidence first so export failure is retryable; preserve concurrent checkout edits and reject collisions with different contents.

## Conclusion

Proceed with automatic file export after configuration and normal PR publication. Treat startup capture, local benchmark publication and Git export as independently verifiable boundaries.
