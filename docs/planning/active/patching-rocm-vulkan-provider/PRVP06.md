## Actual source and execution chain

- Graph construction: pinned llama.cpp b11552 \`src/llama-impl.h::llama_mul_mat_hadamard\` builds \`ggml_mul_mat(ctx, rot, res)\`, sets \`GGML_HINT_SRC0_IS_HADAMARD\`, and reshapes the result. Examples: \`src/models/qwen4exp.cpp\` rotates q/k/v and attention output if the relevant rotation tensor exists; \`src/models/deepseek4.cpp\` has indexer/attention uses. **Measure src1->ne[0] and executed backend for each real node**; do not infer 8192 from model embedding size.
- Pinned \`ggml/src/ggml-vulkan/ggml-vulkan.cpp::ggml_vk_can_use_fwht\` requires zero additional fused ops, Hadamard hint, contiguous src1, F32 src1/dst, and a non-null width-specific pipeline. \`ggml_vk_fwht_pipeline_idx\` recognizes only 64/128/256/512. \`ggml_vk_fwht\` dispatches \`ceil(n_rows/4)\` groups capped by maxComputeWorkGroupCount[0], with grid-stride row iteration and normalized F32 output. Wider widths use ordinary dense \`MUL_MAT\`; the Vulkan backend remains the owner of its fallback, buffers and descriptor lifetime.
- Pinned \`ggml/src/ggml-vulkan/vulkan-shaders/fwht.comp\` uses four rows/workgroup, one subgroup per row with XOR shuffle or a shared-memory alternative, a register array of N/BLOCK_SIZE floats per invocation, and two butterflies phases. \`ggml-vulkan-types.h\` has four F32 pipeline slots; \`vulkan-shaders-gen.cpp\` generates only F32 shader variants.
- Upstream #29772 changes those exact four files: eight width slots (64..8192); width/feature/resource-aware pipeline construction; F16 and F32 source variants; \`fwht_rows_per_wg[idx]\` used at dispatch; a 256-thread, **one-row** shared-memory path for width >512; F32 output. F16 requires \`shaderFloat16\` and the stacked [#29101](https://github.com/ggml-org/llama.cpp/pull/29101) source-variant change. Never apply #29772 as an isolated hunk onto b11552: re-evaluate upstream merge and both prerequisite diffs against the current pin. CUDA [#29100](https://github.com/ggml-org/llama.cpp/pull/29100) was merged 2026-10-08; that does not mean Vulkan is absorbed.
- \`fwht.comp\` for wide N uses \`BLOCK_SIZE=min(N,256)\`, \`ROWS=1\`, \`EL_W=N/256\`, \`shared float shmem[ROWS*N]\`. First log2(256)=8 stages exchange values via LDS with **two barriers per stage**; remaining log2(N/256) stages combine lane-local registers; final barrier protects shared-memory reuse across grid-stride rows. The one-row geometry avoids the four-row 8192*4*4=128 KiB LDS requirement. For N=8192: 32 KiB LDS and 32 F32 values per lane before compiler temporaries. Register allocation, spills, occupancy, bank conflicts and barrier cost are **unmeasured** on gfx1100/gfx1201.
- Admission must preserve the exact current \`ggml_vk_can_use_fwht\` semantics: hint, no fusion, contiguous src1, F32 dst, src1 F32 or supported F16, pipeline non-null, width list, workgroup-invocation and maxComputeSharedMemorySize limits, existing Intel driver exclusion. On unsupported devices/widths (including 16384) preserve dense \`MUL_MAT\` without a new dispatcher, allocator, configuration or telemetry system. Wave32/64 is a **device-reported Vulkan subgroup** condition, not an assumption from PCI identity.

## Work, memory and numerical bounds (theoretical, not measured)

For N=8192, 2048 F16 input rows: 8192*2048*2 = **32 MiB** input, F32 output = **64 MiB**, minimum logical read+write = **96 MiB** per transform, excluding descriptor, cache and fallback traffic. Wide shared tile = 8192*4 = **32 KiB**. An FWHT executes N*log2(N) add/sub results per row: **218,103,808** for 2048 rows. A dense 8192x8192 matrix product with 2048 rows requires about 137.44 billion multiply-adds (about 274.88 GFLOP if counted as two operations). This is an algorithmic work comparison, **not** a physical HBM measurement, E2E ceiling, or proof the dense route materializes its matrix on every call. The transform must still write every output and process every input row; fewer outputs/rows are correctness failures.

The Hadamard transform uses butterfly sign/order and \`1/sqrt(N)\` scaling at input. F16 input is converted to F32 before butterflies, F32 output; compare against dense F32 reference with explicit rounding tolerances. Do not claim universal bit identity with dense GEMM. Test exact integer-input butterflies separately from scaled F32/F16 and track max abs/rel/ULP, logits/KLD and greedy/MTP behavior.

## Bounded discriminator and implementation sequence

**Gate 0 — no shader edit.** On a terminal existing BigCherry receipt or a read-only graph census, capture \`(model digest, GGUF rotation tensor, graph node ID, src1 type, src1.ne[0], rows, strides, hint, fusion count, backend, physical GPU UUID, ICD/driver, subgroup, shaderFloat16, LDS/workgroup limits, actual pipeline identity)\`. \`GGML_VK_PERF_LOGGER=1\` labels \`MUL_MAT_VEC\` from the graph op and **cannot prove FWHT** (upstream #29101). Use a bounded temporary shader-pipeline selection trace or equivalent existing pipeline diagnostic; remove it after the proof. If no 1024–8192 F32/F16 Hadamard-hinted Vulkan node exists on representative BigCherry models, terminalize \`NO_WIDE_FWHT_ROUTE\` and do not port. No unrelated model, Qwen4Exp width or external Bonsai2 receipt may substitute for route proof.

**Gate 1 — source and cheap static tests, only after RRVP02 resumes.** Check #29101/#29772 merge/pin absorption. Prefer bump/adopt upstream as one composed change, not a new local shader fork. Run source/diff composition against the actual pinned tree; check shader variants generated and pipeline arrays initialized, 64..512 unchanged F32 controls, F16 feature negative, no subgroup-shuffle shared fallback, 16/32/64 KiB LDS, max workgroup invocations 128/256/1024, 1/3/4/5/7 row tails, grid-stride coverage, 16384 fallback, non-contiguous and fused negatives. Fail closed on any null pipeline or unsupported feature. Use the existing shader-generation and backend-op tests, not a new provider abstraction.

**Gate 2 — correctness and resource.** \`test-backend-ops -b Vulkan0 -o MUL_MAT_HADAMARD\` and \`-o MUL_MAT\`, direct 64/128/256/512 controls plus 1024/2048/4096/8192 F32/F16, and 16384 fallback. Confirm **actual pipeline identity**, not only pass counts. Compare reference values and outputs at zero, signed, extremes, non-multiple-of-4 row counts, multi-ubatch, repeated same-process requests, long context and graph replay/rebind. Track GPU timestamps, VGPR/spills/occupancy, LDS, shader compilation failures, logical input/output counts, scratch and descriptor lifetime. Test real logits/KLD/greedy and MTP acceptance only if an eligible production route exists. No missing work or silent CPU/BLAS fallback is an optimization.

**Gate 3 — measured admission/promotion.** First measure serialized/exposed FWHT fallback wall share. A 3% throughput target requires >=2.9126% *removable baseline wall latency* even with a perfect replacement. If lower, \`BELOW_CEILING\` without hardware patch. Otherwise paired control/current-pin versus composed upstream candidate on **gfx1100 and gfx1201 separately**, Vulkan driver/ICD pinned, no GPU P2P assumption, n=512 control and n=1024/2048/4096/8192, rows 1/3/7/2048, F32/F16, pp512/pp2048 and tg128/MTP only where executed. Four independent sessions, >=10 order-balanced paired rounds/session; record kernel and E2E, physical bytes/bandwidth plausibility, occupancy/spills, unchanged work/outputs/acceptance and <=1% unrelated-control regression. Promote only if CI95-low >=3% representative E2E gain and all correctness gates pass; else \`NUMERIC_FAIL\`, \`REGRESSION\`, \`NO_GAIN\`, \`UNSUPPORTED_ROUTE\` or \`PIN_ABSORBED\`.
