# Harden rccl_qualify/rccl_qualify_campaign into the durable, reusable RCCL qualification driver

## Description

Per gpt-dev-agent deep review (2026-09-02): tools/bigcherry/profiling/rccl_qualify.py + rccl_qualify_campaign.py are correctly located (bigcherry.profiling is the right domain -- genuinely diagnostic, isolated-subprocess, no production selection influence; do NOT create a new tools/bigcherry/rccl/ package). But the campaign driver as committed is already behind what GP06 actually ran: it is hardcoded to {0,2}/{1,2}/{0,1,2} only, has no {0,1} positive control or {0,3} negative control, one fixed 512KiB size (PRODUCTION_SIZE_ELEMENTS is defined but unused), no repetitions, no RCCL-version/compatibility argument, and no post-fault health/control recheck. GP06's real 3-way RCCL-version comparison was run through an ad-hoc, uncommitted variant instead -- exactly the tool-mess risk this item exists to close.

rccl_qualify.py itself also has real schema/harness gaps found by direct code read, not just the campaign driver:
- No RCCLCompatibilityRevision in RcclCaseResult identity at all -- violates the runbook's own P2.1/P2.3 requirement now that GP06 proved revision matters.
- TopologyIdentityV1 is under-specified: current RcclTopology is just topology_id + ordered device_arches, with ad-hoc labels like xtx_r9700 vs xtx1_r9700 baking an ordinal distinction into what's supposed to be a portable semantic ID.
- _classify() declares PASS without checking observed_algorithm/observed_protocol actually equals the requested plan -- a Ring/LL qualification can PASS after RCCL silently selected something else.
- Repeated-case artifacts (.stdout/.stderr/.rccl.json) are named from case_id alone with no attempt/rep index -- a 20-rep qualification run overwrites its own per-attempt evidence, leaving cases.jsonl rows pointing at the wrong file.
- The six-cell campaign loop does not implement the runbook's own required post-fault rule (re-run a known-good homogeneous control after GPU_FAULT/SIGNAL/TIMEOUT/DEVICE_LOST before trusting further results).
- channels exists in the candidate identity but build_command() never actually applies a channel control -- remove it from controllable identity until verified.

## Steps

1. Add a shared RcclCompatibilityRevision dataclass (source revision, ABI/API compatibility revision, build config relevant to device kernels, code-object/arch coverage) to a new tools/bigcherry/profiling/rccl_schema.py, and make it part of every RcclCase/RcclCaseResult identity -- both rccl_qualify.py and rccl_qualify_campaign.py import from here instead of each owning their own shape.
2. Replace ad-hoc topology labels with canonical topology facts (real edge/locality semantics per the runbook's TopologyIdentityV1, not xtx1_r9700 ordinal-flavored strings).
3. Fix _classify() to require observed_algorithm/observed_protocol == requested before PASS.
4. Add attempt_id/rep_index to every artifact filename and jsonl row so repeated cases don't overwrite each other's evidence.
5. Extend rccl_qualify_campaign.py's CLI surface: --binary, --output-dir, --compatibility-manifest (exact RCCL identity), --topology-config, repeatable --element-count, repeatable --algorithm (default Ring,Tree), repeatable --protocol (default Simple,LL,LL128), --repetitions, --outer-timeout, --control-topology. Default config should encode GP06's exact matrix: {0,1} positive control, {0,2}, {1,2}, {0,3} negative control, element counts {30720, 2621440}, full Ring/Tree x Simple/LL/LL128. Keep {0,1,2} as a separate GP01-Phase-2 extension once the two-rank gate is stable, not folded into the default matrix.
6. Implement the runbook's post-fault rule in the campaign driver: after any GPU_FAULT/SIGNAL/TIMEOUT, re-run the homogeneous control before trusting further results; DEVICE_LOST stops the campaign immediately if health can't be restored.
7. Remove channels from controllable candidate identity (build_command() doesn't implement it) until a verified control exists.
8. Add tools/tests/profiling/test_rccl_qualify_campaign.py -- currently only rccl_qualify.py has a dedicated test module.
9. Re-run GP06's exact matrix through this hardened, checked-in driver (not the ad-hoc script) to produce the durable evidence GP01/GP06 Track A actually needs.
