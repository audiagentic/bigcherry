# PRBE18 — Qwen3.5 GDN pre-scan fusion: reject stale 16-node port, qualify only residual work


## 2026-10-19 b11552 kernel audit — paired GDN Q/K L2 normalization (BCOP330)

**Decision: HOLD / trace-only.** The independently maintained [RDNA fork PR #179](https://github.com/stew675/llama-cpp-rdna-boosts/pull/179) is a *new, narrow launch-fusion* mechanism, not evidence that the rejected 16-node pre-scan fusion should return. It replaces two already-fused `RMS_NORM→SCALE` launches by one launch containing the same two independent per-row reductions. Do not port the fork patch, allocate a patch slot or queue a hardware lane without first-party exposed-wall admission. Keep the existing PRBE18 Gate 1 as the owner; no new norm owner, scheduler, allocator, cache, dispatch table or persistent config.

### Exact implementation/dispatch and upstream comparison

- At pinned [llama.cpp b11552 `src/models/qwen35.cpp`](https://github.com/ggml-org/llama.cpp/blob/b11552/src/models/qwen35.cpp), `build_layer_attn_linear` forms Q and K as separate `ggml_view_4d` views of `conv_output_silu`, with different offsets; V remains a third view. It calls `build_gdn_l2_norm` for Q and K separately. [`src/models/models.h`](https://github.com/ggml-org/llama.cpp/blob/b11552/src/models/models.h) implements each as `ggml_scale(ggml_rms_norm(x,eps/n),1/sqrt(n))`. Preserve Q/K/V alias roots, independent destinations and GDN recurrent-state consumers.
- [`ggml/src/ggml-cuda/ggml-cuda.cu::ggml_cuda_try_fuse`](https://github.com/ggml-org/llama.cpp/blob/b11552/ggml/src/ggml-cuda/ggml-cuda.cu) already dispatches `{GGML_OP_RMS_NORM, GGML_OP_SCALE}` to `ggml_cuda_op_rms_norm_scale_fused`; [`norm.cu::rms_norm_f32_cuda<true>`](https://github.com/ggml-org/llama.cpp/blob/b11552/ggml/src/ggml-cuda/norm.cu) uses 256 threads for `ncols<1024` and 1024 otherwise. Existing [merged #29393](https://github.com/ggml-org/llama.cpp/pull/29393) is the control; it is *not* the paired-fusion candidate. No equivalent paired function was found in the inspected upstream master `norm.cu` (19 Oct 2026).
- Fork [#179 patch](https://github.com/stew675/llama-cpp-rdna-boosts/pull/179/files) adds `norm.cu::rms_norm_scale_pair_f32<256>` and `ggml_cuda_op_rms_norm_scale_pair_fused`; `blockIdx.x` in `[0,nrows)` owns Q, `[nrows,2*nrows)` owns K. It preserves the scalar reduction body, `rsqrtf`, and `scale_out*(scale*x)` order. It adds a matcher in the existing fusion arm; the fork's source uses `ggml-cuda-try-fuse.cu` after a file split, whereas pinned b11552 has the matcher in `ggml-cuda.cu`. **Do not apply its patch verbatim to the older pin.**
- **Cross-pair correctness gap to close before any port:** the fork separately checks each local `RMS_NORM→SCALE` pair, shared `view_src`, F32, identical shape/strides/epsilon/scale, `ncols<1024`, and excludes direct K-read-of-Q-output. It then skips the whole intervening graph interval (`return j+1-i`) without an explicit **two-output** `ggml_can_fuse_subgraph` and `ggml_cuda_check_fusion_memory_ranges` proof across that interval. These existing ggml checks must verify both final output buffers, intermediate no-op/view aliases, all consumers, non-overlap, allocation lifetimes and graph replay. Shared view root does not itself prove safe dual-output fusion. This is a static admission gap, **not** an observed fork memory fault.
- Dispatch only when both local native fusions independently qualify, Q/K are on the same HIP device/stream, both source views and output spans are valid and non-overlapping, exact shape/strides/type/params match, and the full multi-output graph window is safe. Otherwise retain the pinned two-launch `ggml_cuda_op_rms_norm_scale_fused` path. Do not consume or suppress the V branch, gate/beta, snapshot publication or other GDN operations. No host/device transfers or cross-GPU sharing are added.

### Physical work, AMD-specific resource gate and evidence

- For `R=nrows*nchannels*nsamples`, original has **2 launches and 2R CTAs**; candidate has **1 launch and 2R CTAs**. Both must read and normalize all Q and K values and write both F32 outputs. Logical input/output bytes, reduction FLOPs and recurrent-state work do **not** decrease. Benefit is launch/graph overhead, not a claimed memory-bandwidth or arithmetic reduction. Any drop in CTAs, rows or output bytes is a correctness failure.
- Each CTA remains 256 threads (8 wave32 or 4 wave64 logical waves, architecture-dependent), with the fork's 32-float (128 B) dynamic reduction scratch per CTA. The pair-select predicate may add VGPR/branch instructions; verify actual compiled gfx1100/gfx1201 ISA, VGPR/SGPR, LDS, spills, occupancy, synchronization, launch duration and physical byte/work accounting. No normal GPU P2P is assumed on the dual 7900 XTX + R9700 + 6900 XT topology.
- **External measured evidence only:** fork r80, one R9700 gfx1201, Qwen3.6-35B-A3B: 96,360 single norm launches (142 ms aggregate GPU kernel time) → 48,180 pair launches (65 ms), decode 123.54→124.98 t/s (**+1.2%**). Qwen3.8-27B MTP single GPU 67.35→67.50 (**+0.2%**), dual tensor 99.39→99.69 (**+0.3%**). Hybrid Flash-Next dual tensor +0.37%, CI95 [+0.04,+0.70]%. External greedy hashes, P256/P3584 logits, KLD and backend-op tests passed as reported in PR #179; not independently reproduced here. These gains are below BigCherry's **CI95-low ≥3% E2E** promotion bar and cannot be transferred to gfx1100 or the current BigCherry pin.
- **Completed cheap host discriminator:** 144 eligible shape/CTA-coverage cases, 288 same-ordered host F32 reference comparisons, 24 `ncols>=1024` fallback cases, and four output-span fixtures (two overlaps flagged); `python -m py_compile` passed. This checks geometry and the need for output-span admission, **not** compiled GPU equivalence, numerical bit identity, alias-lifetime correctness, or performance. No HIP build, hardware lane, backend-op test or BigCherry benchmark was run.

## Authoritative disposition (2026-10-11, llama.cpp b11474)

**Reject the historical 16-node SSM_CONV→Q/K/V→gate/beta port as specified. No new patch or hardware job is authorized.** The actual Qwen3.5 graph is a *fan-out*, not the claimed single 16-op linear chain. Two of the most obvious opportunities are already native HIP fusions. Keep PRBE18 pending only for a bounded, read-only runtime graph/critical-path discriminator; close if it finds no independently removable cost. This supersedes the b11126 proposal, including its suggested `12xx_rd24` patch, 16-node matcher, raw historical warp geometry, and PRBE05/1235 dependency.

### Pinned source and exact data flow

1. `src/models/qwen35.cpp::graph::build_layer_attn_linear` (b11474, lines ~372–390): `beta` is `build_lora_mm(ssm_beta,cur) → RESHAPE → SIGMOID`; `gate` is `build_lora_mm(ssm_alpha,cur) → RESHAPE → ADD(ssm_dt) → SOFTPLUS → MUL(ssm_a) → RESHAPE`. **Both are independent inputs to GDN, not Q/K normalization outputs and not descendants of SSM_CONV.** No “shared alpha/beta between norm ops” exists.
2. Same function (~399–462): `build_conv_state` forms `conv_input`; `ggml_ssm_conv(conv_input,conv_kernel) → SILU`; the SiLU result has three distinct aliasing `VIEW_4D` consumers (`q_conv`, `k_conv`, `v_conv`) with different offsets. Q/K are separately normalized; V stays a view. `build_recurrent_attn` consumes normalized Q/K, V, gate, beta and recurrent state. The convolution-state update is separately published by `delta-net-base.cpp::build_conv_state`, including K rollback slots.
3. `src/models/models.h::build_gdn_l2_norm` (introduced by merged [#28068](https://github.com/ggml-org/llama.cpp/pull/28068), 2026-09-06) is `ggml_scale(ggml_rms_norm(x,eps/n),1/sqrt(n))`, **RMS_NORM → SCALE**, not an RMS_NORM-only node or a learned alpha/beta pair. In exact arithmetic this equals `x / sqrt(sum(x*x)+eps)`; floating-point evaluation/rounding still requires qualification.
4. `ggml/src/ggml-cuda/ggml-cuda.cu::ggml_cuda_can_fuse/ggml_cuda_try_fuse` already recognizes and executes `SSM_CONV → SILU` (and `SSM_CONV → ADD → SILU`) via `ggml_cuda_op_ssm_conv`; it also recognizes `RMS_NORM → SCALE` via `ggml_cuda_op_rms_norm_scale_fused` (merged [#29393](https://github.com/ggml-org/llama.cpp/pull/29393), 2026-09-25). `ggml/src/ggml-cuda/ssm-conv.cu::ggml_cuda_op_ssm_conv` has **one output** (`silu_dst` or `dst`) and handles the conv/bias/SiLU only. It cannot silently replace Q/K/V branch outputs, their alias lifetimes or recurrent-state publication.
5. `ggml_can_fuse_subgraph` plus `ggml_cuda_check_fusion_memory_ranges` protect source edges, consumers and output aliases. A speculative matcher that skips 16 graph nodes while publishing only one destination would lose Q/K/V or unrelated gate/beta work. A graph-build order alone does not prove a contiguous runtime node window.

**Ownership correction:** former `1235_rd09_q81_activation_cache_foundation` was retired into validated `engines/llamacpp/patches/1307_q81_activation_cache_mmvq` (PRBE05/PRBE06/QFP13). That cache serves MMVQ's Q8_1 activation identity; it is **not a prerequisite for F32 SSM convolution or Q/K RMS_NORM**. Do not reintroduce 1235, import a second cache, or use MMVQ launch geometry to size an SSM_CONV kernel. PNRO04/PNRO05 own GDN recurrence/prefix-tail, not PRBE18. Active QFP49/1360/1361 prefill/Meta work remains excluded and untouched.

### External mechanisms and transfer decision

- Open [llama.cpp #29187](https://github.com/ggml-org/llama.cpp/pull/29187) separately fuses **alpha/beta projection producers**; it is not a conv→Q/K/V 16-node kernel. Inspect its final merged implementation and per-architecture evidence before considering an independent producer optimisation; do not absorb its ownership into PRBE18.
- [vLLM issue #51779](https://github.com/vllm-project/vllm/issues/51779) documents BF16 Q/K normalization/rounding sensitivity in fused GDN implementations. Its measurements are external and do not establish an AMD performance benefit; use it as a precision-parity warning.
- [SGLang KDA backend](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/layers/attention/linear/kda_backend.py) uses shape-gated fused decode with an explicit fallback; CUDA/Triton assumptions and state layout are not directly portable to gfx1100/gfx1201.
- Merged upstream [#30087](https://github.com/ggml-org/llama.cpp/pull/30087) changes GDN **recurrent** warp geometry, not the pre-scan. Do not count its reported NVIDIA benefit as PRBE18 headroom.
