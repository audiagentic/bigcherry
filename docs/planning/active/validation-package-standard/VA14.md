# VA11B: real contract-execution architecture (control/subject lanes, effect aggregation, promotion gate)

## Description

The real missing piece the original VA11 assumed existed, per GPT round-7 review (req_796bde0a1271476b): there is currently no real per-contract-lane benchmark execution system. Design and implement reusable machinery that takes an ExperimentContract's required positive/control/boundary lanes, runs the actual control-vs-subject binaries per lane (not a reinterpretation of the tune campaign's own S6 stock/native/replay measurements -- those are a different domain, see VA07), and produces real ComparisonArtifact/LaneEffect/MarkerArtifact objects consumed by the already-real aggregate_contract_effects(), evaluate_correctness_gate(), evaluate_trigger_proof(), and evaluate_promotion_gate() (all four confirmed to exist in tools/bigcherry/experiment/contract.py). Do not invent an ad-hoc second evidence vocabulary if contract.py's native types already represent the concept. Contract lane coverage becomes authoritative here; final eligibility becomes (adapter PASS AND contract promotion PASS). Bump VALIDATION_FRAMEWORK_VERSION (registry.py) exactly once, here, since this materially changes validation semantics and existing validation digests should invalidate intentionally.
