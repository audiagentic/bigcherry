# Gate promotion on statistical significance (effect CI excludes zero), not point estimates alone

## Description

`evaluate_promotion_gate()` (tools/bigcherry/experiment/contract.py:1557) compares POINT ESTIMATES against acceptance thresholds:

```python
if acceptance.end_to_end_gain_pct is not None:
    measured = aggregated_effects.get("end_to_end_gain_pct")
    if not isinstance(measured, (int, float)) or measured < acceptance.end_to_end_gain_pct:
        reasons.append(...)
```

The confidence interval IS computed and stored, but is not consulted. RD73's 2026-09-04 contract run produced:

```
stats: { geometric_effect_pct 1.855, ci95_low_pct 1.482, ci95_high_pct 2.169,
         paired_rounds 10, resamples 10000, seed 0 }
aggregated_effects: { end_to_end_gain_pct 1.855, target_kernel_gain_pct 1.855,
                      max_control_regression_pct 0.0 }
```

Only the point estimate reaches the gate. That is the wrong half of the data to gate on.

## Detailed Solution & Technical Design

Add a significance requirement so a gain claim must be BOTH large enough and statistically real.

Why this matters in both directions -- it is not merely a loosening or a tightening:

* FALSE POSITIVE the current gate accepts: a point estimate of +3.1% against a
  3.0 bar passes today even if its 95% CI is [-1.2%, +7.4%], i.e. the effect is
  not distinguishable from zero. The gate cannot see that.
* FALSE NEGATIVE the current gate produces: RD73 measured +1.855% with CI
  [1.482%, 2.169%] -- an unambiguously real effect, CI entirely positive --
  and was rejected purely on magnitude.

Proposed shape (design, not final):

1. Plumb the per-effect CI into `aggregated_effects` alongside the point
   estimate (it already exists in the lane artifact's `stats` block), so the
   gate has access to it without re-reading artifacts.
2. Add an acceptance field, defaulted so existing contracts are unchanged,
   e.g. `require_effect_significance = true`, meaning: for any declared gain
   threshold, the effect's CI lower bound must be > 0.
3. When the field is set and the CI is ABSENT, the verdict must be a distinct
   non-pass state (mirroring EC18's "invalid" handling for an unproven
   trigger) -- never a silent pass, and never folded into "fail", since an
   unmeasurable effect is not the same as a measured negative one.
4. Regression side: consider the symmetric test -- a regression budget should
   arguably be violated only when the regression is itself significant, so a
   noise-level -0.2% blip does not fail an otherwise good patch. Decide this
   deliberately; it is a policy choice, not an obvious consequence.

Related policy change already made (2026-09-04): RD73's acceptance was
realigned from `end_to_end_gain_pct = 3.0` / `max_control_regression_pct = 2.3`
to `1.0` / `1.0`, because 3.0 was an unexplained outlier (RD73 is the only
contract gating end-to-end; the other 18 gate kernel gain at 0.3-1.4) and
because the regression side should be the strict side. That change makes the
absence of significance gating MORE consequential, not less -- a 1.0 bar
without a CI requirement is easier to clear on noise than a 3.0 bar was. This
item is the counterweight and should not be left indefinitely unimplemented.

## Notes

Filed 2026-09-04 alongside VA23 (which addresses a different gap: contract-produced artifacts not reaching the generic performance/controls validators at all).

Origin: user direction that "the 3% bar is too high; we should be judging any increase based on any associative regressions". Implementing that principle honestly requires this item -- lowering magnitude bars without adding a significance requirement would make the gate easier to clear on noise, which is the opposite of the intent. The principle is sound; it needs the statistical half to be safe.

Note the machinery already supports a related asymmetric case cleanly: a contract with BOTH gain thresholds None promotes on correctness plus the regression budget alone (see the docstring at contract.py:1583-1592). That is the existing precedent for "judge on regressions", and this item extends the same thinking to contracts that do declare a gain.
