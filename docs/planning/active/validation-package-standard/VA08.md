# Status-aware patch-verify-evidence: ported-benched/deferred-hardware obligations, packaged-patch coverage fix

## Description

patch-verify-evidence currently only evaluates patches with patch.toml state='validated' (returns not-required for everything else). Extend it to also enforce: the ported-benched obligation (current-pin compact evidence proving a real control/subject benchmark occurred with build/hardware identities recorded per VA07's resolved schema; correctness failure forbids the status) and the deferred-hardware obligation (README+validation.toml documenting the intended validation, with the hardware limitation recorded as a structured BLOCKED-evidence entry, not merely absent methodology). Fix the packaged-patch evidence-coverage bug GPT identified: cross_check()/the evidence selection path only checks entries present in the legacy catalog.toml (via set(entries) & modules), silently skipping packaged RD patches never added to that catalog -- pass full registry descriptors into validation_evidence_statuses() instead (this fix lives here, not in VA02's static lint, per GPT round 2's static/dynamic split). No legacy grandfathering: old b10502 evidence remains historically retained but cannot itself authorize a current-pin (b10692) ported-benched/ported-validated status claim -- this is distinct from VA01's structural-grandfather exemption, which only protects the package SHAPE (README/validation.toml presence), never the evidence CONTENT/freshness.
