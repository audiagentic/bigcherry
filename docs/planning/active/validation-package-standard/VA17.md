# VA09B: contract-scoped ValidationPlan semantics + VALIDATION_FRAMEWORK_VERSION bump

## Description

Per GPT round-10 review (req_16d7e7158cb14331). tools/bigcherry/patch/validation.py: CheckSpec gains contract_ids: tuple[str,...]=() (parsed from a generic adapter `contracts = [...]` validation.toml field, routing metadata not validator config); ValidationPlan.contract becomes ValidationPlan.contracts: tuple[ContractBinding,...]; requirements become (contract_id, capability) pairs, not just capability -- build_validation_plan() must independently prove producer coverage for every pair (e.g. 1203's RD05/RD06/RD07 each need their own correctness/controls/etc coverage even where capability names repeat). Invariant: a check scoped to one contract satisfies only that contract's requirement; a check scoped to multiple contracts may satisfy all of them; an UNSCOPED check on a multi-contract patch satisfies NO contract-derived requirement (single-contract patches keep today's implicit-scope-to-the-sole-contract behavior for backward compatibility). plan_canonical_payload() becomes v2, serializing sorted {id,hash,required-capabilities} per contract plus each check's contract scope (so two plans differing only in which contract a check applies to don't hash identically). tools/bigcherry/patch/validation_policy.py: has_contract becomes bool(descriptor.experiment_contracts); require_execution_package() requires non-empty plural bindings; ported-validated's architecture policy becomes the exact UNION of every bound contract's required architectures (1203: gfx1030/gfx1100/gfx1201, since RD05/RD06 require gfx1201 and RD07 requires all three).
