# VA09B: contract-scoped ValidationPlan semantics (multi-contract support)

## Description

Per GPT round-10 review (req_16d7e7158cb14331), corrected 2026-09-01 (GPT session ses_5bbee8ce5c9a4265): tools/bigcherry/patch/validation.py: CheckSpec gains contract_ids: tuple[str,...]=() (parsed from a generic adapter `contracts = [...]` validation.toml field, routing metadata not validator config); ValidationPlan.contract becomes ValidationPlan.contracts: tuple[ContractBinding,...]; requirements become (contract_id, capability) pairs, not just capability -- build_validation_plan() must independently prove producer coverage for every pair (e.g. 1203's RD05/RD06/RD07 each need their own correctness/controls/etc coverage even where capability names repeat). Invariant: a check scoped to one contract satisfies only that contract's requirement; a check scoped to multiple contracts may satisfy all of them; an UNSCOPED check on a multi-contract patch satisfies NO contract-derived requirement (single-contract patches keep today's implicit-scope-to-the-sole-contract behavior for backward compatibility). plan_canonical_payload() becomes v2, serializing sorted {id,hash,required-capabilities} per contract plus each check's contract scope (so two plans differing only in which contract a check applies to don't hash identically). tools/bigcherry/patch/validation_policy.py: has_contract becomes bool(descriptor.experiment_contracts); require_execution_package() requires non-empty plural bindings; ported-validated's architecture policy becomes the exact UNION of every bound contract's required architectures (1203: gfx1030/gfx1100/gfx1201, since RD05/RD06 require gfx1201 and RD07 requires all three).

CORRECTED FRAMING (was stale): VALIDATION_FRAMEWORK_VERSION does NOT bump for this item -- it was already bumped 1->2 by VA14 (a different slice, RD08 correctness+trigger promotion semantics) and stays "2" here; bumping to 3 for this item would needlessly stale existing VA04/VA05 evidence, since this item adds support for a previously fail-closed/unsupported domain (>1 bound contract) rather than changing existing 0/1-contract semantics. VA16 (plural PatchDescriptor.experiment_contracts) and VA14 are BOTH already landed (commits 00fabee, 43296fa) -- this item's dependency on them is satisfied, not blocking.
