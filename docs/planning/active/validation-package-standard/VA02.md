# Extend patch-lint: static validation-package policy (README/validation.toml/contract-binding/coverage)

## Description

Extend tools/bigcherry/cli/patch.py::cmd_patch_lint / patch_catalog.cross_check() to be a purely STATIC/package-policy gate (per GPT review round 2): for any RD patch entering or claiming ported-benched/ported-validated status, require README.md + validation.toml presence, require an Experiment Contract binding in patch.toml (patches without one -- e.g. RD58/RD73 today -- must fail lint, not silently validate on universal apply+build alone), parse validation.toml into a ValidationPlan via tools/bigcherry/patch/validation.py, verify every required capability has a producer (apply/build mandatory; correctness/performance/activation/control only where the bound Experiment Contract requires them), verify custom/fixture validity, check tracked-status vs patch.toml state consistency, and enforce non-empty validation-architectures for any ported-validated claim. Apply the VA01 structural-grandfather migration rule (one-time exemption bound to implementation-digest + tracked-status + a policy/version identifier, no hardcoded per-patch exceptions) so existing nonconforming packages don't break lint immediately. MUST also add an EXECUTION-SIDE anti-grandfather guard (GPT round 3, req_884ce5ce06594e71): structural grandfathering may keep the repository lint-green for an untouched legacy package, but it must NEVER authorize a NEW validation run -- currently the patch-validation-campaign path permits validation_plan is None and still executes/writes evidence, which would let a grandfathered patch silently accumulate real evidence without ever having a real README+validation.toml+resolved-contract. Starting a new validation execution for an RD patch must hard-require README + validation.toml + a resolved Experiment Contract to exist first, regardless of any lint-side grandfather exemption.
