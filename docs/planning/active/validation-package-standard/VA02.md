# Extend patch-lint: static validation-package policy (README/validation.toml/contract-binding/coverage)

## Description

Extend tools/bigcherry/cli/patch.py::cmd_patch_lint / patch_catalog.cross_check() to be a purely STATIC/package-policy gate (per GPT review round 2): for any RD patch entering or claiming ported-benched/ported-validated status, require README.md + validation.toml presence, require an Experiment Contract binding in patch.toml (patches without one -- e.g. RD58/RD73 today -- must fail lint, not silently validate on universal apply+build alone), parse validation.toml into a ValidationPlan via tools/bigcherry/patch/validation.py, verify every required capability has a producer (apply/build mandatory; correctness/performance/activation/control only where the bound Experiment Contract requires them), verify custom/fixture validity, check tracked-status vs patch.toml state consistency, and enforce non-empty validation-architectures for any ported-validated claim. Also owns the FULL structural requirement (README + validation.toml + contract binding) for deferred-hardware status -- GPT round 4 corrected an ownership error: these structural checks belong here, not in VA08 (VA08 verifies only the deferred-hardware BLOCKED-evidence freshness, not the structural package). Apply the VA01 structural-grandfather migration rule (one-time exemption bound to implementation-digest + patch.toml-digest + policy/version identifier + normalized tracked-status set -- GPT round 4: identity was too weak using implementation_digest alone, since that only hashes patch.py and misses patch.toml metadata changes) so existing nonconforming packages don't break lint immediately. MUST also add an EXECUTION-SIDE anti-grandfather guard: structural grandfathering may keep the repository lint-green for an untouched legacy package, but it must NEVER authorize a NEW validation run -- patch-validation-campaign must hard-require README + validation.toml + a resolved Experiment Contract to exist before starting a new validation execution, regardless of any lint-side grandfather exemption. MUST explicitly disable/separate cross_check()'s existing dynamic branch (GPT round 4: cmd_patch_lint() today calls cross_check() with default real-repo behavior, which auto-enables HI83 dynamic evidence verification via set(entries) & modules against the legacy catalog.toml -- this is the actual location of the 'packaged-patch coverage bug', and since VA02 makes patch-lint truly static, the fix here is to disable/remove that dynamic branch from patch-lint entirely, NOT to redesign validation_evidence_statuses() -- that function already correctly resolves packaged descriptors and lives in the real dynamic verifier, patch-verify-evidence).
