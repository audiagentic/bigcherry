# Tracked evidence does not persist pair_ratios or lane effects, so no interval can be re-aggregated from committed evidence

## Notes



## Findings

Found while attempting to adopt session_ci95_threshold_bound_v1 on RD73.

The session estimator (bootstrap_session_effect) needs each session's per-pair ratio vector. block_bootstrap_effect() already computes and returns pair_ratios, and its own VA24 comment names them explicitly as 'the SUFFICIENT STATISTIC for recomputing an AGGREGATE interval across several lanes without re-running the benchmark'. The intent is stated in the code.

But make_record() never persists them. Searching a real RD73 evidence record for 'pair_ratios' or 'geometric_effect_pct' returns nothing. They exist only inside the campaign's rd73-mtp-lane.json / rd73-performance.json artifacts, which live under artifacts/ -- gitignored by design, because raw campaign output is deliberately not committed.

CONSEQUENCE. The committed evidence record retains identity, build provenance, check verdicts and artifact hashes, but not the measurements. So from tracked evidence alone it is impossible to:

  * re-aggregate an interval across sessions (the whole point of the session policy);
  * recompute an aggregate interval across lanes, which VA24's own comment says the sufficient statistic was retained to enable;
  * re-analyse any historical result under a new estimator, which the frozen governance explicitly contemplates ('historical runs may be used to validate or simulate it');
  * audit a recorded effect number against the data that produced it -- the record asserts a verdict whose inputs are unavailable.

The artifact sha256s are bound in the record, so tampering would be detected IF the artifact still exists. On a machine that never ran the campaign, or after the workdir is cleared, it does not. RD73's own run-3 artifacts survive only because I copied them out of the campaign workdir by hand.

This is the third layer of the same underlying problem. RV95: the record did not carry activation/correctness dispositions the verifier needed. RV96: the record could not hold more than one measurement per build. This: the record does not carry the measurements themselves. In each case the evidence system stored identity and verdicts faithfully while omitting what would be needed to check or re-derive them.

Sequencing note: I migrated RD73's contract to session_ci95_threshold_bound_v1 to pre-register its stopping rule, which broke five RD73 campaign tests because the single-session path produces no _sessions count. That was correct gate behaviour and wrong sequencing on my part; the migration was reverted. A contract must not demand evidence no tool can produce -- that is the same failure RV96 fixed.

## Conclusion

Persist per-lane effects, including pair_ratios, into the validation record so an interval can be re-derived from committed evidence alone. The vector is small (one float per paired round; RD73 records 10) and is already computed -- this is a retention decision, not new measurement.

Do this BEFORE adopting session_ci95_threshold_bound_v1 on any contract. The policy and its stopping rule are implemented and tested (commit 583a5607) but deliberately adopted by nothing, because the evidence pipeline cannot yet satisfy them.

Order to finish RD73: (1) persist lane effects in make_record; (2) aggregate sessions from a patch's records into <field>_sessions / _ci95_low / _ci95_high; (3) migrate RD73's contract, which is the pre-registration moment and must precede any further session; (4) collect sessions under the new contract hash until the stopping rule is satisfied -- 4 minimum, 8 maximum, roughly 25 minutes each on the dual-XTX host.

Note for step 4: the four existing sessions (+1.855, +1.717, +1.249, +2.244) were collected under the previous contract hash and under no stopping rule. Per the frozen governance a new policy is prospective, so they inform planning -- they are where the between-session sd of 0.411 comes from -- but must not be reinterpreted to promote the patch whose behaviour motivated the change.
