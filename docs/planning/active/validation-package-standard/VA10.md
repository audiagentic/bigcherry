# RD58 contract vocabulary: new workload tag + correctness token for multi-GPU state-restore claims

## Description

RD58's real claim is repeated multi-GPU state-restore integrity / fault avoidance (the originating SDMA fault). Two distinct vocabulary gaps, both found by GPT (round 3 + round 4 code-grounded): (1) correctness vocabulary is limited to backend_reference, greedy_parity, bit_identical, ppl_equality -- none accurately describes this claim; (2) contract WORKLOADS are a closed vocabulary too, and the available tags include multi_gpu_copy but nothing for state-restore -- do not misuse multi_gpu_copy for this. Add a new workload tag (e.g. state_restore) and a new correctness token. GPT round 4 explicitly rejected 'fault_reproduction_absence' as the correctness token name: failure to observe a fault is not affirmative proof, especially since Brutus historically did NOT reproduce RD58's originating fault -- prefer a token like state_restore_integrity that describes what IS being checked (state correctly restored), not an absence claim. Design both, land them in the Experiment Contract schema, before RD58's own contract (VA05) is written.
