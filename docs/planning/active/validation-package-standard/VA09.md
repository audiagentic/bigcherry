# Multi-contract patch validation binding (RD05/RD06/RD07-style patches)

## Description

PatchDescriptor currently has a singular experiment_contract field, but at least one existing patch (1203_rd050607_rdna4_wmma_fa_q6k_mmq) intentionally represents THREE distinct hypotheses/contracts (RD05, RD06, RD07) that the Experiment Contract registry already models separately. A repo-wide rule of 'a validation-ready RD patch must bind one contract' is therefore not generally correct. Add: patch.toml/descriptor support for plural contract identities; ValidationPlan aggregation across multiple bound contracts without collapsing distinct hypotheses into one; an evidence identity capable of binding multiple {id,hash} contract pairs; verifier freshness checks across every bound contract, not just one. VA07's evidence schema work must not bake in another permanently-singular contract identity -- support a plural contracts representation while still reading legacy single contract_id/contract_hash for older records.
