## Findings

Read at head 93708cd5 (whole item, 555 lines, including the self-review correction). Code claims checked against patches/1281_moe_mul_mat_id_range/patch.py and the production tree (vendor ggml-cuda/mmq.cu, quantize.cu).

VERIFIED
- 1281 does change `dedup_bcast = ne11 == 1 && n_expert_used > 1` to `... && !bc_range` (patch.py L312/L328) and zero-fills ids_src1 for range nodes (L324); upstream's dedup path calls quantize_scatter_mmq_q8_1_cuda with the inverse map from mm_ids_helper (mmq.cu L277-317). The diagnosis is correct: every range gate/up projection quantises n_tokens * top_k rows where the ordinary path quantises n_tokens.
- The design is the minimal one: -1 sentinel in the inverse map, a range-only scatter specialisation, no new helper, no host readback. The self-review's two corrections (keep the ordinary scatter instantiation untouched; test partial-J tiles with a dirtied pool) are right and should be treated as part of the plan, not an appendix.

FINDINGS
1. PATCH ID COLLISION (blocking, trivial). `1342` is taken: patches/1342_fusion_bisect was committed at 9a7b54b0, two minutes before this item was created from head e4798a10. Use the next free id (1343) - or see finding 2.
2. OWNERSHIP. Owner rule (CLAUDE.local.md): a fix or improvement to a patch goes inside that patch; a new patch is for a genuinely new mechanism. This restores an upstream optimisation that 1281's own edit switched off, so it belongs in 1281 behind BIGCHERRY_MOE_RANGE_DEDUP (default 0) from the start, not in a temporary second package that is folded in later. 1281 is in validated-enhancements; a default-off flag leaves its proof intact (flag off = current code), and the lightweight tier re-confirms after the flag flips.
3. PRIORITY / SCOPE. P0 overstates it for production: range nodes exist only with BIGCHERRY_MOE_EP=1 (1283), which is not deployed - the production row split already takes upstream's dedup path. The win can only show in the expert-split layouts (MET04 / MET08). It is still worth doing, and for a specific reason the item does not state: expert split currently EQUALS the row split in prefill (1061-1082 vs 1040-1062 t/s at 8K, 1071-1079 vs 1070-1074 at 24K) while doing ~10x the activation quantisation work, so removing that work is the first change that could put the expert split ahead in prefill. Suggest P1 and a link to MET08.
4. MATERIALITY GATES conflict with owner policy. '>= 3% median or do not promote; park below 1.5%' contradicts the standing rule that small wins count when nothing regresses (bigcherry-benchmark skill: no materiality bar). Because the change is required to be bit-identical and lives inside 1281, the gate should be: bit-identical output, activation evidence, no regression - then keep it whatever the size of the gain. Keep the >= 30% / >= 50% quantiser-time checks only as activation evidence (did the path engage), not as promotion bars.
5. TEST COVERAGE GAP IN 1281 ITSELF (new, relevant here). tests/test-mul-mat-id-range.cpp builds its activation as [n_in, n_used, n_tokens] (patch.py L548, L619), i.e. per-route input with ne11 = n_used. The broadcast shape ne11 == 1 that gate/up actually use is not exercised at op level at all - today it is covered only end to end. The fixture QFP30 asks for is therefore not just for the new path: add the broadcast case for flag off as well, and compare flag on against it.
6. 'QSA path correctness-blocked' is out of date. 1332 (QSA token chunk) is validated at ub1024 + BIGCHERRY_QSA_CHUNK=256 (fidelity 23/24, TV 0.092) and in validated-enhancements. ub512 first is still the right isolation, but ub1024 is not blocked.
7. NUMERICS NOTE for MET09. GPT's earlier suggestion that the disabled dedup is the leading cause of the expert-split vs row-split numeric difference does not hold up under this item's own gate: quantising the same activation row once or top_k times yields the same Q8_1 blocks, which is exactly why A/B is expected to be bit-identical. If the backend test confirms bit-identity, that hypothesis is closed and the difference is summation grouping.
8. MEASUREMENT. Use the tools that now exist: tools/lab/flash-next/queue-env-ab.sh (same-binary ABBA, greedy md5, FIDELITY=1) with the env exported for both arms (BIGCHERRY_MOE_EP=1 and the expert shares) and AB_ENV=BIGCHERRY_MOE_RANGE_DEDUP=1. Draft acceptance must be compared per arm; since output is required identical it should be equal, which also makes decode comparable (unlike comparisons between different expert partitions).
9. STEP 10 (profile one lane first) is the right order and should stay mandatory: the current equality of expert split and row split in prefill may mean the quantiser is a small share, in which case the answer is a quick, cheap negative.

## Conclusion

Sound and implementable; the mechanism and the self-review corrections are correct. Change before coding: (1) do not use id 1342; (2) implement inside 1281 behind the default-off flag instead of a separate package; (3) replace the percentage promotion bars with bit-identity + no-regression, keeping the quantiser-time drop as activation evidence; (4) add the broadcast (ne11 == 1) case to the existing range test for both flag states; (5) priority P1, linked to MET08, since only the expert-split layouts can benefit; (6) drop the 'QSA correctness-blocked' wording.
