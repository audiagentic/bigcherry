## Execution discipline

Do one coherent implementation at a time per overlapping owner. Independent lanes can use separate worktrees, but heavy compiles and measurements are serialized according to lease. Start with actual main/release and reconcile already-merged work before editing. Targeted existing tests, affected-unit harness, one integrated release acceptance only when required. Bit-identical where arithmetic unchanged; otherwise use existing approved quality/noise contract. Record negative results and code; never erase or reopen history. All state changes through planning API, ledger event with actual changes, PR merged and worktree removed only when verified. Do not declare the assumed native migration, any new implementation, or optional feature complete solely because this roadmap exists.
