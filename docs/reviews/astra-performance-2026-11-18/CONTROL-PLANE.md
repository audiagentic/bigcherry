# Radiance recipe loading

## Resolve recipe inputs for one invocation

[core/config.py](../../../tools/bigcherry/core/config.py) calls `_local_env_table` whenever `expand_host_value` sees a non-None string, including literal paths. The file is read and parsed each time. A missing standard variable can also call `environment.load_default()` and recurse into expansion of a host field. In the final runtime profile loop, `components.load_all` repeats per profile, and [load_all](../../../tools/bigcherry/core/components.py) reads engine/component declarations each time. A read-only Path.read_text counter around one Radiance recipe load observed one recipes.toml read, four environment.toml reads, two engine.toml reads and twelve component.toml reads for two profiles on the review host. The host-environment count depends on the loaded configuration; this is a call count, not a wall-time result. This is CLI/planning work, outside token generation.

- Fast path literal strings. Resolve environment against a snapshot obtained once per recipe load, including the explicit environment file and the existing host fallback. Pass the existing engine component declarations to each profile check. A resolver closure is enough; retain standalone `expand_host_value` for callers outside `load`.
- Preserve effective precedence, unresolved placeholders on unused platforms, Windows slash handling and fail-closed use of required paths. Include a visited set or a clear config error for recursive host defaults; avoid widening the expansion syntax. A fresh load must see edits. A process-global cache would give stale reads to long-lived callers and would conflate repo roots or override files.
- **Gate:** instrument reads in a representative recipe load; expect one read of each used declaration and at most one local override read. Compare resolved outputs, errors and build/cache identities against the original path with clear precedence fixtures.

The [Radiance bump adapter](../../../tools/bigcherry/engine_adapters/radiance_bump.py) calls the recipe loader from its build platform resolution. Other callers benefit only if they use this existing loader. Start with the load boundary rather than adding caching to every CLI, and compare read counts with both Radiance profiles present.

## Stop dormant n-gram work from widening production builds

The [component documentation](../../../engines/radiance/components/ngram-helper/README.md) records the owner's decision to shelve GPU n-gram gather and keep its source. [r3_ngram_enabled](../../../engines/radiance/components/ngram-helper/r3_ngram_host.cpp) returns zero unconditionally; [ngram_plugin.cpp](../../../engines/radiance/components/ngram-helper/ngram_plugin.cpp) accordingly reports zero kernel rows. The [engine component declaration](../../../engines/radiance/engine.toml) still enrolls it, and its [CMake build](../../../engines/radiance/components/ngram-helper/CMakeLists.txt) builds both the plugin and multi-ISA helper. The [contract fixture](../../../engines/radiance/components/serving/contract/contract_check.cpp) also names the component explicitly. This is a build and artifact-surface opportunity, not a token-time improvement.

Keep the shelved source and evidence. Inventory users of both shared objects and the current release outputs before separating evaluation builds from the normal component set. Reuse the existing component selection/build machinery where it supports that distinction. Remove brittle hardcoded declaration lists only when the owner already passes the effective component inputs to generator/checker; check generated contract and SDK outputs together. Compare release and component receipts, then build the explicitly selected experimental component once if it remains an advertised build target. A zero-row plugin by itself does not prove the shared objects can be removed from a published asset.

The helper's apparent knobs (a 32,768-row scratch floor and 2,048 MiB reserve) belong to the shelved implementation. Leave them dormant. If reactivated for a genuine topology requirement, derive scratch from the maximum admitted rows and use the admitted spare capacity for reserve; verify failure bounds before exposing either as an operator setting.
