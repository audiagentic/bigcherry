Source inspection at `a1a48cc0a6bc`. The findings cover the Radiance stock lane, its component and pin-bump builders, the documented server comparison and KL inputs, and the repository helper launcher. Counts below describe code paths. No build, model load or timing run was performed.

## Bind benchmark evidence to the runtime that executed

The normal Radiance build installs component outputs in `radiance_home`, including kernel plugins, the MoE worker, and `bc-serve`. The build worker then records digests through a function which starts at `bin/radiance` and only looks beside the binary for shared libraries and under `bin/profile` for INI files. The reuse check and the server comparison use that same restricted search. Replacing only `radiance_home/kernels/libr3.so` can leave those observed digests unchanged. The component **source** digest in the build plan describes the requested build. It cannot establish which compiled plugin an arm actually loaded. A verified release archive already has a file-level manifest, but benchmark preparation reads the installed marker and still uses the bin-relative search. ## Honor the requested build concurrency through the entire lane

The workflow's manual cold trial sets `CMAKE_BUILD_PARALLEL_LEVEL` to 2 or 6. The main build's argument builder deliberately omits bare `-j` under a cap. The runtime-target build, component builds, component-test builds and the pin-bump engine build issue their own commands with bare `-j`, which selects the native build tool's default. A trial labelled “2” cannot establish the cost or peak memory of a two-job whole-lane build from its label. The normal CI default is separately selectable. ## Read a helper launch's directory and detector facts once

On helper layouts the repository launcher invokes `resources derive-launch`. For every RAD directory entry, `_rad_sizes` currently slices the string table from the name offset to its end, then splits that suffix at the first NUL. Across N entries and S string-table bytes this can copy O(N × S) bytes. Routed expert records use their numeric layer, index and slot only. The same operation invokes `bc-serve --explain --json` through `radiance_inventory.resolve`, then invokes the same explanation again with the same site and layout for host memory facts. It also issues a separate unmeasured manifest request for the owner map.
