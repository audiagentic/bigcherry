# Extending Radiance's native RDNA3 kernel library

> Status (2026-11-25): written against pin 1.17 and an earlier upstream snapshot; the production pin is now 2.2.0. Use it as an input to RCS15, not as current fact. Terms used here: **libr3d** is upstream's native RDNA3 kernel library; **libr3** is BigCherry's generated gfx11 provider (to be named libbcr3). Definitions and the plan map: `docs/design/radiance-kernel-composition.md` sections 0 and 8a.


Use upstream `libr3d` as the gfx1100 compute provider. First run it unmodified against the served model bands. Extend its own units, row table and tests only for a missing call or a measured regression on a supported workload. The current production build cannot switch plugins today. Dense 27B needs attention, quantisation and transport that stock native rows do not cover. Flash-Next helpers depend on another calling and weight-layout contract. The [integration sequence](INTEGRATION.md) tracks these as separate changes.

## How much current model coverage is visible?

Joining the **graph** column of each archived 27B skeleton report to native `kKernels[].op` found 38 of 42 MXFP4 op names and 32 of 36 INT8 op names. Both graphs name four ops absent from the native table: `attn_dense`, `gemm_nt_bias`, `grid_embed` and `rope_table`. These are leads for static resolution. Record which calls really issue in the supported workload, including optional media paths only where supported. Check geometry, weight encoding, operand shapes, strides, ranks and launch status for each selected row. For example, native has `attn_paged` but the served 27B requires head dimension 256. The [row inventory](native-rows.tsv) lists every native row and which old graphs mention its **op**. The graph columns do not identify row selection. ## Local code to retain, replace or retire

The generated component reads the pinned `libr4d/CMakeLists.txt` (111 device units at the pristine pin), applies shared and per-file native rewrites, generates one include wrapper per selected unit, and compiles the rewritten upstream declarations under private names. `exclude.txt` has no active exclusions, though partial builds can restrict units. Generated assembly stubs fill undefined entries. `r3_registry.cpp` discards any row with a stubbed launch, init, fini, scratch, layout, relayout, unrelayout, operand-shape, fusion or tuning predicate and maps remaining indices back to the original table. The old library thereby inherits unrelated gfx12 rows, patches and selection decisions. Native builds 62 explicit HIP units and two declaration sources; implement missing rows directly and check their public hooks. ## Why stock selection and transport cannot serve mixed TP

The loader uses `RTLD_NOW | RTLD_LOCAL`, checks ABI version and layout fingerprint, validates shared schemas positionally, and filters a plugin's device rows using code objects registered during its dlopen against one registry `code_device`. A cached mapping may register no new objects on a later open. `rad_plugin_info.build_target` is descriptive. Native `rad_plugin_open` checks for *any* gfx11 node in KFD topology, also relevant to offline tools choosing a weight layout. Selection then takes the first eligible plugin in hierarchy order and the highest priority **within** it. A broad early provider can mask the entire native table. Explicitly bind comparison libraries and preserve per-rank executable eligibility independently of file name, loading order and host inventory. [Loader](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/plugin/loader.cpp) · [Selection](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/plugin/select.cpp)

Upstream `usable_devices` restricts default ranks to the first selected architecture. Merely compiling two code objects does not implement mixed-rank selection. Preserve the existing rad0016 ordered rank map, code eligibility per rank through selection/resolution/bands, per-rank reference gate, collective agreement and receipts. Carry the admitted uneven head/FFN/state partitions and actual rank-local weight layouts. A helper runs in its own process and does not participate in the engine's TP rank rendezvous. [Upstream bring-up](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/engine_bringup.cpp) · [Current mixed-rank owner](../../../engines/radiance/patches/rad0016_vtp14_rank_code_selection/README.md)

Stock gfx12 `r4d_ar_entry.hip` keys a rendezvous by `tp_group` within that DSO, retracts timed-out arrivals and distinguishes peer-visible VRAM from mapped pinned host scratch. A gfx11 copy in another DSO has a separate static store even with identical keys. Implement only the needed native gfx11 transport, share the group rendezvous across the participating DSOs through the existing owner, and preserve per-rank lifetime, poison, timeout and drain. Alternative to assess during design: one narrowly scoped dual-ISA collective provider shared by all ranks if it can express the exact same placements, device-code checks and wire semantics. Do not implement both designs. In either case keep gfx12/gfx11 wire selection in agreement before init/launch. Check exact two-shot TP3, TP2 WHT6 for the dense profile and exact TP2 for Flash-Next on host-mapped memory; P2P requires its own activation proof if claimed. [Upstream collective state](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/libr4d/r4d_ar_entry.hip) · [Local shared-slot implementation](../../../engines/radiance/patches/rad0017_vtp14_n3_shared_rendezvous/README.md)

The optional collective hook returns 1 when the engine owns the link hold. Value 2 permits early release by a kernel that reads its supplied device gate, decrements an odd value at system scope after peer bytes land, and signals `RAD_LINK_ENDED` for that path. With no hook only conventional `all_reduce` is recognized automatically. BigCherry maps live indices back to upstream and clamps every nonzero collective classification to 1. Start with 1 for implemented collective rows, including fused ops. Do not claim early release or chaining until the device path proves it under concurrent bulk DMA, repeated requests, timeout and restart. Test a misconfigured rank, partial start and a fresh engine generation so a bad launch cannot leave later traffic waiting on an odd gate. [ABI contract](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/abi/rad_abi.h) · [Existing live-index mapping](../../../engines/radiance/components/libr3/r3_registry.cpp)

## Helper ABI and ownership

A simple `archs.toml` change to `libr3d.so` would fail before any tensor runs. The worker opens **one** DSO, requires `bc_r4d_configure_helper`, checks ABI/version/fingerprint/build-target/open, then chooses several rows by exact preferred name or the first row for the op. It requires MoE layout and relayout, resolves one specific FP8 MoE row, and unconditionally calls `r4d_moe_gemm_pin_down_tile`. Prefill and long-row tuning setters are conditional. Native `moe_gemm_w4a8` exposes neither the nonlinear encoding nor that local helper ABI. Initialising a second library in the engine's search path cannot satisfy the helper's handle-specific lookups. [Worker loader and layout](../../../engines/radiance/components/moe-remote/moe_remote_gpu.h) · [Helper configuration ABI](../../../engines/radiance/components/moe-remote/worker_plugin_config.h) · [Architecture map](../../../engines/radiance/archs.toml)

Give the existing worker backend explicit supported formats and row/layout selection, validate the expected schema, and replace private r4d setters with typed per-worker settings for the features retained. Keep shared-memory handoff, small/large lane scheduling, ownership, cache admission and combining in their current owners. Prove full-width expert loading, even/odd and packed geometry, activation scales, budgeted scratch, routing and teardown in the real helper process. A candidate may qualify as an engine-rank provider before it qualifies for the helper role. Publish each role's actual availability. Keep the gfx1030 helper build and its qualified layout operative where currently supported. [Backend boundary](../../planning/active/build-radiance-components/RCS01.md) · [Helper plugin checks](../../../engines/radiance/components/libr3/helper_config_exports_test.cmake)

## Stages and verification commands

1. Freeze local baseline, remote source identity, compiler/ROCm, code objects, engine/plugin ABI and layout fingerprints, fixture/container hashes, role and device order. Build unmodified native and its matching oracle in an isolated lane. For kernel attribution, compare matched engine/plugin ABI on identical inputs. Cross-version serving is a separate whole-system comparison. Use KAB01 for A/A and A/B. No implicit legacy provider or debug reference acceptance in the candidate serving home.
2. Capture **issued** geometry, layout/tag, selected library/row and refusals for the supported named configs. Split native compute into unchanged, missing, and regression-only work. Validate native TP1 on a representative gfx1100 case first. Add native tests for the actual missing family before contributing its rows. Fix the INT8 scheme, h256 attention and required MoE layouts where applicable. Repeat the comparison without an override to verify normal selection.
3. Bring up supported homogeneous engine ranks with the correct host wire; qualify helper consumers separately. Then qualify mixed ordered ranks and uneven partitions with the group-rendezvous change. Capture per-rank row/code/provider and exact transport from the real engine. Prove load/drain/restart, logits/KLD, TTFT, multi-stream decode and acceptance under the workload's existing contract; keep matched raw receipts. Check settings/provenance across measure and serve. Stop a failing mode at the last qualified build.
4. Retire the generated gfx1100 component only when every supported mode is verified or explicitly taken out of service, and the remaining gfx1030 build has its own maintained dependencies. Migrate release inventory, lane membership, helper selection, configuration/tests, bench wrappers and drift tooling in the same cutover. Rebuild the new runtime in an empty install home and verify the named launch with no old `libr3.so` present. Keep the previous qualified installation and receipts as a rollback target until the release gate passes.

Suggested commands for the implementation lane follow. Substitute paths from the lane receipt. Use the existing GPU lease for any device phase, A/B, KLD or throughput run.
