# Native RDNA3 integration and retirement gates

The goal is to extend upstream's native gfx11 implementation. Keep BigCherry changes as small source patches to `libr3d` or to the existing independent helper/engine owner for behavior that is not a kernel. Do not add a second source generator, duplicate the native row table, or package two implicit gfx11 providers. See the [Astra assessment](ASSESSMENT.md) for the implementation comparison.

| Stage | Owner | Proof before proceeding |
| --- | --- | --- |
| Baseline | [RCS15](../../planning/active/build-radiance-components/RCS15.md), [KAB01](../../planning/active/run-kernel-ab/KAB01.md) | Refresh upstream HEAD and record exact commits. Load native with a matching oracle and explicit library order, prove actual gfx1100 code object and row selection. Separate reference correctness from timing and uncovered geometry. |
| Compute | [RCS16](../../planning/active/build-radiance-components/RCS16.md) | Reuse native dense coverage first. For each missing row, identify an actual model call and its schema, dtype, shape, packing and constraints. Add a native implementation only when required. Validate decode and prefill independently. Follow RUM07 for KV format and RUM08 for recorded/speculative passes. |
| Transport | [RCS17](../../planning/active/build-radiance-components/RCS17.md) | Preserve actual rank ISA, uneven partitions, exact wire, shared group rendezvous and drain/failure semantics. Establish gfx1100 TP first, then the supported mixed topology and helper cases. A helper loading a plugin and a rank executing a plugin are different interfaces. |
| Cutover | [RCS18](../../planning/active/build-radiance-components/RCS18.md) | Prove installed asset and exact row selection on every claimed lane. Keep prior qualified asset for recovery. Remove the rewrite build only after all live consumers migrate or are explicitly withheld. |

## Update consumers in dependency order

1. **Build and identity.** The [engine recipe](../../../engines/radiance/recipes.toml), [engine declaration](../../../engines/radiance/engine.toml) and [component declaration](../../../engines/radiance/components/libr3/component.toml) currently own targets, membership and generated output. Turn on the target's native gfx11 build and keep the matching gfx12 code where needed. Do not change the meaning of ROCm/compiler identity. Pass BRBC05 runtime identity before reporting timed wins. Scope comparison artifacts explicitly to source, compiler, ABI layout fingerprint and installed binaries; the previous pin is an operational fallback, not a controlled kernel timing arm.
2. **Discovery and helpers.** Audit the architecture-to-plugin map in [archs.toml](../../../engines/radiance/archs.toml), helper component declarations and their [configuration fixture](../../../engines/radiance/components/moe-remote/helper_settings_test.cpp). Derive the exact plugin from a qualified role and format; do not blindly rename it. Confirm helper-only processes see the intended device, load the expected code, and resolve their required row and layout. Preserve independent ownership and fresh admission.
3. **Profiles, release and tests.** Migrate real manifest settings and SDK/release artifact checks, not just file names. Move retained arithmetic fixtures before retiring `r3_selftest` or `r3_rewrite_check`. Archive old timing and provenance records. Drop generated native rewrite inputs only after the build, discovery, generated contract, named configuration and smoke paths no longer refer to them.
4. **Measure with comparable evidence.** The [tracked first A/B arm](../../evidence/2026-11-17-work-root-results/kbench-libr3d/ab1/libr3.report.md) reached four library rows and timed 116 cases; it explicitly checked zero. Reuse its fixture recipe and row bands, not the result as a correctness or cutover gate. Use the existing [A/B wrapper](../../../tools/lab/radiance/kbench_ab.py), preserve absent rows in reports, and record selected-row behavior on a real model before a release claim.

Start with a card-free build/ABI gate and one leased, matched gfx1100 workload. Add hardware cases when changing the claimed device, layout, format, collective or replay mode. A dense result cannot qualify Flash-Next, a TP1 result cannot qualify TP, and a gfx1100 result cannot qualify RDNA3.5 or RDNA2.
