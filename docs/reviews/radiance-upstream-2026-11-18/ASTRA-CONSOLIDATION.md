# Astra review of the Radiance 2.x migration

**Decision for the first release.** Run one managed model through the native fleet configuration and retain one BigCherry admission contract for the processes that need it. Removing the second implementation of native engine configuration is the main reduction. Move only the helper and measurement code that survives that change. The proposed bundle index, normalized native configuration writer, parser-tree extension hook and independent copy of every engine option would each add another interface to maintain on the next bump.

This is a source review of baseline `19d4e8fe`, target `b8bca788` and the BigCherry packages in the [patch inventory](patch-footprint.json). None of these recommendations changes the current pin or confers runtime acceptance.

## A launch path with two owners

1. **Radiance owns engine options.** Author one native YAML document per selected deployment. Native `defaults`, YAML merges, `models`, `server`, `memory` and `scheduler` retain their upstream meanings. A named bc-serve start already selects a deployment. Use that selection for the existing helper/layout, calibration and power inputs. An optional top-level `x-bigcherry` selector is justified only if the entry point must carry this selection in the YAML. Keep any such selector closed and parse only its owned fields. Native YAML already accepts unrelated `x-*` anchors. It does not promise to execute them. Never rely on that namespace to enforce managed admission.
2. **Resolve native options with the target's code.** `fleet::parse(text, origin, &fc)` yields `ModelEntry.cfg`, ordered effective flag material in `entry.args`, and per-option source in `cfg.given`. `Reader::build_model` owns native validation and default merging. Use that implementation at a consumer needing native facts. Only the launcher and engine need those facts. A helper needs its verified role, model identity/path, layout and plugin parameters. Avoid linking the entire runtime into the helper. The current bc-serve builds separately and native config lives within `rad_core`. Share the minimum build target needed for the existing parser, or get only the planning facts from the matched engine if linking drags the GPU runtime into the launcher. The present native `--check` prints just name, model and TP. It cannot supply every planning input.
3. **Bind approved native bytes to measured admission.** Read the authored YAML once under a defined path/environment policy. Bind its byte digest and the exact parser/engine/runtime build identity through the existing versioned admission contract. Use the identical bytes for planning, serving and stored replay. Reuse the sealing logic in `session.cpp::PinnedManifest` for a config input to the exec boundary. Fresh starts as well as stored starts need this guarantee. For a replay to work after the author file changes, retain the exact non-secret config bytes with the existing stored entry or bind a verified immutable source by digest. A reference to a mutable pathname alone fails this condition. Store secrets by reference, never inline credentials in a retained config. A parser in another process can parse the same bytes under the same controlled defaults; duplicating a native parser/serializer would be much more work.
4. **BigCherry owns only cross-process settings, derived decisions and proofs.** Use the existing registry generator, strict reader, role views and S8/S10 machinery for measured memory, ownership and admission, per-role kernel state, power policy and provenance. Change the wire identity when removing fields. Invalidate obsolete measured/replay entries with an actionable way to reprepare them. Avoid multi-version fallback or introducing a fleet contract for a one-model migration. A derived value needed by a helper or a safety check may appear as an identified assertion. Cross-check it against the authoritative native value. It must never act as a second source of operator defaults.
5. **Serve through the native lifecycle.** Managed starts must establish the patched engine's capability and matching build before helpers start. Bind the verified contract at engine creation and check the expected plan before serving. Preserve the measuring-only plan export on the offline route. Admit a single managed model, no park/reload that can evade the contract, and a disjoint helper topology. Handle both admin and SIGHUP paths at the common reload operation. Stock/native-only use can continue through the normal entry point. Re-preparing an input and restarting the session is sufficient in this release.

Upstream evidence is in [fleet/config.h](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/fleet/config.h), [Reader::build_model](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/fleet/config.cpp) and [main.cpp](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/main.cpp).

**Cache and default identity.** A conservative cache miss when only a comment changes is acceptable for the first bump. Combine the native byte identity with the appropriate *existing* model/build, ordered device, selected helper/calibration and placement inputs. Match or explicitly constrain environment-derived settings, notably `RADIANCE_HOME`, `RADIANCE_KERNELS` and secret references. Preserve path resolution for relative model and file inputs across launch and replay. A changed binary can change defaults even for identical bytes. Keep measured outputs (e.g. derived host pool), run-specific shm/nonce and observations outside the input that produced them. If measurement produces an executable limit such as host pool, bind it once as an admitted typed input at engine construction, with documented precedence or refusal for an explicit conflicting native setting. Do not rewrite the operator's YAML with measured outputs to feed the next planning iteration. The producer's `plan_key_inputs`, strict reader's `v2::plan_cache_key` and `static_resolution_key` support different consumers. Keep exact replay identity separate from reusable calibration identity and fresh room checks.

## Placement and lifecycle corrections

**Single-model placement needs no new broker reservation API.** At this specific target `Fleet::use_broker()` is `models_.size() > 1`. `Fleet::run` retains explicit card order, `choose_cards` takes the first TP cards without the broker, and `load_op` assigns the result to `cfg.devices` before constructing the engine. The broker is installed only for a multi-model fleet. Therefore the proposed external helper reservation in `Fleet::grant` would miss the initial production lane. Use an explicit engine-only card set equal to TP (or prove the identical order of the existing process mask), keep helpers disjoint, and retain measured per-BDF GPU and host admission. Refuse mismatch before allocation. Extend shared reservations only when actual managed co-residency or resource sharing is required. [Fleet implementation](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/fleet/fleet.cpp).

**Ordinal namespaces matter.** Existing `plan_engine_only` computes `ROCR_VISIBLE_DEVICES` from physical BDFs and passes HIP child ordinals `0..tp-1`. Native `cards` and `Config.devices` name devices visible *in that process*. Check the native vector against fresh ordered BDFs in that namespace. Native offline main directly constructs `Engine(cfg)` and skips `Fleet::choose_cards`. Arrange the same selection for measurement/KL, including same-architecture cards in a nontrivial order. For mixed architectures, upstream `usable_devices` still filters unlike cards and `set_code_device(devs[0])` checks only one card. Remove rad0016's duplicate selection mechanism where native devices suffice. Retain the mixed-ISA eligibility, actual code-object checks, per-rank reference and collective agreement. A managed fixed selection need not expose a second native-facing `--rank-devices` flag. [Engine bring-up](https://codeberg.org/StillDeadcode/radiance/src/commit/b8bca788/core/engine_bringup.cpp).

**Preserve existing ownership protocols.** For rad0002, replace global `g_layer_maps`, callbacks and function-static cached policy with a model-lifetime view of the admitted plan. Reuse the existing worker admission ledger/parent tickets. Skip local expert bytes only for covered passes. The static plan and runtime local-slot encoding must agree through reload, fallback, speculative passes and teardown. An independent model-byte check in the helper remains valuable across the process boundary. For rad0017, upstream already groups its rendezvous by `tp_group` and rolls back timed-out arrivals. BigCherry's two independently loaded DSOs still need one shared rendezvous for the *same* group. Preserve its failure/poison semantics, drain before releasing buffers, and reuse the upstream group key. A new allocator, placement solver or independent global epoch would add no capability to this migration.

State explicitly how other shipped configurations remain supported, pinned, or withheld before changing a common pin. |

Use one representative native value and one helper extension, one altered input refusal and a helper-off control. Do not build a bundle index or native schema generator. |

| RUM07/RUM08 | Evaluate native alternatives early and independently where their code permits. Resolve format/replay/controller choices *before* porting each affected hunk. Run retained-format and scheduler/replay checks only for the supported paths. Gate integrated qualification on the selected ABI/placement/runtime. |
| RUM09 | Use the existing matched release and measured canary gates. Include the installed normal/measure/stored-start entry points, unchanged build/config admission, stale input refusal and the previous performance/quality thresholds. Report remaining configuration coverage explicitly. |
| RUM10 | Optional after single-model parity. Decide on fleet resource sharing, cross-engine plugin safety, hot reload and immutable multi-model binding only for an actual co-residency requirement. |

**Minimum source-to-runtime proof during implementation.** A native option absent from BigCherry's registry passes through the real named launcher under native validation; a wrong-level native key fails there. Two starts consume the same admitted YAML/contract despite a later author-file edit, or refuse a changed digest before any child/power mutation. Measurement and serving see the identical model, TP ranks and memory semantics. A cached start still refuses inadequate fresh room and a partial helper start still rolls back. Use the existing short hardware gate for the selected workload and the existing helper-off control. No compile, device, quality or performance result was obtained during this review.
