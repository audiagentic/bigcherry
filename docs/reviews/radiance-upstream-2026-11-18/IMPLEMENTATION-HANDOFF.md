Keep the common production pin at v1.17.0 while the candidate is being qualified. BigCherry source for the original handoff is `1f1547e72953`. The frozen candidate for this migration is Radiance v2.1.0 commit `3deabdaeca17b58bad90d332f4b204cf7bb8a10e` (ABI 43); the production endpoint is v1.17.0 commit `19d4e8fe` (see the [review record](README.md)). All commands below are future checks; this handoff records source review and previously recorded evidence, not runtime acceptance.

## Implement the boundary

1. Add one operator-authored fleet document per deployment and mode that changes native settings. Use `engines/radiance/configs/flashnext-4gpu.yaml` and `flashnext-r9700.yaml` as the proposed installed config names. Supply a separate quality fixture where the helper-on arm needs shorter context or depth 0. Retain one BC-only named hardware/helper profile per existing name. A named start selects its YAML and BC profile. Remove migrated native TOML values and competing native `--set` overrides at every migrated caller. Resolve relative model and file paths under an explicitly recorded execution root (the supplied model root for this lane); run planning and child parsing under that same root. Native `fleet::parse(text, origin, &fc)` stores `origin` as `FleetConfig.path` as well as using it for parser context; the fleet reload path can reopen that path. Managed reload must therefore refuse before any file-based re-entry (both SIGHUP and admin), or a future design must bind reload to the same admitted immutable bytes. Avoid shell expansion or a generated YAML writer. Require local model bytes and an explicit, verified runtime home and ordered plugins. For relocatable bundles supply site-local YAML or a stable install-relative path under the bound working directory.
2. Implement native resolution with the target's `Reader::build_model` and `config_parse`. Share the native parser target with bc-serve if it can be linked without device initialization. If separation from `rad_core` is impractical, have the matched engine run its own parser in a read-only subprocess and return only the fields consumed by admission. Pin the actual parser/binary/runtime identity. The native `--check` prints insufficient fields for P1. Keep the helper on its authenticated role view. The [113-row binding inventory](SERVING-OPTION-INVENTORY.md) identifies native mirrors, local consumers and removed options. Move `v2/p1_producer.cpp` model, runtime directory, context and concurrency reads and `v2/helper_settings.cpp` model, runtime directory and TP reads. Move session port/readiness, campaign launch and bench receipts to the actual listener/session receipt. Preserve the effective depth/profiling guard in `runtime_guards.cpp`.
3. Use the existing strict manifest file as the only persisted native snapshot. Proposed successor wire identity is `bigcherry/v3`, contract version 3, with generated schema and semantic fingerprints. Add `spec.native_config.yaml_utf8` (original decoded UTF-8 bytes, losslessly escaped only by JSON), `sha256` (SHA-256 of exactly those bytes), and `resolution_root` (verified site-local working directory). The existing measured engine identity and producer identity bind the binary/runtime; include matched parser identity if separately linked. Compare exact bytes including comments and line endings. Verify size/UTF-8 before expansion and enforce the existing 16 MiB limit on the complete strict document. Only store non-secret configuration. Use `server.api-key-env` where required and refuse literal credentials before storing. Keep an approved secret reference/version in local admission when available, resolved material out of serialized manifests, option dumps and receipts. Limit the first managed inputs to known non-secret site files, including comments and ignored anchors. Preserve the actual path/file identities needed by model, heat and calibration. Require a compatible root, runtime/plugin search order and secret reference on replay.
4. Extend the current registry/generator, strict reader, writer and role views in place. Place immutable bytes in the unmeasured and measured documents, each with its own existing state/digest. Use the existing file `RUN_DIR/manifest-<id>.json`, its `.replay-index.json` attestation and `.s8-evidence.json`, plus the named `stored-<sha256(config)>.index.json` pointer. Keep this 8 KiB index small. Do not store a second YAML sidecar. Only publish the named index after writing and verifying the complete manifest and its required evidence. Reuse session owner locking and the temporary-file/rename writer. For fresh, measured and stored launches pass authenticated bytes across exec in sealed descriptors using `session.cpp::PinnedManifest`. A helper receives only its manifest role. The engine receives the identical native bytes via a sealed config descriptor and the measured contract via a sealed manifest descriptor; verify their digest relationship before constructing the engine. The measurer takes an unmeasured contract only on its explicit offline operation. Serving requires measured state.
5. Delete the rad0009 argv/provenance shim and its static buffers after migrating named daemon, measuring, KL, helper-off, stored start, engine adapter and installed smoke/fake callers. Retain the typed plugin state, launch nonce, BDF assertions and rad0011 expected-plan check under the admitted engine/session. Retain owner-map verification against model bytes, S8/S10 resource/owner/power checks and rollback. Delete native-only branches of `engine_option_fields`, `engine_of`, `leaf_of_key` and the duplicated typed Engine after redirecting readers. Keep BC-owned helper, diagnostic and local patch behavior only for its admitted scope. Refuse managed hot reload at the shared `Fleet::reload()` for both SIGHUP and admin, and prevent managed park, unload or an unadmitted lazy load. Verify one-model/disjoint roles and the matched engine capability before any helper spawn or power mutation. In normal fleet load check the final selected cards before allocation. In offline KL/measure, set the same ordered `Config.devices` explicitly before direct Engine construction.
6. Derive safety-critical limits once per measuring round. An explicit native host-pool/host-KV/reserve/checkpoint setting that conflicts with admitted values is an admission error. If absent, pass the identified admitted limit through a typed per-engine input and log its origin. The same immutable YAML is admissible for a subsequent measuring round that feeds back a different computed limit. Key that trial by its effective input limit and remeasure before accepting it.
