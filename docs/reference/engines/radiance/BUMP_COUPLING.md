# Radiance bump coupling inventory

**Snapshot:** 2026-11-18, production Radiance pin `v1.17.0`. This is a dependency ledger, not a request to move the pin or an acceptance certificate. RUM01–RUM10 own the upstream 2.x migration; BHK02–BHK04 own host-kernel restoration.

## Coupling declaration and mapping rules

- **DECLARED** means a specific upstream header/source, option/env, ABI, or protocol is recorded in managed component.toml/patch.toml and checked mechanically against both its consumer and upstream version. **UNDECLARED** means the complete checked contract is absent. This baseline is UNDECLARED: component built-against, patch.toml requires and patch.py FilePatch targets already exist, but no merged gate covers every ABI/header/option/env consumer.
- **No competing RUM plan.** RUM03 owns dependency/plugin ABI first, RUM04 then binds exact immutable original upstream YAML bytes to the existing measured BigCherry contract and deletes native duplication, RUM02 then extracts surviving injected implementations, RUM05 placement/accounting, RUM06 engine-scoped remote MoE/collectives, RUM07 KV layout, RUM08 MTP/scheduling, RUM09 end-to-end release acceptance; RUM10 optional multi-model support is deferred.
- **Distinct identities:** upstream pin, component built-against, plugin ABI/layout, contract digest, stored-manifest digest, owner-map generation, per-start power ID, and asset tag/digest are separate fields with separate validity gates.
- The machine-checked metadata milestone must update statuses below only after the gate proves each declaration; a clean patch apply does not prove that the runtime API and semantic contract still hold.

## RUM gaps and rules for migration

1. No numbered RUM port item owns rad0005 (FFmpeg 6 writer), rad0007/rad0008 (HC PF2 experimental down/upmix) or rad0023/rad0031 (AR/TS timing diagnostics). Treat them as explicit **GAPS** for RUM01's per-patch retire/reuse/port disposition, not automatic blockers for RUM09's minimal selected configuration. BHK02–BHK04, not RUM, own the host GFXOFF kernel.
2. The current typed RSC12 and step-6 settings enter via serving/contract/serving-v2.toml, session.cpp, serving.cpp, config_loader.cpp and rad0009. For the current pin, reuse the already-generated serving-v2 field registry as the **single temporary translation authority**, with tests for every emitted upstream flag/env and unused entry; do not add a second native-field table. Its header must state that **RUM04 retires this bridge in favour of upstream fleet::parse on the same admitted immutable original YAML bytes plus the existing measured BigCherry contract**. Do not add a normalized config writer, FleetConfig serializer, parallel YAML/JSON resolver or bundle-index service.
3. Keep source/include paths and native plugin ABI separately checked. RUM03's plugin ABI migration cannot update a constant without rebuilding libr3/libr2/moe-remote/ngram-helper/bc-gfx12 for the same layout fingerprint. Preserve strict helper 16-byte ticket and v26 SHM protocol while RUM06 ports TP-group lifetimes.
4. High-overlap patch anchors include core/main.cpp, core/config.cpp, core/engine_bringup.cpp, abi/rad_builder.h, arch/qwen35_fp8/qwen35_fp8.cpp and libr4d/r4d_rows.cpp; use the existing FilePatch dependency and patch-footprint reports rather than ad-hoc source regex edits.
