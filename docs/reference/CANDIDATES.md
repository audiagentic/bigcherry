# Candidate reference

Generated by `PYTHONPATH=tools python -m bigcherry.analysis.candidate_report`. Do not edit by hand --
regenerate it, and add analysis to the plan items under `docs/planning/` instead.

Run `python3 -m bigcherry generate` to produce the current manifest before regenerating this report. Drop new tuning logs into `artifacts/tuning-logs/` named `<arch>-<family>-s<screen>f<final>.log` (or `-native`) and the provenance is picked up automatically.

## How to read this

A candidate existing means the catalog enumerated it. It does **not** mean
it can run on your GPU, and it does not mean it has ever been measured.
Three separate things, and conflating them is how this project has
repeatedly fooled itself:

- **Generated** -- in the manifest.
- **Runnable here** -- `architecture_mask` admits the GPU *and* the
  family's `can_execute` accepts the signature. An `mmf:f32` candidate is
  generated on every build and runnable on none of this project's GPUs.
- **Measured** -- actually timed. A candidate can be eligible on every
  signature and never win one.

For per-signature tuning results (winners, rankings, improvements), consult
the tuning database. This document tracks the candidate space only.
