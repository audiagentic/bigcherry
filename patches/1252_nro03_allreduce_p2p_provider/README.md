# 1252_nro03_allreduce_p2p_provider

Plan `PNRO03`; no required patches (HIP internal AllReduce is native upstream since b11126).

Generated by `work/forks/make_allreduce_ports.py` + `work/forks/nro03_adapt.py` with `bigcherry.patch.port_diff` (verified byte-exact, idempotent). The fork's HIP-enable hunks are already upstream (upstream spelling kept); the fork's orphaned `#endif` is dropped.

BigCherry has real gfx1100 evidence that destination-current/pull peer copies can return success with wrong data, so the fork's design is adapted:
- no `GGML_CUDA_AR_P2P_ISSUER`: each direction has its own stream/events on its SOURCE device and issues `cudaMemcpyPeerAsync` with that device current;
- `ggml_cuda_ar_p2p_probe` at init: asymmetric nonzero patterns, sizes 4 KiB / 64 KiB+256 / 1 MiB / 4 MiB, both directions, two passes, byte compare; any failure leaves P2P off (host staging) with a warning;
- activation marker `BIGCHERRY_PATCH_HIT patch=1252_nro03 path=allreduce_p2p_source_push` under `BIGCHERRY_PATCH_TRACE`.

Kernel-side direct peer reads/writes remain out of scope.
